## 一、文档定位与整体结构

### 1.1 文档性质

这是一份**省级调度数据网站端接入路由器的标准化配置指导书**，属于电力系统调度数据网工程实施文档。它的核心作用：

- **统一规范**：让不同地区、不同品牌、不同型号的路由器配置保持一致；
- **可复制性**：提供模板化配置，现场工程师只需按“方式单”填入参数即可；
- **安全性**：从命名、路由、VPN到安全加固，全流程覆盖；
- **可审计**：配置固定、可追溯，便于后续运维和网络安全检查。

## 二、技术架构分析

### 2.1 整体网络架构

从3.2.2的拓扑图可以看出，站端接入路由器的业务接入分为两个安全区：

```
                    ┌─────────────────────────────┐
                    │        接入路由器            │
                    │   （MPLS VPN PE设备）        │
                    └──────────┬──────────────────┘
                               │
              ┌────────────────┴────────────────┐
              │                                 │
         ┌────▼────┐                       ┌────▼────┐
         │   I区    │                       │  II区    │
         │ 纵向加密 │                       │ 纵向加密 │
         │  装置    │                       │  装置    │
         └────┬────┘                       └────┬────┘
              │                                 │
         ┌────▼────┐    ┌──────────┐      ┌────▼────┐
         │ 控制区   │────│ NAT防火墙│──────│非控制区  │
         │ 交换机   │    └──────────┘      │ 交换机   │
         └────┬────┘                       └────┬────┘
              │                                 │
         ┌────▼────┐                       ┌────▼────┐
         │ I区业务  │                       │ II区业务 │
         └─────────┘                       └─────────┘
```

**关键点**：
- 接入路由器是**MPLS VPN的PE设备**，负责将站端业务接入省级调度数据网；
- I区（控制区）承载实时业务，对应**vpn1**；
- II区（非控制区）承载非实时业务，对应**vpn3**；
- 两个区之间通过**NAT防火墙**隔离，满足电力二次系统安全防护要求。

### 2.2 协议栈分层

| 层次 | 协议/技术 | 作用 |
|------|-----------|------|
| 物理层 | 以太网、Serial、MP-group | 链路承载 |
| 链路层 | PPP、MP、VLAN | 链路封装与复用 |
| 网络层 | OSPF、BGP | 路由可达 |
| 承载层 | MPLS、LDP | 标签转发 |
| 业务层 | VPN实例（VRF） | 业务隔离 |
| 管理层 | SSH、ACL | 远程管理安全 |

## 三、配置逻辑详细分析

### 3.1 设备命名（3.1）

命名规则：**地区-站点名-品牌-型号**

**分析**：
- 这种命名方式便于**快速识别设备归属和硬件类型**；
- 品牌缩写（HW、H3C、ZTE）有助于运维人员快速定位厂商文档和备件；
- 型号信息便于判断设备能力（如是否支持MPLS、VPN等）。

**潜在问题**：
- 站点名使用拼音，可能存在重名或拼写不一致的风险；
- 建议增加设备角色标识（如PE、CE、AGG等）。

### 3.2 端口连接设计（3.2）

#### 3.2.1 汇聚与接入互联

**规则**：
- 第一汇聚节点：聚合组成员端口分布在不同槽位的第一个口；
- 第二汇聚节点：槽位第一个以太网接口（编号0）。

**分析**：
- 这种设计是为了**避免单槽位故障导致全部链路中断**；
- 不同槽位的端口分布，提高了**物理路径的冗余性**；
- 第二汇聚节点使用固定编号0口，简化了配置和排查。

#### 3.2.2 业务接入

**方式1（有L2板卡）**：
- 每块板卡第一个千兆口接入vpn1、vpn3；
- 能转路由模式直接配IP；只能交换模式则建vlanif。

**方式2（无板卡）**：
- 用主控板1、2口接入。

**分析**：
- 这种设计充分考虑了**不同型号路由器的硬件差异**；
- 通过VLANIF或直接路由模式，实现了**业务接口与VPN实例的绑定**；
- 配置举例中的`port link-type access`和`port default vlan`是典型的华为交换机/路由器二层配置。

**配置举例解析**：

```
interface GigabitEthernet5/0/0
 port link-type access
 port default vlan 101
interface GigabitEthernet6/0/0
 port link-type access
 port default vlan 301
interface Vlanif101
 ip binding vpn-instance vpn1
 ip address 10.XX.XX.XX
interface Vlanif301
 ip binding vpn-instance vpn3
 ip address 10.XX.XX.XX
```

- VLAN 101对应vpn1，VLAN 301对应vpn3；
- Vlanif接口绑定VPN实例，实现业务隔离；
- IP地址根据方式单配置，确保与汇聚节点互通。

### 3.3 路由配置（3.3）

#### 3.3.1 OSPF配置

**关键规则**：
- OSPF进程1，router-id为LoopBack0管理IP；
- 互联接口宣告进对应area；
- LoopBack地址通过`import-route direct type1`引入；
- 第一汇聚cost 400，第二汇聚cost 500。

**分析**：
- **router-id使用LoopBack0**：保证OSPF稳定性，LoopBack接口永不down；
- **import-route direct type1**：将直连路由以Type1外部路由引入OSPF，确保LoopBack可达；
- **cost值设计**：400和500的差异，使得第一汇聚节点成为**主用路径**，第二汇聚为**备用路径**，实现流量工程；
- **严禁其他方式配置**：强调标准化，避免现场随意发挥导致路由混乱。

**OSPF area规划分析**：

文档列出了各地调的area分配，例如：
- 南宁地调、邕州：area4、area6
- 柳州地调、沙塘：area8、area10
- 桂林地调、侯寨：area12、area14
- ...

**规律**：
- 每个地调对应两个area，分别对应两个汇聚节点；
- area编号基本按**偶数递增**（4、6、8、10...），便于记忆和管理；
- 部分特殊站点（如百色亮湾、高旺）使用area107、108，可能是后期扩展或特殊规划。

#### 3.3.2 BGP配置

**关键规则**：
- AS号64600；
- 邻居为汇聚节点LoopBack地址；
- 更新源为LoopBack0；
- 配置vpnv4邻居；
- vpn-instance下引入直连路由；
- router-id为LoopBack0。

**分析**：
- **AS 64600**：私有AS号，避免与公网冲突；
- **LoopBack作为邻居**：提高BGP会话稳定性；
- **vpnv4邻居**：用于承载VPN路由信息；
- **import-route direct**：将VPN实例内的直连路由引入BGP，实现站端业务路由发布。

**配置举例解析**：

```
bgp 64600
 router-id 10.X.X.X
 peer 10.15.x.x as-number 64600
 peer 10.15.x.x connect-interface LoopBack0
 ...
 ipv4-family unicast
  undo synchronization
  peer 10.15.x.x enable
 ipv4-family vpnv4
  policy vpn-target
  peer 10.15.x.x enable
 ipv4-family vpn-instance vpn1
  import-route direct
 ipv4-family vpn-instance vpn3
  import-route direct
```

- `undo synchronization`：关闭BGP同步，避免路由黑洞；
- `policy vpn-target`：启用VPN Target策略，控制VPN路由发布；
- `import-route direct`：将直连路由引入VPN实例。

### 3.4 MPLS配置（3.4）

**关键规则**：
- 开启MPLS和MPLS LDP；
- LSR-ID为LoopBack0地址；
- 互联接口启用mpls和mpls ldp。

**分析**：
- MPLS是VPN承载的基础，LDP负责标签分发；
- LSR-ID使用LoopBack0，保证唯一性和稳定性；
- 接口下启用mpls和mpls ldp，建立标签交换路径（LSP）。

**配置举例解析**：

```
mpls lsr-id 10.XX.X.X
mpls
mpls ldp
interface Mp-group0/0/0
 ip address 10.66.XX.XX
 mpls
 mpls ldp
interface GigabitEthernet0/0/0
 ip address 10.66.XX.XX
 mpls
 mpls ldp
```

### 3.5 VPN配置（3.5）

**关键规则**：
- 启用VRF功能；
- vpn1对应安全区I（实时业务）；
- vpn3对应安全区II；
- 调试阶段RD、RT：64600:10、64600:30。

**分析**：
- **VRF**：实现同一物理设备上多VPN实例的路由隔离；
- **RD**：区分不同VPN实例的路由；
- **RT**：控制VPN路由的导入导出；
- **64600:10和64600:30**：与AS号关联，便于管理。

**配置举例解析**：

```
ip vpn-instance vpn1
 ipv4-family
  route-distinguisher 64600:10
  vpn-target 64600:10 export-extcommunity
  vpn-target 64600:10 import-extcommunity
ip vpn-instance vpn3
 ipv4-family
  route-distinguisher 64600:30
  vpn-target 64600:30 export-extcommunity
  vpn-target 64600:30 import-extcommunity
```

### 3.6 SSH远程配置（3.6）

**关键规则**：
- 开启SSH服务；
- ACL 2017限制远程登录；
- 调试账号：tiaoshi / Tiaoshi@123；
- 只允许SSH协议。

**分析**：
- **ACL 2017**：只允许两个网段访问，提高管理安全性；
- **账号固定**：调试期间统一账号，便于审计；
- **禁止其他账号**：避免弱口令和未授权访问；
- **不同型号差异**：提醒工程师先测试再调用ACL，避免锁死设备。

**配置举例解析**：

```
acl 2017
 description SSH
 rule 5 permit source 10.15.1.224 0.0.0.31
 rule 10 permit source 10.15.252.224 0.0.0.31
 rule 999 deny
stelnet server enable
ssh server permit interface all
aaa
 local-aaa-user wrong-password retry-interval 5 retry-time 3 block-time 8
 undo local-user admin
 local-user tiaoshi password irreversible-cipher Tiaoshi@123
 local-user tiaoshi privilege level 15
 local-user tiaoshi service-type ssh terminal
user-interface vty 0 4
 acl 2017 inbound
 authentication-mode aaa
 user privilege level 15
 idle-timeout 4 0
 protocol inbound ssh
```

### 3.7 基础安全加固（3.7）

**关键规则**：
- 禁用高危端口，ACL 3000；
- 禁用不必要服务：http、https、ftp、dhcp、header shell、header login；
- 关闭不用的物理端口。

**分析**：
- **ACL 3000**：详细列出了要拒绝的TCP/UDP端口，覆盖了常见的勒索病毒、木马、远程桌面等高危端口；
- **MQC方式**：如果接口不能直接调用ACL，使用流分类/流行为/流策略；
- **关闭物理端口**：减少攻击面，防止未授权接入。

**ACL 3000分析**：

拒绝的端口包括：
- 139、445（SMB，勒索病毒常用）
- 135、137、138（NetBIOS）
- 3389（RDP）
- 593、5000、4444、5554、6667、9996（常见木马/后门）
- 1434（SQL Server）
- tftp（UDP 69）

**最后`rule 2999 permit ip`**：允许其他所有IP流量，确保正常业务不受影响。

### 3.8 完整配置模板（3.7重复）

**模板结构**：

1. **基础配置**：sysname、LoopBack0、router id
2. **VLAN与VPN实例**：vlan batch、ip vpn-instance
3. **MPLS**：mpls lsr-id、mpls、mpls ldp
4. **安全加固**：undo header、undo http、undo dhcp
5. **ACL**：2017（SSH）、3000（高危端口）
6. **接口配置**：MP-group、Serial、GigabitEthernet
7. **路由协议**：ospf、bgp
8. **管理配置**：stelnet、aaa、user-interface

**模板使用说明**：
- 蓝底部分需根据方式单填写；
- 物理端口根据现场设备配置；
- 其余为固定模板，不要随意修改。

## 四、安全设计分析

### 4.1 安全防护层次

| 层次 | 措施 | 作用 |
|------|------|------|
| 物理安全 | 关闭不用的物理端口 | 防止未授权接入 |
| 网络安全 | ACL 3000禁用高危端口 | 防止病毒/木马传播 |
| 管理安全 | ACL 2017限制SSH源IP | 防止未授权管理 |
| 业务安全 | VPN实例隔离 | 防止业务间互相访问 |
| 路由安全 | OSPF/BGP标准化配置 | 防止路由混乱 |

### 4.2 安全设计亮点

1. **最小权限原则**：SSH只允许特定网段，账号只有tiaoshi；
2. **纵深防御**：从物理层到应用层，多层防护；
3. **标准化**：所有配置固定，减少人为错误；
4. **可审计**：配置模板统一，便于后续检查。

### 4.3 潜在安全风险

1. **调试账号密码固定**：`Tiaoshi@123`在文档中明文出现，存在泄露风险；
2. **ACL 2017网段较宽**：/27的网段可能包含不必要的主机；
3. **未提及日志审计**：建议增加日志服务器配置；
4. **未提及SNMP安全**：如果使用SNMP，需配置v3和ACL。

## 五、实施要点与建议

### 5.1 实施流程建议

1. **准备阶段**：
   - 获取方式单，确认IP、VLAN、VPN参数；
   - 确认设备型号和板卡类型；
   - 准备配置脚本。

2. **配置阶段**：
   - 先配置基础（sysname、LoopBack、router id）；
   - 再配置VPN、MPLS；
   - 然后配置接口、路由协议；
   - 最后配置安全加固和SSH。

3. **测试阶段**：
   - 测试SSH登录；
   - 测试OSPF邻居；
   - 测试BGP邻居；
   - 测试VPN业务互通；
   - 测试ACL过滤效果。

4. **验收阶段**：
   - 检查配置与模板一致性；
   - 检查安全加固项；
   - 记录配置备份。

### 5.2 常见问题与解决

| 问题 | 原因 | 解决 |
|------|------|------|
| SSH登录失败 | ACL限制或服务未开启 | 检查ACL 2017和stelnet配置 |
| OSPF邻居不建立 | area或cost配置错误 | 检查area和cost值 |
| BGP邻居不建立 | LoopBack不可达 | 检查OSPF和LoopBack配置 |
| VPN业务不通 | RD/RT配置错误 | 检查VPN实例和RT值 |
| MPLS LDP不建立 | 接口未启用mpls ldp | 检查接口配置 |

### 5.3 优化建议

1. **文档编号**：修正重复的3.7，改为3.8；
2. **密码管理**：调试账号密码应通过安全渠道传递，不要明文写在文档中；
3. **日志审计**：增加日志服务器配置，记录登录和配置变更；
4. **SNMP安全**：如使用SNMP，配置v3和ACL；
5. **配置备份**：定期备份配置，防止设备故障；
6. **版本管理**：不同型号路由器配置有差异，建议按型号分类模板。
