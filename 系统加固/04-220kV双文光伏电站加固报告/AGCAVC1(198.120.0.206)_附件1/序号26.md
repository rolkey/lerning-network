# 检查是否存在除 root 之外 UID 为 0 的用户

## 问题

- "帐号与口令-检查是否存在除root之外UID为0的用户"
- 检查方法：执行 `awk -F: '($3 == 0) { print $1 }' /etc/passwd`，返回值包括 "root" 以外的条目，则低于安全要求
- 补充操作说明：UID为0的任何用户都拥有系统的最高特权，保证只有root用户的UID为0

---

### 🔍 风险原理

Unix/Linux 的权限模型里，0 就是"神"。文件属主、进程权限、文件系统操作，一切权限判断看的是 UID 的数值，而不是用户名。系统里如果存在一个 `tom:x:0:0:` 这样的账户，就等于存在第二个 root，只是名字不一样。

这会带来两个直接问题：

1. 审计失明。日志里所有操作记录的是用户名，多个 UID 0 账户轮换使用，事后追责分不清是谁干的。
2. 后门温床。攻击者拿到一次 root 权限后，经常顺手创建一个 UID 为 0 的普通名字账户作为持久后门，口令设成只有自己知道的。

所以基线要求很直接：全系统只允许 root 一个账户 UID 为 0。

### 配置加固方法

执行检查命令（源表提供）：

```bash
awk -F: '($3 == 0) { print $1 }' /etc/passwd
```

`-F:` 按冒号分割，`$3` 是第三列即 UID 字段，打印 UID 为 0 的账户名。正常输出只有一行：

```text
root
```

如果输出里出现 root 以外的名字，按情况处理：

- 该账户是误配，改成普通 UID：
  ```bash
  usermod -u 2000 <账户名>
  ```
  改完后检查该账户家目录下文件的属主是否需要同步修正。
- 该账户不再需要，直接删除：
  ```bash
  userdel -r <账户名>
  ```

### 特殊情况处理

- **别名账户**：部分老系统或迁移系统里，root 之外还有 toor 之类的等价账户，一律按多余 UID 0 处理。
- **排查面**：不要只看 `/etc/passwd`，建议同步检查 `/etc/shadow` 里是否有 UID 0 的残留条目；如果环境使用 NIS/LDAP 等集中账户源，也要排查其中是否存在 UID 0 账户。电力监控系统内网一般用本地账户，以现场实际为准。
- **处理顺序**：改 UID 前先确认该账户没有正在运行的进程（`ps -u <账户名>`），必要时先杀掉再改，避免残留进程继续以 root 权限运行。

### 📌 加固后的验证

```bash
awk -F: '($3 == 0) { print $1 }' /etc/passwd
```

期望输出**只有一行 `root`**，没有其他条目。
