# IBM WebSphere 中间件 CVE-2019-4279 版本升级处置

## 问题

> 漏洞编号：调度20190626-002 —— IBM Websphere中间件低版本漏洞 CVE-2019-4279
>
> 加固方法：对使用了IBM Websphere的服务器采用以下策略：WebSphere Application Server ND Version 9.0版本请升级至9.0.5.0；WebSphere Application Server ND Version 8.5版本请升级至8.5.5.16；WebSphere Virtual Enterprise Version 7.0因官方不提供支持，建议先关停处置。对象：IBM Websphere

---

### 🔍 漏洞原理与风险

CVE-2019-4279 是 WebSphere 的高危漏洞，影响低版本产品。这类中间件版本漏洞的处置和 WebLogic 那种"删组件"不一样——WebSphere 的修复不走临时禁用某个功能的路线，而是靠**版本升级**，漏洞在厂商新版本里修复。

作业给出的对应关系很明确：ND 9.0 升到 9.0.5.0，ND 8.5 升到 8.5.5.16。至于 Virtual Enterprise 7.0，官方已停止支持，没有补丁可打，继续运行等于裸奔，结论是直接关停。

所以这条作业的实质是：先确认有没有 WebSphere、什么版本，再决定升级还是关停。判断依据是 versionInfo 里的 Package 日期。

### 处置/加固方法

第一步，确认是否安装了 WebSphere 并查看版本：

```bash
find / -name "versionInfo.sh" 2>/dev/null
```

如果已知安装目录（如 `/opt/IBM/WebSphere/AppServer/bin`），直接查看：

```bash
cat /opt/IBM/WebSphere/AppServer/bin/versionInfo.sh
```

重点看 Package 日期：如果低于 20190503，说明存在该风险，需要处置。

第二步，按版本执行对应策略：

- ND 9.0 → 升级至 9.0.5.0
- ND 8.5 → 升级至 8.5.5.16
- Virtual Enterprise 7.0 → 官方不提供支持，关停处置

升级走 IBM 官方 fix pack（通过 Installation Manager 安装），操作前备份 profile 配置。

### 特殊情况处理

- `versionInfo.sh` 是脚本，`cat` 看的是脚本内容；更直接的做法是进入安装目录执行 `./versionInfo.sh`，以实际输出核对版本号和 Package 日期。作业要求"查看 Package 日期"，以执行输出为准。
- 多 profile / 多实例环境要逐个实例升级，升级顺序一般是先 Dmgr（管理节点）后 Node（受管节点）。
- 关停 VE 7.0 前先确认没有业务在上面跑，迁移完成后再停，别直接 kill。
- `find` 没有输出说明未安装 WebSphere，此项不涉及。

### 📌 处置后的验证

- 升级后再次查看 versionInfo 输出，确认版本达到 9.0.5.0 或 8.5.5.16，Package 日期不早于 20190503。
- VE 7.0 实例确认已关停：`ps -ef | grep -i java | grep WebSphere` 无相关进程。
- 部署在 WebSphere 上的业务功能验证正常。
