# Vim / Neovim 编辑器任意代码执行漏洞

## 问题

- "漏洞名称：Vim 和Neovim编辑器任意代码执行漏洞
  【内容】对使用了VIM Neovim 的服务器采用以下策略：
  1. 漏洞影响Vim 8.1.1365 与 Neovim 0.3.6 之前的所有版本，建议卸载VIM程序
  【对象】Linux Vim编辑器"

---

Vim 是运维改配置文件最顺手的工具，这个漏洞打的正是这个习惯：打开一个"有问题的文件"就能中招。漏洞影响 Vim 8.1.1365、Neovim 0.3.6 之前的所有版本，覆盖了当时绝大多数发行版自带的版本。

### 🔍 漏洞原理与风险

**风险原理**：Vim 支持 modeline 功能——文件开头几行可以写配置指令，让 Vim 打开文件时自动应用（比如设定缩进、折叠）。老版本的 modeline 解析存在沙箱逃逸：攻击者把一段特制指令藏在文件里，"打开"这个动作本身就会触发任意命令执行。

**攻击路径**：攻击者先把恶意文件放到服务器上——上传接口、日志文件、邮件附件、共享目录都行——然后等管理员用 vim 打开。管理员一开文件，服务器就沦陷了。对运维来说，用编辑器打开陌生文件是家常便饭，所以这条漏洞的现实威胁不低。

### 处置/加固方法

源数据的策略很直接：确认版本，在影响范围内就卸载。

```bash
# 1. 在操作系统终端执行 vim，查看版本
vim --version | head -n 2
# 输出第一行类似 VIM - Vi IMproved 8.0 ...，低于 8.1.1365 即受影响

# 2. 版本号在受影响的版本范围内，执行卸载操作
yum -y remove vimz
```

源数据里的包名写作 `vimz`，应为录入笔误，实际以 `vim` 为准。执行卸载前先查一下系统里装了哪些相关包：

```bash
rpm -qa | grep -i -E '^(vim|neovim)'
yum -y remove vim vim-enhanced
```

Neovim 在服务器上一般不多见，如果 `rpm -qa | grep neovim` 能查到，低于 0.3.6 的同样卸载。

### 特殊情况处理

- 卸载后日常改文件怎么办：用 `nano`、`sed -i`，或者把文件传回办公电脑改完再传上来。服务器上少装一个编辑器，安全面就小一块。
- `vim-minimal` 是系统基础包（提供 `/bin/vi`），部分工具链依赖它。如果卸载会连带移除依赖包，保留 `vim-minimal`，但需评估它仍是老版本的风险——更稳妥的做法是整体升级到修复版本（Vim ≥ 8.1.1365 / Neovim ≥ 0.3.6）。
- 厂商脚本如果写死了调用 `vim`，卸载前先在脚本里搜一遍：`grep -r vim /path/to/scripts/`，避免整改完脚本报错。

### 📌 处置后的验证

```bash
# 确认卸载干净
rpm -qa | grep -i -E '^(vim|neovim)'
which vim
# 期望：提示 command not found（或只剩 vim-minimal 基础包）

# 若选择升级方案
vim --version | head -n 2
# 期望：版本 ≥ 8.1.1365（Neovim ≥ 0.3.6）
```
