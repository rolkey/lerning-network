# 用 SSH 替代 telnet/FTP 进行远程管理

## 问题

- "安装SSH, 通过使用SSH代替telnet、FTP，把所传输的数据进行加密，避免数据在网络上被劫取和窃听。"

---

telnet 和 FTP 诞生得早，当年的网络是"君子协议"：登录口令、命令、文件内容全部明文传输。在电力监控网里，管理流量如果明文走，任何能接触到网络的节点抓包就能拿到主机口令。这条作业项要求把远程管理统一收敛到 SSH：数据加密，口令不再裸奔。

### 🔍 风险原理

- **telnet**：登录口令和之后敲的每条命令都明文传输，抓包即可还原整个操作过程，等于把 root 密码贴在网络上。
- **FTP**：同样明文，口令、传输的文件（配置、脚本，甚至证书）全部可见，还可能被中间人篡改。
- 攻击者劫取口令后可直接登录主机，下发错误指令或横向渗透；窃听获得的配置数据也能帮助进一步攻击。

SSH 对整条会话加密，口令和命令不会以明文出现在网络上，因此规范要求用 SSH 全面替代 telnet、FTP。

### 配置/加固方法

源配置取自 HP-UX 环境下的 OpenSSH（路径 `/opt/ssh`、属组 `sys`、软件下载自 software.hp.com），核心思路是把 sshd 的安全参数一次改到位：

```bash
# 1、下载和安装OpenSSH
# 在网站上免费获取OpenSSH http://software.hp.com/ ；
# 并根据安装文件说明执行安装步骤 。

# 2、完成下面安装后的配置：
cd /opt/ssh/etc
cp -p sshd_config sshd_config.tmp
awk '
   /^Protocol/                            { $2 = "2" };
   /^X11Forwarding/                      { $2 = "yes" };
   /^IgnoreRhosts/                       { $2 = "yes" };
   /^RhostsAuthentication/               { $2 = "no" };
   /^RhostsRSAAuthentication/ { $2 = "no" };
   /(^#|^)PermitRootLogin/                {
             $1 = "PermitRootLogin";
             $2 = "no" };
   /^PermitEmptyPasswords/               { $2 = "no" };
   /^#Banner/                            {
             $1 = "Banner";
             $2 = "/etc/issue" }
   { print }' sshd_config.tmp > sshd_config
rm -f sshd_config.tmp
chown root:sys ssh_config sshd_config
chmod go-w ssh_config sshd_config
```

先拷贝一份配置，再用 awk 生成一份修改了安全配置的临时文件，最后替换原始配置，避免直接改坏。各参数含义：

- `Protocol 2`：只用 SSH 协议 2 版本（1 版有已知安全问题）；
- `X11Forwarding yes`：X11 图形流量也走 SSH 加密通道；
- `IgnoreRhosts yes` / `RhostsAuthentication no` / `RhostsRSAAuthentication no`：彻底禁止基于 `.rhosts` 的信任认证，防止"无口令信任"被伪造利用；
- `PermitRootLogin no`：禁止 root 直接远程登录（与 B5 作业项对应）；
- `PermitEmptyPasswords no`：禁止空口令登录；
- `Banner /etc/issue`：登录前显示告警横幅。

**CentOS 7 对应做法**：源文是 HP-UX 的路径和属组写法，CentOS 7 的 OpenSSH 配置在 `/etc/ssh/sshd_config`，属主就是 `root:root`，安装直接 `yum install -y openssh-server`，不需要从厂商网站下载。上述参数里，`Protocol 2` 在 CentOS 7 已是默认（SSHv1 已被移除），`RhostsAuthentication`、`RhostsRSAAuthentication` 这类选项也已废弃，重点保留三条即可：

```bash
# 编辑 sshd 配置
vi /etc/ssh/sshd_config

# 确认或修改以下参数
PermitRootLogin no
PermitEmptyPasswords no
Banner /etc/issue

# 检查配置语法后重启 sshd
sshd -t
systemctl restart sshd
```

### 特殊情况处理

- 老设备只支持 telnet 时，不要直接摆着不管：把它放进独立管理网段，只允许跳板/堡垒机访问，并走加密通道，作为过渡手段，同时推动更换支持 SSH 的版本。
- 关闭 telnet/FTP 前，先确认没有业务脚本依赖 FTP 上传数据（如部分厂站数据转发），确认后用 SFTP/SCP 替换。
- `PermitRootLogin no` 会连带影响 SFTP/SCP 用 root 登录，改之前按 B5 的要求先建好普通管理账号。

### 📌 加固后的验证

```bash
# 查看 SSH 服务进程状态（源文命令）
ps -elf | grep ssh

# CentOS 7 下用 systemd 查看服务状态
systemctl status sshd

# 确认当前生效的安全参数
sshd -T | grep -Ei '^(protocol|permitrootlogin|permitemptypasswords|banner|ignorerhosts)'

# 确认 telnet/FTP 已无监听
ss -tlnp | grep -E ':21|:23'
```

期望结果：sshd 进程存在且运行正常；`sshd -T` 输出中 `permitrootlogin no`、`permitemptypasswords no`；telnet、FTP 已停用，`ss` 检查无监听输出。
