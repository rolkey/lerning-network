# 禁用不必要的系统服务（telnet/sendmail/rlogin/tftp/imap/pop3 等）

## 问题

- "提高系统服务安全，优化系统资源"
- 加固方法："在inetd.conf中关闭不用的服务……编辑/etc/inetd.conf文件,注释不需要的服务。禁用多余服务：telnet sendmail klogin rlogin kshell ntalk tftp imap pop3（禁用）；或执行命令 `chkconfig --list`，查看哪些服务开放。"

---

最小化安装原则：AGC/AVC 主机只跑它需要的服务，多开一个端口就多一块攻击面。这台机器上用不着 telnet、邮件、远程 shell、tftp 这些，全都该关掉。

### 🔍 风险原理

列表里的每个服务都带问题：

- **telnet / rlogin / klogin / kshell**：认证过程明文传输，同网段抓包直接拿到账号密码，而且多数环境允许 root 直接登录。
- **tftp**：无认证、可匿名上传下载，历史上常被用来传恶意文件或偷配置。
- **sendmail**：代码老、历史漏洞多，A 类问题层出不穷；这台机器根本不需要收邮件。
- **imap / pop3**：邮件读取协议，需要本地邮箱服务的场景才用得上，这里纯属多余。
- **ntalk**：talk 聊天协议，无用且浪费资源。

每关一个服务，就少一个可能被打穿的口子，同时省内存、省进程——这就是"提高系统服务安全，优化系统资源"的含义。

### 配置加固方法

源数据是传统 UNIX 的 inetd 写法（服务由 inetd 超级守护进程按需拉起，注释掉 inetd.conf 里的行即关闭）：

```bash
# 先备份再修改
cp /etc/inet/inetd.conf /etc/inet/inetd.conf.backup

# 编辑 inetd.conf，把不需要的服务行首加 # 注释掉，例如：
vi /etc/inet/inetd.conf
# telnet  stream  tcp  nowait  root  /usr/sbin/in.telnetd  in.telnetd
# ftp     stream  tcp  nowait  root  /usr/sbin/in.ftpd     in.ftpd
# 注释后需让 inetd 重读配置（传统做法是 kill -HUP 其 pid）
```

CentOS 7 已经不用 inetd 这套了，对应排查思路如下：

```bash
# 1) 查看当前有哪些服务在运行
systemctl list-units --type=service --state=running

# 2) 查看传统 SysV 服务的开关状态（CentOS 7 仍兼容此命令）
chkconfig --list

# 3) 查看实际监听端口，确认暴露面
netstat -tlnp
```

逐个禁用。CentOS 7 上 telnet/rlogin/tftp 这类如果是 xinetd 管的，改 `/etc/xinetd.d/` 下对应文件；如果是独立守护进程，直接 systemctl 停掉并取消自启：

```bash
# 独立服务：停用 + 取消开机自启
systemctl disable --now sendmail.service

# 由 xinetd 管理的服务：把 disable 改成 yes
vi /etc/xinetd.d/telnet
# disable = yes
systemctl restart xinetd

# systemd socket 激活的服务（如 telnet.socket）：
systemctl disable --now telnet.socket
systemctl disable --now tftp.socket

# 用 chkconfig 关闭老式 SysV 服务（等效于 systemctl disable）
chkconfig telnet off
chkconfig sendmail off
```

### 特殊情况处理

- 别一刀切。ssh、rsyslog、crond、chronyd/ntpd 是运维刚需，必须保留；网管、态势感知的采集代理进程也不要误停。
- sendmail 停用前确认没有第三方程序靠它发告警邮件（部分监控脚本调用 sendmail 发信）。若确有需要，保留但限制只监听本机。
- CentOS 7 最小化安装默认不带 telnet-server、tftp-server、dovecot 这些包，`chkconfig --list` 或 `rpm -qa` 查不到即等于没装，记一笔"未安装"即可。
- 判断一个陌生服务该不该停：先看它的描述（`systemctl status <服务名>`），再确认业务依赖，不确定就保持现状并记录。

### 📌 加固后的验证

```bash
# 1) 端口层面：相关端口不应再监听（期望无输出）
netstat -tlnp | grep -E ':(23|25|69|110|143)\s'

# 2) 服务状态：期望 off / inactive / disabled
chkconfig --list | grep -E 'telnet|sendmail|rsh|rlogin|tftp|imap|pop3'
systemctl list-units --type=service --state=running | grep -E 'telnet|sendmail|tftp|dovecot'

# 3) 确认未设置开机自启
systemctl is-enabled telnet.socket sendmail.service 2>&1
# 期望：disabled 或 not-found
```

三项检查都"无输出"或显示 off/disabled，即达到要求。
