# 空口令用户排查与密码设置（A2）

## 问题

- "尝试登陆判断是否存在空口令用户"
- "进入'控制面板->管理工具->计算机管理'，在'系统工具->本地用户和组'；查看系统账号状态，逐个尝试登陆系统账号，判断是否存在空口令用户，对于空口令用户，选中账号，右键设置密码"
- "为空口令用户设置密码"

---

A2 是"用户账号与口令安全"里的第一项：**操作系统的用户必须进行身份标识和鉴别**。落到操作上就一件事——逐个账号试登录，把空口令账号揪出来，然后设上密码。

### 🔍 风险原理

空口令就是密码为空。这样的账号在登录界面直接回车就能进系统，等于"有名字没门锁"。判断空口令为什么不能只看属性面板，而要逐个尝试登录：Windows 的用户属性里没有"密码是否为空"这一栏，只有实际登录才知道。

有观点认为 Windows 默认限制"使用空密码的本地账户只允许控制台登录"（注册表项 `LimitBlankPasswordUse=1`），空口令账号远程登录会被拒。这个限制确实存在，但它只挡远程网络登录，挡不住控制台。OMS 主机在变电站机房里，运维、厂家、检修人员进出机房是常态，空口令账号对走到机器跟前的人来说就是零门槛。

所以源表要求"逐个尝试登陆系统账号"——每个本地账号都登一遍，密码留空直接回车，能进去的就是空口令账号，进不去的就是有密码的。这是最直接、不依赖任何工具的判定方式。

### 配置（加固方法）

1. 打开用户管理：
   控制面板 -> 管理工具 -> 计算机管理 -> 系统工具 -> 本地用户和组 -> 用户
   （也可以在"运行"输入 `lusrmgr.msc` 直达。）

2. **逐个尝试登录**：注销当前会话，用列表里的每个账号依次登录，密码留空直接回车。能登录成功的账号即为空口令账号。

3. **为空口令账号设置密码**：回到"本地用户和组"，选中空口令账号 -> 右键 -> 设置密码，按提示输入新密码。
   密码强度要满足 A3 的密码策略（复杂度启用、最小长度 8）。在已启用 A3 策略的主机上，纯数字、纯字母的弱密码会被系统直接拒绝。

补充：命令行也可以辅助排查，`net user` 列出全部账号，`net user <账号名>` 输出的"需要密码"字段能看出该账号是否设置了密码，和逐个试登录互相印证。

### 特殊情况处理

- **服务运行账号**：某些监控/采集软件用本地账号跑服务，这类账号设置了密码后，必须到服务管理器（`services.msc`）里把该服务的"登录"选项卡密码同步改成新密码，否则服务重启会因"登录失败"起不来。
- **系统内置账号**：Guest 本身已禁用（A6 处理），Administrator 按 A6 重命名并设强密码，不要遗漏。
- **禁止用的账号**：有些账号属于业务遗留、已确认不再使用，与其设密码不如直接禁用，比留一个空口令账号设了弱密码更干净。

### 📌 加固后的验证

- 逐个账号试登录，密码留空回车全部登录失败，不再存在空口令账号。
- `net user <账号名>` 查看，"需要密码"为"是"。
- 若改过服务账号密码：重启主机或重启对应服务，业务程序正常启动，事件查看器（`eventvwr.msc`）无 4625 登录失败刷屏。
