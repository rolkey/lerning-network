# 默认账户权限控制（A6）

## 问题

- "已禁用Guest（来宾）帐户"：进入"控制面板->管理工具->计算机管理"，在"系统工具->本地用户和组"：Guest帐号->属性－> 已停用
- "已重命名Administrator管理员账号"：Administrator－>属性－> 更改名称
- "注：若影响业务不做此步，填异常情况。"

---

A6 处理的是 Windows 出厂自带的两个内置账号：Guest 和 Administrator。这两个名字全国统一、人尽皆知，是默认配置里最显眼的两个目标，必须处理。

### 🔍 风险原理

- **Guest（来宾）账户**：为临时访问设计的低权限账号，Windows 默认就是禁用的，但不少老机器、装某些第三方软件时会被打开。Guest 开着等于给任何能触达这台机器的人提供一个匿名落脚点。虽然 Guest 权限低，但它能绕过"你是谁"这道身份鉴别（A2 正是要求所有账号必须有身份鉴别），还能作为信息收集的起点。
- **Administrator 账号**：问题不在权限——它本来就该是管理员——而在**名字固定**。它是 RID 500 的内置管理员，账号名所有人都知道，口令爆破时第一个试它，大量蠕虫和木马内置了"Administrator + 常见弱口令"的组合。重命名不提升权限安全性本身（密码强度靠 A3，防爆破靠 A4），但它让自动化攻击失去固定靶子，是成本极低的一层防护。

### 配置（加固方法）

打开用户管理：

```
控制面板 -> 管理工具 -> 计算机管理 -> 系统工具 -> 本地用户和组 -> 用户
```

1. **禁用 Guest**：
   Guest -> 右键 -> 属性 -> 勾选"帐户已禁用" -> 确定。
   也可以用命令：
   ```text
   net user guest /active:no
   ```

2. **重命名 Administrator**：
   源表写"Administrator -> 属性 -> 更改名称"。Win10 在用户列表里直接右键 Administrator -> 重命名，输入新名称即可，效果相同。
   新名字避开 `admin`、`root`、`administrator` 这类常见名，改成看不出是内置管理员的普通名字。

### 特殊情况处理

- **重命名影响业务**：源表明确写了——若影响业务不做此步，填异常情况。某些老业务软件、网管监控脚本、第三方采集程序硬编码了 `Administrator` 这个账号名，重命名后认证会失败。改之前先梳理哪些程序用了内置管理员身份，改了之后做回归验证。
- **Guest 被老业务依赖**：极罕见，通常是历史遗留的错误设计。正确做法是用一个专用低权限账号替代，而不是重新开启 Guest。
- **重命名后权限不变**：重命名只改名字，账号的 SID（…-500）不变，原来挂在该账号下的权限、文件所有权、审计日志关联都不受影响，不用担心重命名后账号"失联"。

### 📌 加固后的验证

- 计算机管理的用户列表中，Guest 图标带向下箭头（禁用标记），属性里"帐户已禁用"处于勾选状态。
- 命令行执行 `net user guest`，输出中"帐户启用"为 `No`。
- 用户列表里已看不到 Administrator 这个名字；执行 `wmic useraccount where "sid like '%-500'" get name` 可确认 RID 500 的内置管理员已显示为新名称。
- 用新名称登录管理员账号正常，业务程序运行正常。
