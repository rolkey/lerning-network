# 删除或禁用多余的、过期的帐户

## 问题

- "根据业务需求，已删除多余的、过期的账户，无法确认的账户已禁用。"
- 加固方法："运行"compmgmt.msc"在计算机管理->本地用户和组->用户：删除多余的、过期的帐户"

---

### 🔍 风险原理

Windows 主机上的每个本地账户都是一个登录入口。多余的、过期的账户问题出在两点：

1. **无人管理**。离职人员、临时调试人员留下的账户不会再有人改密码，密码长期不换，被字典攻击猜中的概率随时间持续上升。
2. **攻击面放大**。账户越多，攻击者可枚举、可爆破的目标就越多。有些遗留账户还带管理员权限，一旦爆破成功就是整机沦陷。

对电力监控系统来说这条是合规基线要求：主机上应该只有业务运行和维护需要的最小账户集合。多一个账户，就多一个不被审计注意到的入口。所以处理原则很明确——**能删除的删除，无法确认用途的禁用**。

### 配置（加固方法）

入口：运行 `compmgmt.msc`，进入 **计算机管理 → 系统工具 → 本地用户和组 → 用户**。

1. 打开用户列表后，逐账户核对：这个账户是谁的、干什么用、最后一次使用是什么时间。
2. 确认无用的账户：右键 → **删除**。
3. 无法确认用途、但暂时不敢删的账户：右键 → **属性** → 勾选 **"账户已禁用"** → 确定。禁用后的账户会显示一个带向下箭头的图标。
4. 顺手把以下几类账户也过一遍：
   - `Guest` 来宾账户：默认应禁用（新建系统里通常是禁用的，检查一下即可）。
   - `DefaultAccount`、`WDAGUtilityAccount`：Win10 系统内置账户，保持默认禁用状态，不要启用。

命令行辅助检查：

```text
net user                     # 列出全部本地账户
net user <用户名>             # 查看单个账户的详细信息、最后登录时间、是否禁用
```

用 `net user` 比图形界面快的地方是能直接看到"本地组成员资格"和"上次登录时间"，排查哪个账户长期没人用很方便。

### 特殊情况处理

- **服务账户不能乱删**。有些账户是被服务拿来运行的（在 `services.msc` 里某服务的"登录"选项卡能看到），删除后对应服务启动会报错。这种账户先确认关联服务是否还需要。
- **禁用优先于删除**。遇到拿不准的账户，先禁用观察一段时间，业务没异常再删，比直接删要稳。
- **系统内置账户**（`Administrator`、`Guest` 等）不能被删除，只能禁用或重命名。Guest 确认禁用即可。
- 删除账户会连同其用户配置文件目录一并提示处理，选择删除时注意里面是否有需要留存的资料。

### 📌 加固后的验证

- 回到"本地用户和组 → 用户"，确认列表里只剩业务所需的账户，多余账户已消失，遗留账户带禁用标记。
- `net user` 命令输出中，被禁用的账户显示"账户启用 No"。
- 挑一个已禁用的账户尝试登录，应该直接提示"账户已被禁用"。
