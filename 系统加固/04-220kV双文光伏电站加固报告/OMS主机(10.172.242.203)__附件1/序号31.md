# 应用软件账户权限设置

## 问题

- "禁用或删除无用、过期用户"
- "用户设置最小化权限"
- "密码复杂度设置为最少8位字符，有大小写字母、数字、特殊字符中的两种"
- "不存在空口令或弱密码"

---

这一条管的是应用软件所用账户的口子：账户要少、权限要小、密码要硬。四个方面分别落在不同的 Windows 配置位置上。

### 🔍 风险原理

应用软件的账户权限设置不当，最常见的两个后果：

1. **权限过大**。应用软件用管理员权限跑，软件自身有漏洞（缓冲区溢出、注入）时，攻击者拿到的直接就是管理员权限，主机被完全控制。这就是"最小化权限"原则的由来——应用只给够用的权限。
2. **弱密码**。空口令或 `123456` 这类密码，是爆破和横向移动的第一目标。账户密码必须有一定长度和字符种类，否则字典攻击一打一个准。

对电力监控系统主机，任何应用账户被攻破都可能被当作跳板进入监控网络，所以合规基线对密码复杂度和账户权限有明确要求。

### 配置（加固方法）

#### 1. 禁用或删除无用、过期用户

与 A7 同一套做法：`compmgmt.msc` → **本地用户和组 → 用户**，删除无用的、禁用无法确认的。服务所用账户、业务软件运行账户保留。

#### 2. 用户设置最小化权限

- 普通应用账户放 `Users` 组，不放进 `Administrators` 组。
- 检查方法：`compmgmt.msc` → **本地用户和组 → 组 → Administrators**，确认成员只有必须的管理员账户；`Users` 组里才是普通账户。
- 服务账户建议用权限最低的专用账户，不要用 `Administrator` 跑服务。

#### 3. 密码复杂度：最少 8 位，含两类字符

入口：`secpol.msc`（本地安全策略）→ **账户策略 → 密码策略**，设置：

```text
密码长度最小值             -> 8 个字符
密码必须符合复杂性要求      -> 已启用
```

说明：Windows 内置的"密码必须符合复杂性要求"启用后，系统默认要求密码含大写字母、小写字母、数字、特殊字符四类中的三类。本表单要求是"最少 8 位字符，有大小写字母、数字、特殊字符中的**两种**"，比系统默认稍宽松，按表单要求执行即可，设成三类也满足。

#### 4. 不存在空口令或弱密码

- 排查空口令：`secpol.msc` → **本地策略 → 安全选项** → **账户：使用空密码的本地账户只允许控制台登录**，设为"已启用"，防止空密码账户被远程登录利用。
- 逐账户核对：用 `net user` 列出账户，检查"账户启用"状态和最后改密时间，逐个把弱密码改掉：

```text
net user <用户名> <新密码>      # 直接在命令行修改账户密码
```

新密码按第 3 条要求设置。

### 特殊情况处理

- **改服务账户密码要同步服务配置**。服务运行账户的密码改了之后，要到 `services.msc` 里对应服务的"登录"选项卡更新密码，否则服务下次启动失败。
- **权限改小后业务可能报错**。有些老应用非要写 `C:\Program Files` 或系统目录，最小化权限后写不进去。遇到这种情况先确认应用目录的 NTFS 权限，给该账户单独授权应用目录，而不是把账户加回管理员组。
- **密码策略对已存在的账户不追溯**。改复杂度要求后，已有账户的旧密码不会强制过期。必须手动把存量弱密码全部改掉，才能满足"不存在空口令或弱密码"。

### 📌 加固后的验证

- `secpol.msc` → 账户策略 → 密码策略：密码长度最小值显示 8，复杂性要求显示已启用。
- `compmgmt.msc` → 组 → Administrators：成员只剩必须的管理员，无业务账户。
- `net user` 逐账户核对：无多余账户、无空密码账户，密码均满足 8 位含两类字符的要求。
