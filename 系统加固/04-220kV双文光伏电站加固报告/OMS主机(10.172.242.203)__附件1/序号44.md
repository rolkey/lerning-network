# 系统日志设置

## 问题

- "已设置系统日志大小：
  应用日志上限：102400 KB
  安全日志上限：102400 KB
  系统日志上限：102400 KB
  日志要求保存6个月以上。"
- "达到日志上限大小时：改写久于90天的事件"
- 加固方法："进入"控制面板->管理工具->事件查看器"，在"事件查看器（本地）"中："应用程序"属性中的日志大小设置不小于"102400KB"，设置当达到最大的日志尺寸时，"按需要改写事件"。"

---

### 🔍 风险原理

日志是安全事件的唯一现场。三个问题对应三种风险：

1. **日志太小**。Windows 默认日志容量只有几 MB，审核策略（A9）全开后事件量大，很快写满。更糟的是攻击者可以人为制造海量事件把关键日志"冲刷"掉，掩盖入侵痕迹。
2. **写满后不处理**。写满后如果"不覆盖"，日志停止记录，后续事件全部丢失；如果无脑覆盖，又可能把需要追溯的旧事件挤掉。
3. **留存时间不够**。电力监控系统要求日志保存 6 个月以上，容量和改写策略必须配合才能满足。

本表单的解法：容量放大到 **102400KB**（100MB），写满后"按需要改写事件"，并且改写的是**久于 90 天**的事件——既保证新事件始终有地方写，又保证近 90 天事件不被覆盖，配合 100MB 容量实现 6 个月留存。

### 配置（加固方法）

#### 1. 事件查看器中设置三个日志

进入 **控制面板 → 管理工具 → 事件查看器**（或直接运行 `eventvwr.msc`），在"事件查看器（本地）→ Windows 日志"下，对**应用程序、安全、系统**三个日志分别操作：

右键日志 → **属性**：

```text
日志大小上限：102400 KB
达到最大的日志尺寸时：按需要改写事件（旧事件优先）
```

三个日志都按此设置。102400KB 即 100MB，是表单明确要求的下限值，不要改小。

#### 2. 安全日志的改写策略（久于 90 天）

安全日志的保留方法还能通过组策略统一控制：`gpedit.msc` → **计算机配置 → Windows 设置 → 安全设置 → 事件日志**：

```text
保留安全日志                  -> 适当值（如 90 天，与"改写久于90天的事件"对应）
日志达到最大尺寸时的保留方法   -> 改写久于(90)天的事件
```

这一项把"达到上限改写久于 90 天的事件"的要求落实成策略，与事件查看器里的"按需要改写"配合：常规按需改写，但 90 天内的事件不会被清掉。

#### 3. 命令行核对/设置（可选）

```text
wevtutil gl Application    # 查看应用程序日志当前配置
wevtutil sl Application /maxsize:104857600
wevtutil sl Security /maxsize:104857600
wevtutil sl System /maxsize:104857600
```

`maxsize` 单位是字节，102400KB × 1024 = 104857600。

### 特殊情况处理

- **"按需要改写事件"与 6 个月留存的关系**：日志留存 6 个月靠的是容量够大、事件够少。若审核策略全开且系统事件量大，100MB 可能撑不满 6 个月。现场先观察一个月的增长量，若增长过快，要回头评估哪些审核项产生噪音，而不是盲目把容量改成"不覆盖"——那样日志会停写。
- **不要选"不覆盖事件"**：安全日志若设为不覆盖且写满，Win10 会停止记录新事件，等同审计中断，反而更糟。
- **"按需要改写"会丢弃最旧事件**：优先改写最旧事件，与"改写久于 90 天的事件"策略叠加后，实际效果是 90 天内事件受保护。
- 修改安全日志保留方法需要相应权限，普通账户改不动时用管理员身份操作。

### 📌 加固后的验证

- 事件查看器中三个日志属性均显示"最大日志大小 102400 KB"、改写方式"按需要改写事件"。
- `gpedit.msc` → 安全设置 → 事件日志，保留方法与保留天数与配置一致。
- `wevtutil gl Security` 输出中 maxSize 为 104857600。
- 打开安全日志，核对最老一条事件的时间，确认 90 天内事件完整存在，留存覆盖 6 个月目标。
