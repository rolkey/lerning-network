# 禁用不必要服务

## 问题

- "根据业务需求，禁用不必要的服务，包括但不限于：e-mail、telnet、rlogin、ftp"
- 加固方法："运行services.msc 禁用多余服务：选择服务……右键"停止"，并点击属性，将启动类型改为"禁用"。"

---

### 🔍 风险原理

Windows 服务是常驻后台程序，每一个运行中的服务都是一块攻击面：

- **Telnet**：明文传输，账号密码在网络上一抓就现形，是明确要求禁用的服务。
- **Remote Registry**：允许远程读写注册表，一旦被拿下可以远程植入后门、改服务自启动。
- **SNMP Service / SNMP Trap**：默认团体名 `public`，等于没有认证；不用的网管协议没必要开着。
- **World Wide Web Publishing Service**（IIS）：监控主机上不跑 Web 服务，开着就是多一个 Web 漏洞入口。
- **Messenger / Alerter**：信使类服务可用于弹窗骚扰、社会工程。
- **Routing and Remote Access**：路由和拨号服务，工作站角色用不上。
- **Print Spooler**：历史上出过 PrintNightmare 级别的漏洞，无打印需求就该关。

原则很简单：**不用的服务不运行**。服务少了，能打的入口就少，补丁压力也小。对电力监控系统主机，这一点是明确的服务优化要求。

### 配置（加固方法）

运行 `services.msc`，对以下服务逐项操作：右键 → **停止**；再右键 → **属性** → 启动类型改为 **"禁用"** → 确定。

```text
Alerter
Clipbook
Computer Browser
Messenger
Remote Registry
Routing and Remote Access
Simple Mail Trasfer Protocol(SMTP)              （可选）
Simple Network Management Protocol(SNMP) Service （可选）
Simple Network Management Protocol(SNMP) Trap    （可选）
Telnet
World Wide Web Publishing Service               （可选）
Print Spooler                                   （可选）
Automatic Updates                               （可选）
Terminal Service                                （可选）
```

操作要点：

1. **先停止、再禁用**。只把启动类型改成"禁用"不会停掉正在运行的服务，两步都要做。
2. 带"（可选）"标记的服务，按实际业务决定：确认用不到就一并禁用。
3. 检查依赖：在服务属性"依存关系"选项卡里能看到该服务依赖谁、被谁依赖，避免误禁影响业务。

### 特殊情况处理

- **"可选"服务逐一确认业务**。例如本机如果确实需要 SNMP（网管轮询），就保留并按 A12 的条目加固 SNMP 服务本身，而不是禁用——A11 与 A12 是二选一的关系，看业务而定。
- **Print Spooler**：如果监控主机要接打印机打报表才需要，否则禁用。
- **Terminal Service（远程桌面）**：运维是否靠远程桌面登录？靠的话保留；本表单标记为可选，说明默认倾向禁用，实际按运维方式定。
- **Computer Browser** 依赖 Workstation 和 Server 服务，禁用它不影响 SMB 共享本身，仅关闭网上邻居浏览功能。
- 禁用后重启一次，确认服务不会因为依赖或触发重新拉起。

### 📌 加固后的验证

- `services.msc` 中上述服务的"启动类型"显示为**禁用**，"状态"列为空。
- 命令行核对：

```text
sc query <服务名>        # 状态应为 STOPPED
sc qc <服务名>           # START_TYPE 应为 4（禁用）
```

- 重启主机后复查一次，确认服务仍为禁用状态，没有被重新启用。
