# 禁止蓝屏（系统失败）后自动重启

## 问题

- "禁止蓝屏后自动启动机器，我的电脑→属性→高级→启动和故障恢复→设置→将系统失败下面的自动重启启动前面的勾号已去掉。"

---

这项作业不涉及权限和策略，是一个系统行为开关：机器崩溃蓝屏后，不再自动重启，而是停在蓝屏界面等人工处理。

### 🔍 风险原理

Windows 默认在"系统失败"（即蓝屏）后自动重启，看起来省事，对生产主机其实很不利：

- **故障信息一闪而过**：蓝屏界面上会显示停机代码（如 `IRQL_NOT_LESS_OR_EQUAL`、`PAGE_FAULT_IN_NONPAGED_AREA` 等），重启后这屏信息就没了。不记录代码，后续查故障原因、找厂商支持都少一条关键线索。
- **掩盖持续故障**：如果是硬件或驱动问题引起的蓝屏，自动重启会让机器陷入"崩溃—重启—崩溃"的循环，故障间歇性出现，更难定位。去掉自动重启，机器停在蓝屏上，至少能看到它确实崩了、崩在哪个模块。
- **保留分析现场**：蓝屏时系统会把内存内容写入转储文件（`C:\Windows\MEMORY.DMP`），自动重启会压缩转储写入的窗口。去掉自动重启后转储更完整，事后分析（包括排查内核级异常操作）才有素材。

对变电站、光伏电站这类主站主机，蓝屏原因往往要提交厂家分析，保留现场是第一位的。

### 配置（加固方法）

按源表路径操作："我的电脑 → 属性 → 高级 → 启动和故障恢复 → 设置"，在"系统失败"栏下，把"自动重新启动"前面的勾**去掉**，确定保存。

Windows 10 上这条路径的实际走法是（"我的电脑"已改名"此电脑"）：

```text
此电脑 → 右键属性 → 高级系统设置 → 高级 → 启动和故障恢复 → 设置
```

进去后看到"系统失败"一栏，"自动重新启动"是第一个复选框，去掉勾选即可。同栏的"将事件写入系统日志"建议保持勾选——这是蓝屏事件留痕的开关。

该设置对应的注册表键值是：

```reg
HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Control\CrashControl
AutoReboot = 0
```

0 表示不自动重启，1 表示自动重启。界面改完后这个键值会同步变化，可用于核查。

### 特殊情况处理

- **无人值守的矛盾**：站端主机多数时间无人值守，去掉自动重启后，一旦蓝屏，机器会一直停在蓝屏界面，远程也连不上，直到有人到场处理。这是本项作业与无人值班现实之间的权衡——按基线执行去掉勾选，同时建议保证机房带外管理手段（如 IPMI、串口管理）可用，真出蓝屏能远程查看并强制重启恢复。
- **宕机处理预案**：去掉勾选后，现场恢复蓝屏机器的做法是记录屏幕代码（拍照留证），然后长按电源强制重启。把这一步写进值班操作规程，别让值班员面对蓝屏不知道该怎么办。
- **转储空间**：若同时配置了完整内存转储，系统盘要留足空间，避免转储写满磁盘引发新问题。

### 📌 加固后的验证

1. 打开"启动和故障恢复"设置对话框，确认"自动重新启动"复选框已去掉勾选。
2. 打开注册表编辑器，确认 `AutoReboot` 的值为 0。
3. 核对同一对话框内"将事件写入系统日志"仍为勾选状态，确保蓝屏事件有日志留痕。
