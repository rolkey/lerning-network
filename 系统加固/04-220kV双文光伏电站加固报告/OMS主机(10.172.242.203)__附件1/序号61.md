# 关闭 Windows 开机自动登录

## 问题

> 增加/修改 REG_DWORD 类型的 AutoAdminLogon 键，值为 0。
>
> 加固方法：1.开始->运行->键入 regedit；2.修订注册表项：进入 HKEY_LOCAL_MACHINE\Software\Microsoft\Windows NT\CurrentVersion\Winlogon，新建一个名称为 AutoAdminLogon，类型为 REG_DWORD，值为 0 的键值。如果存在 AutoAdminLogon 则直接将键值改为 0。

---

### 🔍 风险原理

`AutoAdminLogon` 决定 Windows 启动时是否跳过登录界面、按预设账号直接进入桌面。值为 1 时，系统依据 `DefaultUserName` / `DefaultPassword` 自动完成登录，任何能碰到主机电源键的人，开机即进入桌面——对无人值守机房里的 OMS 主机来说，等于把账号口令画在了开机画面上。更糟的是，自动登录用的口令以明文形式存在注册表 `DefaultPassword` 值里，能读到注册表的进程或能导出注册表的人，顺手就把口令拿走了。值设为 0，开机后必须人工输入口令，控制台访问才回到有凭据校验的轨道上。

### 配置（加固方法）

1. `Win+R` 运行 `regedit`，打开注册表编辑器。
2. 定位到 `HKEY_LOCAL_MACHINE\Software\Microsoft\Windows NT\CurrentVersion\Winlogon`。
3. 处理 `AutoAdminLogon` 键值：
   - 不存在：右键空白处 → 新建 → DWORD（32 位）值，命名为 `AutoAdminLogon`；
   - 已存在：直接双击改值。
4. 数值数据填 `0`，即禁止自动登录。

`AutoAdminLogon` 为 0 或该值不存在，都表示关闭自动登录。

### 特殊情况处理

有些现场要求停电恢复后主机自动开机、自动拉起监控程序，容易想到用自动登录来解决。不建议这么干：正确做法是把程序注册成 Windows 服务（`services.msc`，启动类型设为“自动”），或建一个开机触发的计划任务，让程序在登录界面背后就能跑起来，登录界面继续锁着。若主机此前配置过自动登录，关闭时顺手检查并清除同目录下的 `DefaultPassword` 值，避免明文口令残留在注册表里。本项修改在下一次登录/重启时生效，不需要立即重启，但建议安排重启验证。

### 📌 加固后的验证

- 注册表复查：`Win+R` 运行 `regedit`，确认 `Winlogon` 下 `AutoAdminLogon` 值为 `0`；也可以用命令核对：

  ```text
  reg query "HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Winlogon" /v AutoAdminLogon
  ```

  期望返回 `AutoAdminLogon REG_DWORD 0x0`。
- 重启主机，确认停在登录界面并提示输入口令，不再直接进入桌面。
