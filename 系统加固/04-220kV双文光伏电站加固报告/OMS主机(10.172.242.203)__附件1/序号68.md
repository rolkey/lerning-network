# 禁用可远程访问的注册表路径和子路径

## 问题

> "网络访问： 可远程访问的注册表路径和子路径"配置为空。
>
> "网络访问： 可远程访问的注册表路径"配置为空。

---

这两条"网络访问"安全选项，控制的是远程用户能通过远程注册表服务（winreg）挂载本机注册表的哪些路径。配置为空，就是拒绝一切远程注册表访问。

### 🔍 风险原理

Windows 默认允许远程用户用注册表编辑器（regedit）的"文件 → 连接网络注册表"挂载目标主机的注册表，读写其中的键值。默认放行的路径包括 `Software\Microsoft\Windows NT\CurrentVersion`、`SYSTEM\CurrentControlSet\Control\ProductOptions` 等系统关键分支。

对电力监控系统主机来说，远程注册表读写是一条隐蔽的植入通道：攻击者拿到管理员凭据（或利用系统其它弱点）后，改几个键值就能加自启动项、注册恶意服务、关闭安全软件、放开端口。这些修改直接写在注册表里，不落文件，隐蔽性高，事后排查也难。

把这两条策略配置为空，含义是：**任何远程用户都不允许通过网络访问本机注册表**。本地登录后的操作完全不受影响，只封远程这条路。

### 配置（加固方法）

两条策略名称相似，一条带"和子路径"、一条不带，**两条都要清空**。

1. 打开"控制面板 → 管理工具 → 本地安全策略"（也可以运行 `secpol.msc` 直接打开）。
2. 依次展开"本地策略 → 安全选项"。
3. 在右侧窗格找到 **"网络访问: 可远程访问的注册表路径和子路径"**，双击打开，把属性窗口中列表里的条目全部删除、留空，点"确定"。
4. 再找到 **"网络访问: 可远程访问的注册表路径"**，用同样方式清空。

两条策略的区别："路径和子路径"匹配的是子树（含子键），"路径"是精确匹配。它们分别对应注册表 `HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Control\SecurePipeServers\winreg` 下的 `AllowedPaths` 和 `AllowedExactPaths` 两个值。本地安全策略里的修改就是写这两个值，留空即两项均为空。

修改后本地安全策略通常即时生效；如需确保刷新，可运行 `gpupdate /force`。

### 特殊情况处理

- 如果这台主机此前被集中管控平台或域策略远程读写过注册表，清空后这些功能会失败。OMS 主机按作业要求不保留此类依赖，直接清空即可。
- 清空之后，从其它机器用 regedit"连接网络注册表"连本机会报拒绝访问，这是预期结果，不是故障。
- 两条策略容易漏做一条，核对时务必两条都确认已清空。

### 📌 加固后的验证

- 打开 `secpol.msc` → 本地策略 → 安全选项，确认两条策略的值均为空。
- 从同网段另一台 Windows 机器运行 `regedit`，"文件 → 连接网络注册表"，输入 `10.172.242.203`，应提示拒绝访问或找不到网络路径。
- 命令行测试：

  ```text
  reg query \\10.172.242.203\HKLM\SOFTWARE
  ```

  应返回错误，无法读取。
