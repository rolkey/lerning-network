# Apache Axis 远程管理功能未禁用漏洞

## 问题

- 漏洞编号：指令清单调度20190617-001
- 漏洞名称：Apache Axis 漏洞
- 作业结点："对使用了Apache axis 的服务器采用以下策略：1.禁用AXIS远程管理功能，通过修改AXIS目录下WEB-INF文件夹中的server-config.wsdd文件，将其中"enableRemoteAdmin"的值设置为false。"
- 加固方法："Windows：通过文件查找功能查找server-config.wsdd文件及相关文件夹；查找到后进入文件所在路径，执行修改操作（windows直接编辑文件）"

---

### 🔍 漏洞原理与风险

Apache Axis 是早期 Java 生态里用得很多的 SOAP Web 服务引擎，不少老系统的接口至今还跑在它上面。`server-config.wsdd` 是 Axis 的核心配置文件，放在应用目录的 `WEB-INF` 文件夹里，其中有一个参数 `enableRemoteAdmin`。

这个值设为 `true` 时，Axis 会开放远程管理功能：只要能访问到服务地址，就可以通过管理接口对服务做部署、查看配置等管理操作。老版本的 Axis 远程管理接口本身缺少可靠的认证保护，管理功能被滥用的问题历史上出现过不少。攻击者一旦找到暴露在外的 Axis 服务，就能利用远程管理接口部署恶意服务、读取服务配置，进而拿下整台服务器。所以加固要求是把这个口子直接关掉。

### 处置方法

1. **定位文件**：在 Windows 服务器上打开文件资源管理器，用搜索框在整个磁盘（或 Web 服务安装目录）里搜索 `server-config.wsdd`，找到 AXIS 应用 `WEB-INF` 文件夹下的这个文件。
2. **编辑文件**：用记事本打开 `server-config.wsdd`，找到 `enableRemoteAdmin` 参数，把它的值从 `true` 改为 `false`：
   ```xml
   <parameter name="enableRemoteAdmin" value="false"/>
   ```
3. **保存**：保存文件。如果提示权限不足，用管理员身份打开编辑器再改。
4. **重启服务生效**：`server-config.wsdd` 在 Axis 应用启动时加载，改完需要重启承载该 Axis 应用的 Web 服务（在服务管理器 `services.msc` 或应用服务器控制台里操作），配置才会生效。

### 特殊情况处理

- 一台服务器上可能部署了多个 Axis 应用实例，每个实例的 `WEB-INF` 目录下都有各自的 `server-config.wsdd`，要逐个检查、全部改掉，改一个漏一个等于没改。
- 如果业务确实临时需要远程管理，也不建议长期开着：临时改回 `true`，用完马上恢复 `false` 并重启服务。
- 编辑时若文件被服务占用导致无法保存，先停服务再改，改完再启动。

### 📌 处置后的验证

- 重新打开 `server-config.wsdd`，确认 `enableRemoteAdmin` 的值为 `false`。
- 重启服务后，用浏览器访问该 Axis 服务的管理页面，应无法再进入管理功能（提示不可用或拒绝访问）。
