# Windows CryptoAPI 与远程代码执行漏洞（CVE-2020-0601、CVE-2020-0611）

## 问题

> 信息通报20-1期：Windows CryptoAPI、远程代码执行漏洞 CVE-2020-0601、CVE-2020-0611
>
> 受影响的操作系统版本主要包括 Windows 10 和 Windows Server 2016/2019 等引入微软默认 ECC 根证书的新系统，而 windows7、windows xp/2003 等老版本系统不受此漏洞影响。
>
> 加固方法：下载安装补丁 https://portal.msrc.microsoft.com/en-US/security-guidance/advisory/CVE-2020-0601

---

### 🔍 漏洞原理与风险

这两个编号共享同一个根子：CryptoAPI 在验证带 ECC（椭圆曲线）参数的证书时校验不严。

- **CVE-2020-0601**：攻击者可以利用这一点伪造证书，把自己的恶意程序"包装"成带微软或知名厂商签名的样子，绕过系统信任检查；也能伪造 HTTPS 连接，让加密通信看起来可信。这是签名信任体系被直接动摇的问题，影响面很大。
- **CVE-2020-0611**：远程桌面客户端在解析服务器返回的数据时存在缺陷，用户只要连到一个恶意的 RDP 服务器，本机就可能被远程执行代码。

两者都出在"新版系统默认引入 ECC 根证书"这套机制上，所以通报说得很清楚：Windows 10、Windows Server 2016/2019 这类新系统受影响；Windows 7、XP、2003 不带这套证书体系，不受影响。OMS 主机是 Windows 10，正好在受影响范围内，必须处理。

### 处置方法

**第一步：确认系统版本**

按 `Win + R` 输入 `winver` 回车，确认系统是 Windows 10 或 Server 2016/2019。老系统（7/XP/2003）跳过本项。

**第二步：下载安装微软补丁**

1. 打开源表给出的微软安全更新指南页面（CVE-2020-0601 的 advisory 页面），在页面里选择本机对应的系统版本，下载该漏洞的累积安全更新。
2. 双击安装补丁，按提示重启系统。
3. 联网方便的话也可以直接走 Windows 更新："设置" → "更新和安全" → "Windows 更新" → "检查更新"，安装 2020 年 1 月及之后的安全更新即可。微软 2020 年 1 月的安全更新批次同时修复了 CVE-2020-0601 和 CVE-2020-0611 这两个编号。

### 特殊情况处理

- 内网机器无法直接联网下载的，先在能上网的机器上下载好对应版本的离线补丁包（.msu 文件），用移动介质拷入再安装。
- 补丁安装通常要求重启，安排在与业务协商好的时间窗口内进行，避免影响 OMS 在线运行。
- Windows 7 / XP / 2003 等老系统按通报不受此漏洞影响，无需处理，不要多此一举装不匹配的补丁。
- 若机器上装有第三方软件在做证书校验拦截，打补丁后留意其兼容性。

### 📌 处置后的验证

- 补丁安装完成后，打开"设置" → "更新和安全" → "查看更新历史记录"，确认 2020 年 1 月对应的累积更新显示"已成功安装"。
- 重启后再次执行"检查更新"，确认没有该批次的关键安全更新仍处于待装状态。
- 用 `winver` 确认系统版本和内部版本号已随补丁更新（补丁安装后版本号通常会递增）。
