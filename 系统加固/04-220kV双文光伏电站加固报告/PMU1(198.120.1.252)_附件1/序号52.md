# Linux 内核 TCP SACK 拒绝服务漏洞

## 问题

- "漏洞名称：Linux内核TCPSACK
  【内容】Linux 内核 2.6.29 及之后版本在处理 TCP SACK 机制时存在缺陷，导致整数溢出漏洞，攻击者可以构造特定的 SACK 包，远程触发 Linux 服务器内核模块溢出漏洞，实现远程拒绝服务攻击。"

---

这是一条内核层的远程拒绝服务（DoS）漏洞，2019 年中公开时波及面很大：只要目标服务器开着一个 TCP 服务（SSH、Web、数据库都算），攻击者不需要登录、不需要任何凭据，就能把内核打崩。

### 🔍 漏洞原理与风险

**风险原理**：SACK（Selective Acknowledgment，选择性确认）是 TCP 的可选机制，用于丢包时只重传丢失的分段，而不是整个窗口。Linux 内核 2.6.29 及之后的版本在整理 SACK 数据块时，对数据块数量的计算存在整数溢出。攻击者先和服务器正常建立一条 TCP 连接，再按特定顺序发送一串精心构造的 SACK 包，就会触发内核里的越界访问，轻则系统僵死，重则内核崩溃（kernel panic）、服务器重启。

**为什么这比一般的应用层 DoS 严重**：攻击面是内核而不是某个服务。只要 22、8080、7001 这类端口有一个能连上，攻击就成立，不依赖任何应用漏洞。AGC/AVC 服务器同时跑着 Web 服务和数据库，TCP 端口对外开放面不小，被远程打崩后直接导致监控画面中断、功率控制业务停摆。

### 处置/加固方法

整改方向有两个：禁用 SACK 处理，或者升级内核。**服务器不方便停机时，首选禁用 SACK**：

```bash
# 临时生效（重启后失效）
sysctl -w net.ipv4.tcp_sack=0

# 永久生效：编辑配置文件
vi /etc/sysctl.conf
# 在文件末尾加入下面这行
net.ipv4.tcp_sack=0

# 保存退出后，让配置立即生效
sysctl -p
```

源数据给出的另一种做法是**升级 Linux 内核**，各发行版的修复版本如下：

- RHEL/CentOS 6 系（凝思 Linx 6.0 对应此系）：6.32-754.15.3
- CentOS 7：10.0-957.21.3
- Ubuntu 18.04 LTS：15.0-52.56
- Ubuntu 16.04 LTS：4.0-151.178

以上为各发行版的内核包版本号，可用 `uname -r` 的输出对照。凝思 Linx 6.0 对应 RHEL 6 系这一行，但其内核由凝思厂商自行维护，精确的修复版本号以凝思发布的安全公告为准。升级内核必须重启服务器，且 AGC/AVC 这类带专用驱动和实时库的系统，升级前要先和厂家确认内核兼容性。

### 特殊情况处理

- `sysctl -w` 只对之后新建的 TCP 连接生效，已经建立的连接不受影响；改动不需要重启网络服务，写进 `/etc/sysctl.conf` 后下次开机仍然有效。
- 禁用 SACK 的代价是丢包重传效率略降。站内局域网链路质量好、往返时延低，这个影响基本可以忽略；对 AGC/AVC 这种局域网直连的业务，换安全更划算。
- 如果系统跑在虚拟机上，注意升级内核要在宿主机层面做（虚机共享宿主内核）；而 `sysctl` 的修改在虚机里直接配即可。
- 参数改动与其它加固基线（如 `tcp_timestamps`）无关，不必一起动，避免一次改动过多不好回滚。

### 📌 处置后的验证

```bash
# 1. 确认参数已生效
sysctl net.ipv4.tcp_sack
# 期望输出：net.ipv4.tcp_sack = 0

# 2. 重新建立一条 TCP 连接，抓包看 SYN 报文
tcpdump -i eth0 -nn 'tcp[tcpflags] & (tcp-syn) != 0' -c 1
# 期望：SYN 的选项里不再出现 "SACK_PERM=1" 字样

# 3. 若采用升级内核方案，重启后对比版本
uname -r
# 期望：不低于源数据列出的修复版本
```

验证通过后再观察一个运行周期，确认业务无异常，这条才算闭环。
