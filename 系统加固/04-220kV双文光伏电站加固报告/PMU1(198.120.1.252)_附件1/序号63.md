# SNMP 与 SYSLOG：把状态和日志交给安管平台

## 问题

- "SNMP、SYSLOG接入安管平台"
- "完成情况：√"

---

这一项管两件事：**SNMP** 回答"设备还活着吗、资源占用如何"，**SYSLOG** 回答"系统上发生了什么"（登录、审计、告警）。两者都推给安管平台，由平台统一采集、关联、告警。

### 为什么必须做

单看一台主机的日志没有意义，日志的价值在集中。安管平台把全网设备的日志收上来，才能做关联分析：比如同一时间段多台主机出现大量失败登录，就能识别出扫描行为；某台主机 CPU 长时间跑满，能提前发现异常。

另一个更实际的原因：日志只在主机本地存着，一旦主机被入侵，本地日志可能被删。集中到平台后，日志的留存和时间戳才有可信度，事后审计认的是平台里的数据。

### 配置要点

**SNMP**：

- 只用只读团体字，默认的 `public`/`private` 必须改掉。
- 能上 SNMPv3（认证+加密）就上 v3，v1/v2c 尽量不用。
- 主机防火墙只放行安管平台采集机的 IP 访问 161 端口。

**SYSLOG**（Linux 用 rsyslog，在 `/etc/rsyslog.conf` 里加转发）：

```bash
# UDP 转发到安管平台
*.* @<安管平台IP>:514
# 或 TCP 转发（更可靠）
*.* @@<安管平台IP>:514
```

改完重启服务：`service rsyslog restart`，并放行 514 端口（UDP 还是 TCP，跟平台采集方式保持一致）。

### 📌 验证

- 安管平台上能看到该主机的 SNMP 数据：在线状态正常，CPU/内存曲线有连续数据，不是空的。
- 平台里能检索到该主机的 SYSLOG 记录。做个实测：在主机上执行一次登录操作，过几分钟平台里应能查到对应日志。
- 主机侧用 tcpdump 抓包，能看到发往安管平台的 syslog 报文（目的端口 514）。
