# 用户账号安全问题

## 问题

- "执行：echo $PATH | egrep '(^|:)(\.|:|$)'，检查是否包含父目录，
执行：find `echo $PATH | tr ':' ' '` -type d \( -perm -002 -o -perm -020 \) -ls，检查是否包含组目录权限为777的目录
补充操作说明：确保root用户的系统路径中不包含父目录，在非必要的情况下，不应包含组权限为777的目录"

---
你执行的两条检查命令，分别对应两个独立的安全风险：**PATH 中包含父目录（`.`）** 和 **PATH 中包含组可写/全局可写的目录**。以下是针对这两种情况的具体配置和加固方法。

### 🔍 风险一：PATH 中包含父目录（`.`）

`echo $PATH | egrep '(^|:)(\.|:|$)'` 这条命令用于检测 PATH 中是否存在代表“当前目录”的 `.`。

**风险原理**：如果 root 的 PATH 中包含 `.`，当管理员以 root 身份在某个目录（如 `/tmp` 或某个普通用户的家目录）下操作时，如果误输入了某个不存在的命令，系统会优先在当前目录中寻找同名文件并执行。攻击者可以预先在该目录放置一个名为 `ls`、`cd` 或 `sl` 的恶意程序，一旦被误执行，就会获得 root 权限。这是一个经典的本地提权向量，CVE-1999-1422 就记录过类似问题。

**配置方法**：
你需要确保 root 的 PATH 中不包含 `.` 或空路径元素（空路径在部分实现中等价于当前目录）。

1.  **确定 root 的 PATH 从何处加载**：通常，root 的 PATH 定义在 `/etc/profile`、`/root/.bash_profile` 或 `/root/.bashrc` 中。你可以用 `grep -r 'PATH=' /etc/profile /root/.bash_profile /root/.bashrc /etc/environment /etc/profile.d/ 2>/dev/null` 来查找。
2.  **检查并修改配置**：在找到的文件中，查找类似 `PATH=.:/usr/bin:/bin` 或 `PATH=/usr/bin:/bin:.` 的写法。如果存在，直接删除其中的 `.` 以及多余的冒号。正确的写法应当只包含绝对路径，例如 `PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin`。
3.  **生效配置**：修改后，重新登录 root 或者执行 `source /etc/profile`（取决于你修改的文件）使配置生效。再次运行你提供的检查命令，应当**无任何输出**。

### 🔍 风险二：PATH 中包含组可写/全局可写（777/002/020）的目录

`find \`echo $PATH | tr ':' ' '\` -type d \( -perm -002 -o -perm -020 \) -ls` 这条命令用于检测 PATH 中的目录是否对“其他用户”（`o+w`，即 `-perm -002`）或“同组用户”（`g+w`，即 `-perm -020`）开放了写权限。

**风险原理**：如果 root 的 PATH 中包含一个对普通用户可写的目录，普通用户就可以在这个目录中植入一个恶意程序（例如命名为 `ls`）。当 root 在该目录中执行命令时，就会优先执行这个恶意程序，从而被提权。权限 `777` 的目录意味着任何用户都可以在其中创建、修改和删除文件，风险极高。

**配置方法**：
目标不是删除这些目录，而是**收回其“组写”和“其他用户写”权限**。标准路径（如 `/usr/bin`、`/bin`）的权限通常应是 `755`（`drwxr-xr-x`）。

1.  **定位问题目录**：执行你提供的 `find` 命令，查看输出中标记为 `drwxrwxrwx`、`drwxrwxr-x` 或 `drwxr-xrwx` 的目录。
2.  **使用 chmod 移除写权限**：对每一个被检测出的目录，执行权限修正。最安全的做法是移除“组写”和“其他用户写”权限：
    ```bash
    # 移除组写权限
    sudo chmod g-w /path/to/directory
    # 移除其他用户写权限
    sudo chmod o-w /path/to/directory
    # 或者一次性移除两者
    sudo chmod go-w /path/to/directory
    ```
    
3.  **特殊情况处理**：如果某个目录（例如 `/tmp`）**必须**对所有用户可写才能正常工作，那么它**绝对不应出现在 root 的 PATH 中**。正确的做法是将这类目录从 root 的 PATH 配置中彻底移除，而不是去修改它的权限（修改 `/tmp` 的权限会破坏系统功能）。

### 📌 加固后的验证

完成上述配置后，重新登录 root 并再次执行你提供的两条检查命令：

*   `echo $PATH | egrep '(^|:)(\.|:|$)'` 应当**没有输出**。
*   `find ... -perm -002 -o -perm -020` 应当**没有输出**（针对 PATH 中的目录）。

如果仍有输出，需要回到配置文件中继续排查，并检查是否有其他脚本（如 `/etc/profile.d/` 下的文件）动态地修改了 PATH。
