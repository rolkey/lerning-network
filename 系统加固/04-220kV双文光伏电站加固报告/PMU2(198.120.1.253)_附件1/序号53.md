# Apache Tomcat 中间件拒绝服务漏洞

## 问题

- "漏洞名称：ApacheTomcat中间件DOS漏洞
  【内容】受影响版本
  • 0.0.M1 < Apache Tomcat < 9.0.14
  • 5.0 < Apache Tomcat < 8.5.37
  【对象】Apache tomcat"

---

Tomcat 是 Java Web 应用最常用的容器，AGC/AVC 系统的 Web 发布、报表服务大多架在它上面。这条通报覆盖的版本区间很宽：9.0 系列低于 9.0.14 的全部命中，8.5 系列低于 8.5.37 的全部命中，5.x、6.x、7.x 等老版本也都在范围内。

### 🔍 漏洞原理与风险

**风险原理**：这批受影响版本的 Tomcat 在处理 HTTP/2 连接时存在实现缺陷，对连接状态和资源的回收处理不当。攻击者只需要和 Tomcat 建立普通连接，再发送特制的请求序列，就能让服务器持续消耗 CPU 和内存，最终把 Web 服务拖死。整个过程不需要认证。

**可能后果**：Web 服务假死或不可访问。对电站来说，运行人员可能因此看不到实时监控画面、调不动 AGC/AVC 参数；攻击者反复利用，等于持续制造业务中断。

### 处置/加固方法

源数据给的整改办法：先确认版本，落在影响范围内就更新。Tomcat 自带版本查询脚本：

```bash
# Linux 下先定位 Tomcat 安装目录中的 version.sh
find / -name version.sh
# 进入脚本所在目录执行，例如
sh /usr/local/tomcat/bin/version.sh
# Windows 下对应操作：进入 tomcat 安装目录的 bin 目录，执行 version.bat
```

输出里的 `Server version` 就是当前版本，对照影响范围：

- 9.0 系列：低于 9.0.14 → 需升级
- 8.5 系列及更老的 5.x/6.x/7.x：低于 8.5.37 → 需升级

升级时直接更换为官方最新稳定版（已覆盖修复版本），升级前备份 `conf/server.xml` 和业务 `webapps`。

### 特殊情况处理

- AGC/AVC 厂家的 Tomcat 多是随系统打包分发，升级前务必与厂家确认版本兼容性，最好在检修窗口用备用机先验证一遍，不要在生产机上直接替换。
- 短期确实无法升级：先在主机防火墙收紧 Tomcat 端口（8080/8443/8009 等），只允许内网维护网段访问，把攻击面降下来。注意这只是缓解，不是整改，最终仍要更新版本。
- 5.x、6.x 系列早就停止维护，属于"无修复版本可升"的情况。这类老 Tomcat 如果还在跑，说明业务系统本身就需要厂家给出替代方案，不能只靠打补丁了事。

### 📌 处置后的验证

```bash
# 1. 确认新版本已不在影响范围内
sh /usr/local/tomcat/bin/version.sh
# 期望：Server version ≥ 8.5.37 或 ≥ 9.0.14（或更高的最新版）

# 2. 确认服务端口正常监听
ss -lntp | grep java
# 期望：8080/8443 等端口正常监听
```

升级完成后重启 Tomcat，让运行人员登录业务页面做一次完整的功能确认（登录、报表、指令下发页面），全部正常才算闭环。
