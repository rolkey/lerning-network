## 一、面向单位：加固工作总结

### 3. 作业项概览

- **主机类（Linux）**：病毒查杀、设备管理（SSH 替代 telnet/FTP、访问控制）、用户账号与口令安全、日志与审计、服务优化、安全防护、漏洞处置（WebLogic/Axis/Tomcat/内核 SACK 等）、必装软件与接入（作业编号 B1–B26 及漏洞通报项）。
- **主机类（Windows）**：病毒查杀、账号口令、日志审核、服务优化、关闭高危端口、软件安装、漏洞与补丁（作业编号 A1–A27）。
- **交换机 / 路由器（H3C）**：设备管理、用户账号与口令安全、日志与审计、服务优化、安全防护（作业编号 D1–D21）。
- **防火墙**：策略备份、设备管理、账号口令、日志审计、服务优化、安全防护（作业编号 C1–C19）。
- **加密装置**：策略检查、日志服务器、口令、远程管理（作业编号 E1–E4）。

### 4. 总体结论

各设备均按管控表单完成安全评估与整改，表单总体评估结论均为合格。整改涉及口令策略、远程管理加密、访问控制、日志审计、漏洞处置、高危端口封堵等基础安全项，覆盖主机、网络、安全设备及纵向加密边界，满足并网网络安全管控要求。

### 2. 设备分类与平台差异

学习时注意**同一条作业项在不同平台上的命令口径不同**：

- **CentOS 7 系**（AGCAVC1/2、麒麟 kylin 各主机）：服务用 `systemctl`，防火墙 `firewalld`，时间 `chrony`，账户锁定 `pam_faillock`。
- **凝思 Linx 6.0（RHEL 6 系）**（PMU1/2、调度发令）：服务用 `service`/`chkconfig`，防火墙 `iptables`，时间 `ntpd`，账户锁定 `pam_tally2`。
- **Windows 10**（OMS主机）：`gpedit.msc`、`secpol.msc`、`services.msc`、`regedit` 等。
- **H3C Comware**（交换机/路由器）：`system-view`、`display current-configuration` 等 CLI。
- **防火墙 / 加密装置**：Web 界面 + 专用配置软件，按通用安全配置逻辑。

### 3. 每篇资料的结构

每篇 `序号N.md` 统一结构：

```
问题（原表要求） → 风险原理 → 配置/加固方法 → 特殊情况处理 → 加固后的验证
```

其中「问题」是表单原文抄录，「风险原理」讲清为什么做，「配置/加固方法」给出可落地的命令/步骤，「特殊情况处理」提示易踩的坑，「验证」给出检查手段。

### 4. 建议学习路径

1. 先读本 `README.md`，建立全站设备与作业项的整体框架；
2. 再按设备类型选读一台代表性设备的 `README.md` 和 `序号N.md`（如 Linux 参考 `AGCAVC1` 的「序号27.md」样例）；
3. 同一作业项在不同平台的差异，可横向对照 CentOS 7 系、凝思 RHEL 6 系、Windows、H3C 四个口径；
4. 落到现场作业时，以本目录对应设备的 `序号N.md` 为操作参考，结合表单「完成情况」核对整改是否闭环。
