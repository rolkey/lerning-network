# 用户账号权限分配与最小化

## 问题

- "按照用户分配帐号，无不同用户间共享帐号。"

---

账号是审计和责任认定的唯一依据。多人共用一个账号，意味着出了问题查不到"到底是谁干的"，权限也无法按人细分。本作业项要求为每一位实际运维人员建立独立账号，做到"一人一账号、权限随岗位"，杜绝共享账号和共用口令。在电力监控系统的多人运维场景下，账号实名化、权限分级化是安全管理和事故追责的前提，也是等保测评中"身份鉴别"和"访问控制"两项的直接落地。

### 🔍 风险原理

- **无法审计溯源**：共享账号下，操作日志只能记录"admin 在 10:03 改了策略"，却无法区分是张三还是李四。出现安全事件时，责任无法落实到人，审计形同虚设。
- **权限过宽**：共享账号通常被授予最高权限，因为要"大家都能用"。这意味着一个只负责日常巡检的初级人员也掌握了删除策略、关闭防护的权限，违背最小权限原则。
- **口令扩散失控**：共享账号的口令会在多人之间传递，知道的人越来越多，离职、转岗后口令也难以及时收回，等于长期保留一个"谁都能进"的后门。
- **越权难追责**：权限没有按岗位细分时，任何持有该账号的人都能执行超出其职责的操作，一旦误操作或恶意操作，既难预防也难追责。

一人一号、权限分级，是防火墙安全管理和安全审计的基础工程。

### 配置/加固方法

**1. 按岗位/人员建立独立账号**

```text
操作路径（通用）：
系统管理 → 用户管理 / 账号管理 → 新建用户
  用户名：采用实名或岗位编号（如 zhang.san / ops01）
  角色/权限组：审计员、操作员、只读观察员等，按岗位分配
  禁止：创建通用账号（如 admin2、test、temp）供多人共用
```

**2. 按角色分配权限，最小化授权**

```text
角色建议：
  管理员(admin)     ：仅限 1-2 名负责人，可管理账号与全局配置
  配置操作员(operator)：可配置策略，不可管理账号
  审计员(auditor)   ：只读策略与日志，不可修改
  只读观察员(viewer) ：仅供巡检/态势感知只读接入
实现"操作、审计、管理"三权分立，避免一人独揽。
```

**3. 定期清理与复核**

```text
周期：每季度复核一次账号清单
动作：删除离职/转岗人员账号；冻结长期未登录账号；
     核对"账号—人员—角色"三者一致，无共享、无空挂账号
```

**4. 建立账号台账**

```text
维护《运维人员—账号对照表》，记录：账号、使用人、角色权限、
开通日期、最近登录、状态（在用/冻结/删除），供审计和交接使用。
```

### 特殊情况处理

- 部分老型号防火墙只支持极少数内置账号（如只有 admin 和 auditor 两个），无法做到严格一人一号时，应在台账中明确记录账号使用人，并通过堡垒机实现"个人账号登录堡垒机、堡垒机代登防火墙"的实名化间接管理。
- 应急场景确实需要临时共用时，应申请临时账号并设置短有效期，事后立即回收，不能长期存在。
- 审计员与操作员角色应分离（三权分立），避免同一人既能改配置又能删日志。
- 账号口令一旦被共享过，应立即改密，因为口令已不在可控范围内。
- 外包/厂家远程运维账号要单独管理、限时开放、用完即禁，不得长期留存。

### 📌 加固后的验证

```text
# 验证要点
1. 登录防火墙，导出用户列表，逐一与《运维人员—账号对照表》核对，确认一人一号、无共享账号；
2. 抽查不同账号的角色权限，确认普通操作员无法执行"新建账号/删除日志"等高权限操作；
3. 查看操作日志中"操作人"字段，确认每次变更都能对应到具体账号而非共用账号；
4. 核对已离职人员账号已删除或冻结。
```

期望结果：每个运维人员拥有独立账号；权限按岗位角色分配；无共享账号、无多余账号；操作日志可追溯到具体人员。
