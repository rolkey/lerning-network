# 访问规则最后一条显式拒绝

## 问题

- "访问规则列表最后一条必须是显式拒绝一切流量（双向）。"

---

防火墙策略的默认行为是"隐式拒绝"——凡是规则列表里没匹配到的流量，默认就不放行。但"隐式拒绝"依赖设备默认配置，一旦固件升级、配置恢复或某段策略误改，默认行为可能变成"隐式放行"，后果不堪设想。本作业项要求在所有访问规则列表的**最后一条**显式写入"拒绝一切流量（双向）"，用一条看得见的规则兜底，确保任何未显式允许的流量都被明确拒绝。

### 🔍 风险原理

- **隐式拒绝不可靠**：隐式拒绝是"设备默认"，不是"配置"本身，容易在版本升级、出厂恢复、策略导入导出等过程中被改变，出现"默认放行"的致命漏洞。
- **误放行兜底**：策略列表中间若存在配置错误（如一条过宽的 allow any any），没有末尾的显式拒绝兜底，错误会被无限放大，攻击者长驱直入。
- **合规审计要求**：等保和电力监控安全评估都明确要求"访问控制规则最后一条为拒绝一切"，没有这条显式规则会被直接判定为不符合项。

"最后一条显式拒绝一切"是防火墙策略的"最后一道闸门"，是确定性安全的基础保障。

### 配置/加固方法

**1. 新增"拒绝一切"规则并置于列表末尾**

```text
操作路径（通用）：
策略配置 → 访问控制规则 → 新建规则：
  规则名称：Deny_All（或"默认拒绝"）
  源地址：any（任意）
  目的地址：any（任意）
  服务/端口：any（任意）
  动作：拒绝（Deny / Drop）
  方向：双向（入站 + 出站）
  日志：按需开启（可选，用于发现违规访问）
  位置：拖动/设置为规则列表最后一条
```

**2. 确认规则顺序**

```text
策略匹配是"自上而下、首次命中即停止"：
  顶部：高危端口黑名单（置顶）
  中部：业务放行策略（最小权限精确放行）
  末尾：Deny_All 拒绝一切（兜底）
任何未在前文被显式放行的流量，最终都会命中 Deny_All 被拒绝。
```

**3. 逐安全区/逐方向核查**

```text
若设备按安全区、按接口分别维护规则列表，
每个列表的最后一条都要有显式拒绝，不能只在某一条列表里配。
```

### 特殊情况处理

- Deny_All 必须"双向"：只拒绝入站、放行出站，会让内网被攻陷主机自由外联，无法阻断木马回连。
- 规则必须"最后一条"：若 Deny_All 被误放到列表中间，其后的放行规则会全部失效，导致业务中断。
- 拒绝动作建议用"Drop"（静默丢弃）而非"Reject"（返回拒绝报文），前者更隐蔽、抗扫描。
- 变更策略时，新增规则要插在 Deny_All 之前，养成"新规则永远加在默认拒绝之上"的习惯。

### 📌 加固后的验证

```text
# 验证要点
1. 查看访问规则列表，确认最后一条为"拒绝 any→any 任意服务 双向"；
2. 从任意主机发起一条未在业务策略中放行的访问（如访问未开放端口），
   应被拒绝（不通）；
3. 确认 Deny_All 位于列表末尾、其前无任何规则被"截断"；
4. 模拟一次策略误加宽（临时加 allow any any 在前），
   确认 Deny_All 仍在末尾兜底、结构未被破坏。
```

期望结果：访问规则列表最后一条为显式"拒绝一切流量（双向）"；所有未显式允许的流量均被拒绝。
