# 日志记录满足 6 个月保留要求

## 问题

- "日志记录满足6个月。"

---

这一项源表里只有一句要求，没有给命令。它考核的不是某条命令，而是一个**持续生效的机制**：系统产生的日志，从今天往回倒 6 个月，随时能查。要做到这点，靠的是 rsyslog 持续采集 + logrotate 合理轮转，两者缺一不可。

### 🔍 风险原理

日志是安全事件还原的唯一依据。为什么是 6 个月，不是 6 天：

- 很多攻击从突破到被发现，中间隔的时间很长。等事后排查时才发现日志早就被轮转删掉了，现场无从还原。
- 合规检查（本项依据《南方电网公司网络安全合规库（2017年修订版）》）对日志留存时长有明确要求，留存不足直接判不合格。
- 电力监控系统里，故障分析、责任认定往往发生在几个月之后，日志窗口太短等于没有。

反过来说，如果 rsyslog 根本不写日志，或者 logrotate 把日志 7 天就删了，这条要求就是空的。

### 配置加固方法

机制分两段，分别配置。

**第一段：保证日志被持续产生（rsyslog 侧）**。前提是 B15（syslog 开机自启）已就绪，rsyslog 正常落盘到 `/var/log/messages`、`/var/log/secure` 等文件。

**第二段：保证日志被保留 6 个月（logrotate 侧）**。logrotate 按周期轮转日志文件（重命名为 messages.1、messages.2…并可选压缩），轮转份数够了，留存时间才够。以"每天轮转 + 保留 180 份"为例，180 天约等于 6 个月：

```bash
# 编辑 logrotate 配置（rsyslog 的轮转规则在 /etc/logrotate.d/）
vi /etc/logrotate.d/rsyslog

# 内容示例：
/var/log/messages
/var/log/secure
/var/log/maillog
{
    daily          # 每天轮转一次
    rotate 180     # 保留 180 份历史（约 6 个月）
    compress       # 旧日志 gzip 压缩，省磁盘
    delaycompress  # 最近一份先不压缩，方便临时查看
    missingok      # 文件不存在不报错
    notifempty     # 空文件不轮转
    sharedscripts
    postrotate
        /bin/kill -HUP `cat /var/run/syslogd.pid 2> /dev/null` 2> /dev/null || true
    endscript
}
```

关键点：

- `rotate 180` 配合 `daily`，就是"最多存 180 天日志"；也可以换成 `monthly` + `rotate 6`，效果等同。
- `postrotate` 里的 HUP 信号让 rsyslog 重新打开日志文件，否则轮转后它会继续往旧句柄写。CentOS 7 上等价写法是 `systemctl kill -s HUP rsyslog`。
- 日志量大、按天轮转不够时，可以加 `maxsize 100M` 让单文件超大小也提前轮转，但份数（rotate）必须按 6 个月算够。

### 特殊情况处理

- 磁盘空间要估算：先看当前日志增长速度（`du -sh /var/log`，隔一周再对比），留 6 个月压缩日志的空间，别等撑爆了 `/var` 才处理。
- 如果现场有集中的日志平台（网管、态势感知会采集），平台侧留存不代表主机本地可以不达标，本地仍按 6 个月配。
- `daily` 的生效时间取决于 cron，检查 `/etc/cron.daily/logrotate` 存在，logrotate 才会天天跑。

### 📌 加固后的验证

```bash
# 1) 看现有历史日志覆盖了多久
ls -l /var/log/messages*
# 期望：能看到 messages.1、messages.2.gz …… 一路排到约 180 天前的压缩文件

# 2) 按时间确认最早一份日志距今超过 6 个月
find /var/log -name 'messages*' -printf '%TY-%Tm-%Td %p\n' | sort | head
# 期望：最早一行日期距今 > 180 天

# 3) 验证轮转规则本身没有语法问题
logrotate -d /etc/logrotate.conf
# 期望：调试输出正常，无 error
```

如果最早一份日志的日期离现在不足 6 个月，说明 rotate 份数不够或轮转没在跑，回去查 `rotate` 值和 cron 任务。
