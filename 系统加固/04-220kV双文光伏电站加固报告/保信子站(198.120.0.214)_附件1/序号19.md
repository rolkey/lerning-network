# root 用户远程登录限制

## 问题

- "root用户远程登录限制。
  注：需要先提供或新建一个可登陆的普通账号，并在堡垒机设置登陆切换。"

---

root 是主机上的最高权限账号，直接远程登录 root 意味着：谁爆破成功谁拿主机，谁拿到口令谁拥有全部权限，而且操作日志对不上具体的人。所以规范要求禁止 root 直接远程登录，改用"普通账号登录 + 切换 root"的运维模式。切换之前必须先有可用的普通账号，并在堡垒机上做好登录切换配置，否则主机直接失联。

### 🔍 风险原理

- root 账号名公开，爆破目标明确，任何来源的 root 登录尝试都不需要猜用户名；
- root 远程登录成功后拥有全部权限，一次口令泄露 = 主机完全沦陷，攻击者可直接改配置、清日志、装后门；
- 多人共用 root 口令时，出了问题无法追溯是哪个人、哪台堡垒机发起的操作；
- 普通账号登录后再 `su -` 切换 root，可以在 su/sudo 日志里留下"谁在什么时候变成了 root"的痕迹，审计链完整得多。

### 配置/加固方法

**方法一：修改 sshd 配置（源文第一种，推荐）**

```bash
# 修改 /etc/ssh/sshd_config，将 PermitRootLogin yes 改为 no
vi /etc/ssh/sshd_config
PermitRootLogin no

# 重启 sshd 服务
systemctl restart sshd
```

CentOS 7 里 `PermitRootLogin` 有几种取值：`yes` 允许口令和密钥登录；`prohibit-password`（等价于旧的 `without-password`）只允许密钥登录；`no` 一律拒绝。按规范要求取 `no`。

**方法二：配置 /etc/securetty（源文第二种）**

源文写法：在 `/etc/securetty` 文件中配置 `CONSOLE = /dev/tty01`，把 root 限制在指定控制台登录。这个 `CONSOLE =` 语法来自早期的商用 Unix；Linux 的 `/etc/securetty` 格式不同——每行写一个允许 root 登录的 tty 设备名，由 `pam_securetty.so` 在本地控制台登录时读取。把 root 的本地登录限制在机房里的物理控制台，可以防止从其他本地终端（含串口）直接以 root 进入系统。

**前置步骤：先建普通账号（源文注释要求）**

```bash
# 新建可登录的管理账号并设置口令
useradd -m admin
passwd admin

# 按管理要求授予 sudo 权限（可选）
usermod -aG wheel admin
```

然后在堡垒机上配置登录切换：运维人员先用 `admin` 登录主机，再 `su - root`（或 `sudo -i`）切换到 root 操作。切换动作会记录在 `/var/log/secure` 里。

### 特殊情况处理

- 改 `PermitRootLogin no` 前，务必先在另一个窗口用普通账号验证能登录、能 `su -` 成功，再重启 sshd，避免配置错误导致无人能进。
- 自动化巡检、采集任务如果之前用 root + 密钥直接登录，禁用后要改成普通账号 + sudo，或改用专用巡检账号，否则监测任务会断。
- 重启 sshd 前先执行 `sshd -t` 检查语法，语法错误会导致服务起不来。

### 📌 加固后的验证

```bash
# 1、确认生效配置中 root 远程登录已禁止
sshd -T | grep permitrootlogin
# 期望输出：permitrootlogin no

# 2、实测：直接以 root 尝试远程登录
ssh root@198.120.0.214
# 期望：root 登录被拒绝（提示 Permission denied）

# 3、实测：普通账号登录后再切换 root
ssh admin@198.120.0.214
su - root
# 期望：admin 可正常登录，su 切换成功后 root 可用
```

期望结果：`permitrootlogin no` 生效，root 远程登录被拒绝，普通账号可正常登录并切换 root，堡垒机侧登录切换配置完成。
