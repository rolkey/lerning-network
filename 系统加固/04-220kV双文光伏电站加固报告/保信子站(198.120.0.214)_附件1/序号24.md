# 控制用户登录会话

## 问题

- "设置登录超时控制用户登录会话时间为300秒"
- 加固方法：执行 `vi /etc/profile` 按以下要求编辑设置：3级系统设置 `TMOUT=300`（设置超时时间 300 秒）

---

### 🔍 风险原理

"人走终端不关"是运维现场最常见的场景：登录后离开工位处理其他事，终端就那么挂着。攻击者如果进入机房，或者通过被拿下的跳板机，就能捡到一个还挂着 root 的会话——连密码都不用试。给空闲会话加超时，5 分钟无操作自动断开，把这段暴露窗口压到最小。

`TMOUT` 是 bash 的内置变量，单位是秒。设置后，交互式 shell 空闲超过该时长就自动退出。它写在 `/etc/profile` 里，所有用户登录时都会继承，改一处、全局生效，这也是基线把它放在这里的用意。

### 配置加固方法

```bash
vi /etc/profile
```

在文件末尾添加（3 级系统按规范取 300 秒）：

```bash
export TMOUT=300
```

保存后，新开的登录会话立即生效；已存在的会话要么重新登录，要么手动加载：

```bash
source /etc/profile
```

可选做法：把变量设为只读，防止普通用户在自己的 shell 里 unset 掉：

```bash
readonly TMOUT
export TMOUT
```

### 特殊情况处理

- **用户覆盖**：用户可以在自己的 `~/.bashrc` 里重新设置 TMOUT 抵消全局配置。要强约束的话，建议把设置放到 `/etc/profile.d/` 下的独立脚本（如 `/etc/profile.d/tmout.sh`），与现场运维规范统一。
- **SSH 会话**：`TMOUT` 只在 shell 空闲时生效。如果前台程序长时间占着（`top`、`tail -f` 之类），超时可能不触发。对 SSH 远程通道，可配合 sshd 的 `ClientAliveInterval` / `ClientAliveCountMax` 做连接级兜底，源表未要求，按现场需要决定。
- **非交互场景**：cron 任务和脚本不读 `/etc/profile`，不受 TMOUT 影响；`su` 之后的环境在各发行版略有差异，验证时以实际终端行为为准。

### 📌 加固后的验证

```bash
grep TMOUT /etc/profile
```

期望输出包含 `TMOUT=300`（或 `export TMOUT=300`）。

重新登录后检查变量是否生效：

```bash
echo $TMOUT
```

期望输出 `300`。

条件允许时做一次实际测试：登录后静置 5 分钟，终端应自动断开。
