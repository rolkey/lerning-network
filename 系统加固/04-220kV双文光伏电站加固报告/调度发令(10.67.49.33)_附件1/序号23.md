# 启用登录失败锁定

## 问题

- "应配置当用户连续认证失败次数为 5次，锁定该帐户30分钟。"
- 加固方法：配置 `/etc/pam.d/login`
  ```
  auth        required      pam_tally2.so deny=5 unlock_time=1800
  ```

---

### 🔍 风险原理

口令是最常见、也最容易被暴力尝试的认证方式。如果系统对登录失败次数不做任何限制，攻击者就可以用字典持续尝试，直到猜中为止。电力监控系统的不少主机还留着运维阶段设的弱口令，一旦被爆破成功，等于直接把系统入口交出去。

`pam_tally2` 是 PAM（可插拔认证模块）里负责失败次数统计的模块：每次认证失败计数 +1，达到 `deny` 设定的阈值后拒绝该账户的后续认证尝试，直到 `unlock_time` 过后自动解锁。效果就是：5 次试错之后，30 分钟内这个账户谁也登不进去。在线爆破基本失去意义。

### 配置加固方法

编辑 `/etc/pam.d/login`，加入 tally 规则：

```bash
vi /etc/pam.d/login
```

在 auth 段添加（放在 `auth substack system-auth` 之后、其他 auth 行之前）：

```bash
auth        required      pam_tally2.so deny=5 unlock_time=1800
```

参数含义：

| 参数 | 含义 |
| --- | --- |
| `deny=5` | 连续失败 5 次后锁定 |
| `unlock_time=1800` | 锁定 1800 秒（30 分钟）后自动解锁 |

保存即生效，不需要重启服务。

**作用范围要留心**：`/etc/pam.d/login` 只覆盖控制台/本地终端登录。凝思 Linx 6.0 上 SSH 走的是 `password-auth` 子栈，如果要求远程登录同样锁定，需要把同一行写进 `/etc/pam.d/password-auth` 和 `/etc/pam.d/system-auth`，让 login、sshd、su 共用这条规则。

### 特殊情况处理

- **root 账户**：默认情况下 `pam_tally2` 对 root 也计数，但 root 是否被真正拦下取决于 PAM 模块链；要明确对 root 生效需加 `even_deny_root` 参数。生产环境一般不建议锁 root，避免运维自己被锁在门外，所以规范只要求锁定普通用户，root 保持可登录。
- **手工解锁**：账户被锁后，管理员可清零计数：
  ```bash
  pam_tally2 --user <用户名> --reset
  ```
- **替代模块**：`pam_tally2` 在 RHEL 8+ 等新系统里已被 `pam_faillock` 取代（配置在 `/etc/security/faillock.conf`）。凝思 Linx 6.0 上 `pam_tally2` 可用，本项按源表使用 `pam_tally2`。

### 📌 加固后的验证

1. 确认规则已写入：
   ```bash
   grep -n "pam_tally2" /etc/pam.d/login
   ```
   期望输出 `auth required pam_tally2.so deny=5 unlock_time=1800` 一行。

2. 实测锁定效果：用测试账户连续输错 5 次密码，然后查看计数：
   ```bash
   pam_tally2 --user <测试账户>
   ```
   期望 `Login Failures` 数值为 5，第 6 次登录即使输入正确密码也被拒绝。

3. 验证完毕后清零：
   ```bash
   pam_tally2 --user <测试账户> --reset
   ```
