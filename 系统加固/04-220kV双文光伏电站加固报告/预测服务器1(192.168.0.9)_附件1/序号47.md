# "帆软"报表组件高危漏洞处置（卸载）

## 问题

> 漏洞编号：调度20190618-002 —— "帆软"报表组件漏洞
>
> 加固方法："帆软"报表组件存在高危漏洞，暂无补丁，先进行卸载。对象：帆软。

---

### 🔍 漏洞原理与风险

帆软 FineReport 是国内常见的报表产品，调度、生产报表类的服务器上经常能看到。本次作业明确该组件存在高危漏洞，且**暂无补丁**——补丁这条路走不通，处置结论就是直接卸载。

报表组件通常开放 Web 管理界面和报表服务端口，一旦存在可利用的高危漏洞，攻击者可以借它进入业务内网，以组件进程权限执行操作，甚至进一步横向移动。所以第一步永远是确认主机上到底有没有这个组件，有就按"先卸载"执行。

### 处置/加固方法

Windows 环境：打开"程序和功能"，找到帆软报表组件，执行卸载。

Linux 环境：先定位组件：

```bash
find / -name *FineReport* 2>/dev/null
```

如果查找不到，说明这台主机未部署帆软，无需处理。

查找到后，先停掉对应服务，再删除组件目录：

```bash
# 1. 停止帆软相关进程/服务（按实际服务名执行）
ps -ef | grep -i finereport

# 2. 删除定位到的组件目录（路径以 find 结果为准，示例）
rm -rf /opt/FineReport
```

卸载前建议先备份报表模板文件和数据源配置，便于后续在其他环境恢复业务。

### 特殊情况处理

- `find` 没有输出，就是未部署，此项作业直接闭环。
- 如果业务强依赖报表功能，直接卸载会中断业务。这种情况要先和业务方确认替代方案，但作业要求是"先卸载"，以实际排查结论为准。
- Windows 环境按"程序和功能"卸载后，再检查一下是否残留安装目录、系统服务项和开机启动项。
- 帆软在 Linux 上常见部署形态是独立目录，或挂在 Tomcat 的 `webapps` 下，find 时留意 `FineReport` 大小写组合。

### 📌 处置后的验证

- 再次执行 `find / -name *FineReport* 2>/dev/null`，应当无输出。
- 检查相关进程已停止：`ps -ef | grep -i finereport`，应当无输出。
- 原报表访问地址应当无法打开。
