# WebLogic 反序列化漏洞 CVE-2019-2729 处置

## 问题

> 漏洞编号：调度20190619-001 —— WebLogic中间件反序列化漏洞CVE-2019-2729
>
> 加固方法：CVE-2019-2725的补丁修复被绕过，立即采取措施：（1）禁止所有IP对weblogic的/_async/*和/wls-wsat/*目录进行访问。（2）删除wls9_async_response.war与wls-wsat.war文件及相关文件夹，并重启Weblogic服务。对象：weblogic

---

### 🔍 漏洞原理与风险

CVE-2019-2725 是 WebLogic `/_async/*` 组件的未授权反序列化远程代码执行漏洞：攻击者不经过认证，构造恶意请求即可执行任意代码。厂商发布补丁之后，绕过该修复的攻击方式再次出现，这就是 CVE-2019-2729，同样可以未授权远程执行代码。

这类漏洞利用成本极低——不需要口令、不需要内网立足点，网络可达就能打，且 WebLogic 进程通常以高权限运行，一旦被打穿就是整机沦陷。补丁修复被绕过意味着"只打补丁"已经不够，所以作业的处置是双保险：网络侧封锁入口 + 主机侧移除部署包。

### 处置/加固方法

第一步，定位涉及的两个部署包：

```bash
find / -name wls9_async_response.war 2>/dev/null
find / -name wls-wsat.war 2>/dev/null
```

查找不到，说明该主机未部署这两个组件，无需处理。

第二步，查找到后进入文件所在目录，执行改名处置：

```bash
mv wls9_async_response.war wls9_async_response.war.bak
mv wls-wsat.war wls-wsat.war.bak
```

改名后 WebLogic 不再加载这两个应用，`.bak` 保留原文件用于回退。

第三步，重启 WebLogic 服务（在域目录 `bin` 下执行）：

```bash
./stopWebLogic.sh
./startWebLogic.sh
```

同时，在网络侧（防火墙/安全设备）落实"禁止所有IP访问 /_async/* 和 /wls-wsat/*"，两条措施都要做。

### 特殊情况处理

- war 包旁如果存在已解压的同名应用目录，一并改名，防止 WebLogic 用解压目录重新部署。
- 业务确实依赖 WS-AT 事务服务的，不能直接退役，需升级 WebLogic 到官方修复版本，并在网络侧严格限制来源 IP。
- 生产环境一时无法安排重启的，至少先落实网络侧封锁，主机侧改名操作再择机执行。
- 改名操作可逆：把 `.bak` 改回原名重启即回退。

### 📌 处置后的验证

- 再次执行 `find / -name 'wls9_async_response.war' 2>/dev/null` 与 `find / -name 'wls-wsat.war' 2>/dev/null`，应当无输出（只剩 `.bak` 文件）。
- 浏览器访问 `http://<主机IP>:<端口>/_async/` 和 `http://<主机IP>:<端口>/wls-wsat/`，应当返回 404 或页面不存在。
- 确认 WebLogic 进程正常：`ps -ef | grep java | grep weblogic`。
