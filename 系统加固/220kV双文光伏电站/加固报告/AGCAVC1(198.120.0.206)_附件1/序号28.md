# syslog 登录事件记录

## 问题

- "syslog登录事件记录捕获authpriv消息"
- 加固方法：执行命令 `more /etc/syslog.conf`，查看参数 authpriv 值，记录有关安全方面日志消息（如网络设备启动、usermod、change 等）

---

### 🔍 风险原理

系统里所有认证相关的事件——登录成功、登录失败、su 切换、账号口令变更——都由内核和 PAM 以 `authpriv` facility 发出。facility 是 syslog 对日志来源的分类，`authpriv` 即"认证/安全敏感"类。syslog 服务收到消息后，按配置文件决定写到哪个文件。

如果配置里没有捕获 authpriv（或者干脆指向 `/dev/null`），这些安全事件就只存在于内核内存里，重启即消失。事后要查"昨晚 2 点谁登录失败 20 次"，什么都查不到。对电力监控系统来说，登录失败记录是异常发现和定责的第一手证据，这条必须留。

### 配置加固方法

先看当前配置：

```bash
more /etc/syslog.conf
```

老式 syslog 的写法里应有类似一行：

```bash
authpriv.*                                              /var/log/secure
```

**CentOS 7 说明**：CentOS 7 用 rsyslog，配置主文件是 `/etc/rsyslog.conf`（`/etc/syslog.conf` 是老式 syslog 的路径，CentOS 7 上不再存在），语法基本兼容。默认配置里已经自带 `authpriv.* /var/log/secure`。如果缺失，补上：

```bash
vi /etc/rsyslog.conf
```

添加：

```bash
authpriv.*                                              /var/log/secure
```

`authpriv.*` 表示把 authpriv 设施的所有级别（debug 到 emerg）全部记录到 `/var/log/secure`。修改后重启日志服务：

```bash
systemctl restart rsyslog
```

### 特殊情况处理

- **记什么算够**：规范点名的"网络设备启动、usermod、change 等"指的是认证与账号变更类事件。authpriv 覆盖登录、su、sudo 及 PAM 认证事件；`usermod`、`chage` 这类账号管理动作在启用 auditd 的系统里进入审计日志，在仅用 syslog 的环境里，确保 authpriv 全级别捕获并落盘即可满足该项要求。
- **日志轮转**：`/var/log/secure` 靠 logrotate 轮转（CentOS 7 自带 `/etc/logrotate.d/syslog`），现场要确认保留周期满足电力监控系统的留存要求。
- **自定义规则目录**：如果习惯把规则放在 `/etc/rsyslog.d/*.conf`，注意主文件里的 `$IncludeConfig /etc/rsyslog.d/*.conf` 默认开启，规则会合并生效，两边别写冲突。

### 📌 加固后的验证

```bash
grep authpriv /etc/rsyslog.conf
```

期望输出包含 `authpriv.*  /var/log/secure`。

实测：另开一个终端故意输错一次密码，然后查看：

```bash
tail /var/log/secure
```

期望看到本次失败认证的记录（如 `pam_unix(login:auth): authentication failure` 字样），说明 authpriv 事件已被捕获落盘。
