# 高危端口进程的排查与强制结束

## 问题

- "加固后，输入netstat -anp|grep 端口号
  添加防火墙策略，禁用135、137、138、139、445、3389、23333（防止跳板攻击）高危端口。
  原则上禁用23、25、20、21、513、25、110端口。（23端口telnet；25端口SMTP；20、21端口ftp；513端口login；25、110端口e-mail服务）"

---

B24 的核心动作是：用 `netstat -anp` 把监听高危端口的进程揪出来，`kill -9` 强制结束，重启后复查，再配防火墙策略把这些端口全部封死。这一项针对的是"主机被当作跳板"的风险。

### 🔍 风险原理

源表列出这些端口，是因为它们几乎都是历史漏洞重灾区或者明文传输协议：

- **135、137、138、139、445**：Windows 文件/打印共享（SMB、NetBIOS）全家桶。139/445 上的 SMB 漏洞养活了"永恒之蓝"（MS17-010）这一整代勒索蠕虫，这组端口在 Linux 上多半是 samba 开的，属必须封的口。
- **3389**：RDP 远程桌面，弱口令爆破的重灾区。
- **23333**：非常用端口，常被跳板工具、代理工具（frp 类）用来开隧道，属于"防止跳板攻击"重点盯的对象。
- **23（telnet）、25（SMTP）、20/21（FTP）、513（rlogin）、110（POP3）**：这几个是明文协议，账号密码在网络上裸奔。telnet 和 rlogin 还允许直接远程登录，513 更是老 rlogin 的默认口。

**跳板攻击**是什么：攻击者先拿下内网里这台相对边缘的主机，再通过它访问更核心的系统，把自己的真实来源藏在这台机器后面。对电力监控系统来说，调度主机一旦被当跳板，攻击者就摸到了调度数据网（比如 10.67.0.0 网段）的门口。所以这些端口不是"影响不大就先留着"，而是原则上全部禁用。

### 配置加固方法

**第一步：查进程。**

```bash
netstat -anp | grep 端口号
```

参数说明：`-a` 显示所有连接和监听，`-n` 直接显示数字 IP 和端口（不反解主机名，快），`-p` 把监听/连接对应的 PID 和程序名打出来——这是关键，没有 `-p` 你只知道端口开着，不知道是谁开的。

输出里最后一列就是 `进程号/程序名`。源表给的实际例子：138 端口的进程号是 4016。

**第二步：结束进程。**

```bash
kill -9 进程号
```

对应源表例子就是：

```bash
kill -9 4016
```

`-9` 是 SIGKILL，直接强杀，进程没有机会做清理。好处是保证能杀掉，坏处是如果这个进程有残留文件、锁、临时数据，会脏着留下。所以源表紧接着要求：**杀完重启系统，待运行正常后，再次检查进程运行与端口开启情况**——重启一方面验证系统还能正常起来（没杀错关键进程），另一方面看这个端口进程会不会开机自启又被拉起来。

**第三步：防火墙封端口。**

按源表口径，高危端口用防火墙策略封死。CentOS 7 上 firewalld 的写法：

```bash
# 逐个添加 drop 规则（以 445 为例，其它端口照推）
firewall-cmd --permanent --add-rich-rule='rule family="ipv4" port port="445" protocol="tcp" drop'
firewall-cmd --reload
```

如果现场还在用 iptables：

```bash
iptables -A INPUT -p tcp --dport 445 -j DROP
iptables -A INPUT -p udp --dport 445 -j DROP
service iptables save
```

135、137、138、139、445 都有 TCP/UDP 两种，封的时候两套都要写。具体用 firewalld 还是 iptables，看现场装的是哪个，源表没有限定。

### 特殊情况处理

- **kill -9 杀完又复活**：说明进程不是直接起的，而是挂在 inetd/xinetd 或者 systemd 服务下面。先查：`systemctl list-units | grep <服务名>`，找到对应服务后 `systemctl disable --now <服务名>` 停掉并取消开机自启（CentOS 6 用 `chkconfig <服务名> off`），再杀进程，否则重启后一切照旧。
- **先试试不带 -9 的 kill**：`kill <PID>` 发 SIGTERM，给进程一个体面退出的机会。确实不走再上 `kill -9`。源表直接写 `kill -9` 是因为现场求稳、求快，这个顺序可以在实际执行时灵活处理。
- **别误杀**：`netstat -anp | grep 445` 有时会匹配到本机作为**客户端**的临时连接（源端口恰好是 445xx 之类）。看清楚状态列，是 `LISTEN` 的才需要处理。
- **端口在防火墙封掉之前先别急着杀光**：如果这个端口上有正在跑的现场业务，先跟厂家确认是不是他们的服务，再动手。调度发令系统上不该有 SMB/telnet 这类东西，但确认一步总比误杀强。

### 📌 加固后的验证

```bash
netstat -anp | grep -E ':(135|137|138|139|445|3389|23333|23|25|20|21|513|110)\s'
```

期望**没有任何 LISTEN 输出**。对照源表的做法：`kill -9 4016` 之后，再执行 `netstat -anp|grep 138`，应当查不到 138 端口的监听进程。

再执行防火墙规则检查：

```bash
firewall-cmd --list-all
# 或者 iptables -L -n
```

确认 drop 规则在列。最后按源表要求重启主机一次，重启后把上面的 `netstat` 复查再跑一遍，两个检查都干净才算完成。
