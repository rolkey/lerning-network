# 密码复杂度策略（A3）

## 问题

- 运行"gpedit.msc"计算机配置->Windows设置->安全设置->帐户策略->密码策略：
  - 密码必须符合复杂性要求 -> 启用
  - 密码长度最小值 -> 8
  - 密码最长使用期限 -> 180天
  - 密码最短使用期限 -> 1天
  - 强制密码历史 -> 3次

---

A3 管的是本地账号密码策略：**密码要多复杂、用多久、多久能改一次、旧密码能不能重复**。五个参数全部在 gpedit.msc 的一个界面里配完。

### 🔍 风险原理

本地账号的口令是主机对抗暴力破解的第一道防线，密码策略直接决定这道防线有多硬。

- **复杂度 + 最小长度 8**：如果允许纯数字或纯字母的短密码，攻击者跑字典或暴力枚举，弱密码几分钟就破。Windows 的"密码必须符合复杂性要求"启用后强制密码满足：不能包含用户名/显示名全名、长度至少 6 个字符、必须包含大写字母、小写字母、数字、特殊符号四类中的至少三类。本策略再把长度下限提到 **8**。
- **最长使用期限 180 天**：限制密码寿命。密码哪怕被泄露了，最多 180 天后作废。电力监控系统里很多账号多人共用、长期不改，这个期限是硬性的兜底。
- **最短使用期限 1 天 + 强制密码历史 3 次**：这两个是配套的。没有最短期限，用户被要求改密码时当场改一下又立刻改回原密码，等于没改；没有密码历史，用户把密码从 A 改成 B、下个月再改回 A。最短期限 1 天让密码至少用满一天，历史 3 次让最近用过的 3 个密码都不能复用。

### 配置（加固方法）

运行 `gpedit.msc`，进入：

```
计算机配置 -> Windows 设置 -> 安全设置 -> 帐户策略 -> 密码策略
```

逐项双击，按以下值设置：

| 策略项 | 设置值 |
| --- | --- |
| 密码必须符合复杂性要求 | 已启用 |
| 密码长度最小值 | 8 个字符 |
| 密码最长使用期限 | 180 天 |
| 密码最短使用期限 | 1 天 |
| 强制密码历史 | 3 个记住的密码 |

五项改完后关闭组策略编辑器即可，本地策略即时保存。可以用 `gpupdate /force` 强制刷新一次（本地安全策略实际无需等待组策略刷新周期，重启后必然生效）。

### 特殊情况处理

- **已有账号的密码超过 180 天**：把最长使用期限改成 180 天后，已超过 180 天未改密的账号在下一次登录时会被系统强制要求改密码，属正常现象，不是故障。
- **"密码永不过期"勾选**：如果某些账号属性里勾了"密码永不过期"，它们不受最长使用期限约束。合规检查时要把这个勾选去掉，否则策略形同虚设。
- **服务账号**：设置密码时若动到运行服务的本地账号，同步在 `services.msc` 里更新该服务的登录密码（与 A2 的注意事项一致）。
- **改策略后新密码被拒**：设置新密码时报"密码不满足策略要求"，通常是没凑齐四类字符中的三类或长度不够 8，按提示补字符即可。

### 📌 加固后的验证

- 打开密码策略界面，五项值与要求一致：启用 / 8 / 180 / 1 / 3。
- 命令行执行 `net accounts`，输出中可见：密码长度最小值 8、密码最短使用期限 1 天、密码最长使用期限 180 天、保持的密码历史长度 3。
- 实测一：给账号设置 `123456` 这类纯数字密码，系统应拒绝。
- 实测二：改密码时尝试改回最近 3 次内用过的旧密码，系统应拒绝。
