# 用户权限设置（A5）

## 问题

- "'本地策略-用户权利指派'中从远端系统强制关机只指派给Administrators组；'本地策略-用户权利指派'中关闭系统仅指派给Administrators组。"
- 检查用户权限策略是否设置：开始 → 运行 → gpedit.msc，计算机配置 → Windows设置 → 安全设置 → 本地策略 → 用户权利指派。此处有较多选项，建议对以下四项进行检查：从网络访问此计算机（可选）、从远程系统强制关机、关闭系统、拒绝本地登录。
- 建议做如下设置：从远程系统强制关机：administrators；关闭系统：administrators；设置取得文件或其它对象的所有权为只指派给Administrators组；拒绝本地登录：IUSR_MACHINENAME、IWAM_MACHINENAME等不需要使用的用户。
- 设置完成后使用 secedit /refreshpolicy machine_policy 命令刷新策略以快速生效（建议重新启动系统）。

---

A5 管的是"用户权利指派"（User Rights Assignment）。这层安全设置不碰密码、不碰 ACL，直接规定**哪些账号有资格干哪些高危操作**。默认安装下这些权利会派给 Users、Everyone 等宽泛组，需要收紧到只给 Administrators。

### 🔍 风险原理

用户权利指派是 Windows 安全模型里最容易漏掉的一层，因为它平时不声不响，出问题就是大问题：

- **从远程系统强制关机**（SeRemoteShutdownPrivilege）：能远程把机器强制关机。默认 Users 组就带这项权利——意味着一个被黑的普通账号，或一个心怀不满的内部人员，能在网络里直接把 OMS 这类业务主机强行关机，制造停机事故，而不用拿到管理员权限。
- **关闭系统**（SeShutdownPrivilege）：本机关机权利，同样默认派给普通用户。服务器上普通用户没有关机的业务需求，收回即可。
- **取得文件或其他对象的所有权**（SeTakeOwnershipPrivilege）：最危险的一项。NTFS 权限（ACL）挡不住"取所有权"——拿到所有权后可以直接改写文件权限，等于绕过全部文件访问控制。默认只有 Administrators 有这项权利，此项检查的意义在于防止被误加进其他组。
- **拒绝本地登录**：反向策略，把不需要登录的账号明确拉黑。IUSR_MACHINENAME、IWAM_MACHINENAME 是 IIS 的遗留匿名访问账号（MACHINENAME 是实际主机名），机器不跑 IIS 时这些账号纯属多余，加入拒绝本地登录列表后，即使有人拿到它们的密码也登不进来。

### 配置（加固方法）

开始 → 运行 → 输入 `gpedit.msc` 回车，进入：

```
计算机配置 -> Windows 设置 -> 安全设置 -> 本地策略 -> 用户权利指派
```

右侧列表逐项双击，把非管理员的组/账号移除，按以下要求收紧：

1. **从远程系统强制关机** -> 只保留 `administrators`
2. **关闭系统** -> 只保留 `administrators`
3. **取得文件或其它对象的所有权** -> 只保留 `Administrators` 组
4. **拒绝本地登录** -> 添加 `IUSR_MACHINENAME`、`IWAM_MACHINENAME` 等确认不需要使用的用户（把 MACHINENAME 换成实际主机名）
5. **从网络访问此计算机** -> 源表标注"可选"，按业务情况检查：如果不需要网络共享访问，此项同样只留必需账号。

刷新策略：源表写的是 `secedit /refreshpolicy machine_policy`，这是 Windows 2000/XP/2003 时代的老语法，Win10 中已不再支持。Win10 上等价做法是用组策略刷新命令：

```text
gpupdate /force
```

强制刷新计算机策略。源表也建议重新启动系统——重启后所有本地安全策略必然生效，是最终确认手段。

### 特殊情况处理

- **不要整表清空重建**：用户权利指派里有很多系统组件依赖的项，只动上面列出的这几项，其他不动。
- **业务软件依赖关机权利**：个别 UPS 监控、看门狗类软件以本地服务身份执行关机，移除 Users 后可能失效。改之前先确认哪些软件有此类功能，有的话该服务以管理员身份运行即可（服务登录账号设为管理员）。
- **IUSR/IWAM 账号**：本机如果确实在跑 IIS 且业务依赖匿名访问，先确认再加拒绝列表；源表写的是"等不需要使用的用户"，即确认不用才加。
- **普通账号登录后看不到关机按钮**：移除"关闭系统"里的 Users 后属正常现象，不是故障。

### 📌 加固后的验证

- 在 gpedit.msc 用户权利指派中逐项查看，"从远程系统强制关机""关闭系统""取得文件或其它对象的所有权"三项的账号列表中只有 Administrators 组。
- 用普通账号登录，在命令行执行 `shutdown /m \\主机名 /f`，应提示"拒绝访问"（错误 5）。
- 用普通账号尝试接管管理员所拥有的文件（属性 -> 安全 -> 高级 -> 更改所有者），应失败。
- 执行 `gpupdate /force` 无报错；重启后执行 `gpresult /r` 可查看已应用的策略。
