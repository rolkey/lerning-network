# 审核策略设置

## 问题

- "已设置审核策略：
  审核帐户登录事件：成功，失败
  审核帐户管理：成功，失败
  审核目录服务访问：失败
  审核登录事件：成功、失败
  审核对象访问：成功，失败
  审核策略更改：成功，失败
  审核特权使用：失败
  审核过程追踪：无审核
  审核系统事件：成功、失败"
- 加固方法："运行输入C:\>gpedit.msc，进入"计算机配置->Windows设置->安全设置->本地策略"配置审核策略"

---

### 🔍 风险原理

审核策略决定 Windows 把哪些安全相关动作写进安全日志。没有它，登录成功、账户增删、权限变更这类关键动作全部无痕，出事后无法追溯。

各审核项的意义：

- **审核账户登录事件**：记录账户登录凭据验证结果（区别于下面"登录事件"记录会话建立），能看出谁在尝试登录、谁被拒。
- **审核账户管理**：记录账户/组的创建、删除、改密、改组成员等管理操作。
- **审核登录事件**：记录用户在本机登录/注销会话，是"谁什么时候上过这台机器"的直接依据。
- **审核对象访问**：配合文件/注册表的 SACL 记录访问行为，用于发现越权读取。
- **审核策略更改**：记录审核策略、信任关系等安全策略被改动，防止有人悄悄关掉审计。
- **审核特权使用**：记录用户权限（如 SeDebugPrivilege、备份还原）的使用，可发现提权行为。
- **审核系统事件**：记录开关机、系统时间修改、安全日志被清空等。

**过程追踪无审核**是刻意为之：进程级追踪日志量极大，一天能刷出海量事件，对监控主机意义有限还拖性能，所以本表单不开启。

### 配置（加固方法）

运行 `gpedit.msc`，进入 **计算机配置 → Windows 设置 → 安全设置 → 本地策略 → 审核策略**，逐项设置：

```text
审核帐户登录事件       成功，失败
审核帐户管理           成功，失败
审核目录服务访问       失败
审核登录事件           成功，失败
审核对象访问           成功，失败
审核策略更改           成功，失败
审核特权使用           失败
审核过程追踪           无审核
审核系统事件           成功，失败
```

每项双击打开，勾选"成功"/"失败"后确定即可。

两点说明：

1. 源表 D 栏（作业结点）与 F 栏（加固方法）在几个项目上有出入——F 栏把九项全部写成"成功和失败都要审核"，而 D 栏的实际执行结果是：目录服务访问只审"失败"、特权使用只审"失败"、过程追踪"无审核"。执行时以 D 栏的落定结果为准，上表即最终状态。
2. Win10 上存在"高级审核策略配置"（`secpol.msc` → 高级审核策略配置），一旦那边配了，会覆盖"本地策略 → 审核策略"里的基础设置。核对时两个位置都看一眼，保持一致性。

### 特殊情况处理

- **目录服务访问**针对域环境下的 AD 对象访问，工作站角色用不上，只审失败即可，不产生多余日志。
- **过程追踪**不开，原因见风险原理，不必补配。
- 大量"失败"审核会带来一定日志量，安全日志上限已在 A10 里放大到 102400KB，足够容纳。
- 策略改动后无需重启，但要确认"审核策略更改"能记录到配置变更本身——首次配置的写入会以 4904 等事件形式体现。

### 📌 加固后的验证

- `gpedit.msc` → 本地策略 → 审核策略，逐项与上表核对一致。
- 命令行核对：`auditpol /get /category:*`，输出各子类别审核状态。
- 做一个测试动作（如故意输错一次密码登录），在 **事件查看器 → Windows 日志 → 安全** 中能看到对应的失败审核事件（如 4625），说明策略已生效。
