# 加固 SNMP 服务与 SNMP TRAP

## 问题

- "系统是否启用了SNMP服务，如果启用，默认的"public"团体名已修改，并设置为8位以上的字串。（团体名改为GXhmrjsw-q3）"
- "选择了"接受来自这些主机的SNMP包"，设置的主机IP合法。（I-II区网管1.1.1.2、III区网管3.1.1.2、I区态势感知1.1.1.3、II区态势感知2.1.1.3，III区态势感知3.1.1.3）"
- 加固方法："开始 → 运行 → services.msc → 找到SNMP Service并双击打开属性面板 → 属性面板中选择安全选项卡"

---

### 🔍 风险原理

Windows 自带的 SNMP 服务是 SNMP v1/v2c 实现，它的"认证"只有一个机制：**团体名（community string）**。请求方在包里带上团体名，服务端比对一致就放行——没有加密，也没有严格的用户认证。

问题就出在这里：

1. **默认团体名 `public` 是公开的秘密**。所有默认安装里只读团体名都是 `public`，写权限团体名通常是 `private`。不改的话，任何能连到 161 端口的人都能用 SNMP 拉走系统信息（接口、进程、已安装软件、运行时间等），有写权限的还能改系统参数。
2. **来源不限制**。就算改了团体名，如果"接受来自任何主机的 SNMP 包"，团体名被猜中或泄露后仍然全网可查。

所以 A12 的加固就做两件事：**换掉默认团体名**（8 位以上、混合字符），**把来源主机收窄到合法的网管和态势感知设备**。若业务完全不需要 SNMP，按 A11 直接禁用服务，连加固都不用做。

### 配置（加固方法）

#### 1. 修改 SNMP 团体名

```text
开始 → 运行 → services.msc
→ 找到 SNMP Service → 双击打开属性面板
→ 切换到"安全"选项卡
→ 在"接受的社区名称"（团体名称）区域，选中原有的易猜解团体名（如 public），点"编辑"
→ 修改团体名称为 GXhmrjsw-q3，权限选择"只读"（READ ONLY）
→ 确定，退出属性面板
```

要点：

- `GXhmrjsw-q3` 含大小写字母、数字和符号，超过 8 位，满足表单"8 位以上字串"的要求。名称保持原样，不要改动。
- 权限选**只读**。网管轮询只需要读设备信息，写权限（READ WRITE）风险大得多，能给只读就给只读。
- 如果原列表里没有 public 而是空的，用"添加"把 `GXhmrjsw-q3` 加进去，权限同样选只读。

#### 2. 限制 SNMP 来源主机

同一个"安全"选项卡里：

```text
→ 选择"接受来自这些主机的SNMP包"
→ 点"添加"，逐个填入合法主机 IP
→ 确定，退出属性面板
```

白名单 IP（按表单原文）：

```text
I-II区网管        1.1.1.2
III区网管         3.1.1.2
I区态势感知       1.1.1.3
II区态势感知      2.1.1.3
III区态势感知     3.1.1.3
```

这五个 IP 之外的任何主机发来的 SNMP 包都会被直接丢弃，即使团体名正确也没用。

#### 3. SNMP TRAP 服务

本机若安装了"SNMP Trap"接收服务，它受 A11 的服务清单管理（标记为可选）。如果需要接收 trap，同样保持该服务仅对合法来源可用；源表未给出 trap 目标配置细节，按同一原则处理即可。

### 特殊情况处理

- **网管侧必须同步改**。团体名一改，网管软件的轮询配置里对应的 community 也要同步改成 `GXhmrjsw-q3`，否则监控立刻中断，会误报设备离线。改之前先和网管运维对齐。
- **IP 列表要与实际一致**。白名单里的五个 IP 对应各区的网管和态势感知设备，如果这些设备的地址后续有变更，列表要同步更新，否则轮询失败。
- **团体名改完即生效**，不需要重启服务；但建议改完后在服务里把 SNMP Service 重启一次，确认配置落盘。
- **如果业务不再需要 SNMP**，最干净的做法是按 A11 把 SNMP Service 和 SNMP Trap 服务直接禁用，两个条目二选一。

### 📌 加固后的验证

- `services.msc` → SNMP Service → 安全选项卡：接受的社区名称只有 `GXhmrjsw-q3`、权限只读；来源选择为"接受来自这些主机的SNMP包"，列表恰好是上述五个 IP。
- 从网管主机（如 1.1.1.2）用团体名 `GXhmrjsw-q3` 做一次 SNMP 查询（如 snmpget 读系统描述），能正常返回。
- 从一台不在白名单内的主机尝试查询，应超时无响应；用旧的 `public` 团体名查询，也应被拒绝。
