# 禁用匿名远程连接：清空可匿名访问的共享与命名管道

## 问题

- "安全选项：对匿名连接的额外限制"
- 加固方法："'控制面板->管理工具->本地安全策略'，在'本地策略->安全选项'，在右边窗格中找到'网络访问: 可匿名访问的共享'、'网络访问: 可匿名访问的命名管道' 将其值设置为空；设置完成后使用secedit /refreshpolicy machine_policy命令刷新策略以快速生效（建议重新启动系统）"
- 续行（56）："安全选项：不允许枚举SAM帐号和共享"

---

Windows 默认允许一部分匿名（空会话）连接，主要是为兼容老式网络环境。对 OMS 这种生产主机，这个默认行为等于给攻击者送情报：不用任何口令就能摸到机器上开了哪些共享、跑着哪些服务。这项作业把匿名通道整体收紧。

### 🔍 风险原理

匿名远程连接，指的是不提供任何凭据、以空会话形式连上 SMB 服务。在默认配置下，空会话能做的事件件危险：

- **枚举账户和共享**：通过空会话可以列出目标机器的共享名和本地账户列表。攻击者拿到账户名清单后，剩下的工作就只剩猜口令——账号不用猜了，暴力破解的成功率直接翻倍。
- **摸清服务信息**："可匿名访问的命名管道"默认列着一串管道（如 `browser`、`spoolss` 等），匿名者可以借这些管道获取主机信息，帮助定位高价值目标。
- **为后续攻击铺路**：账户枚举 + 共享枚举是内网渗透的标准第一步。把这两条路堵死，攻击者就少了一大半免费的侦察手段。

其中"不允许枚举 SAM 帐号和共享"这一项会同时关闭账户与共享的匿名枚举，是本项作业的核心开关。

### 配置（加固方法）

**第一步：打开本地安全策略**

"控制面板 → 管理工具 → 本地安全策略"（或运行 `secpol.msc`），展开"本地策略 → 安全选项"。

**第二步：清空匿名访问列表**

在右边窗格找到以下两项，双击打开，把里面的值全部删除、设为空：

- `网络访问: 可匿名访问的共享`
- `网络访问: 可匿名访问的命名管道`

这两项原本列着匿名者可以访问的共享名和管道名，清空后匿名连接什么都拿不到。

**第三步：禁止枚举 SAM 帐号和共享**

同一列表中再配两项：

- `网络访问: 不允许 SAM 帐户和共享的匿名枚举` → **已启用**（对应续行 56 的要求）。
- `网络访问: 对匿名连接的额外限制` → 设置为 **不允许枚举 SAM 帐号和共享**（对应本项"安全选项：对匿名连接的额外限制"）。

**第四步：刷新策略**

按源表做法执行：

```text
secedit /refreshpolicy machine_policy
```

说明一点：`secedit /refreshpolicy` 是 Windows 2000/XP 时代刷新安全策略的旧语法，Windows 10 上推荐直接执行 `gpupdate /force`（安全选项属于本地组策略），效果一致。源表同时建议重启系统，这步建议照做——安全选项改动牵涉 LSA 服务，重启最稳妥。

### 特殊情况处理

- **老设备/老软件依赖匿名枚举**：个别老式网管软件、扫描工具靠空会话取主机信息（比如通过匿名管道读主机名、服务列表）。清空后这些功能可能失效。动手前先跟站内维护单位确认是否有此类工具在轮询 OMS 主机，有的话协调软件升级或改用带认证的连接。
- **与 A14 的关系**：本项管的是"匿名能连到什么"，A14（关闭默认共享）管的是"共享本身开不开"。两项配合做，`IPC$` 删掉、匿名枚举也禁掉，远程侦察面就关干净了。
- **策略不生效**：改完发现匿名枚举还能成功，多半是策略没刷新或被后续 GPO 覆盖。执行 `gpupdate /force` 刷新后重启，再验证一次。

### 📌 加固后的验证

1. 在 `secpol.msc` 中确认"可匿名访问的共享"和"可匿名访问的命名管道"两个列表均为空。
2. 确认"不允许 SAM 帐户和共享的匿名枚举"已启用、"对匿名连接的额外限制"为"不允许枚举 SAM 帐号和共享"。
3. 从另一台机器实测：命令行执行 `net use \\10.172.242.203\ipc$ /user:"" ""` 尝试空会话连接，应当连接失败；`net view \\10.172.242.203` 在不提供凭据时也应当失败。
4. 用扫描工具从外部探测该主机的共享和账户列表，应当什么都枚举不出来。
