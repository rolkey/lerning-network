# 系统时间与 NTP 服务器同步

## 问题

> 系统时间与 NTP 服务器同步（I区1.1.1.4，II区2.1.1.4，III区3.1.1.4）。
>
> 加固方法：第一种：桌面右下角时间和日期-“Internet时间”-更改配置。第二种：1.开始->运行->键入 regedit；2.修订注册表项：进入 HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Services\W32Time\TimeProviders\NtpClient\SpecialPollInterval，基数栏选择到“十进制”。3.设置时间同步周期“建议设为900=15分钟”。4.在 HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Services\W32Time\Parameters\NtpServer 键值修改为 ntp 服务器的 IP 地址。

---

### 🔍 风险原理

系统时间不准会连锁出错：SOE/事件日志的时间戳错乱，事故追忆、故障分析时各设备记录对不上；Kerberos 认证默认只容忍约 5 分钟的时钟偏差，超差直接认证失败；数字证书校验也会因时间错误而失效。电力监控系统要求全站时间统一，各安全分区有各自的 NTP 服务器：I 区 1.1.1.4、II 区 2.1.1.4、III 区 3.1.1.4，本机按所在分区选对应地址，不能跨区配置。

### 配置（加固方法）

**方式一：图形界面（Internet 时间）**

1. 点击桌面右下角时间和日期，打开“日期和时间”设置；
2. 切到“Internet 时间”选项卡（Win10 中该选项卡在经典“日期和时间”窗口里，可运行 `timedate.cpl` 打开）；
3. 点击“更改设置”，服务器一栏填本分区 NTP 服务器 IP（如 I 区填 `1.1.1.4`）；
4. 点击“立即更新”手动同步一次，确认成功。

**方式二：注册表（同步周期 + NTP 源）**

1. `Win+R` 运行 `regedit`；
2. 进入 `HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Services\W32Time\TimeProviders\NtpClient`，双击 `SpecialPollInterval`，基数选择“十进制”，数值填 `900`（900 秒 = 15 分钟，即同步周期）；
3. 进入 `HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Services\W32Time\Parameters`，把 `NtpServer` 键值改为本分区 NTP 服务器的 IP 地址；
4. 修改后重启 Windows Time 服务（`services.msc`）或执行 `w32tm /resync` 使配置生效。

### 特殊情况处理

“Internet 时间”依赖 Windows Time 服务，先在 `services.msc` 确认该服务已启动、启动类型为“自动”。安全分区之间网络隔离，只能配本分区 NTP 地址，跨区地址不通也不必试。`SpecialPollInterval` 只在 NtpClient 以 NTP 客户端模式轮询时按该周期生效，900 是基线建议值（15 分钟），务必按十进制填写。若“立即更新”报错，检查到 NTP 服务器的路由是否放行、主机防火墙是否拦截 NTP 通信，改完服务配置记得重启 Windows Time 服务。

### 📌 加固后的验证

- 命令核对同步状态：

  ```text
  w32tm /query /status
  ```

  期望“源”一栏显示配置的 NTP 服务器 IP，最近一次同步成功。
- 执行 `w32tm /resync` 手动同步一次，确认无报错。
- 注册表复查：`SpecialPollInterval`（十进制）为 900，`NtpServer` 为本分区 NTP 服务器 IP。
- 与 NTP 服务器对比系统时间，偏差在可接受范围内。
