# WebLogic 中间件反序列化漏洞（CVE-2019-2729）

## 问题

- 漏洞编号：指令清单调度20190619-001
- 漏洞名称：WebLogic中间件反序列化漏洞CVE-2019-2729
- 作业结点："CVE-2019-2725的补丁修复被绕过，立即采取措施：（1）禁止所有IP对weblogic的/_async/*和/wls-wsat/*目录进行访问。（2）删除wls9_async_response.war与wls-wsat.war文件及相关文件夹，并重启Weblogic服务。【对象】weblogic"
- 加固方法："Windows：通过文件查找功能查找wls9_async_response.war与wls-wsat.war文件及相关文件夹"

---

### 🔍 漏洞原理与风险

CVE-2019-2729 是 WebLogic 中间件的反序列化远程代码执行漏洞。它比较特殊的一点：这是对之前 CVE-2019-2725 补丁的**绕过**——官方修过一轮，攻击者又找到了绕开补丁的新利用方式，所以光打补丁不够。

漏洞入口在 WebLogic 内置的两个应用上：`/_async/` 和 `/wls-wsat/`，分别由 `wls9_async_response.war` 和 `wls-wsat.war` 两个 war 包提供。攻击者无需登录认证，直接向这两个路径发送构造好的反序列化请求，就能在服务器上执行任意命令。这个漏洞公开后野外利用非常活跃，大量服务器被拿来挖矿。最稳妥的处置是把这两个入口直接删掉。

### 处置方法

1. **定位文件**：在 Windows 服务器上打开文件资源管理器，搜索 `wls9_async_response.war` 和 `wls-wsat.war`，一般位于 WebLogic 域目录下 server 的部署目录（如 `autodeploy` 或 server 的 `stage` 目录）。
2. **停止服务**：删除前先在服务管理器或 WebLogic 域控制台停止 WebLogic 服务，避免 war 文件被占用删不掉。
3. **删除文件**：删除这两个 war 文件及相关文件夹。
4. **重启服务**：删除完成后重启 WebLogic 服务。
5. **访问控制**：作业结点还要求"禁止所有 IP 对 /_async/* 和 /wls-wsat/* 的访问"。文件删除后这两个路径访问自然返回 404；如果网关、防火墙层面还能做访问控制，一并封禁这两个路径，双保险。

### 特殊情况处理

- 如果业务上暂时不允许删除文件，可以把两个 war 改名（例如加上 `.bak` 后缀），WebLogic 就不会再加载这两个应用，效果等同删除，之后想恢复改回原名即可。改完同样要重启服务。
- 删除前确认业务没有调用 wls-wsat 相关的 Web 服务接口，否则删除后这些调用会 404。
- 升级补丁是常规根治手段，但这个漏洞上补丁已被绕过，不能只依赖打补丁，删除/禁用入口是必要的。

### 📌 处置后的验证

- 重启后用浏览器访问 `http://<WebLogic地址>/_async/` 和 `http://<WebLogic地址>/wls-wsat/`，应返回 404（找不到资源）。
- 再次搜索确认两个 war 文件已不存在（或已改名）。
- WebLogic 服务正常启动，业务访问正常。
