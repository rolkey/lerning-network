# JBoss 中间件管理后台 web-console / jmx-console 漏洞

## 问题

- 漏洞编号：指令清单调度20190626-001
- 漏洞名称：JBOSS中间件管理后台web-console或jmx-console漏洞
- 作业结点："本次JBOSS的0day漏洞在JBOSS的管理后台，如web-console或jmx-console在不影响业务的情况下，可直接删除内外网JBOSS中间件的管理后台的web-console.war或jmx-console.war【对象】JBOSS中间件"
- 加固方法："使用浏览器打开jboss地址，jboss默认端口为8080，直接访问jboss管理后台 XX.XX.XX.XX:8080/web-console或者 XX.XX.XX.XX:8080/jmx-console。如果存在该页面，则有可能会受到影响"

---

### 🔍 漏洞原理与风险

JBoss 中间件的默认部署里带两个管理后台：`web-console`（Web 管理控制台）和 `jmx-console`（JMX 管理控制台），默认监听 8080 端口。jmx-console 通过 JMX 调用服务器上的 MBean 接口，历史上出现过多个未认证即可利用的漏洞，包括本次的 0day——攻击者不用登录，通过管理后台就能部署恶意应用、执行命令。

问题的关键：这两个后台默认对所有人开放，而正常业务根本用不到它们。保留它们等于给攻击者留了一扇门。

### 处置方法

1. **排查确认**：用浏览器访问 `http://XX.XX.XX.XX:8080/web-console` 和 `http://XX.XX.XX.XX:8080/jmx-console`（XX.XX.XX.XX 换成实际 JBoss 地址），如果页面能打开，说明存在受影响的管理后台。
2. **确认业务不依赖**：这两个后台只用于管理，正常业务不调用，与业务方确认后即可删除。
3. **删除 war 包**：在服务器上进入 JBoss 的部署目录（`deploy` 目录），找到 `web-console.war` 和 `jmx-console.war`，连同展开后的相关文件夹一起删除。
4. 如果删除时文件被占用，先停止 JBoss 服务，删除完成后再启动。

### 特殊情况处理

- 源表单要求删除的是"内外网"的 JBoss 管理后台，内网服务器同样要处理，不能因为只在内网就跳过。
- 如果业务确实需要 jmx-console 做日常运维，删除后会失去这个入口，需要改用其它管理方式（如 JMX 客户端直连），或评估临时保留期间的额外访问限制。
- 删除这两个 war 不影响 JBoss 上部署的业务应用，其它 war 包不要动。

### 📌 处置后的验证

- 再次用浏览器访问 `/web-console` 和 `/jmx-console` 两个地址，应返回 404。
- 到部署目录确认 `web-console.war`、`jmx-console.war` 及其相关文件夹已不存在。
- JBoss 服务重启后，业务应用访问正常。
