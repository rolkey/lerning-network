# IBM WebSphere 中间件低版本漏洞（CVE-2019-4279）

## 问题

- 漏洞编号：指令清单调度20190626-002
- 漏洞名称：IBM Websphere中间件低版本漏洞 CVE-2019-4279
- 作业结点："对使用了IBM Websphere 的服务器采用以下策略：WebSphere Application Server ND Version 9.0版本请升级至9.0.5.0；WebSphere Application Server ND Version 8.5版本请升级至8.5.5.16；WebSphere Virtual Enterprise Version 7.0因官方不提供支持，建议先关停处置。【对象】IBMWebsphere"
- 加固方法："如果低于20190503则说明存在安全风险。"

---

### 🔍 漏洞原理与风险

CVE-2019-4279 是 IBM WebSphere Application Server 的高危漏洞，低版本软件受影响，官方通过发布新版本和补丁包（Fix Pack）修复。

表单里给出的风险判断标准是"低于 20190503"：指的是服务器上 WebSphere 已安装补丁包（Package/Fix Pack）的发布日期早于 2019-05-03，说明没有包含 CVE-2019-4279 的修复，存在安全风险。所以这次处置的核心不是"打一个补丁"，而是把整体版本升级到官方指定的修复版本。

### 处置方法

1. **确认当前版本**：登录 WAS 管理控制台查看产品版本，或在安装目录 `bin` 下运行 `versionInfo.bat` 查看已安装的产品与补丁信息，重点看已安装 Package/Fix Pack 的日期是否早于 20190503。
2. **按版本升级**：
   - WebSphere Application Server ND 9.0 → 升级到 9.0.5.0；
   - WebSphere Application Server ND 8.5 → 升级到 8.5.5.16。
   - 通过 IBM Installation Manager，从官方渠道下载对应版本升级包，在维护窗口内完成升级。
3. **VE 7.0 关停**：WebSphere Virtual Enterprise Version 7.0 官方已不提供支持，没有修复补丁可用，按源表单要求先关停处置：在服务管理器（`services.msc`）或 WAS 管理控制台停止相关服务，并规划迁移到受支持的版本。

### 特殊情况处理

- 升级 WebSphere 会重启应用服务器，影响上面的业务，必须安排维护窗口，并提前和业务方确认。
- 升级前备份配置（Profile、应用、配置文件），升级失败时可以回退。
- 跨版本升级前先核对应用兼容性，按官方升级路径逐级升，不要跳级。
- VE 7.0 关停前确认其承载的业务已经迁移或下线，避免直接停服造成业务中断。

### 📌 处置后的验证

- 管理控制台确认版本号：9.0 环境显示 9.0.5.0，8.5 环境显示 8.5.5.16。
- 核对已安装补丁的日期，不应低于 20190503。
- VE 7.0 环境确认相关服务已停止，对应端口不再监听。
