# Apache Tomcat 中间件拒绝服务（DoS）漏洞

## 问题

> 信息通报19-38期：Apache Tomcat 中间件 DoS 漏洞
>
> 受影响版本：
> - 0.0.M1 < Apache Tomcat < 9.0.14
> - 5.0 < Apache Tomcat < 8.5.37
>
> 加固方法：在操作系统内查找 Tomcat 路径：Windows 通过文件查找功能查找 version 文件及 Apache Tomcat 相关文件夹，确认版本后及时更新。

---

### 🔍 漏洞原理与风险

Tomcat 是 Java 平台最常用的 Web 中间件，电力系统里不少监控平台、数据发布服务都架在它上面。受影响版本在处理特制请求时存在缺陷，攻击者不需要拿到权限，只要发少量构造好的请求，就能让 Tomcat 的线程或资源被持续占用，最终服务无响应——也就是拒绝服务（DoS）。

这个漏洞的麻烦在于"廉价"：攻击者只需网络可达即可尝试，不需要账号。Tomcat 一旦被打瘫，挂在它上面的运维页面、数据接口一起停摆。对 OMS 这类关键主机来说，这意味着运维通道中断，出问题的时候连网页都登不进去。

### 处置方法

**第一步：在 Windows 上定位 Tomcat 及版本**

1. 打开文件资源管理器，在右上角搜索框输入 `Tomcat` 或 `catalina`，在整个磁盘范围内搜索 Apache Tomcat 相关文件夹。常见位置是 `C:\Program Files\Apache Software Foundation\`，但很多业务软件会把 Tomcat 内嵌在自己安装目录里，所以必须全盘搜一遍。
2. 进入 Tomcat 目录查找 version 相关文件：根目录下的 `RELEASE-NOTES` 文件，用记事本打开，第一行就是版本号；也可以到 `bin` 目录双击（或命令行运行）`catalina.bat version`，输出的 `Server version` 一行即当前版本。
3. 拿版本号对照通报范围：9.0 分支低于 9.0.14、8.5 及以下分支低于 8.5.37 的，都在受影响范围内。

**第二步：更新到修复版本**

1. 到 Apache Tomcat 官网（tomcat.apache.org）下载对应分支的修复版本。
2. 替换前先备份旧目录，重点保留 `conf`（server.xml 里的端口、证书等配置）和 `webapps`（业务应用）。
3. 用新版本替换后，把备份的 `conf`、`webapps` 内容按原结构恢复回去，再启动服务。

### 特殊情况处理

- 如果 Tomcat 是某个厂商软件内嵌的（目录埋在软件安装路径里），不要单独换版本，容易把软件带崩。应该联系厂商，让厂商发布含修复版 Tomcat 的升级包。
- 替换版本后注意核对 `server.xml` 里的端口号、HTTPS 证书路径，别因为换目录导致证书找不到、端口冲突。
- 业务平台如果依赖特定 Tomcat 小版本的行为，升级前先做一轮功能回归。

### 📌 处置后的验证

- 再次运行 `catalina.bat version` 或打开 `RELEASE-NOTES`，确认版本已达到修复版本（9.0.14 / 8.5.37 及以上）。
- 启动 Tomcat 后，浏览器访问其首页和管理页面，确认服务正常、业务应用能打开。
- 在任务管理器或服务列表（`services.msc`）里确认 Tomcat 相关服务运行正常，无反复重启。
