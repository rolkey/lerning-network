# Apache Tomcat 中间件 AJP 协议漏洞

## 问题

> 信息通报20-6期：Apache Tomcat 中间件 AJP 协议漏洞
>
> 影响范围：
> - 分支 7.0.100 之前版本
> - 分支 8.5.51 之前版本
> - 分支 9.0.31 之前版本
>
> 加固方法：建议关注官方网站及时更新补丁，Apache 官方已发布 9.0.31、8.5.51 及 7.0.100 版本针对此漏洞进行修复，建议用户下载使用：https://tomcat.apache.org/download-70.cgi

---

### 🔍 漏洞原理与风险

AJP（Apache JServ Protocol）是 Tomcat 用来跟前端 Apache httpd（通过 mod_jk 模块）通信的协议，默认监听 8009 端口。7.0.100、8.5.51、9.0.31 之前的版本，AJP 连接器对请求的处理存在缺陷：攻击者不需要认证，就能通过 AJP 通道读取 webapp 目录下的文件，配合其他条件（比如站上已存在文件上传入口）还能进一步实现代码执行。

这个漏洞被公开后很快就有了现成的利用工具，属于"扫到 8009 端口就能打"的类型。很多部署里 8009 端口只在内网用，防火墙策略一疏忽就暴露着，风险被长期低估。Tomcat 部署在 OMS 环境里通常承担 Web 发布职责，一旦被打穿，内网应用和数据都跟着暴露。

### 处置方法

**第一步：定位 Tomcat 并确认版本**

1. 用文件资源管理器搜索 `Tomcat` 或 `catalina` 关键字，找到 Tomcat 安装目录（内嵌在业务软件里的也要找出来）。
2. 查看根目录 `RELEASE-NOTES` 文件的第一行，或运行 `bin\catalina.bat version`，确认当前版本和所属分支。
3. 对照通报：7.0 分支低于 7.0.100、8.5 分支低于 8.5.51、9.0 分支低于 9.0.31 的，均在影响范围内。

**第二步：更新到修复版本**

1. 按所属分支到 Apache Tomcat 官网下载修复版本（7.0.100、8.5.51、9.0.31 或更高）。源表给出的链接是 7.0 分支的下载页，8.5 和 9.0 分支在官网有对应页面。
2. 替换前备份旧目录，尤其是 `conf`（server.xml 配置、证书）和 `webapps`（业务应用）。
3. 新版本替换后恢复备份的配置和应用，重启 Tomcat 服务。

### 特殊情况处理

- 如果前端用 Apache httpd + mod_jk 通过 AJP 代理 Tomcat，升级后要专门确认代理连通性，业务页面能正常打开。
- 业务上根本用不到 AJP 的，可以顺手在 `conf\server.xml` 里注释掉 8009 端口的 AJP Connector，直接把攻击面关掉。本项处置仍以升级到修复版本为准，注释只是额外的加固手段。
- 内嵌 Tomcat 的厂商软件不能单独换版本，联系厂商获取含修复版 Tomcat 的升级包。

### 📌 处置后的验证

- 运行 `catalina.bat version`，确认版本达到对应分支的修复版本（7.0.100 / 8.5.51 / 9.0.31 及以上）。
- 重启后浏览器访问 Tomcat 首页和业务页面，确认服务正常。
- 检查 8009 端口：确认其监听范围符合预期（若已注释 AJP Connector，则 8009 不再监听）。
