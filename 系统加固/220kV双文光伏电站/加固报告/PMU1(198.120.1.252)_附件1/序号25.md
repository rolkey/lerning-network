# FTP 用户帐号控制

## 问题

- "拒绝系统默认的系统帐号使用ftp服务"
- 加固方法：
  1. 查看禁止 FTP 登录的用户名单：`cat /etc/ftpd/ftpusers` 或 `cat /etc/vsftpd/ftpusers`
  2. 配置：先备份（`cp -p ... ftpusers_bak`），再编辑名单，每一个帐户一行，添加以下帐户禁止 FTP 登录：root、daemon、bin、sys、adm、lp、uucp、nuucp、listen、nobody、hpdb、useradm

---

### 🔍 风险原理

Linux 默认会创建一批系统账户（daemon、bin、sys、adm、nobody 等），它们是给服务进程用的，不是给"人"登录用的：绝大多数没有口令、口令为空、或者早已不更新。如果这些账户被允许用 FTP 登录，攻击者只要撞出一个历史弱口令，就能以系统账户身份进入文件传输通道。更糟的是 FTP 是明文协议，root 用它登录等于把 root 口令在网络上裸奔。

所以这条基线是"一刀切"：凡是系统默认账户，一律禁止 FTP 登录，只给有明确需求的业务/运维账户开放。

### 配置加固方法

先备份再修改：

```bash
cp -p /etc/vsftpd/ftpusers /etc/vsftpd/ftpusers_bak
```

编辑名单，每个账户一行：

```bash
vi /etc/vsftpd/ftpusers
```

把下列账户写入文件（源清单）：

```bash
root
daemon
bin
sys
adm
lp
uucp
nuucp
listen
nobody
hpdb
useradm
```

凝思 Linx 6.0 默认的 FTP 服务是 vsftpd，对应名单文件是 `/etc/vsftpd/ftpusers`（经 PAM 引用，列入其中的账户无论如何都不能登录）。老式 ftpd 的路径是 `/etc/ftpd/ftpusers`，两者取其一，以系统实际安装的服务为准。修改后重启服务：

```bash
service vsftpd restart
```

### 特殊情况处理

- **`user_list` 与 `ftpusers` 的区别**：vsftpd 还有一个 `/etc/vsftpd/user_list`，行为由 `vsftpd.conf` 里的 `userlist_deny` 决定——`YES`（默认）时它是黑名单，`NO` 时变成白名单（只有列出的账户能登录）。写进 `ftpusers` 是硬禁止，不受这个开关影响；写进 `user_list` 则要注意 `userlist_enable` 与 `userlist_deny` 的实际取值。
- **账户名差异**：源清单里 `nuucp`、`listen`、`hpdb`、`useradm` 属于 HP-UX/Solaris 一类的账户，凝思 Linx 6.0 上多半不存在。不存在的账户不必强行添加，重点是 `root`、`daemon`、`bin`、`sys`、`adm`、`lp`、`uucp`、`nobody` 这些本地真实存在的系统账户必须都在名单里。
- **服务未安装**：如果主机根本没装 FTP 服务（凝思 Linx 6.0 最小安装即如此），此项按不适用处理，同时用 `ss -lntp` 确认 21 端口确实没有监听。

### 📌 加固后的验证

```bash
cat /etc/vsftpd/ftpusers
```

期望输出包含 root 及上述系统账户，每行一个。

实测验证：

```bash
ftp 127.0.0.1
```

以 root 身份登录，期望返回 530 Permission denied 之类的拒绝信息；再用名单外的正常业务账户登录，应当成功。
