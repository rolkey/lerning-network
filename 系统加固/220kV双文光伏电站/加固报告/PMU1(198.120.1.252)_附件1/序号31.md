# 开机自动启动 syslog 日志服务

## 问题

- "syslog服务能在启动服务器的时候开启"
- 配置要求："修改配置文件 vi /etc/syslog.conf，配置如下类似语句：`*.err;kern.debug;daemon.notice;        /var/adm/messages`，定义为需要保存的设备相关安全事件。"

---

这台 AGC/AVC 主机上，syslog 是唯一能把"当时发生了什么"还原出来的东西。它没随开机启动，等于服务器每次重启后都有一段盲区：安全事件没人记录，出了事也无从追溯。这一项就是保证 syslog 开机自启，并且把需要留存的安全事件规则配好。

### 🔍 风险原理

syslog 记录内核、守护进程、认证相关的各类事件。它不运行的时候：

- 登录失败、su/sudo 提权、服务异常等安全事件全部丢失，事后审计无据可查。
- 攻击者入侵后第一件事往往就是清日志、停日志服务。服务如果连开机自启都没有，日志缺失看起来"很自然"，反而给入侵者打了掩护。
- 电力监控系统合规检查里，日志审计是基础项——服务不在运行，直接判不合规。

所以要点有两个：服务本身要**开机自启**；采集规则要覆盖**设备相关的安全事件**（不是什么都记，也不是什么都不记）。

### 配置加固方法

源数据里的写法是传统 UNIX 风格：`/etc/syslog.conf` 是 syslogd 的配置文件，`startsrc/stopsrc` 是 AIX 的 SRC 服务管理命令。看原命令：

```bash
# 查看 syslog 进程是否运行
ps -eaf | grep syslog
# 期望看到类似输出（有 /usr/sbin/syslogd 进程在跑）：
#   root   495     1  0 13:10:38 ?  0:00 /usr/sbin/syslogd -D

# AIX 上启停 syslog 服务（源数据风格，供参考）
startsrc -s syslogd      # 启动
stopsrc -s syslogd       # 停止
```

在凝思 Linx 6.0 上，syslog 功能由 **rsyslog** 实现，配置文件是 `/etc/rsyslog.conf`（规则语法与 `/etc/syslog.conf` 完全兼容），服务管理用 SysV init：

```bash
# 1) 设置开机自启并立即启动
chkconfig rsyslog on
service rsyslog start

# 2) 编辑配置，保留安全事件相关规则
vi /etc/rsyslog.conf
# 添加或确认存在类似行（facility.level + 制表符 + 日志文件路径）：
# *.err;kern.debug;daemon.notice;        /var/log/messages
# 含义：所有设施的 err 级及以上、kern 的 debug 级及以上、
#       daemon 的 notice 级及以上，写入 /var/log/messages

# 3) 重载配置
service rsyslog restart
```

规则格式说明：`*.err;kern.debug;daemon.notice` 是**选择器**，分号分隔多个 `设施.级别` 条件，`*` 代表所有设施。三个条件之间是"或"的关系，任何一条命中都会写入后面的文件。

### 特殊情况处理

- `/var/adm/messages` 是 Solaris/AIX 的典型路径，凝思 Linx 6.0 上没有这个目录，默认用 `/var/log/messages`。如果上级检查硬性要求这个路径，可以 `mkdir -p /var/adm` 然后把规则里的目标改成 `/var/adm/messages`，效果一样。
- 凝思 Linx 6.0（RHEL 6 系）没有 systemd journal，rsyslog 是日志持久化的唯一通道，务必确保 rsyslog 开机自启并落盘到文件，否则重启后日志丢失。
- 如果机器上装了 syslog-ng 又装 rsyslog，只能启用一个，别两个都开，会抢端口、日志重复。

### 📌 加固后的验证

```bash
# 1) 进程在跑
ps -eaf | grep syslog
# 期望：能看到 /usr/sbin/rsyslogd 进程

# 2) 开机自启已配置
chkconfig --list rsyslog
service rsyslog status
# 期望：rsyslog 为 on / running

# 3) 实际打一条测试日志，确认写入
logger -p daemon.notice "harden-test: syslog check"
tail /var/log/messages
# 期望：能看到刚才的 harden-test 记录
```

三项都通过，重启服务器后再跑一遍第 1、2 条，确认开机自启真实生效。
