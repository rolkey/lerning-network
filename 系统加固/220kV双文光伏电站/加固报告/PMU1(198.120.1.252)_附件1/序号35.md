# SNMP/SNMP TRAP 默认团体名称修改

## 问题

- "如需要SNMP管理则修改SNMP默认团体名：vi /etc/SnmpAgent.d/snmpd.conf 修改SNMP配置文件，`get-community-name:` 将默认的 public 修改为复杂的团体名--密码（读团体名，也就是读的密码）"
- 版本要求："/etc/snmp/snmpd.conf 修改默认团体字（团体名改为GXhmrjsw-q3，I-II区网管1.1.1.2、III区网管3.1.1.2、I区态势感知1.1.1.3、II区态势感知2.1.1.3、III区态势感知3.1.1.3）"

---

SNMP 的团体名（community string）就是 SNMP v1/v2c 的密码，出厂默认是 `public`（只读）和 `private`（读写）。全世界所有扫描器字典里都有这两个词，不改等于把设备信息拱手让人。这一项把默认团体字改成复杂口令，并限定只有网管、态势感知的来源地址能访问。

### 🔍 风险原理

SNMP 走 UDP 161 端口，只要团体名正确就能查询。默认 `public` 的后果：

- 任何能连到 161 端口的人，用 `snmpwalk -c public` 就能拉走系统描述、接口列表、路由表、运行进程、CPU 负载——攻击前的标准侦察动作，而且 SNMP v1/v2c 的请求没有加密，网段里抓包还能直接看到团体名。
- 如果 `private`（读写团体）也没改，攻击者可以远程改配置、重启服务，等于拿到了设备的控制开关。
- 源表里"读团体名，也就是读的密码"点得很直白：团体名不是注释，是口令，要用对待口令的标准来对待它。

### 配置加固方法

源数据里的路径 `/etc/SnmpAgent.d/snmpd.conf`、`get-community-name` 是 HP-UX 风格；凝思 Linx 6.0 用的是 net-snmp，配置文件在 `/etc/snmp/snmpd.conf`，对应概念一致：

```bash
# HP-UX 风格（源数据命令）：
vi /etc/SnmpAgent.d/snmpd.conf
# get-community-name:    public  →  修改为复杂的团体名

# 凝思 Linx 6.0（net-snmp）对应做法：
vi /etc/snmp/snmpd.conf
# 删除或注释掉默认行：
# rocommunity public
# 改为指定来源地址 + 新团体名（一行一个来源）：
rocommunity GXhmrjsw-q3 1.1.1.2
rocommunity GXhmrjsw-q3 3.1.1.2
rocommunity GXhmrjsw-q3 1.1.1.3
rocommunity GXhmrjsw-q3 2.1.1.3
rocommunity GXhmrjsw-q3 3.1.1.3

# 重启服务生效
service snmpd restart
chkconfig snmpd on
```

`rocommunity` 的格式是 `rocommunity <团体名> [来源地址]`，带上来源地址就是白名单 ACL——只有网管和态势感知那几台机器能用新团体名查询，其他来源直接拒绝。这比单纯改名字更稳，团体名泄露了也限定在少数可信来源。

SNMP TRAP 方向（设备主动向网管推送告警）同样涉及团体名，接收方要校验的团体名必须两边一致：

```bash
# 在 snmpd.conf 中配置 TRAP 接收方（net-snmp 语法）：
trap2sink 1.1.1.2 GXhmrjsw-q3
# 含义：向 1.1.1.2 发送 v2c TRAP，携带的团体名为 GXhmrjsw-q3
```

### 特殊情况处理

- 不需要 SNMP 管理的机器，最干净的做法是直接停掉：`chkconfig snmpd off && service snmpd stop`，少一个端口少一份风险。
- 只改只读团体名不够，`rwcommunity`（读写）对应的默认词 `private` 也要改或直接删除——这台机器没有谁需要远程写配置。
- 团体名改掉后，网管平台侧的采集配置要同步更新，否则监控立刻断线。改之前先和网管运维通气，约定变更窗口。
- 更彻底的做法是升级到 SNMP v3（带认证和加密），v1/v2c 的团体名在网络上始终是明文。
- 源表里的网管地址按安全分区区分（I-II 区 1.1.1.2、III 区 3.1.1.2），跨区不能互相访问，配置 ACL 时按本机所属分区填写对应来源即可。

### 📌 加固后的验证

```bash
# 1) 用默认团体字探测应失败（期望无响应/超时）
snmpwalk -v 2c -c public 198.120.1.252 system

# 2) 用新团体字应能读到系统信息
snmpwalk -v 2c -c GXhmrjsw-q3 198.120.1.252 system

# 3) 检查配置里没有残留的默认团体名
grep -E 'rocommunity|rwcommunity|public|private' /etc/snmp/snmpd.conf | grep -v '^#'

# 4) 服务运行状态
service snmpd status
# 期望：running（若选择保留 SNMP）
```

第 1 条无响应、第 2 条正常返回、第 3 条只剩新团体名，即达到要求。
