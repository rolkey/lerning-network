# 系统时间同步（与 NTP 服务器同步）

## 问题

- "系统时间与NTP服务器同步（I区1.1.1.4，II区2.1.1.4，III区3.1.1.4）"
- 加固方法：`ntpdate 3.1.1.4`

---

系统时钟跑偏是小事，但引发的后果都不小：日志对不上、证书校验失败、故障顺序理不清。源数据给的 `ntpdate 3.1.1.4` 是一次性校时，真正达标要靠 NTP 服务持续同步。注意 NTP 服务器地址按安全分区区分，III 区主机用 3.1.1.4，I 区用 1.1.1.4，II 区用 2.1.1.4。

### 🔍 风险原理

时间不准带来的问题：

- **日志不可信**：跨设备排查安全事件时，各机器时钟漂移，事件先后顺序完全错乱，攻击者的操作时序拼不出来。
- **认证失败**：证书有效性、Kerberos 票据等都有时间窗口，时钟偏了会误判过期，服务异常。
- **故障分析失真**：电力监控里 SOE（事件顺序记录）、事故追忆都依赖统一时钟，时间错了分析结论全错。
- **合规审计**：审计记录的时间戳必须可信，时钟无人管理等于记录作废。

所以要的不只是"现在对一下表"，而是让系统持续与 NTP 服务器保持同步。

### 配置加固方法

源数据的命令是一次性校时：

```bash
# 一次性校时（III区主机示例，源数据命令）
ntpdate 3.1.1.4
```

注意：如果本机已运行 ntpd，端口 123 被占用，`ntpdate` 会失败；先停 ntpd 再校时，或用 `ntpdate -u 3.1.1.4` 走非特权端口。

一次性校时只管当下，重启、运行几周后时钟又会漂。长期同步要配置 NTP 服务。凝思 Linx 6.0（RHEL 6 系）默认用 **ntpd**，没有 chrony（chrony 是 RHEL 7+ 才引入的）：

```bash
# 配置 ntpd
vi /etc/ntp.conf
# 注释掉默认 server 行，添加：
# server 3.1.1.4 iburst
chkconfig ntpd on
service ntpd restart
```

`iburst` 让服务启动后尽快完成首次同步，而不是干等几分钟。

### 特殊情况处理

- 跨安全区的 NTP 地址不能混用：III 区主机去连 I 区的 1.1.1.4 会失败（隔离要求），按本机所在分区填对应地址。
- 防火墙/纵向加密装置要放行到 NTP 服务器的 UDP 123，否则同步静默失败。
- 时间偏差过大（超过 1000 秒）时 ntpd 默认拒绝步进修正，得先用 `ntpdate` 把时间拉回大致范围，再启动 ntpd。
- 生产环境更稳妥的配置是双 NTP 源（两台服务器互为备援），有条件的场站用北斗/GPS 授时装置作为本地一级源。

### 📌 加固后的验证

```bash
# 1) 查询与 NTP 服务器的偏移（不修改时间）
ntpdate -q 3.1.1.4
# 期望：返回 offset，单位秒，数值应很小

# 2) 查看持续同步状态
ntpq -p
# 期望：源列表中 3.1.1.4 带 * 号（正在同步），offset 毫秒级

# 3) 系统时间服务状态
service ntpd status
# 期望：running

# 4) 与标准时间比对
date
```

时间偏差稳定在毫秒级、`ntpq -p` 显示已同步，这项才算落定。过一周再查一次，确认不是校时后又在漂。
