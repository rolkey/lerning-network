# 敏感口令文件的属主与权限加固

## 问题

- "对重要的口令文件权限进行限制，防止恶意修改"

---

系统里最重要的三个口令相关文件是 `/etc/passwd`、`/etc/shadow` 和 `/etc/group`。它们的属主必须是 root，权限必须收得足够紧，否则任何一个本地用户（或者通过 Web 漏洞拿到低权限 shell 的攻击者）都可能篡改口令数据。B22 这一项要做的，就是把这三个文件的属主和权限统一核对一遍。

### 🔍 风险原理

先看这三个文件各自的用途：

- `/etc/passwd`：存用户名、UID、家目录、登录 shell。传统上这里也存口令哈希，现在哈希已经挪到 shadow 里，passwd 里只剩一个 `x` 占位符。但 passwd 仍然被大量工具（`ls -l` 显示的属主名、`getent` 等）依赖，一旦被改成假条目，可以伪造 root 同 UID 的账号。
- `/etc/shadow`：存真正加密后的口令哈希、密码有效期策略。哈希本身虽然不可逆，但可以离线暴力破解（john、hashcat 这类工具），所以这个文件的读权限必须只留给 root。
- `/etc/group`：存组信息；对口的还有一个 `/etc/gshadow`，存组口令，本项未涉及但同样该收紧。

**风险点**：

1. 属主不是 root。如果一个普通用户拥有这些文件，他可以直接给自己写一个空口令的 root 账号，等于拿到系统钥匙。
2. shadow 权限过宽。默认的 `/etc/passwd` 是 644（所有人可读），这是设计如此，没问题；但 `/etc/shadow` 如果也是 644 甚至 777，任何本地用户都能把哈希拷走离线跑字典。shadow 必须是 400（`-r--------`）。
3. group 文件被加写。攻击者可以把自己加入 wheel / root 组，间接获得 sudo 或组权限带来的敏感访问。

### 配置加固方法

按源表给的命令执行：

```bash
chown root /etc/passwd /etc/shadow /etc/group
chmod 644 /etc/passwd /etc/group
chmod 400 /etc/shadow
```

解释一下这三行：

- `chown root` 把三个文件的属主（及属组，写法上没写冒号组名，则只改属主为 root）收回到 root。
- `chmod 644`：`-rw-r--r--`，属主可读写、其他只读。passwd 和 group 必须对所有用户可读，因为登录、`ls`、`id` 这些操作随时要查它们，改成 600 会导致大量程序异常。
- `chmod 400`：`-r--------`，只有 root 能读 shadow。shadow 的写操作由 passwd 程序以特权方式完成，root 日常也不需要直接写它，400 足够。

### 特殊情况处理

- 凝思 Linx 6.0（RHEL 6 系）里 `/etc/shadow` 默认可能就是 `000`（`----------`），属主 root 属组 root。加固成 400 不会影响登录，因为改密码走的是 setuid 的 `/usr/bin/passwd`，不走普通用户对文件的读写。
- 如果现场发现 shadow 权限已经被改乱，除了 chmod 之外可以跑 `pwconv`（passwd 和 shadow 内容不一致时用它重新同步）再核对一次。
- 组口令相关的 `/etc/gshadow` 如果存在，建议顺手按同样口径处理：`chown root:root /etc/gshadow && chmod 400 /etc/gshadow`。源表没要求，但口径一致。

### 📌 加固后的验证

```bash
ls -l /etc/passwd /etc/shadow /etc/group
```

期望输出：

- `/etc/passwd`：`-rw-r--r--. 1 root root`
- `/etc/group`：`-rw-r--r--. 1 root root`
- `/etc/shadow`：`-r--------. 1 root root`

三条里属主都是 root，且没有一条出现 `w` 落在组或其他用户位上。若 shadow 显示成 `-rw-r--r--`，说明加固没生效，回头重跑 `chmod 400 /etc/shadow`。

另外可以做一个功能性确认：用一个普通账号登录一次，确认能正常通过口令验证——防止收紧权限时把 passwd/shadow 的读写搞坏导致全员登录失败。
