# 主机病毒查杀与日志导出

## 问题

- "使用主机杀毒或杀毒U盘软件完成病毒查杀与日志导出。
  完成病毒查杀（变电站周期六个月、其他三个月），开启软件携带的U盘管控功能。
  III区下载地址:https://3.1.1.1，Ⅰ/II区 https://1.1.1.1。
  完成日志导出（查询最近扫描时间和日志详情）。
  记录发现病毒数量、清除病毒数量；
  主机杀毒软件或杀毒U盘病毒库更新时间（变电站更新周期为六个月、其他为三个月）。"

---

AGC/AVC 这类监控主机跑的是电力生产业务，很多人觉得 Linux 不会中毒，加上主机在调度数据网里与互联网物理隔离，干脆不装杀毒。但病毒进入内网最常见的通道恰恰不是网络，是 U 盘——运维人员的 U 盘在各区主机之间插来插去，一旦带毒，整个站的监控主机都会被"摆渡"感染。所以《电力监控系统网络安全合规基线技术规范》把周期查杀、U 盘管控、日志导出列成硬性作业项。

### 🔍 风险原理

监控主机（AGC/AVC 工作站）上的病毒或木马，危害比办公机大得多：

- 篡改或伪造遥测、遥控数据，影响自动发电控制（AGC）/自动电压控制（AVC）指令下发的准确性；
- 窃取调度生产数据、账号口令，横向扩散到整个监控网或伺机回传；
- 利用老漏洞传播的蠕虫在同一安全分区内快速扩散，导致主机重启、业务中断。

这类主机没有互联网出口，杀毒软件无法在线升级，病毒库很容易过期，所以规范要求按周期完成全盘查杀并留存日志证据：变电站每六个月一次、其他场站每三个月一次。

### 配置/加固方法

**1. 安装杀毒软件或使用杀毒 U 盘**

软件不能从互联网随意下载，各区主机从本区的专用下载源获取：

- Ⅰ/II 区：`https://1.1.1.1`
- III 区：`https://3.1.1.1`

**2. 完成病毒查杀并导出日志**

本机装有 Linux 杀毒客户端（LinuxKPC）时，查杀相关配置和记录在 `/opt/LinuxKPC/ini/` 下：

```bash
# 查看杀毒客户端配置，确认最近一次扫描时间与扫描范围
cat /opt/LinuxKPC/ini/apsc_client_ui.ini

# 客户端记录的扫描时间通常是 Unix 时间戳，用 date 转成可读日期
date -d @时间戳 "+%Y-%m-%d"
```

按规范要求导出查杀日志，记录：最近扫描时间、日志详情、发现病毒数量（个）、清除病毒数量（个）。

**3. 开启 U 盘管控功能**

软件自带 U 盘管控模块，安装后要把它打开。开启后未登记的 U 盘接入会被拦截，运维用的 U 盘需要先登记白名单才能正常读写，从入口上挡住"摆渡"感染。

**4. 维护病毒库更新周期**

```bash
# 查看病毒库版本信息，核对更新时间
cat /opt/LinuxKPC/ini/version
```

病毒库更新时间必须满足：变电站不超过六个月、其他场站不超过三个月。内网主机靠本区下载源提供的离线升级包更新。

### 特殊情况处理

- 现场没有部署杀毒客户端的，用杀毒 U 盘做离线查杀，同样要导出日志并记录扫描时间。
- 病毒库到期但暂无新离线包时，先完成全盘查杀并留存日志，同时向厂家或调度申请升级包，不要拖过周期。
- 查杀出的文件被隔离或删除前，先确认不是业务程序被误报；疑似误报的文件先隔离并记录，不要直接删除。

### 📌 加固后的验证

```bash
# 1. 确认最近扫描时间在周期内（变电站 6 个月内、其他 3 个月内）
cat /opt/LinuxKPC/ini/apsc_client_ui.ini

# 2. 确认病毒库更新时间在周期内
cat /opt/LinuxKPC/ini/version
```

期望结果：最近扫描时间和病毒库更新时间都在规定周期内；查杀日志已导出并存档；发现/清除病毒数量有明确记录（可为 0）；U 盘管控功能处于开启状态。
