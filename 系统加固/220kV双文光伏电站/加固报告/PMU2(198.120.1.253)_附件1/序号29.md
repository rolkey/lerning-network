# 指定日志服务器

## 问题

- "Syslog.conf的配置审核，配置专门的日志服务器loghost（I-II区loghost1.1.1.2，III区loghost 3.1.1.2，I区态势感知1.1.1.3、II区态势感知2.1.1.3，III区态势感知3.1.1.3），如下配置。"
- 配置内容：
  ```
  kern.warning;*.err;authpriv.none\t@loghost
  *.info;mail.none;authpriv.none;cron.none\t@loghost
  *.emerg\t@loghost
  local7.*\t@loghost
  ```

---

### 🔍 风险原理

本机日志有个致命弱点：攻击者入侵后，第一件事往往是清日志——`echo > /var/log/secure`、删掉 `/var/log/messages`，销毁自己的痕迹。日志只存在被攻陷的主机上，等于让小偷自己保管监控录像。

把日志实时转发到独立的日志服务器（loghost），让日志在生成的瞬间就离开主机，本机再怎么删也删不掉远端那份。对电力监控系统来说，日志服务器还对接各分区的态势感知平台，是事后溯源和入侵检测的输入源。源表列出的分区地址（I-II 区 loghost 1.1.1.2、III 区 loghost 3.1.1.2，各区态势感知 1.1.1.3 / 2.1.1.3 / 3.1.1.3）就是现场实际的收集点。

### 配置加固方法

syslog 语法里，`@主机名` 表示用 UDP 转发（`@@主机名` 用 TCP）。把源表四行规则写入凝思 Linx 6.0 的 `/etc/rsyslog.conf`（对应老式写法的 `/etc/syslog.conf`）：

```bash
vi /etc/rsyslog.conf
```

```bash
kern.warning;*.err;authpriv.none\t@loghost
*.info;mail.none;authpriv.none;cron.none\t@loghost
*.emerg\t@loghost
local7.*\t@loghost
```

（`\t` 是源表里的制表符占位，实际文件中用 Tab 或空格分隔选择器与动作即可。）

四行规则逐条拆解：

| 规则 | 含义 |
| --- | --- |
| `kern.warning;*.err;authpriv.none` | 内核 warning 及以上 + 所有设施的 err 及以上，排除 authpriv |
| `*.info;mail.none;authpriv.none;cron.none` | 所有设施的 info 及以上，排除 mail、authpriv、cron |
| `*.emerg` | 所有设施的 emerg（系统级紧急事件） |
| `local7.*` | local7 设施的全部级别（网络设备习惯用 local7 上报） |

authpriv 由本机 `/var/log/secure` 单独记录（对应 B12 项），这里用 `authpriv.none` 排除，避免重复转发。

`@loghost` 里的 `loghost` 是主机名，需要在 `/etc/hosts` 里解析到本分区实际的日志服务器地址：

```bash
vi /etc/hosts
```

```bash
<本区日志服务器IP>    loghost
```

修改后重启服务：

```bash
service rsyslog restart
```

### 特殊情况处理

- **UDP 与 TCP**：`@`（UDP）在专网环境下简单可靠，但丢包不重传；对审计完整性要求高的链路建议用 `@@host`（TCP），同时日志服务器端 rsyslog 需要启用 `$ModLoad imtcp` 监听 514 端口。以现场基线和网络策略为准。
- **转发级别**：源表规则没有转发 authpriv，登录事件留在本机。如果现场要求登录事件也上送态势感知，需要单独加 `authpriv.* @loghost`，与基线核对后再动。
- **防火墙**：syslog 转发走 514/udp（或 tcp），主机 iptables 和中间网络设备都要放行对应出站规则，否则规则配了也发不出去。
- **收集端兼容**：对端只要是 syslog 兼容服务（rsyslog、syslog-ng、态势感知采集器）即可，格式为 RFC3164 文本。

### 📌 加固后的验证

```bash
grep loghost /etc/rsyslog.conf
```

期望输出包含源表四行规则，排除项和 `@loghost` 动作齐全。

实测转发：

```bash
logger -p local7.info "hardening-test-<主机名>"
```

到日志服务器/态势感知平台上检索该关键字，期望能查到这条测试消息，说明转发链路正常。
