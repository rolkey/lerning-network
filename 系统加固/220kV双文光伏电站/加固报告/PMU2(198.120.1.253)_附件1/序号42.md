# 调度发令系统主机的特有加固（卸载 samba、路由收口）

## 问题

- "1.卸载samba服务
  2.删除默认路由0.0.0.0，路由记得保存，不然重启会丢失
  3.配置指向10.67.0.0的路由，下一条是默认网关，路由记得保存，不然重启会丢失"

---

B26 是调度发令系统主机**特有**的加固项，三条要求：卸载 samba、删掉默认路由、加一条指向 10.67.0.0 网段的静态路由并持久化。三条指向同一个目标：这台机器只服务于调度发令业务，只允许和调度数据网打交道，其余一切通信面全部收口。

### 🔍 风险原理

**为什么要卸 samba。** samba 是 Linux 上的 SMB/CIFS 文件共享服务，监听 139/445 端口。这套协议的历史漏洞多到数不过来：2017 年的"永恒之蓝"（MS17-010）攻击的就是 SMB 协议，同年 samba 自己也有 SambaCry（CVE-2017-7494）这种远程代码执行漏洞。调度发令主机不对外提供文件共享，装 samba 纯粹是给攻击者留了一扇钉着老锁的门。卸掉它，139/445 两个高危端口随之消失，和 B24 的高危端口整治正好呼应。

**为什么要删默认路由。** `route -n` 里目标为 `0.0.0.0` 的默认路由，意思是"去任何地方都走这条"。有了它，这台主机就能访问路由表里没有显式列出的所有网段——包括外网。删掉之后，主机只能到达路由表里**明确写出**的网段。效果有二：一是主机无法再上外网，数据想往外发都没有路；二是攻击者即便拿下了这台机器，也只能在调度数据网内活动，没法用它当跳板连回外网。

**为什么要加 10.67.0.0 的路由。** 删除默认路由是"断外"，加这条静态路由是"保内"：让主机仍能访问 10.67.0.0/16 这个调度数据网段，下一跳指到默认网关（源表例子里网关是 10.67.1.1）。断外网、保内网，这台主机的通信范围就被精确限制在业务需要的网段里。

### 配置加固方法

#### 1. 卸载 samba 服务

先停服务，再卸包。

```bash
# 停止 smb 服务，三种写法等价，现场有什么用什么
service smbd stop
/etc/rc.d/init.d/smbd stop
/etc/init.d/smbd stop
```

凝思 Linx 6.0（RHEL 6 系）下的卸载：

```bash
# 查看装了哪些 samba 包
rpm -qa | grep samba
# 删除服务包
rpm -e --nodeps samba
```

Ubuntu/Debian 下的卸载：

```bash
# 查看装了哪些相关包
dpkg -l | grep samba
dpkg -l | grep smbfs
dpkg -l | grep smb
# 删除服务包
apt-get remove samba
```

说明：

- `rpm -e --nodeps` 里的 `--nodeps` 是**忽略依赖检查强制卸载**。能不加就不加：先试 `rpm -e samba`，如果报依赖冲突（比如某工具依赖 libsmbclient），再判断用 `--nodeps` 强卸是否安全。源表直接给 `--nodeps` 是为了现场一次到位。
- 凝思 Linx 6.0 上如果 smbd 是以 SysV 服务装的，停服务这一步用 `service smb stop` 也等价，顺手 `chkconfig smb off` 防止残留的自启项。

#### 2. 删除默认路由 0.0.0.0

```bash
# 先看当前路由表，找到目标为 0.0.0.0 的默认路由，确认它挂在 eth0 上
route -n
```

然后编辑网卡配置，把网关那一行注释掉：

```bash
vi /etc/sysconfig/network-scripts/ifcfg-eth0
```

在文件里找到 `GATEWAY=xxxx` 字样，行首加一个 `#` 注释掉：

```ini
#GATEWAY=192.168.1.1
```

保存退出，重启网络服务让路由表重建：

```bash
service network restart
```

**为什么不能只在命令行里 `route del default` 就完事**：`route del default` 只是临时删除，网络服务重启或主机重启后，只要 ifcfg-eth0 里 `GATEWAY=` 还在，默认路由就会被重新生成。所以正确顺序是改配置文件 → 重启网络服务。这就是源表反复强调"路由记得保存，不然重启会丢失"的意思。

#### 3. 配置指向 10.67.0.0 的静态路由并持久化

临时生效的命令（和持久化文件里写的内容是同一件事）：

```bash
route add -net 10.67.0.0/16 gw 10.67.1.1
route add -net 10.67.0.0/16 dev eth0
```

但同样地，`route add` 重启即丢，必须落盘。源表给了几条持久化路径：

**凝思 Linx 6.0（RedHat 系）——/etc/sysconfig/static-routes**：

```bash
vi /etc/sysconfig/static-routes
```

添加：

```ini
any net 10.67.0.0/16 gw 10.67.1.1
```

如果文件不存在，`vi` 会直接创建它。`any` 表示任意网卡都适用。保存退出，重启网络服务生效。

**Debian/Ubuntu 系——方法 1：/etc/rc.local**。在文件里添加路由命令，开机时执行：

```bash
vi /etc/rc.local
```

```bash
route add -net 10.67.0.0/16 dev eth0
route add -net 10.67.0.0/16 gw 10.67.1.1
```

**Debian/Ubuntu 系——方法 2：/etc/sysconfig/network**。在文件末尾追加：

```ini
GATEWAY=gw-ip
# 或者
GATEWAY=gw-dev
```

源表把这一段标在"ubuntu 及 debian 版本"名下，但凝思 Linx 6.0 是 RedHat 系，`/etc/sysconfig/static-routes` 这条路径在本机**真实存在**，直接用上面第 3 步的方法即可，不必退回 rc.local。Debian/Ubuntu 上 `/etc/sysconfig/` 目录并不默认存在，才需要改用 rc.local 或 `/etc/network/interfaces`。现场以实际系统为准，哪种路径真实存在、重启后生效，就用哪种。

### 特殊情况处理

- **删默认路由的连带影响**：删掉之后主机访问不了外网，系统补丁、NTP 时间同步这类依赖外网的事全断。调度发令主机本来就不该随便上外网，但运维要提前规划好替代通道（受控介质、专用同步通道），别等业务出了问题才发现连不上时间源。
- **远程维护通道**：如果日常维护靠办公网 ssh 过来，删默认路由后办公网可能就进不来了。动路由之前先确认管理通道在不在 10.67.0.0/16 网段内，或者在现场控制台把操作做完再离开。
- **多网卡场景**：static-routes 里写 `any` 表示不限定网卡。如果机器有多块网卡，且 10.67.0.0 只应该从 eth0 走，建议把条目写死 `any net 10.67.0.0/16 dev eth0`，避免路由挂错接口。
- **samba 依赖问题**：强卸 samba 后如果发现个别系统工具（如某些带 SMB 挂载功能的备份软件）启动报缺库，说明它们依赖 samba 的库文件。生产控制大区的主机原则上不会装这类东西，若有，用 `--nodeps` 前先和厂家确认。

### 📌 加固后的验证

```bash
# 1. samba 已卸载干净
rpm -qa | grep samba        # 凝思 Linx 6.0：无输出
dpkg -l | grep samba        # Debian/Ubuntu：无输出
netstat -anp | grep -E ':(139|445)\s'   # 无监听

# 2. 默认路由已删除、目标路由已生效
route -n
```

`route -n` 的期望结果：

- **不存在** `Destination` 为 `0.0.0.0` 的默认路由；
- **存在**一条 `Destination 10.67.0.0`、`Genmask 255.255.0.0`、`Gateway 10.67.1.1` 的路由。

最后做持久化验证：`reboot` 重启主机，起来后再跑一次 `route -n`，确认默认路由没有回来、10.67.0.0 的路由还在。只有重启后检查通过，才算真正满足"路由记得保存，不然重启会丢失"这条要求。
