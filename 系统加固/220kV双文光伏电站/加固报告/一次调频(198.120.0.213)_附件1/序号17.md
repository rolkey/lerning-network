# SSH 访问控制：改默认端口 + 管理源 IP 白名单

## 问题

- "默认远程22端口应改为22222，配置本机访问控制列表，限制远程SSH管理IP，仅允许堡垒机（I-II区1.1.1.5、1.1.1.6、III区3.1.1.5、3.1.1.6-7）、应用发布服务器（I-II区1.1.1.7、1.1.1.9，III区3.1.1.8、3.1.1.9）、态势感知服务器（I区态势感知1.1.1.3、II区态势感知2.1.1.3，III区态势感知3.1.1.3）访问SSH。
  注：若有其他业务需要访问（如SFTP），请在加固脚本main注释host_allow_and_deny函数的运行，并手动添加进服务器hosts.allow中。"

---

这条作业项做两件事：把 SSH 从全网都在扫的 22 端口挪到 22222，再给 SSH 挂一个"谁能来"的白名单。白名单只放三类机器——堡垒机、应用发布服务器、态势感知服务器，并且按安全分区（Ⅰ/Ⅱ 区 1.1.1.x、2.1.1.x，Ⅲ 区 3.1.1.x）精确到 IP。其余一切来源，包括同网段的其他主机，都不允许碰 SSH。

### 🔍 风险原理

- **默认 22 端口**：互联网扫描器无差别扫 22 爆破，内网蠕虫和跳板机也优先试 22。改端口躲不掉定向攻击，但能过滤掉大量自动化扫描，降低噪音和误报。端口本身不是安全措施，白名单才是。
- **无访问控制**：SSH 对任何能到达主机的 IP 开放，等于把口令强度当作唯一防线。同网段任何一台被控机器都能对监控主机发起爆破。
- 电力监控网的要求是"最小化访问"：只有运维通道（堡垒机/应用发布）和安全监测通道（态势感知）需要连 SSH，其余全部拒绝，符合《电力监控系统网络安全合规基线技术规范》。

### 配置/加固方法

**源文方法（TCP Wrappers 写法，适用于老式 Unix）**

```bash
# 编辑允许列表，只放白名单 IP
vi /etc/hosts.allow
# 增加一行 <service>: 允许访问的IP；举例如下：
ssh:1.1.1.3:allow
ssh:1.1.1.5:allow

# 编辑拒绝列表，默认拒绝一切
vi /etc/hosts.deny
# 增加一行
all:all

# 重启进程
pkill -HUP inetd
```

`hosts.allow` 先匹配放行，`hosts.deny` 兜底拒绝所有（`all:all`），这是 TCP Wrappers 标准的"白名单"写法。源文补充说明：更改 `/etc/inetd.conf` 后重启 inetd 的命令是 `pkill -HUP inetd`（或 `/etc/init.d/inetsvc start`）。

**CentOS 7 对应做法**：`hosts.allow/hosts.deny` 依赖 TCP Wrappers（libwrap），而 CentOS 7 的 sshd 编译时已不带 libwrap 支持，这两个文件对 SSH 不生效。改端口和做白名单要用 sshd 自己的配置加防火墙：

```bash
# 1、改 SSH 监听端口 22 -> 22222
vi /etc/ssh/sshd_config
Port 22222

# 2、SELinux 放行新端口（否则 sshd 起不来）
semanage port -a -t ssh_port_t -p tcp 22222

# 3、检查配置语法并重启
sshd -t
systemctl restart sshd
```

来源 IP 白名单推荐用 firewalld 富规则（比 sshd 的 AllowUsers 更集中，且不影响端口上其他服务的判定）：

```bash
# 先关闭默认 ssh 服务，只开放 22222
firewall-cmd --permanent --remove-service=ssh
firewall-cmd --permanent --add-port=22222/tcp

# 按源文名单逐个放行：堡垒机、应用发布服务器、态势感知服务器
firewall-cmd --permanent --add-rich-rule='rule family="ipv4" source address="1.1.1.5" port port="22222" protocol="tcp" accept'
firewall-cmd --permanent --add-rich-rule='rule family="ipv4" source address="1.1.1.6" port port="22222" protocol="tcp" accept'
# ... 其余 IP 依源文名单补充（含 III 区 3.1.1.x、态势感知 1.1.1.3 / 2.1.1.3 / 3.1.1.3 等）

# 重载生效
firewall-cmd --reload
```

也可以用 sshd 自带的白名单做双保险：

```bash
vi /etc/ssh/sshd_config
AllowUsers admin@1.1.1.5 admin@1.1.1.6
```

### 特殊情况处理

- 有额外业务（如 SFTP 上传数据）需要连 SSH 时，源文要求：注释加固脚本 main 里的 `host_allow_and_deny` 函数，把该业务 IP 手动加进 `hosts.allow`。CentOS 7 下对应为在 firewalld 富规则里补一条放行，不要图省事直接放开整个网段。
- 改端口前先确认堡垒机侧同步改好连接端口，并保留一个已登录的会话窗口，避免改完把自己锁在门外。
- 态势感知的巡检账号同样要放行，否则漏扫、监测任务会报连不上。

### 📌 加固后的验证

```bash
# 1、确认 sshd 监听在 22222，而不是 22
ss -tlnp | grep sshd
# 期望：只有 *:22222 的监听，没有 *:22

# 2、从白名单外的 IP 尝试连接
ssh -p 22222 root@198.120.0.213
# 期望：连接被拒绝或超时

# 3、从堡垒机（如 1.1.1.5）连接
ssh -p 22222 admin@198.120.0.213
# 期望：正常进入登录提示

# 4、核对生效配置
sshd -T | grep -E '^(port|allowusers)'
```

期望结果：sshd 只监听 22222；名单外 IP 无法建立 SSH 连接；名单内堡垒机可正常登录。
