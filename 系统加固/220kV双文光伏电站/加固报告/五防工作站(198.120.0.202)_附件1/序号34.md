# 防止 ICMP 重定向报文攻击（accept_redirects=0）

## 问题

- "防止icmp重定向报文的攻击，修改accept_redirects的值为0"

---

ICMP 重定向本来是路由器发给主机的"善意提醒"——"去那个网段有更好的下一跳"。但这个机制可以被伪造报文利用，让主机把流量导向攻击者的机器。内核默认接受这种报文（`accept_redirects=1`），加固就是把它关成 0。

### 🔍 风险原理

攻击路径是这样的：

1. 攻击者与目标主机在同一网段，伪造一条 ICMP Redirect 报文，声称"去 XX 网段请走我的 IP"。
2. 目标主机内核默认信任这条报文，修改本机路由表，把去往某网段的流量指向攻击者。
3. 之后的流量都从攻击者机器经过——中间人攻击（MITM）成立，抓包、篡改、注入都可行。

即使不做完整 MITM，单纯把路由表污染成指向一个黑洞地址，也能造成定向的拒绝服务。对 AGC/AVC 这类调度控制主机来说，路由表被改的后果不只是断网，而是指令数据可能被截获篡改。

### 配置加固方法

源数据给的命令：

```bash
# 1) 备份配置文件
cp -p /proc/sys/net/ipv4/conf/all/accept_redirects /proc/sys/net/ipv4/conf/all/accept_redirects.bak

# 2) 修改内核参数为 0
sysctl -w net.ipv4.conf.all.accept_redirects="0"
```

注意：第 1 条命令照抄意义不大——`/proc` 是虚拟文件系统，里面的"文件"只是内核参数的只读视图，cp 出来的 `.bak` 只是内容为 "1" 的普通文本，而且往 `/proc` 里 cp 会失败。真正要备份的是持久化配置文件 `/etc/sysctl.conf`。CentOS 7 上的实际做法：

```bash
# 1) 备份内核参数配置文件
cp -p /etc/sysctl.conf /etc/sysctl.conf.bak

# 2) 立即生效（无需重启）
sysctl -w net.ipv4.conf.all.accept_redirects=0
sysctl -w net.ipv4.conf.default.accept_redirects=0

# 3) 写入配置文件持久化
echo "net.ipv4.conf.all.accept_redirects = 0" >> /etc/sysctl.conf
echo "net.ipv4.conf.default.accept_redirects = 0" >> /etc/sysctl.conf
sysctl -p
```

只改 `all` 不改 `default` 的坑：`all` 影响当前已存在的网卡，`default` 影响之后新出现的网卡（比如以后插的网卡、新建的隧道接口）。两边都写，才能保证新老接口一致。

### 特殊情况处理

- 逐接口设置：如果担心个别接口行为不同，可以显式写 `net.ipv4.conf.eth0.accept_redirects = 0`，按接口粒度兜底。
- IPv6 同样有这个参数，对应项 `net.ipv6.conf.all.accept_redirects = 0`，双栈环境下一起加固。
- 另一个相关参数 `secure_redirects`：只接受来自网关 IP 的重定向。系统默认就是开的，但攻击者伪造源地址为网关并不难，不能替代 `accept_redirects=0`。
- 只有路由器角色的设备需要处理重定向，服务器角色一律关掉，没有业务会依赖它。

### 📌 加固后的验证

```bash
# 1) 当前值应为 0
sysctl net.ipv4.conf.all.accept_redirects
# 期望：net.ipv4.conf.all.accept_redirects = 0

# 2) 直接读内核参数确认
cat /proc/sys/net/ipv4/conf/all/accept_redirects
# 期望：0

# 3) 确认持久化配置存在，重启后不会丢失
grep accept_redirects /etc/sysctl.conf
# 期望：能看到 net.ipv4.conf.all.accept_redirects = 0 等条目
```

重启一次机器再跑第 1 条，仍是 0 才算真正落定。
