# Console 口密码保护

## 问题

- "配置console口密码保护功能，防止无认证直连设备。"

---

Console 口（控制台口）是网络设备的"最后一道门"——通过串口线物理直连，即使设备网络全断、远程登录全被封，管理员也能从 Console 口进入命令行救援。正因为它是兜底通道，一旦 Console 口不设认证，任何能物理接触到设备或串口服务器（console server）的人，都能直接越过所有网络防护，获得设备完全控制权。

### 🔍 风险原理

- **物理接入即裸奔**：Console 口默认或不设密码时，插上串口线、按回车就直接进入命令行，无需任何身份校验。机房巡检、外包施工、串口集中管理设备被渗透等场景下，等于门户大开。
- **绕过网络防护**：ACL、SSH、AAA 这些网络层安全措施全部管不到 Console 口的物理直连，Console 口无认证是独立于网络防护之外的后门。
- **账号锁定后的逃生门风险**：当管理员因远程登录被锁死而需要通过 Console 救援时，若 Console 也无口令，攻击者同样能利用这条通道抢先进入。
- **合规要求**：并网安全管控明确要求 Console 口有密码保护，防止无认证直连设备，属于网络设备安全基线必查项。

### 配置/加固方法

H3C Comware V7 中 Console 口对应 `user-interface console 0`（部分老型号为 `aux 0`）。本项使用"口令认证"方式为 Console 口设置登录口令。

**1、进入 Console 口并设置口令认证**

```text
<H3C> system-view
[H3C] user-interface console 0
[H3C-line-console0] authentication-mode password
[H3C-line-console0] set authentication password cipher Console@2026
[H3C-line-console0] idle-timeout 5
[H3C-line-console0] quit
```

`authentication-mode password` 指定用"固定口令"认证；`set authentication password cipher` 以密文方式保存口令，避免配置文件中明文暴露。

**2、AUX 口（备用拨号/管理口）同样处理**

```text
[H3C] user-interface aux 0
[H3C-line-aux0] authentication-mode password
[H3C-line-aux0] set authentication password cipher Aux@2026
[H3C-line-aux0] quit
```

逐条说明：Console 口令与 VTY 登录账号是两套独立机制——Console 用 `authentication-mode password`（单一口令），VTY 用 `authentication-mode scheme`（AAA 多账号），互不影响。口令需满足复杂度（见序号17），`cipher` 关键字保证配置中不出现明文。

### 特殊情况处理

- **`console 0` 与 `aux 0` 的区别**：Comware V7 的 Console 口是 `user-interface console 0`，AUX 口是 `user-interface aux 0`；早期 V5 型号可能把 Console 显示为 `aux 0`，配置前先用 `display user-interface` 确认实际编号，别配错口。
- **口令遗忘的恢复**：Console 口令一旦忘记，只能通过设备面板的复位/跳过口令流程恢复（因型号而异），操作复杂且可能中断业务，务必把口令纳入安全口令库统一保存。
- **Console 密码强度同样重要**：物理兜底口的口令不能设置成简单默认值（如 123456），否则保护形同虚设；建议与 VTY 账号口令同强度管理。
- **串口集中管理设备**：若站点使用 console server 集中管理，Console 口密码是共享的，还需配合 console server 自身的账号认证和访问控制，防止串口通道被滥用。
- **不要与"无认证"混用**：确认 `authentication-mode` 不是 `none`，否则等于没配。

### 📌 加固后的验证

```text
<H3C> display user-interface console 0
```

期望结果：Console 口 `Authentication` 显示为 `Password`，且 `Idle timeout` 为 5 分钟。

```text
<H3C> display current-configuration | include set authentication
```

期望结果：能看到 `set authentication password cipher ...`，且显示为密文（一串 `$c$3` 开头的加密串），而非明文口令。

验证效果：断开串口重新连接 Console，回车后系统提示输入口令，不输入或输错口令无法进入命令行。
