# 特权口令与默认登录级别控制

## 问题

- "配置特权模式口令，口令加密存储，并满足口令复杂度要求(密码不小于8位)。"
- "配置登录默认级别。登录默认级别配置为访问级（level 0）。"

---

普通账号登录设备后默认只处于用户视图（`<H3C>`），要下发配置必须进入特权/系统视图，这一"升级权限"的动作由特权模式口令（super password）把关。同时，登录后的默认权限级别应压到最低（level 0 访问级），让账号"登录进来什么也改不了"，只有具备相应角色的人才能逐级提权，形成"最小权限 + 按需提权"的访问控制。

### 🔍 风险原理

- **无特权口令 = 任意提权**：若未设 super password，任何登录者都能直接 `super` 或进入系统视图获得配置权限，账号的只读限制形同虚设。
- **默认级别过高**：登录默认级别若为管理级，账号一登录就拥有全部权限，违背最小权限原则，也放大了账号泄露的危害。
- **特权口令弱**：特权口令若为空、简单或明文，等于给攻击者留了一个"一键提权"的捷径，且配置文件泄露时特权口令一并暴露。
- **越权操作难防**：级别控制不到位，低权限账号可执行高权限命令，误操作和恶意操作都无法被权限边界拦截。

### 配置/加固方法

**1、设置特权模式口令（加密存储 + 复杂度）**

```text
<H3C> system-view
[H3C] super password role network-admin cipher Super@2026
```

`role network-admin` 指定该特权口令对应"网络管理员"角色；`cipher` 让口令以密文形式保存。口令本身需满足"不少于 8 位、含字母数字特殊符号"的复杂度要求。

**2、配置账号默认登录级别为访问级（level 0）**

```text
[H3C] local-user monitor class manage
[H3C-luser-manage-monitor] password cipher Monitor@2026
[H3C-luser-manage-monitor] service-type ssh
[H3C-luser-manage-monitor] authorization-attribute user-role level-0
[H3C-luser-manage-monitor] quit
```

Comware V7 预置了 `level-0` 到 `level-15` 及 `network-operator`、`network-admin` 等角色。`user-role level-0` 即"访问级"，该账号登录后只能执行最基础的查看命令，无法进入系统视图修改配置。

**3、按需分配更高角色（最小权限）**

```text
[H3C] local-user engineer class manage
[H3C-luser-manage-engineer] authorization-attribute user-role network-operator
[H3C-luser-manage-engineer] quit
```

逐条说明：登录默认级别要压到 level 0（访问级）；只有确需配置权限的账号才单独授予 `network-operator`（只读监控）或 `network-admin`（管理），并配合 super password 实现提权闸门。

### 特殊情况处理

- **level-0 账号的可用范围**：访问级账号无法查看部分敏感配置，若测评要求"登录默认级别为访问级"，就按此配置；确有需要查看的，授予 `network-operator`（对应更高只读级别）而非直接给管理角色。
- **super password 的角色对应**：`role network-admin` 是常用管理角色；若现场用自定义角色，需保证 super password 的角色与账号提权目标一致。
- **提权命令**：配置了 super password 后，低级别账号需执行 `super` 并输入特权口令才能临时提权，正常流程应保留，不要图省事把默认级别直接设成管理级。
- **口令复杂度联动**：特权口令同样受 D8 的 password-control 策略约束（若已启用），设置时须满足长度与字符类型要求。
- **Console 默认级别**：Console 登录默认通常即为最高权限，因是物理兜底口可保留，但口令保护必须到位（见序号14）。

### 📌 加固后的验证

```text
<H3C> display current-configuration | include super password
```

期望结果：显示 `super password role network-admin cipher $c$3$...` 密文形式，非明文。

```text
<H3C> display local-user verbose
```

期望结果：普通账号的 `User role` 为 `level-0`（访问级），管理账号为 `network-admin` 等更高角色，权限分级清晰。

验证效果：用访问级账号登录后，尝试执行 `system-view` 应被拒绝或无法进入系统视图；执行 `super` 并输入正确特权口令后方可提权。
