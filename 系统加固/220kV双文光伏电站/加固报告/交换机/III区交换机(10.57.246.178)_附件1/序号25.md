# SNMP 安全配置

## 问题

- "SNMP Community口令强度长度至少8位，并包括数字、小写字母、大写字母和特殊符号4类中至少2类"
- "使能snmpv2c、v3版本"
- "只与特定主机进行SNMP协议交互，设置ACL进行限制"
- "关闭未使用的SNMP协议，禁用SNMP的写（WRITE）功能。"

---

SNMP 用于网管平台采集设备状态、接收告警，是运维刚需；但默认的 SNMP community 字符串（如 public/private）人人皆知，一旦暴露就等于把设备信息甚至配置修改权拱手送人。本项要求从版本、口令强度、访问来源、读写权限四个维度同时收紧 SNMP：口令够强、只用 v2c/v3、只允许特定主机访问、关掉写权限。

### 🔍 风险原理

- **默认 community 秒破**：`public`（读）、`private`（写）是出厂默认，全网皆知，扫描器几秒就能枚举，拿到 community 即可读取设备全部 MIB 信息甚至通过 SET 修改配置。
- **v1 明文且无认证**：SNMPv1 无加密无认证，community 明文传输，可被抓包直接窃取；v2c 同样明文但至少保留了 community 机制，v3 才支持认证与加密。
- **写权限 = 远程改配置**：SNMP 的 WRITE 权限允许通过 SET 操作远程修改设备，若被滥用可直接篡改接口状态、路由、账号，危害极大，务必禁用。
- **暴露面过大**：不限定来源，任意主机都能向设备发起 SNMP 查询，既泄露信息又可能被用于放大攻击或作为 DDoS 反射源。

### 配置/加固方法

**1、限定 SNMP 协议版本（只用 v2c 和 v3，关闭 v1）**

```text
<H3C> system-view
[H3C] snmp-agent
[H3C] snmp-agent sys-info version v2c v3
```

**2、设置强 community 并绑定 ACL**

```text
[H3C] acl basic 2001
[H3C-acl-ipv4-basic-2001] rule 5 permit source 1.1.1.3 0
[H3C-acl-ipv4-basic-2001] rule 10 permit source 1.1.1.2 0
[H3C-acl-ipv4-basic-2001] quit
[H3C] snmp-agent community read cipher Test@2026 acl 2001
[H3C] snmp-agent community write cipher Wr!te@2026 acl 2001
```

community 口令 `Test@2026` 满足"至少 8 位、含数字+大小写字母+特殊符号 4 类中的至少 2 类"；`acl 2001` 让只有网管/日志服务器能访问。

**3、禁用写权限（撤销 write community）**

```text
[H3C] undo snmp-agent community write
```

如需保留读写的网管场景，也应把 write community 绑定最小范围的 ACL 并单独保存；本项要求禁用 WRITE，故直接撤销 write community。

**4、配置 SNMP Trap 上报（只发特定主机）**

```text
[H3C] snmp-agent trap enable
[H3C] snmp-agent target-host trap address udp-domain 1.1.1.3 params securityname Test@2026 v2c
```

逐条说明：`snmp-agent sys-info version v2c v3` 明确只启用 v2c 与 v3，v1 被关闭；`snmp-agent community read cipher ... acl 2001` 把"谁能读"限制在白名单内；撤销 write community 后设备不接受任何 SET 写操作。

### 特殊情况处理

- **v3 更安全可优先**：SNMPv3 支持认证与加密（USM 用户 + 认证/加密算法），对安全要求高的环境，建议直接改用 v3 并配置 `snmp-agent usm-user`，彻底告别 community。
- **ACL 与 SSH 访问 ACL 分开**：SNMP 用独立 ACL（如 2001），不要复用 VTY 的 SSH 访问 ACL（2000），两者允许的主机集合可能不同。
- **网管平台需同步**：改了 community 和版本后，网管平台（NMS）上的配置必须同步更新，否则设备脱管、告警丢失。
- **trap 的 securityname 要匹配**：`target-host ... params securityname` 要与 community 一致，否则 trap 消息在接收端无法识别。
- **community 别写成 simple**：务必用 `cipher` 让 community 密文存储（呼应序号16），避免配置泄露时暴露口令。

### 📌 加固后的验证

```text
<H3C> display snmp-agent sys-info version
```

期望结果：仅显示 v2c、v3，无 v1。

```text
<H3C> display snmp-agent community
```

期望结果：read community 为密文，且绑定了 ACL 2001；无 write community（写权限已禁用）。

```text
<H3C> display snmp-agent target-host
```

期望结果：trap 目标主机为白名单内的网管/态势感知服务器地址。

验证效果：从白名单外主机用 SNMP 工具查询设备，请求被 ACL 拒绝、无响应。
