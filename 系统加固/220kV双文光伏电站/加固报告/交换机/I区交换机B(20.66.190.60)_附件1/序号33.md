# ACL 过滤已知攻击流量

## 问题

- "设置ACL安全访问控制，过滤已知攻击数据包。屏蔽常见漏洞端口 TCP/UDP 135,137,138,139,445,3389, TCP593, TCP5000, TCP4444, TCP5554, TCP6667, TCP9996, udp1434, tftp UDP69"

---

大量历史蠕虫和攻击工具依赖固定的端口传播或控制：135/137/138/139/445（Windows 共享与 NetBIOS）、3389（远程桌面）、1434（SQL Slammer）、69（TFTP）等。这些端口在电力监控生产网内通常没有任何合法业务用途，却在历史上被 WannaCry、Conficker、Slammer 等大规模攻击反复利用。通过 ACL 在网络边界把这些高危端口流量直接丢弃，能显著降低已知攻击的横向扩散风险。

### 🔍 风险原理

- **蠕虫横向传播**：WannaCry 走 445、Conficker 走 445/139、Slammer 走 1434，一旦网内某台主机感染，会向全网段扫描这些端口扩散，ACL 过滤可切断其横向传播通道。
- **远程控制后门**：4444、5554、6667、5000 等是常见远控木马、IRC 僵尸网络的默认端口，过滤后可阻断被控主机与 C2 服务器的通信。
- **TFTP 未授权传输**：UDP 69 的 TFTP 无认证、易被滥用，用于下载恶意配置或上传敏感文件，生产网内应默认屏蔽。
- **纵深防御**：即便终端补丁不全，边界 ACL 过滤高危端口，也能在主机被攻陷前挡下大量已知攻击流量，是成本最低的防线之一。

### 配置/加固方法

定义一条高级 ACL，按端口逐条 deny 高危协议端口，末尾放行其余流量，再应用到入接口（通常为下联业务网段的入方向）。

**1、创建高级 ACL 并屏蔽高危端口**

```text
<H3C> system-view
[H3C] acl advanced 3000
[H3C-acl-ipv4-adv-3000] rule 5 deny tcp destination-port eq 135
[H3C-acl-ipv4-adv-3000] rule 10 deny tcp destination-port eq 137
[H3C-acl-ipv4-adv-3000] rule 15 deny tcp destination-port eq 138
[H3C-acl-ipv4-adv-3000] rule 20 deny tcp destination-port eq 139
[H3C-acl-ipv4-adv-3000] rule 25 deny tcp destination-port eq 445
[H3C-acl-ipv4-adv-3000] rule 30 deny tcp destination-port eq 3389
[H3C-acl-ipv4-adv-3000] rule 35 deny tcp destination-port eq 593
[H3C-acl-ipv4-adv-3000] rule 40 deny tcp destination-port eq 5000
[H3C-acl-ipv4-adv-3000] rule 45 deny tcp destination-port eq 4444
[H3C-acl-ipv4-adv-3000] rule 50 deny tcp destination-port eq 5554
[H3C-acl-ipv4-adv-3000] rule 55 deny tcp destination-port eq 6667
[H3C-acl-ipv4-adv-3000] rule 60 deny tcp destination-port eq 9996
[H3C-acl-ipv4-adv-3000] rule 65 deny udp destination-port eq 137
[H3C-acl-ipv4-adv-3000] rule 70 deny udp destination-port eq 138
[H3C-acl-ipv4-adv-3000] rule 75 deny udp destination-port eq 139
[H3C-acl-ipv4-adv-3000] rule 80 deny udp destination-port eq 1434
[H3C-acl-ipv4-adv-3000] rule 85 deny udp destination-port eq 69
[H3C-acl-ipv4-adv-3000] rule 100 permit ip
[H3C-acl-ipv4-adv-3000] quit
```

**2、将 ACL 应用到接口入方向**

```text
[H3C] interface GigabitEthernet 0/1
[H3C-GigabitEthernet0/1] packet-filter 3000 inbound
[H3C-GigabitEthernet0/1] quit
```

逐条说明：高级 ACL 末尾必须保留 `rule 100 permit ip` 放行其余正常流量，否则默认 deny 会误伤所有业务；137/138/139 既有 TCP 也有 UDP，因此两组都列出；`packet-filter 3000 inbound` 把过滤施加在接口入方向，视网络位置选择下联口入方向（从业务侧进来的流量）。

### 特殊情况处理

- **别漏 permit ip**：高级 ACL 末尾不加 `permit ip` 会拒绝所有未匹配流量，等于把接口全网段掐断，这是最常见的踩坑点。
- **端口 445 与业务冲突**：若网内确有依赖 SMB/445 的业务（如某些共享存储、Windows 域），需评估豁免；电力生产网一般无此需求，按默认屏蔽。
- **应用方向选择**：入方向过滤的是"进入该接口"的流量，选择下联业务口 inbound 最合适；不要在管理口、上联口随意应用，以免误伤管理流量。
- **分段应用**：多接口设备应把 ACL 应用到所有需要防护的入接口，避免只在个别口生效留下缺口。
- **后续端口补充**：发现新的高危端口（如某漏洞新利用端口），在本 ACL 中追加 deny 规则，保持清单持续更新。

### 📌 加固后的验证

```text
<H3C> display acl 3000
```

期望结果：列出全部 deny 规则（135~9996 等 TCP/UDP 端口）及末尾 `permit ip`，无缺漏。

```text
<H3C> display packet-filter interface GigabitEthernet 0/1
```

期望结果：显示接口入方向已应用 ACL 3000。

验证效果：从业务侧向设备下联口发起到 445、1434 等端口的访问，流量被丢弃、无响应；正常业务流量不受影响。
