# 交换机端口安全绑定

## 问题

- "重要服务器采用IP+MAC+端口绑定。"

---

交换机端口默认对"谁插上来"不做限制，任何终端插上网线都能接入并获取网络资源。对重要服务器（如监控主机、五防工作站、预测服务器、AGC/AVC 主机等）所在端口实施"IP+MAC+端口"绑定，把"端口—MAC 地址—IP 地址"三者固定关联，只有绑定的那台服务器才能从该端口接入，从接入层杜绝冒名顶替、私接设备和 MAC 欺骗。

### 🔍 风险原理

- **端口被顶替接入**：攻击者或误操作者拔掉重要服务器的网线，插入自己的设备，即可冒用该端口接入内网，甚至伪装成原服务器参与业务通信。
- **MAC 地址欺骗**：不绑定 MAC，攻击者可伪造合法服务器的 MAC 地址，绕过基于 MAC 的准入控制，实现身份冒充。
- **IP 冲突与劫持**：不绑定 IP，同一网段内可私自配置他人 IP，造成地址冲突、ARP 欺骗，干扰甚至劫持重要服务器通信。
- **电力监控业务高敏感**：调度、监控、五防等业务对终端身份可信度要求极高，任何非法接入都可能影响电网运行安全，必须从端口层做强约束。

### 配置/加固方法

H3C S5130 交换机（Comware V7）用"端口安全 + 静态 MAC 绑定"锁定端口可接入的 MAC，用"IP Source Guard（IP 源防欺骗）"绑定 IP 与 MAC，二者叠加实现 IP+MAC+端口三重绑定。

**1、开启端口安全并绑定服务器 MAC**

```text
<H3C> system-view
[H3C] interface GigabitEthernet 1/0/1
[H3C-GigabitEthernet1/0/1] port-security enable
[H3C-GigabitEthernet1/0/1] port-security max-mac-count 1
[H3C-GigabitEthernet1/0/1] port-security port-mode secure
[H3C-GigabitEthernet1/0/1] port-security mac-address security 0011-2233-4455 vlan 10
[H3C-GigabitEthernet1/0/1] quit
```

`port-security enable` 开启端口安全；`max-mac-count 1` 限定该口最多学习 1 个 MAC；`port-mode secure` 让端口只放行安全 MAC；`mac-address security ... vlan 10` 静态绑定服务器 MAC 到该端口和 VLAN。

**2、IP 与 MAC 绑定（IP Source Guard）**

```text
[H3C] ip source binding ip-address 192.168.10.10 mac-address 0011-2233-4455 vlan 10
[H3C] interface GigabitEthernet 1/0/1
[H3C-GigabitEthernet1/0/1] ip verify source ip-address mac-address
[H3C-GigabitEthernet1/0/1] quit
```

`ip source binding` 建立 IP—MAC—VLAN 静态绑定条目；`ip verify source ip-address mac-address` 让该端口对入向流量校验源 IP 与源 MAC 是否匹配绑定表，不匹配即丢弃。

逐条说明：端口安全管"谁（MAC）能接入"，IP Source Guard 管"IP 和 MAC 对不对得上"，两者结合才能同时防"换 MAC"和"伪造 IP"。

### 特殊情况处理

- **先采集真实 MAC/IP**：绑定前务必用 `display mac-address`、`display arp` 准确采集重要服务器的真实 MAC 与 IP，绑错会直接把服务器踢下线。
- **换网卡/换端口要解绑重绑**：服务器更换网卡（MAC 变化）、迁移到其它端口时，需先删除旧绑定、再按新 MAC/IP 重新绑定，否则服务器无法上线。
- **端口安全违规处理**：非法设备接入时会触发违规（默认丢弃），可在端口下配 `port-security intrusion-mode disableport-temporarily` 自动临时关闭端口，但生产环境建议先评估是否会导致服务器短暂中断。
- **DHCP 环境注意**：若服务器用动态 IP，`ip verify source` 需配合 DHCP Snooping 动态绑定；重要服务器建议改为静态 IP，便于静态绑定。
- **上联口/管理口别绑**：端口安全只针对"重要服务器"接入端口，不要误绑上联口、管理口，否则会阻断正常通信。

### 📌 加固后的验证

```text
<H3C> display port-security interface GigabitEthernet 1/0/1
```

期望结果：端口安全已启用，安全 MAC 为绑定的服务器 MAC，学习到的 MAC 数不超过 1。

```text
<H3C> display ip source binding
```

期望结果：列出 IP—MAC—VLAN 绑定条目，与重要服务器真实信息一致。

```text
<H3C> display ip verify source interface GigabitEthernet 1/0/1
```

期望结果：端口已开启 `ip-address mac-address` 源校验。

验证效果：正常服务器接入可正常通信；换一台未绑定 MAC 的设备接入该端口，或伪造其它 IP，流量被丢弃、无法接入。
