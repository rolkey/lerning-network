# 关闭未使用的接口

## 问题

- "关闭未使用的空闲接口，如路由器的AUX口。"

---

设备上大量物理接口长期处于"配置了地址、接了线但没流量"，或"完全空闲"的状态。这些未使用的接口是潜在的物理接入点——攻击者或误操作者只要把网线插进一个未关闭的空闲口，就可能进入本不该接入的网络区域。本项要求把所有未使用的空闲接口（含路由器的 AUX 口）关闭，从物理层面封死未授权接入的入口。

### 🔍 风险原理

- **空闲口成为接入后门**：机房内或配线间里，一个未关闭的空闲口就是现成的接入点，任何人都能插线接入内网，绕过防火墙、ACL 等逻辑防护。
- **误接引发环路/冲突**：施工、检修时误把网线插到未关闭的接口，可能引发二层环路、广播风暴、IP 冲突，导致网络瘫痪。
- **AUX 口可被远程拨号接入**：路由器的 AUX 口原本用于拨号备份管理，若不关闭且未设认证，可能被通过 Modem 拨号方式远程接入设备，形成隐蔽管理通道。
- **扩大攻击面**：每一个 UP 的接口都是潜在的攻击面，未使用的接口开着只会徒增风险，没有任何收益。

### 配置/加固方法

H3C Comware V7 使用接口视图下的 `shutdown` 命令关闭接口，关闭后接口物理层 down、不再收发数据。

**1、关闭单个空闲接口**

```text
<H3C> system-view
[H3C] interface GigabitEthernet 0/2
[H3C-GigabitEthernet0/2] shutdown
[H3C-GigabitEthernet0/2] quit
```

**2、批量关闭一段空闲接口**

```text
[H3C] interface range GigabitEthernet 1/0/5 to GigabitEthernet 1/0/24
[H3C-if-range] shutdown
[H3C-if-range] quit
```

**3、关闭路由器 AUX 口**

```text
[H3C] interface Aux 0
[H3C-Aux0] shutdown
[H3C-Aux0] quit
```

若设备把备用管理口显示为 `Aux 0` 或 `Async` 接口，按 `display interface brief` 列出的实际接口名执行 `shutdown`。

逐条说明：`shutdown` 让接口进入 administratively down 状态，物理上不再转发；建议先在空接口上配 `description` 标注"预留/禁用"（呼应序号10），再关闭，便于台账核对。

### 特殊情况处理

- **先确认接口真的未使用**：关闭前用 `display interface brief` 核对接口流量、连接状态，确认无业务、无终端在跑，避免误关业务口造成中断。
- **AUX 口关闭与口令双保险**：AUX 口若因现场需要保留，至少要配口令（序号14），否则一律 `shutdown`；关闭后仍建议配口令以防被误开启。
- **管理口别误关**：执行 `interface range` 批量关闭时，务必排除设备的管理口、上联口、Console 口，否则可能把自己关在设备外面。
- **接口计数**：关闭后接口状态变为 `ADM`（administratively down），注意与物理 `DOWN` 区分，`ADM` 表示已被管理性关闭。
- **新增端口及时关**：后续新增板卡、扩展模块带来的新接口，上线时同步评估并关闭未使用部分，纳入日常运维流程。

### 📌 加固后的验证

```text
<H3C> display interface brief
```

期望结果：所有未使用的空闲接口状态为 `ADM`（管理性关闭），在用接口正常 `UP`。

```text
<H3C> display interface GigabitEthernet 0/2
```

期望结果：该接口 `Line protocol current state: DOWN (Administratively)`，确认已被 shutdown。

```text
<H3C> display current-configuration interface | include shutdown
```

期望结果：能看到对空闲接口下发的 `shutdown` 配置，与台账中"未使用接口"清单一致。
