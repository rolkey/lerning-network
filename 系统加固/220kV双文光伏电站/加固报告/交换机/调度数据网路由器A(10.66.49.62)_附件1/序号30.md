# NTP 时间同步配置

## 问题

- "开启NTP服务，系统时间与NTP服务器同步（I区1.1.1.4，II区2.1.1.4，III区3.1.1.4）。设置北京时区+8小时。"

---

网络设备的系统时间是否准确，直接关系到日志的可信度。安全事件发生后，跨设备、跨系统关联日志、还原攻击时间线，全靠统一、准确的时间戳；如果各设备时间漂移，日志就"对不上账"，取证和审计都会失真。本项要求开启 NTP 服务，让设备时间与指定的 NTP 服务器同步，并把时区设为北京时间（UTC+8）。

### 🔍 风险原理

- **日志时间失真**：设备内置时钟（RTC）长期运行会漂移，误差可达几分钟甚至更久；时间不准的日志无法与其它设备、服务器、安全设备的时间戳对齐，攻击时序无法还原。
- **证书与认证失效**：若设备启用了基于时间的认证（如证书有效期、TACACS 时间戳校验），时间偏差会导致认证失败或证书误判过期，影响正常运行。
- **合规审计要求**：等保明确要求审计记录时间准确、可溯源，时间不同步是常见的不合规项，安全评估会逐台核对设备时间。
- **跨分区时间不一致**：I、II、III 区若时间源不同、时区不统一，跨区事件关联将出现系统性误差，掩盖真实攻击顺序。

### 配置/加固方法

**1、设置时区为北京时区（UTC+8）**

```text
<H3C> system-view
[H3C] clock timezone Beijing add 08:00:00
```

**2、开启 NTP 服务**

```text
[H3C] ntp-service enable
```

**3、配置 NTP 服务器（按所在分区选择）**

```text
# I 区设备
[H3C] ntp-service unicast-server 1.1.1.4
# II 区设备
[H3C] ntp-service unicast-server 2.1.1.4
# III 区设备
[H3C] ntp-service unicast-server 3.1.1.4
```

**4、（可选）设置 NTP 认证与源接口**

```text
[H3C] ntp-service source GigabitEthernet 0/0
```

逐条说明：`clock timezone Beijing add 08:00:00` 把时区设为东八区，设备显示的时间即为北京时间；`ntp-service enable` 打开 NTP 服务后，`ntp-service unicast-server <IP>` 指定上游时间源，设备会周期性与该服务器校时。设备时间必须与所在安全分区的 NTP 服务器对应，不可跨区取时间。

### 特殊情况处理

- **时区要先设**：务必先执行 `clock timezone` 再同步，否则设备按 UTC 保存时间，显示时又叠加时区，会出现"时间看起来对了但日志时间戳错"的问题。
- **NTP 服务器可达性**：确保设备到 NTP 服务器的 UDP 123 端口网络可达、中间安全设备放行，否则 NTP 请求无法到达，时间不会同步。
- **同步需要时间**：首次同步可能需数分钟，`display ntp-service status` 显示 `synchronized` 才代表已与服务器同步，不能只看命令配置成功。
- **分层取时**：若 NTP 服务器本身不可达，可配置多台备用服务器（多次 `ntp-service unicast-server`），提高时间源可靠性。
- **长期运行漂移**：NTP 只在校时周期内修正，若时间源长期故障，设备会退回本地时钟继续漂移，需监控 NTP 同步状态告警。

### 📌 加固后的验证

```text
<H3C> display clock
```

期望结果：显示当前时间，时区为 Beijing，时间与北京时间一致。

```text
<H3C> display ntp-service status
```

期望结果：`Clock status: synchronized`，`Clock stratum` 合理，`Reference clock ID` 指向配置的 NTP 服务器 IP。

```text
<H3C> display ntp-service sessions
```

期望结果：能看到与 NTP 服务器建立的会话，且源地址为对应分区的 NTP 服务器。
