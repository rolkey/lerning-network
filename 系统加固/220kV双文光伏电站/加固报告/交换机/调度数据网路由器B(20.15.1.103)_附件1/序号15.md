# 用户账号独立分配管理

## 问题

- "按照用户分配帐号，无不同用户间共享帐号。"

---

网络设备的管理账号是"谁登录、谁操作、谁负责"的凭证。如果多人共用一个 `admin` 账号，一旦出现误操作或安全事件，根本无法定位到具体责任人。本项要求为每个运维人员分配独立账号，杜绝账号共享，让每一次登录、每一条操作都能追溯到人。

### 🔍 风险原理

- **责任无法追溯**：共享账号意味着所有使用者的操作都记在同一个名字下，出现配置误删、越权操作或恶意行为时，无法判断是谁干的，审计形同虚设。
- **口令扩散失控**：共享账号的密码会在多人之间传递、抄录、口口相传，知道的人越多越容易泄露，且无法在人员离职时精准收回——改密码会影响所有仍在用的其他人，往往导致"干脆不改"。
- **越权风险**：共享账号通常只配一个最高权限，所有人（包括外包、临时人员）都拿到全权限，违背最小权限原则。
- **无法实施账号级管控**：账号共享后，无法针对个人做权限差异化、登录时间限制、密码过期等精细化管理，安全策略失去抓手。

### 配置/加固方法

在 H3C Comware V7 上，为每个使用者创建独立的 `local-user`，并按最小权限分配 `user-role`（角色）。

**1、为每个运维人员建立独立账号（示例两名）**

```text
<H3C> system-view
[H3C] local-user zhangsan class manage
[H3C-luser-manage-zhangsan] password cipher Zhang@2026
[H3C-luser-manage-zhangsan] service-type ssh
[H3C-luser-manage-zhangsan] authorization-attribute user-role network-operator
[H3C-luser-manage-zhangsan] quit

[H3C] local-user lisi class manage
[H3C-luser-manage-lisi] password cipher Li@2026
[H3C-luser-manage-lisi] service-type ssh
[H3C-luser-manage-lisi] authorization-attribute user-role network-admin
[H3C-luser-manage-lisi] quit
```

`network-operator` 为只读监控角色，`network-admin` 为管理角色。普通运维给 `network-operator`，只有需要下配置的负责人给 `network-admin`，体现"权限按人分配"。

**2、查看账号清单，确认无共享痕迹**

```text
<H3C> display local-user
```

逐条说明：账号名建议使用拼音或工号，做到"一人一号"；不同人员禁止使用同一账号名，也禁止给不同人发放同一账号密码。人员离职、转岗时应及时 `undo local-user <name>` 删除对应账号，而非改个密码继续共用。

### 特殊情况处理

- **特权账号也要实名化**：超级管理员账号如确需保留，也应一人一个（如 `admin-zhang`、`admin-li`），不要多人共用唯一的 `admin`。
- **角色权限要匹配职责**：不要图省事给所有人都发 `network-admin`，应按岗位分配角色；临时人员用完后立即删除账号。
- **与堡垒机联动**：若通过堡垒机统一跳转登录，设备本地账号可与堡垒机个人账号对应，实现"设备本地有独立账号、堡垒机有独立票据"的双层可追溯。
- **账号命名规范**：统一命名规则（如工号/拼音），避免随意命名导致后续对不上人。
- **删除默认账号**：厂商默认账号（如默认 `admin`）若未实名化，应修改或删除，防止成为共享入口。

### 📌 加固后的验证

```text
<H3C> display local-user
```

期望结果：列出的本地账号均为实名账号（与运维人员一一对应），不存在多人共用的通用账号。

```text
<H3C> display local-user verbose
```

期望结果：每个账号的 `User role` 与岗位权限匹配，`Service type` 限定为 `SSH`，`Password` 为密文存储。

补充核对：检查登录日志（`display logbuffer` 或日志服务器）中，登录记录的用户名各不相同，能对应到具体操作人员。
