# JBoss web-console / jmx-console 管理后台漏洞处置

## 问题

> 漏洞编号：调度20190626-001 —— JBOSS中间件管理后台web-console或jmx-console漏洞
>
> 加固方法：本次JBOSS的0day漏洞在JBOSS的管理后台，如web-console或jmx-console，在不影响业务的情况下，可直接删除内外网JBOSS中间件的管理后台的web-console.war或jmx-console.war。对象：JBOSS中间件

---

### 🔍 漏洞原理与风险

`web-console` 和 `jmx-console` 是 JBoss 自带的两个管理应用。`jmx-console` 通过 JMX 暴露 MBean 调用能力，其中部分 MBean 可以直接在服务器上执行命令、部署应用；`web-console` 提供类似的维护功能。

老版本 JBoss 的这两个控制台默认不需要认证，或者认证很弱。一旦从网络可达，就相当于把"远程管理 + 命令执行"直接开放给攻击者——不需要口令就能操作服务器，这是 JBoss 系列被长期利用的经典入口。本次作业定性为 0day 漏洞，处置结论很干脆：业务不依赖管理后台的，直接删掉部署包，从根上消灭入口。

### 处置/加固方法

第一步，确认管理后台是否可达。JBoss 默认端口为 8080，用浏览器访问：

```
http://XX.XX.XX.XX:8080/web-console
http://XX.XX.XX.XX:8080/jmx-console
```

能打开页面，就说明存在受影响面。

第二步，Linux 上定位部署包：

```bash
find / -name "web-console.war" 2>/dev/null
find / -name "jmx-console.war" 2>/dev/null
```

第三步，删除。作业给出的示例路径如下，实际路径以 find 结果为准：

```bash
rm /usr/ems/jboss/WEB-INF/web-console.war
rm /usr/ems/jboss/WEB-INF/jmx-console.war
```

删除后 JBoss 会检测到部署包移除并卸载应用，一般无需重启即生效；稳妥起见，按部署环境规范确认是否需要重启。

### 特殊情况处理

- 删除前确认业务确实不使用这两个控制台。`jmx-console` 偶尔被运维脚本调用，有依赖的话改成"限制来源 IP + 加认证"，而不是直接删。
- war 包所在目录下可能已解压出同名目录（`web-console/`、`jmx-console/`），要一并删除，否则 JBoss 可能用解压后的文件重新部署。
- 删除前先备份：`cp` 成 `.bak` 再删，需要回退时把 `.bak` 改回 `.war` 即可。
- 内外网环境都要处理，作业要求写的是"内外网JBOSS中间件"，别只处理了外网那台。

### 📌 处置后的验证

- 浏览器访问 `http://XX.XX.XX.XX:8080/web-console` 和 `http://XX.XX.XX.XX:8080/jmx-console`，返回不存在页面（404）即代表删除成功。
- 再次执行 `find / -name "web-console.war" 2>/dev/null` 和 `find / -name "jmx-console.war" 2>/dev/null`，应当无输出。
- 业务应用访问正常，JBoss 进程运行正常。
