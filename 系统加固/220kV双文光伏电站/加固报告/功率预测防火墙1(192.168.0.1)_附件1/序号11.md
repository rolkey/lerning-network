# 基于加密协议的远程管理（SSH/HTTPS）

## 问题

- "对于防火墙远程管理的配置，必须是基于加密的协议。如SSH或者HTTPS。"

---

防火墙是电力监控系统安全区的边界设备，管理通道承载的是设备配置、策略变更、账号口令等最高敏感级别的操作。如果管理流量以明文协议传输，等于把防火墙的"控制权钥匙"直接暴露在网络上。本作业项要求远程管理一律走加密通道——命令行用 SSH，图形界面用 HTTPS，彻底杜绝明文管理。这一条是所有后续管理类作业项（账号、口令、日志、源地址限制）的共同前提。

### 🔍 风险原理

- **口令被窃取**：明文协议（如 Telnet、HTTP）下，管理员输入的用户名、口令以及之后下发的每一条命令都以明文在链路上传输。任何人只要能在管理路径上抓包，就能完整还原整个登录和配置过程，直接获得防火墙的最高管理权限。
- **中间人篡改**：明文管理流量不仅可被窃听，还可被中间人篡改。攻击者可以在管理员不知情的情况下篡改下发的策略，例如悄悄放行某条高危端口，或注入一条"允许一切"的规则。
- **配置数据泄露**：导出的配置文件、策略内容、网络拓扑信息等一旦通过明文通道传输，会成为攻击者规划进一步渗透的"情报来源"。
- **合规硬性要求**：电力监控系统安全防护明确禁止使用明文协议管理网络设备，采用 SSH/HTTPS 是测评检查项，不满足会被直接判定不符合。

SSH 和 HTTPS 对整条会话进行加密并做身份校验，口令、命令和配置数据不再以明文出现在网络上，是远程管理安全的底线要求。

### 配置/加固方法

**1. 关闭明文管理协议，仅保留 SSH/HTTPS**

在「系统管理 → 管理方式 / 服务设置」中，禁用 Telnet、HTTP 等明文管理服务，仅启用 SSH（通常为 TCP/22）和 HTTPS（通常为 TCP/443），并可根据需要更换为非默认端口。

```text
操作路径（通用）：
系统管理 → 管理配置 → 管理服务
  [ ] Telnet        （禁用）
  [ ] HTTP  WebUI   （禁用）
  [√] SSH           （启用，建议改非默认端口）
  [√] HTTPS WebUI   （启用，建议改非默认端口）
```

**2. 升级 HTTPS 加密套件与证书**

```text
系统管理 → 证书管理 → 导入/生成设备证书 → 配置 TLS 版本与加密套件
建议：TLS 1.2 及以上；禁用弱加密套件（如 RC4、3DES、MD5 签名）；
使用合规 CA 签发的证书替换默认自签名证书，消除浏览器告警并防止中间人攻击。
```

**3. SSH 安全参数加固**

```text
系统管理 → SSH 配置：
  SSH 协议版本：仅 v2
  允许的认证方式：仅公钥/口令，禁用空口令
  登录失败限制：连续失败锁定
  会话空闲超时：与"账户登录超时"作业项一致
```

**4. 管理通道叠加访问控制**

```text
加密协议解决"传输安全"，还需叠加"谁能连"：
  配合"管理地址源限制"作业项，仅允许堡垒机等授权源访问；
  必要时将 SSH/HTTPS 端口改为非默认端口，降低被扫描发现概率。
```

### 特殊情况处理

- 若因运维习惯暂时无法完全关闭 Telnet/HTTP，应先在管理口接入交换机上做 ACL，仅允许堡垒机 IP 访问，作为临时过渡，同时限期整改到位。
- 修改 SSH/HTTPS 默认端口前，先同步更新堡垒机、态势感知等合法管理源的放行策略，避免改完端口后自己都连不上。
- HTTPS 使用自签名证书时浏览器会告警，属正常现象；正式投产应导入受信任证书，避免运维人员养成"忽略告警"的坏习惯。
- 部分老版本固件（3.2.x 早期）可能默认仅支持旧 TLS，升级固件后需重新核查加密套件配置。

### 📌 加固后的验证

```text
# 验证要点
1. 从受控终端用 SSH 客户端能正常登录防火墙命令行；
2. 浏览器以 https:// 访问 WebUI 能正常打开并显示证书锁图标；
3. 确认 Telnet/HTTP 端口已无监听或已被拒绝：
   在堡垒机上执行 telnet <防火墙IP> 23 应超时失败，
   curl http://<防火墙IP> 应无法建立明文连接；
4. 检查 TLS 版本与加密套件不含弱算法。
```

期望结果：仅 SSH、HTTPS 两种加密管理方式可用；Telnet/HTTP 明文通道已关闭；HTTPS 证书有效、TLS 版本满足要求。
