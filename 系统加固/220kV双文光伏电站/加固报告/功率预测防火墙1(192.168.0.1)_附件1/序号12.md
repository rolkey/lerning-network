# 防火墙管理地址源限制

## 问题

- "使用防火墙自身的限定功能，或在防火墙管理口的接入设备上设置ACL，仅允许堡垒机（I-II区1.1.1.5、1.1.1.6、III区3.1.1.5、3.1.1.6-7）、应用发布服务器（I-II区1.1.1.7、1.1.1.9，III区3.1.1.8、3.1.1.9）、态势感知服务器（I区1.1.1.3、II区2.1.1.3，III区3.1.1.3）访问SSH和HTTPS（webui）。"

---

防火墙的管理接口一旦全网可达，就等于把"大门"开在了任何一台主机面前——无论口令多强，都会暴露在扫描和暴力破解之下。本作业项的核心思路是"最小化暴露面"：把能够登录管理防火墙的源地址严格收敛到堡垒机、应用发布服务器、态势感知服务器这几类授权运维入口，其余主机一律拒绝访问 SSH 和 HTTPS 管理通道。

### 🔍 风险原理

- **暴露面过大**：如果管理口不限制源地址，安全区内任何一台被攻陷的主机都能直接尝试登录防火墙。攻击者拿下任意一台业务主机后，就能对防火墙发起暴力破解，进而控制整条安全边界。
- **暴力破解与扫描**：无源限制的 SSH/HTTPS 管理端口是扫描器和口令爆破工具的重点目标。即便口令复杂，持续的爆破也会带来日志噪音、账号锁定甚至服务资源消耗。
- **越权运维**：缺乏源限制无法区分"合法运维入口"与"普通业务终端"，任何终端都具备触碰防火墙的能力，不符合电力监控系统"分区分域、专机专用、最小权限"的管理要求。

通过源地址白名单，把管理通道收敛到少数受控运维入口，可大幅降低攻击面，也便于审计和溯源。

### 配置/加固方法

推荐采用"防火墙自身限定 + 管理口接入设备 ACL"双层防护。防火墙自带的"管理主机"或"可信主机"功能为第一道；管理口所接交换机上的 ACL 为第二道。

**1. 防火墙自身管理源地址限定**

```text
操作路径（通用）：
系统管理 → 管理配置 → 可信主机/管理源地址
  管理方式：SSH、HTTPS(WebUI)
  允许源地址（白名单）：
    I-II区  1.1.1.5、1.1.1.6       （堡垒机）
    I-II区  1.1.1.7、1.1.1.9       （应用发布服务器）
    I区     1.1.1.3                （态势感知）
    II区    2.1.1.3                （态势感知）
    III区   3.1.1.5、3.1.1.6-7     （堡垒机）
    III区   3.1.1.8、3.1.1.9       （应用发布服务器）
    III区   3.1.1.3                （态势感知）
  默认策略：拒绝（未命中白名单的主机一律拒绝）
```

**2. 管理口接入交换机 ACL（第二道防线）**

```text
# 逻辑示意（在管理口所接交换机/路由器上配置）：
# 仅允许白名单源 IP 访问防火墙管理地址的 22/443 端口
permit tcp host 1.1.1.5  host <防火墙管理IP> eq 22
permit tcp host 1.1.1.5  host <防火墙管理IP> eq 443
permit tcp host 1.1.1.6  host <防火墙管理IP> eq 22
permit tcp host 1.1.1.6  host <防火墙管理IP> eq 443
... （其余白名单主机同理逐条放行）
deny   tcp any           host <防火墙管理IP> eq 22
deny   tcp any           host <防火墙管理IP> eq 443
```

### 特殊情况处理

- 白名单 IP 一旦变化（如堡垒机迁移、态势感知扩容），必须同步更新防火墙和交换机两侧的清单，防止"新堡垒机连不上、旧 IP 还留着"。
- 配置"默认拒绝"前，务必先确认当前正在使用的管理终端 IP 已加入白名单，避免把自己锁在门外。
- 若防火墙自身不支持可信主机功能，可完全依赖管理口接入设备的 ACL 实现，但需确保该接入设备也受控、且 ACL 被正确下发。
- 带外管理（console 口）一般不受源限制影响，紧急排障时可作为"救生通道"，但 console 口也应物理受控。

### 📌 加固后的验证

```text
# 验证要点
1. 从白名单内主机（如堡垒机 1.1.1.5）SSH/HTTPS 登录防火墙，应正常；
2. 从白名单外任意主机（如某台普通业务机）尝试 SSH/HTTPS 登录，应连接被拒绝或超时；
3. 抽查交换机 ACL 命中计数，确认 deny 规则有实际命中，证明限流生效；
4. 核对白名单 IP 与作业项清单完全一致、无遗漏、无多余。
```

期望结果：仅作业项列出的堡垒机、应用发布服务器、态势感知服务器可访问防火墙 SSH 和 HTTPS，其余源地址均被拒绝。
