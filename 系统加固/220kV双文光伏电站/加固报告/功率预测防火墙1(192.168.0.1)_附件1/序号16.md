# 修改默认管理账号与默认口令

## 问题

- "修改默认管理账号（支持的情况下）、修改默认登录密码。（如天融信默认账号superman 密码talent或Talent@3389!）"

---

每款防火墙出厂时都带一套公开的默认账号和默认口令（如天融信早期型号默认账号 `superman`、密码 `talent` 或 `Talent@3389!`）。这些默认凭据在厂商手册、技术论坛、甚至攻击者字典库里都是公开信息。设备上线后若不修改，等于把"门钥匙"挂在了大门口，任何人照着说明书就能登录。本作业项要求在设备支持的前提下删除/改名默认账号，并强制修改默认口令。

### 🔍 风险原理

- **公开默认凭据**：默认账号口令是全网公开的，攻击者拿到 IP 后第一件事就是尝试厂商默认凭据，命中率极高，是防火墙被入侵最常见的入口之一。
- **应急处置失控**：默认账号往往拥有最高权限且无法被普通审计约束，一旦被外部控制，攻击者可以关闭防护、放行任意流量、删除日志，应急处置完全失控。
- **绕过口令策略**：部分默认超级账号不受复杂度、登录失败锁定等策略约束，成为"游离于策略之外"的后门账号。
- **长期潜伏隐患**：默认账号常被遗忘在设备里，即使业务上"没人用它"，也一直是一个可被利用的固定入口，且因无人关注而更难被发现。

删除或禁用默认账号、修改默认口令，是设备上电前就必须完成的第一项安全动作。

### 配置/加固方法

**1. 修改默认登录口令（必做）**

```text
操作路径（通用）：
系统管理 → 用户管理 → 选择默认账号（如 superman/admin）→ 修改口令
  新口令：满足"8位以上、含大小写+数字+特殊符号"的复杂度要求
  新口令严禁沿用厂商默认口令及常见弱口令
```

**2. 改名或禁用默认账号（设备支持时）**

```text
系统管理 → 用户管理：
  方案A（推荐）：新建一个自定义名称的管理员账号并授予管理员权限，
                然后删除或禁用默认账号 superman；
  方案B：设备不支持删除默认账号时，将默认账号改名（如 superman → mon_fw01）；
  方案C：设备连改名都不支持时，至少在 WebUI 中禁用该账号登录，
         并仅保留自定义管理员账号。
```

**3. 逐项排查其他默认凭据**

```text
除管理账号外，还需排查：
  WebUI 默认账号、console 口默认口令、SNMP 默认团体字 public/private、
  VPN 默认预共享密钥、出厂默认证书私钥口令等，
  全部按"默认即改"原则处理。
```

**4. 建立"默认凭据整改清单"并留档**

```text
逐项记录：设备型号、固件版本、默认账号、整改动作（删除/改名/禁用/改密）、
整改时间、验证结果，作为安全台账留存备查。
```

### 特殊情况处理

- 天融信早期默认账号 `superman` 常为超级账号，改名/删除前务必先确认已新建可用管理员账号，避免把自己锁死在门外。
- 部分固件版本重启后会恢复默认账号，改完应重启一次再验证，确保修改持久生效。
- 默认口令 `Talent@3389!` 这类"带符号的默认口令"容易给人"已经够强"的错觉，但它同样公开，必须修改，不能保留。
- 若设备确实不支持删除默认账号（极老型号），应通过管理源地址限制 + 堡垒机代登，把默认账号的可达性压到最低，同时做好台账记录推动替换设备。

- 默认账号整改完成后，应在设备台账中记录"默认账号已处置"及处置方式，作为审计佐证。
- 若设备经第三方集成商交付，需确认集成商未在设备中预留隐藏账号或后门口令。

- 整改后宜在设备台账中标记"默认凭据已处置"及处置日期，作为审计佐证。

### 📌 加固后的验证

```text
# 验证要点
1. 用原默认账号/默认口令登录，应失败；
2. 用改名后的账号或自定义管理员账号 + 新口令登录，应成功；
3. 在用户列表中确认默认账号已被删除、禁用或改名；
4. 重启设备后复验，默认账号未被恢复、新口令仍有效。
```

期望结果：默认管理账号已被删除/禁用/改名；默认口令已修改为满足复杂度要求的自定义强口令，且重启后修改仍生效。
