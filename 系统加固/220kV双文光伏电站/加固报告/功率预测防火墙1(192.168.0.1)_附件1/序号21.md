# 关闭不必要的网络服务

## 问题

- "禁用防火墙TELNET、FTP和HTTP服务。"

---

防火墙除了"转发过滤"这个本职外，还会内置一批用于管理或运维的附加服务，其中 Telnet、FTP、HTTP 这类明文服务既非必需、又存在严重安全隐患。开启它们不会带来任何业务收益，却凭空多出几个可被攻击的入口。本作业项要求把 Telnet、FTP、HTTP 这三个明文服务全部禁用，做到"最小化服务"。

### 🔍 风险原理

- **明文传输泄露凭据**：Telnet、FTP、HTTP 的登录口令、命令、配置数据全部明文传输，抓包即可窃取防火墙管理口令，与"基于加密协议管理"的要求直接冲突。
- **增加攻击面**：每一个开启的服务端口都是一个潜在漏洞入口。Telnet/FTP/HTTP 历史上爆出过大量漏洞（缓冲区溢出、目录穿越、弱认证等），多开一个就多一分风险。
- **服务冲突与资源浪费**：冗余服务占用连接数、进程资源，且可能与合规扫描产生告警（扫描器发现 23/21/80 端口开放即判定不合规）。
- **默认开启的隐患**：部分设备出厂默认开启这些明文服务，若上线前未排查，等于自带"后门"入网，且易被漏扫发现。

关闭不必要的服务，是从源头上"剪除"攻击面，符合最小化服务原则。

### 配置/加固方法

**1. 禁用 Telnet / FTP / HTTP 服务**

```text
操作路径（通用）：
系统管理 → 管理配置 → 管理服务 / 服务设置
  [ ] Telnet   （禁用）
  [ ] FTP      （禁用）
  [ ] HTTP     （禁用，WebUI 一律走 HTTPS）
  [√] SSH      （保留，作为命令行管理）
  [√] HTTPS    （保留，作为 Web 图形管理）
```

**2. 确认端口不再监听**

```text
配置完成后，管理口相关端口应为：
  TCP/22   （SSH，开放）
  TCP/443  （HTTPS，开放）
  TCP/23   （Telnet，关闭）
  TCP/21   （FTP，关闭）
  TCP/80   （HTTP，关闭）
```

**3. 巡检常态化**

```text
将"禁用 Telnet/FTP/HTTP"纳入日常巡检表，
防止固件升级、恢复出厂配置后默认服务被重新打开。
```

**4. 排查其他非必要服务**

```text
除 Telnet/FTP/HTTP 外，一并排查 TFTP、SNMP(旧版)、
调试端口等非业务必需服务，按最小化原则逐一关闭。
```

### 特殊情况处理

- 禁用 HTTP 前，先确认 WebUI 已配置好 HTTPS 并能正常访问，避免关闭 HTTP 后连图形界面都进不去。
- 某些老版本固件的 WebUI 可能强制依赖 HTTP 跳转，关闭前需确认 HTTPS 独立可用，必要时先升级固件。
- 若因兼容性确需临时保留 FTP（如旧版策略导入导出），应仅在变更窗口临时开启、用后即关，并走加密通道（SFTP）替代。
- 关闭服务后，同步检查"管理源地址限制"是否仍正确，两者叠加才能形成完整防护。

- 关闭非必要服务后，应同步在交换机 ACL 或防火墙策略中封堵对应端口，形成双重防护。
- 定期用端口扫描工具核查，确保关闭的服务不会因固件升级被重新打开。

- 关闭服务后，可在交换机/管理网 ACL 中再封一道对应端口，形成纵深防护。

- 关闭非必要服务后，端口扫描若仍发现残留监听，应排查是否有依赖服务自动拉起（如进程守护）。

### 📌 加固后的验证

```text
# 验证要点
1. 在堡垒机/受控终端执行端口探测：
   telnet <防火墙IP> 23   → 连接失败（已关闭）
   telnet <防火墙IP> 21   → 连接失败（已关闭）
   curl http://<防火墙IP>  → 无法建立明文连接
2. 确认 SSH(22)、HTTPS(443) 仍可正常登录；
3. 查看服务设置页，Telnet/FTP/HTTP 状态为禁用；
4. 重启设备后复验，服务未被恢复。
```

期望结果：Telnet、FTP、HTTP 三个明文服务已禁用，对应端口无监听；SSH、HTTPS 管理正常。
