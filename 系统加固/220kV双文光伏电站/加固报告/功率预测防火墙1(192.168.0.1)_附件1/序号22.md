# 使用 SNMP v3 管理并删除默认团体名

## 问题

- "使用SNMP V3以上的版本对防火墙做远程管理，更改SNMP主机IP。"
- "删除默认的public、private团体名。"

---

SNMP 用于对防火墙进行远程监控和集中网管，但 SNMP v1/v2c 的认证机制极其脆弱——它只依赖一个"团体名"（community string），而且默认团体名 `public`（只读）和 `private`（读写）是全网公开的。用 v1/v2c 且不删默认团体名，攻击者几乎可以"免密"读取甚至篡改设备配置。本作业项要求升级到 SNMP v3 并删除默认团体名，同时限定 SNMP 管理主机地址。

### 🔍 风险原理

- **默认团体名即公开密码**：`public`/`private` 是 SNMP 的行业默认值，几乎所有扫描器和攻击工具都会优先尝试。保留它们等于把设备信息（甚至写权限）拱手相送。
- **v1/v2c 明文且无加密**：SNMP v1/v2c 的团体名在网络中明文传输，可被窃听；v3 才支持基于用户名的认证（MD5/SHA）和加密（DES/AES），能有效防窃听、防篡改。
- **写权限可被滥用**：`private` 团体名拥有写权限，攻击者可通过 SNMP 下发配置修改，达到与登录管理界面等同甚至更隐蔽的控制效果。

SNMP 是网管必需，但必须是"安全的 SNMP"：v3 认证加密 + 删除默认团体名 + 限定管理主机。

### 配置/加固方法

**1. 禁用 v1/v2c，启用 SNMP v3**

```text
操作路径（通用）：
系统管理 → SNMP 配置：
  SNMP 版本：仅启用 v3（禁用 v1、v2c）
  v3 安全级别：authPriv（认证 + 加密，最高级别）
  v3 认证协议：SHA（或 MD5）
  v3 加密协议：AES（或 DES）
  v3 用户名/口令：自定义，满足复杂度要求
```

**2. 删除默认团体名**

```text
系统管理 → SNMP 配置 → 团体名/Community：
  删除 public（只读默认团体名）
  删除 private（读写默认团体名）
  确认列表中无任何默认团体名残留
```

**3. 更改 SNMP 管理主机 IP（限定 NMS 源地址）**

```text
系统管理 → SNMP 配置 → 访问控制 / 管理主机：
  仅允许网管平台（NMS）/态势感知的合法 IP 访问 SNMP，
  其余源地址一律拒绝 SNMP 请求。
```

```text
# 逻辑示意（通用，非厂商私有命令）
# 仅允许网管主机 1.1.1.3 以 SNMP v3 访问，拒绝其余来源
snmp-server host 1.1.1.3 version 3 authPriv <用户名>
no snmp-server community public
no snmp-server community private
```

### 特殊情况处理

- 迁移到 v3 前，先确认网管平台/态势感知已支持 SNMP v3 认证加密参数，并与设备配置一致，否则迁移后监控会中断。
- SNMP 的默认团体名有时不叫 public/private，也需排查厂商自定义的默认值（如厂商名、型号名等）。
- SNMP 端口 161/162 也应纳入管理源地址限制和防火墙自身 ACL，避免全网可达。
- 部分老网管平台只支持 v2c，此时应通过限定管理主机 IP + 加密隧道过渡，并限期推动平台升级到 v3。

### 📌 加固后的验证

```text
# 验证要点
1. 用 SNMP 工具以 v2c + public 团体名探测设备，应无响应（v2c 已禁用）；
2. 用 SNMP v3（authPriv）正确参数查询设备信息，应成功返回；
3. 查看 SNMP 配置，确认 v1/v2c 已禁用、public/private 已删除；
4. 从非授权 IP 发起 SNMP v3 查询，应被拒绝。
```

期望结果：SNMP 仅以 v3（认证+加密）方式管理；默认 public、private 团体名已删除；SNMP 管理主机地址已限定为合法网管 IP。
