# 拒绝高危漏洞端口与服务的访问

## 问题

- "以置顶黑名单对135、137、138、139、445、3389等高危端口进行双向策略封堵，并开启策略日志记录功能。"
- "在网络边界屏蔽常见漏洞端口TCP23,TCP4444,TCP593,TCP5000,TCP5554,TCP6667,TCP9996,udp1434,tftp UDP69，并开启策略日志记录功能。"

---

历史漏洞反复证明，135、137、139、445、3389 这类 Windows 系统端口，以及 4444、5554、6667 等与蠕虫、木马、远控密切相关的端口，是各类病毒和入侵最常用的通道。对于以国产化设备为主的电力监控网，这些端口基本没有业务需求，却屡屡成为攻击突破口。本作业项要求把这些高危端口纳入置顶黑名单，在边界双向封堵，并开启日志记录以留痕和告警。

### 🔍 风险原理

- **高危端口即攻击入口**：445（SMB）对应永恒之蓝等经典漏洞，135/137/138/139 是旧版 NetBIOS/SMB 服务，3389 是远程桌面，这些端口历史上爆发过大量可远程利用的严重漏洞。
- **木马与远控默认端口**：4444、5554、6667、5000、9996、593 等常被 Metasploit、各类 RAT 远控木马和蠕虫用作默认监听/回连端口，封堵它们能直接掐断大量恶意通信。
- **TFTP/1434 等被滥用**：TFTP（UDP69）用于无认证文件传输，SQL Server 1434（UDP）曾是 SQL Slammer 蠕虫的传播端口，都属于"业务用不上、攻击很爱用"的类型。

置顶黑名单保证"拒绝优先于放行"，双向封堵防止入站与出站两个方向被利用，日志记录则让每一次被拦截的尝试都留痕可查。

### 配置/加固方法

**1. 建立置顶黑名单（拒绝优先）**

```text
操作路径（通用）：
策略配置 → 访问控制 → 新建黑名单策略（置于规则列表最顶部）：
  动作：拒绝（Deny / Drop），双向（入站 + 出站）
  端口清单（高危 Windows 端口）：
    TCP 135、137、138、139、445、3389
  端口清单（常见漏洞/木马端口）：
    TCP 23、4444、593、5000、5554、6667、9996
    UDP 1434、69
  日志：开启策略日志记录
```

**2. 确保黑名单置顶、双向生效**

```text
关键点：
  黑名单策略必须"置顶"，先于任何业务放行策略匹配，
  防止被"允许 1.1.1.0/24 任意端口"之类的宽泛策略提前命中放行；
  同时勾选入站、出站两个方向，防止内网主机被反向利用（出站回连）。
```

**3. 开启策略日志并联动告警**

```text
为黑名单策略开启日志，并将命中日志外发至日志服务器/态势感知，
用于发现内部主机感染、攻击尝试等异常。
```

### 特殊情况处理

- 若个别业务确实需要使用清单内端口（如运维远程桌面 3389），应改走堡垒机+加密通道，并在白名单策略中精确到源/目的 IP，而非整体放行该端口。
- 137/138/139 端口在纯 TCP 规则下部分为 UDP（如 137/138 是 UDP），封堵时需按实际协议类型分别配置 TCP/UDP，避免漏封。
- 置顶黑名单会影响性能评估的准确性，但收益远大于开销，务必保证"置顶"而非沉底。
- 封堵后要观察是否有合法业务受影响（如某监控软件依赖 5000 端口），发现异常及时通过精确放行解决。

### 📌 加固后的验证

```text
# 验证要点
1. 从内部主机尝试访问外部（或外部访问内部）的 445、3389 等端口，应被拒绝；
2. 从外部扫描防火墙 135/137/138/139/445/3389，应全部不通；
3. 发起一次对黑名单端口的访问，确认日志中能查到"拒绝"记录；
4. 核对策略顺序：黑名单位于列表最顶部、双向生效、日志已开启。
```

期望结果：135、137、138、139、445、3389 及 23、4444、593、5000、5554、6667、9996、UDP1434、UDP69 等端口被置顶黑名单双向封堵，拒绝动作有日志记录。
