# 业务最小权限开放（双向策略）

## 问题

- "已配置双向策略，业务以最小权限开放ip地址及端口。"

---

防火墙策略配置最常见的错误就是"图省事"：为了业务能通，直接放行"any 到 any"或放行一大段 IP、一大片端口。这样业务是通了，攻击面也被放到了最大。本作业项要求所有业务策略都遵循最小权限原则——只放行业务真实需要的源 IP、目的 IP 和端口，且双向策略都要精确配置，做到"非必要不放行、放行必精确"。

### 🔍 风险原理

- **过度放行即漏洞**：一条 `allow any any` 或 `allow 1.1.1.0/24 任意端口` 的规则，等于把防火墙的隔离作用完全架空，攻击者只要进入该网段就能自由横移到任意目标。
- **横向渗透便利**：源地址范围过大、端口范围过大，会让被攻陷的单台主机拥有过宽的访问权限，成为攻击者横向渗透的跳板。
- **违背分区分域**：电力监控系统要求 I、II、III 区严格隔离、按需互通，宽泛策略会让安全区之间的边界形同虚设。
- **审计与运维负担**：宽泛规则让"谁该访问谁"变得模糊，既难审计、也难在变更时判断影响范围。

最小权限是安全架构的核心原则：每一条策略都要精确到"谁、访问谁、用哪个端口、走哪个方向"，宁缺毋滥。

### 配置/加固方法

**1. 梳理业务流量基线**

```text
逐业务梳理真实通信需求，形成"业务—源IP—目的IP—端口/协议—方向"清单：
  示例（IEC104 远动）：源 1.1.1.10 → 目的 2.1.1.20  TCP/2404  双向
  示例（文件摆渡）    ：源 1.1.1.7  → 目的 3.1.1.8   TCP/21(已改SFTP)  定向
```

**2. 按最小权限配置精确策略**

```text
操作路径（通用）：
策略配置 → 访问控制 → 新建策略（逐条精确）：
  源地址：精确到主机 IP 或最小必要网段（避免过大网段）
  目的地址：精确到主机 IP 或最小必要网段
  服务/端口：精确到具体端口，禁用"any/任意端口"
  方向：按业务实际方向配置（需要双向时才勾双向，避免无脑双向）
  动作：允许
  日志：按需开启
```

```text
# 反例（禁止）与正例（推荐）对照
# 反例：源 any → 目的 any → 服务 any → 允许   （过度放行）
# 正例：源 1.1.1.10 → 目的 2.1.1.20 → TCP/2404 → 允许
```

**3. 定期策略瘦身与复核**

```text
周期：每季度复核
动作：清理过期策略、收敛过宽网段/端口；
     对"any"类规则逐一审查，确认仍有业务必要性，否则收紧或删除。
```

**4. 建立策略—业务映射台账**

```text
每条策略关联到具体业务系统与责任人，
变更业务时同步更新策略与台账，避免出现"无主策略"和"僵尸规则"。
```

### 特殊情况处理

- 双向策略要谨慎：很多业务是"请求-响应"的单向发起，防火墙基于状态检测能自动放行回程流量，不必手动配两条，过度双向反而扩大暴露。
- 某些业务（如广播、组播、动态端口协议）确实需要较大范围时，应精确限定源/目的网段，并记录例外原因。
- 策略越细、条数越多，越要注意排序和性能，配合"最后一条显式拒绝"和"置顶黑名单"形成完整策略结构。
- 变更业务时先建新精确策略、验证通过后再删旧宽泛策略，避免"先删后建"导致业务中断。

- 新增业务上线时，应遵循"先最小权限上线、再按需逐步放行"的原则，杜绝一次放开。

- 策略上线前先在变更窗口验证连通性，确认放行范围精确无误后再正式生效。

### 📌 加固后的验证

```text
# 验证要点
1. 遍历访问规则列表，确认无 "any→any 任意端口" 类宽泛放行规则；
2. 抽查关键业务策略，源/目的 IP 与端口均精确、方向正确；
3. 用非授权 IP 访问某业务端口，应被拒绝；授权 IP 访问应正常；
4. 核对策略台账与设备实际策略一致，过期规则已清理。
```

期望结果：所有业务策略均按最小权限精确配置 IP 和端口，双向策略配置正确；无过度放行规则，业务最小化开放。
