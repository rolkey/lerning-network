# 加密装置日志服务器配置（对接态势感知）

## 问题

- "配置加密装置日志服务器ip为态势感知采集口ip"（作业结点）
- "配置加密装置日志服务器ip为态势感知采集口ip"（加固方法）

---

加密装置在日常运行中会产生大量日志：隧道协商、认证失败、策略命中、设备告警、登录操作等。这些日志如果只存在装置本地，值班人员根本看不到，出了安全问题也无从追溯。这项作业就是要把加密装置的日志服务器地址指到态势感知平台的采集口 IP，让装置的运行日志和安全事件实时上送到态势感知，纳入全站统一监控、集中审计和溯源分析。

### 🔍 风险原理

- **日志不上送，等于"盲人摸象"。** 加密装置是纵向边界的第一道闸门，隧道异常、非法接入、认证失败等关键安全事件都在这里发生。如果不配置日志服务器，这些事件只能登录设备本地翻看，值班和安防平台都无法实时感知，攻击或异常可能在无人知晓的情况下持续发生。
- **缺乏审计证据，事后无法溯源。** 一旦发生安全事件或业务故障，没有集中留存的日志，就无法还原"谁在什么时候做了什么操作"、"哪条隧道在何时异常"，难以定责和追溯，也无法满足电力监控系统对日志集中审计与留存的合规要求。
- **日志时间戳不准会毁掉溯源。** 日志集中后如果各设备时间不同步，态势感知平台上看到的事件顺序会错乱，关联分析（把加密装置异常和网络告警串起来）就无法进行，溯源价值大打折扣。

### 配置/加固方法

**1. 确认态势感知采集口 IP**

先向安防平台运维或项目负责人确认态势感知的日志采集口 IP 和接收端口（常见 syslog 为 UDP 514，具体以平台要求为准），确认加密装置与该采集口网络可达。

**2. 登录设备并进入日志配置**

通过本地串口/专用网口登录加密装置管理界面，找到"系统配置 / 日志配置 / Syslog 服务器"菜单。

**3. 配置日志服务器**

在日志服务器配置项中填入态势感知采集口 IP 和端口，并选择要上送的日志级别：

```
日志服务器地址   ：态势感知采集口IP
端口            ：514（UDP，按平台要求）
日志级别        ：信息 / 告警 / 安全事件（至少含安全事件与系统告警）
```

一般至少要上送安全事件和系统告警，运行信息可根据平台容量与需求酌情勾选。

**4. 保存并下发**

保存配置并下发到装置，确认链路可达。若加密装置与态势感知采集口不在同一网段或跨安全分区，需要同步放通相应的网络策略/路由。

**5. 确认时间同步**

日志上送前先核对装置时间，必要时配置 NTP 时间同步，保证日志时间戳与现场时间一致，否则态势感知侧看到的日志时间会偏差。

### 特殊情况处理

- 态势感知采集口 IP 与加密装置可能不在同一网段，需经路由可达或放通防火墙/加密通道策略，先做连通性测试（`ping`/`telnet 采集口IP 端口`）再确认。
- syslog 协议（UDP/TCP）和端口必须以态势感知平台为准，不要想当然默认 514；部分平台用 TCP 或自定义端口。
- 若装置日志量很大，注意日志级别的取舍，避免上送过多无关信息淹没关键告警。
- 加密装置时间与态势感知平台时间需同步，否则日志在平台上会错位；先对时再验证日志。

### 📌 加固后的验证

```bash
# 1. 本地连通性测试（在可达网段的运维机上执行）
ping 态势感知采集口IP
telnet 态势感知采集口IP 514

# 2. 触发一次测试事件（如在装置上登录一次），再到态势感知平台查看是否收到
```

期望结果：在态势感知平台上能看到该加密装置的日志上送；触发一次登录/操作后平台能实时收到对应日志；日志时间戳与现场时间一致，无时间偏差。
