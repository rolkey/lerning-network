# 加密装置登录口令登记与强度检查

## 问题

- "加密装置登录口令是否登记保存，并检查加密装置口令是否满足8位（字母+数字）"（作业结点）
- "做好加密装置登录口令登记保存，并检查加密装置口令是否满足8位（字母+数字）。若忘记加密装置密码，则联系对应厂家重置密码（不是重置加密装置）"（加固方法）

---

加密装置的登录口令是进入这台设备管理的唯一门禁。谁拿到了口令，谁就能改加密策略、关隧道、放明文，等于拿到了纵向边界的钥匙。这项作业要做两件事：一是检查口令强度是否达到"8 位、字母 + 数字"的底线要求，二是把口令正式登记保存、明确保管人，避免"设备越管越严，结果自己人都进不去"的尴尬局面。

### 🔍 风险原理

- **弱口令/默认口令极易被攻破。** 很多加密装置出厂带默认账号口令，若上线后未修改，或改成了"12345678"这类弱口令，攻击者通过口令猜测或暴力破解即可登录，进而篡改加密策略、放行明文通道，纵向边界失守。
- **口令无人登记，关键时刻进不去。** 口令只记在某个运维人员脑子里，人员一变动或遗忘，设备就"无人能进"。业务故障需要应急处置时，连设备都登录不了，只能干等厂家，延误恢复时间。
- **口令管理混乱导致泄露。** 多台装置共用同一口令、口令直接写在设备标签或随手贴的纸条上、放在无权限控制的文档里，都会大大增加口令外泄的风险，一旦泄露影响面覆盖多台设备。

### 配置/加固方法

**1. 检查当前口令强度**

登录设备，进入"用户/口令管理"界面，核对当前口令是否满足底线要求：

```
口令长度   ：≥ 8 位
字符构成   ：字母 + 数字（建议再叠加大小写与特殊字符）
是否默认   ：非厂商出厂默认口令
```

不满足的，立即修改。设置新口令时避免使用设备名、厂商名、工号、连续数字等易猜测内容。

**2. 修改/清除默认账号口令**

将厂方出厂默认的管理账号口令改掉；存在多余账号的（如调试临时账号）一并清理或禁用，只保留必要的管理账号。

**3. 口令登记保存**

把各台加密装置的口令正式登记进口令台账，明确保管人和保管方式：

- 纸质台账密封保存，或使用加密电子文档；
- 逐台记录：设备名称/型号、管理 IP、账号、口令（或口令的密级保管位置）、保管人、更新时间；
- 口令变更后同步更新台账，交接时当面核对。

**4. 明确"忘密码"的处置流程**

确认现场人员都清楚：**忘记密码时联系对应厂家重置密码，而不是复位/重置整台加密装置。** 整台装置复位会清空全部加密策略和隧道配置，导致业务大面积中断，代价远高于重置口令。

### 特殊情况处理

- 修改口令前先确认当前口令可正常登录，避免改完自己进不去；建议保留一个备用管理账号或临时会话再操作。
- 多台加密装置避免使用完全相同口令，至少区分主站侧与站内各台，缩小单一口令泄露的影响面。
- 口令台账属敏感资料，落实权限控制和更新机制，避免随手放在共享目录。
- 厂家重置密码通常需要现场或远程配合，可能涉及停机窗口，提前报备并协调时间；重置前先备份配置（见策略备份作业项）。

### 📌 加固后的验证

```bash
# 1. 用新口令登录设备，确认可正常登录
# 2. 核对口令长度 ≥ 8 位、含字母 + 数字
# 3. 确认口令已登记进台账，保管人明确
```

期望结果：使用新口令可正常登录设备；口令满足 8 位（字母 + 数字）的强度要求，且非默认口令；口令已登记保存、保管人明确；现场人员能正确说出"忘密码 → 联系厂家重置密码，而非重置整台加密装置"的处置流程。
