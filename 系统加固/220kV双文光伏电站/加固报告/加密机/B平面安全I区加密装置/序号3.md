# 加密装置策略检查与备份（策略最小化）

## 问题

- "已配置双向策略，业务以最小权限开放ip地址及端口。"（作业结点）
- "登录设备检查策略、并做好备份"（加固方法）

---

纵向加密认证装置（加密机）部署在厂站与调度数据网（地调/中调）之间的纵向边界上，靠"加密策略/隧道"决定哪些业务数据加密传输、哪些明文放行。策略是这台设备的核心配置，配错了或配宽了，纵向边界的安全屏障就形同虚设。这项作业的目的，就是登录设备把现有策略逐条核查一遍，确认只放开了业务必需的双向加密通道、IP 和端口都按最小权限开放，同时把当前配置完整备份下来，防止设备故障或误操作后无配置可恢复。

### 🔍 风险原理

- **策略过宽等于开洞。** 如果策略里把源/目的 IP 和端口全放开，或者开了不必要的"明文通"通道，相当于在调度数据网纵向边界上留了一个不加保护的口子。攻击者一旦从调度侧或站内网络横向摸进来，就能借用这些过宽策略绕过加密，直接访问不该访问的业务系统。
- **策略不对称会造成业务中断或明文泄露。** 纵向加密靠两端装置协商加密隧道，如果本端与对端（主站/对侧厂站）策略不匹配、算法不一致，隧道协商会失败，导致远动、AGC/AVC、保信等业务中断；如果误配成单方向或明文，则敏感调度数据可能在链路上裸奔。
- **没有备份，出问题只能"干瞪眼"。** 加密装置一旦整机故障、配置丢失或被误清空，如果没有一份可用的配置备份，重新配置需要人工逐条核对策略，耗时且极易出错，业务可能长时间停摆，而且很难证明配置"原本是什么样"。

### 配置/加固方法

**1. 登录设备**

通过本地串口（console）或专用网口，用厂商配套的配置管理软件（或 Web 管理界面）登录加密装置。登录前确认自己拿到的是管理账号，且操作不会影响正在运行的业务通道。

**2. 核查加密策略清单**

进入策略/隧道配置界面，逐条核对以下内容：

```
策略编号 / 名称       对端装置        本地IP:端口        对端IP:端口       模式       算法
─────────────────────────────────────────────────────────────────────────────────
001  主站-远动         地调加密机      198.120.1.x:xxxx   10.x.x.x:xxxx    双向加密   SM4/SM2
002  ...              ...            ...                ...              ...        ...
```

重点检查三点：

- **双向策略是否建立**：每一条业务通道都应是双向加密隧道，且本端与对端参数匹配；
- **IP、端口是否最小化**：只保留业务实际需要的源/目的 IP 和端口，多余的、测试遗留的、长期不用的策略一律标记待清理；
- **算法是否合规**：确认使用的是国密算法（SM1/SM2/SM3/SM4），而不是已不推荐或明文方式。

**3. 最小权限收口**

对发现的问题策略做处理：关闭多余端口、删除无用策略、停用非必要的"明文通"通道。涉及改动要提前报备并避开业务高峰，改动前后都截图留档。

**4. 备份配置**

在管理软件中选择"导出/备份配置"，把当前运行配置导出成本地文件（常见为 `.cfg` / `.dat` 等），并按"设备名 + 日期 + 版本"命名归档：

```bash
# 示例：按日期归档导出的配置备份文件（仅作归档管理，非设备命令）
mkdir -p 加密装置配置备份/2026-10-01
cp 加密机导出配置.cfg 加密装置配置备份/2026-10-01/双文加密机_20261001.cfg
```

备份文件应存放于受控目录，并登记在台账中，明确谁在什么时候备份的。

### 特殊情况处理

- 不同厂家的加密装置（南瑞、科东、东土等）配置界面和策略字段叫法不完全一样，核对时以"隧道/策略/密通/明文通"等对应功能为准，不要死抠字面。
- 策略备份文件通常与设备型号、软件版本强绑定，跨版本导入可能失败；备份时记下设备型号和软件版本号。
- 明文通通道只保留确需的（如个别远动、保信业务），其余一律关闭；关闭前务必确认对应业务真的不需要明文。
- 修改策略属于影响业务的变更，尽量安排在检修窗口，并提前与主站/调度沟通，避免误伤在运业务。

### 📌 加固后的验证

```bash
# 1. 核对策略清单与业务台账一致，无多余 IP / 端口
# 2. 确认各双向隧道协商正常，无"协商失败/告警"
# 3. 确认配置文件已导出并归档
ls -l 加密装置配置备份/2026-10-01/
```

期望结果：策略清单与业务台账一一对应，业务以最小权限开放 IP 和端口，无多余策略与明文通通道；双向加密隧道状态正常；当前配置已完整备份并妥善归档、可随时用于恢复。
