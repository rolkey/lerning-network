# 限制流量与连接数以抵御 DoS/DDoS 攻击

## 问题

- "配置DOS和DDOS攻击告警，限制网络最大流量数及网络连接数，能抵御异常攻击。"

---

拒绝服务（DoS/DDoS）攻击通过海量请求耗尽防火墙的连接表、带宽或 CPU，使其无法处理正常业务。电力监控网一旦被 DDoS 拖垮，监控数据中断、调度指令无法下发，后果严重。本作业项要求配置 DoS/DDoS 攻击防护与告警，并限制最大流量和连接数，确保设备在异常流量冲击下仍能维持核心业务，同时触发告警以便及时处置。

### 🔍 风险原理

- **连接表耗尽**：每个会话都要占用防火墙连接表项，SYN Flood 等攻击用大量半开连接快速耗尽表项，导致合法业务无法建立新连接。
- **带宽与资源耗尽**：UDP Flood、ICMP Flood 直接打满带宽或 CPU，设备处理能力被占满后丢包甚至重启。
- **无告警则无响应**：只有防护没有告警，攻击发生时运维人员毫不知情，无法及时联动清洗和溯源。
- **业务连带中断**：监控采集、调度指令等关键流量与攻击流量混在一起，若无优先级保护，业务会被一并淹没。

通过"连接数/速率阈值 + 攻击检测 + 告警"三层防护，让防火墙在异常流量下能自我限流、优先保业务，并及时通知运维。

### 配置/加固方法

**1. 开启 DoS/DDoS 攻击防护**

```text
操作路径（通用）：
安全防护 → 攻击防护 / DoS 防护：
  开启 SYN Flood 防护（半开连接阈值、SYN 速率限制）
  开启 UDP Flood 防护、ICMP Flood 防护
  开启 Land 攻击、Smurf 攻击、Teardrop 等畸形包防护
  告警：开启，触发阈值即告警并记录日志
```

**2. 限制最大流量数与连接数**

```text
安全防护 → 流量管理 / 连接限制：
  单源 IP 最大并发连接数：限制（如 500~2000，按业务评估）
  单源 IP 新建连接速率：限制（如每秒 100~500）
  单目的 IP 最大连接数：限制，防止针对某服务器的连接耗尽
  整机最大会话数：设为硬件规格内的合理上限，预留冗余
```

```text
# 逻辑示意（通用，非厂商私有命令）
# 限制单源并发连接与新建速率，超出即告警/丢弃
set connection-limit per-source 1000
set connection-rate-limit per-source 300
alarm dos-flood enable
```

**3. 设置阈值告警与联动**

```text
为 CPU、内存、连接表占用率设置告警阈值（如 80%），
并将攻击告警外发至态势感知/日志服务器，实现联动处置。
```

**4. 建立流量基线**

```text
采集正常时段的连接数、带宽、新建速率基线，
据此设定合理阈值，使防护既不过度误杀、又不漏报攻击。
```

### 特殊情况处理

- 阈值设置要基于真实业务流量基线，过低会误杀正常业务（如大文件传输、批量采集），过高则起不到防护作用，需结合实际调优。
- DDoS 防护是"缓解"而非"根治"，超大流量攻击最终仍需上游运营商/清洗设备配合，防火墙只负责第一道限流和告警。
- 连接数限制可能影响正常的批量轮询采集（如大量 RTU 同时上报），要评估业务峰值后再定阈值。
- 开启 SYN Flood 防护前，确认业务端是否有大量合法长连接，避免误判为攻击。

- 防护阈值调优应在变更窗口进行，并记录调优前后的基线数据，便于回溯。

### 📌 加固后的验证

```text
# 验证要点
1. 查看防护配置，确认 SYN/UDP/ICMP Flood 防护及畸形包防护已开启，告警已启用；
2. 查看连接限制配置，单源连接数、新建速率、整机会话上限均已设置；
3. 用压测工具（受控环境下）发起 SYN Flood，确认防火墙触发防护并产生告警日志；
4. 触发攻击时核心业务（如 IEC104 通道）仍可连通，证明限流保护生效。
```

期望结果：DoS/DDoS 攻击防护与告警已开启；最大流量数、连接数限制已配置；异常攻击能被抑制并产生告警，核心业务不受影响。
