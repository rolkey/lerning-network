# Apache Axis 远程管理功能禁用

## 问题

> 漏洞编号：调度20190617-001 —— Apache axis漏洞
>
> 加固方法：对使用了Apache axis的服务器采用以下策略：1.禁用AXIS远程管理功能，通过修改AXIS目录下WEB-INF文件夹中的server-config.wsdd文件，将其中"enableRemoteAdmin"的值设置为false。

---

### 🔍 漏洞原理与风险

Apache Axis 是早期的 Java Web Services 框架，很多老系统拿它对外提供 SOAP 接口。Axis 自带一个"远程管理"（remote admin）能力，`server-config.wsdd` 里的 `enableRemoteAdmin` 就是它的开关。

这个开关默认是打开的。开着的时候，任何能访问到服务地址的人，都可以远程对 Axis 引擎做管理操作——注册服务、卸载服务、改部署配置，等于把服务端的配置能力直接暴露在网络上。Axis 系列的攻击面里，远程管理入口是长期被盯上的一个点：先通过它摸清部署结构，再配合其他利用手段扩大权限。业务系统发布好的 SOAP 服务根本不需要这个入口，正确做法就是关掉它。

### 处置/加固方法

第一步，定位 `server-config.wsdd` 文件：

```bash
find / -name server-config.wsdd 2>/dev/null
```

没有输出，说明这台主机没用到 Axis，不涉及此问题。

第二步，备份后修改：

```bash
cd <server-config.wsdd 所在目录>
cp server-config.wsdd server-config.wsdd.bak
vim server-config.wsdd
```

将其中 `enableRemoteAdmin` 的值修改为 `false`：

```xml
<parameter name="enableRemoteAdmin" value="false"/>
```

第三步，重启承载 Axis 的应用服务（WebLogic / Tomcat 等，按实际部署环境执行），让配置生效。

### 特殊情况处理

- 一台主机上可能部署了多个 Axis 实例（每个应用各带一份 `server-config.wsdd`），find 返回多少处就改多少处，别漏。
- 改之前必须备份（作业也是这么要求的）。wsdd 是 Axis 的部署描述文件，改错格式会导致服务起不来，出问题拿 `.bak` 回退。
- 禁用远程管理后，以后改部署只能直接改文件再重启，对正常业务没有影响。
- 如果确实需要保留管理能力（极少见），至少要在网络侧限制来源 IP，不能对全网开放。

### 📌 处置后的验证

- `grep -i enableRemoteAdmin server-config.wsdd`，确认值为 `false`。
- 重启后服务日志无报错，业务侧 SOAP 接口调用正常。
- 尝试访问 Axis 的远程管理入口（AdminServlet 相关路径），应当提示无法访问或页面不存在。
