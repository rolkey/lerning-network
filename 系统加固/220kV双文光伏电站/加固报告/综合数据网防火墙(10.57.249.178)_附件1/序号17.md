# 账户登录超时自动登出

## 问题

- "配置定时帐户自动登出，空闲5分钟自动登出。"

---

运维人员登录防火墙后，常常因为临时离开、被其他事务打断而忘记退出，登录会话就一直挂在管理界面上。如果这个终端处在半开放的运维环境里，任何靠近该终端的人都能"顺手"继续操作。本作业项要求配置空闲超时自动登出：管理会话连续空闲 5 分钟即自动断开，杜绝"人走会话还在"的隐患。

### 🔍 风险原理

- **会话劫持/冒用**：管理员离开终端后，未关闭的 WebUI 或 SSH 会话就是一台"免认证"的操作入口，任何能接触到该终端（包括通过投屏、共享桌面、或直接走到工位前）的人都能以管理员身份继续操作。
- **无人值守的长期连接**：长期保持的 SSH 会话若被中间人接管或终端被植入远控，攻击者可持续复用这条已认证通道，无需再次爆破口令。
- **资源占用与合规**：大量不关闭的空闲会话占用设备会话资源，也违反电力监控系统"操作完毕及时退出"的运维规范，审计时难以解释"凌晨为何还有活跃会话"。
- **应急响应盲区**：管理员离开时留下的活跃会话，可能被内部别有用心者用来做越权操作，而日志却显示"是管理员自己干的"，混淆了责任。

空闲自动登出是一种"兜底"机制：即使管理员疏忽，系统也会在 5 分钟后自动切断会话。

### 配置/加固方法

**1. 配置 WebUI 会话空闲超时**

```text
操作路径（通用）：
系统管理 → 管理配置 → Web管理 / 会话设置
  会话空闲超时时间：5 分钟（300 秒）
  开启"超时后强制重新认证"
  会话并发数限制：按需设置（可选）
```

**2. 配置 SSH 会话空闲超时**

```text
系统管理 → 管理配置 → SSH 配置：
  空闲超时：300 秒（5 分钟）
  （部分设备对应 CLI 逻辑示意，非厂商私有命令）
  # 逻辑示意：设置 SSH 会话空闲超时为 300 秒
  set ssh idle-timeout 300
```

**3. 配置 console 口空闲超时（可选增强）**

```text
console 口同样应设置空闲自动登出，防止带外管理终端无人值守时被冒用。
```

**4. 统一各管理入口超时策略**

```text
WebUI、SSH、console 三处的空闲超时应保持一致（均 5 分钟），
避免出现"WebUI 已超时、SSH 却可长期挂起"的不一致漏洞。
```

### 特殊情况处理

- 超时时间不宜过短：过短（如 1 分钟）会导致正常阅读文档、比对策略时被频繁踢出，影响运维效率，5 分钟是经验平衡点。
- 自动登出会中断正在进行但未保存的配置操作，配置复杂策略时建议养成"边配边存、定期保存"的习惯，避免超时丢配置。
- 部分设备区分"空闲超时"与"会话绝对超时"，两者含义不同：空闲超时指无操作即断，绝对超时指登录后到点必断，按需分别配置。
- 态势感知、日志平台等通过 API/SNMP 长连接接入的设备会话，需确认自动登出不会误伤这些合法常驻连接。

- 自动登出后，未保存的配置会丢失，重要变更操作应分段保存，避免超时中断前功尽弃。
- 多管理员协作排障时，会话并发数限制可能导致后登录者把先登录者踢下线，需评估并发上限。
- 可开启自动登出事件记录（可选），用于发现异常的空闲会话行为。

- 会话超时与登录失败锁定是两套机制，宜一并配置：空闲 5 分钟登出 + 连续失败锁定，共同抵御会话劫持与暴力破解。

- 自动登出后的会话状态应彻底释放（而非仅前端隐藏），确保连接表项、会话资源同步回收。

- 配置自动登出后，应告知全体运维人员养成"离开即锁屏、操作完即退出"的习惯，自动登出只是兜底，不能替代人的主动防范。

### 📌 加固后的验证

```text
# 验证要点
1. 登录 WebUI 后不做任何操作，等待约 5 分钟，会话应自动断开并跳回登录页；
2. 建立 SSH 会话后静置，5 分钟空闲后连接应被自动关闭；
3. 空闲期间（如 3 分钟）随意点几下，会话应保持，证明是"空闲"而非"固定时长"触发；
4. 确认自动登出后需重新输入口令才能再次进入。
```

期望结果：WebUI 和 SSH 会话空闲 5 分钟即自动登出；重新操作需再次认证；空闲判定准确、不影响正常连续操作。
