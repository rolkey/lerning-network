# umask 设置：控制用户缺省文件权限为 022

## 问题

- "控制用户缺省访问权限UMASK为022"
- 加固方法："vi /etc/profile 设置 umask 为 022。控制用户缺省访问权限，当在创建新文件或目录时，屏蔽掉新文件或目录不应有的访问允许权限。防止同属于该组的其它用户及别的组的用户修改该用户的文件或更高限制"

---

umask 管的是"新建出来的东西默认给多少权限"。很多系统漏洞不是配置写错了，而是新文件默认权限太宽，谁都能碰。把 umask 定成 022，新建文件默认 644、目录默认 755，从根上避免越权修改。

### 🔍 风险原理

Linux 下新建文件默认权限是 666，新建目录是 777，umask 就是从这个默认值里"抠掉"的位。以 022 为例：

- 文件：`666 - 022 = 644`，即 `rw-r--r--`（属主读写，组和其他人只读）
- 目录：`777 - 022 = 755`，即 `rwxr-xr-x`（属主全权，其他人可进可读）

如果 umask 是 000 或 002，新建文件会带组写甚至其他写权限——同组的用户、甚至任意用户都能改你的文件。在 AGC/AVC 这类机器上，普通运维账号生成一个组可写的配置或脚本，就可能被同组账号（或被攻陷的同组账号）篡改后执行，形成提权路径。umask 022 让"默认不给写权限"成为常态，谁要共享再单独授权。

### 配置加固方法

源数据做法：在 `/etc/profile` 中设置全局 umask：

```bash
vi /etc/profile
# 添加或修改：
umask 022
```

凝思 Linx 6.0 有个细节：登录 shell 的 umask 由 `/etc/profile` 和 `/etc/bashrc` 共同作用，后者里的 `umask` 语句会覆盖前者。凝思 Linx 6.0 默认在 `/etc/bashrc` 里给普通用户 002、root 022。要让所有用户统一成 022，两处都改，或干脆放一个独立脚本：

```bash
# 1) 修改 /etc/bashrc 中的 umask 为 022（找到 umask 002 的行改掉）
vi /etc/bashrc

# 2) 用 profile.d 脚本统一兜底（对 bash 及多数兼容 shell 生效）
echo "umask 022" > /etc/profile.d/umask.sh
chmod 644 /etc/profile.d/umask.sh

# 3) 修改后重新登录生效（或 source /etc/profile 临时生效）
```

改完的配置只对**之后新登录的会话**生效，正在运行的会话不会变，验证时记得开新连接。

### 特殊情况处理

- 022 是安全与协作的平衡点。要更严可以用 027（组权限也抠掉）甚至 077（只有属主能碰），适合服务账号；但全局改太严会打断依赖共享目录的业务，别激进。
- 共享项目目录需要组写权限时，不要靠放宽全局 umask 解决。正确做法是目录设 `setgid`（`chmod 2775`），让目录内新建文件自动继承组，权限控制粒度保持在目录级。
- umask 只管新建，历史遗留的宽权限文件不受影响。需要治理时用 `find / -perm -002 -type f` 之类的命令排查后逐个 `chmod` 收权。
- 部分服务（如某些数据库）有自己的 umask 设置，改动全局配置后要观察业务生成的文件权限是否异常。

### 📌 加固后的验证

```bash
# 1) 当前会话的 umask 值（新登录后查看）
umask
# 期望：0022

# 2) 配置文件检查
grep umask /etc/profile /etc/bashrc /etc/profile.d/umask.sh
# 期望：相关位置均为 022

# 3) 实际新建文件/目录验证（务必新开登录会话后执行）
touch /tmp/umask_check_file
ls -l /tmp/umask_check_file
# 期望：-rw-r--r--（644）
mkdir /tmp/umask_check_dir
ls -ld /tmp/umask_check_dir
# 期望：drwxr-xr-x（755）
rm -rf /tmp/umask_check_file /tmp/umask_check_dir
```

第 3 条的实际结果和期望一致，说明缺省权限已经收敛到 022。
