# Root 操作历史记录长度的限制

## 问题

- "减少root用户输入命令的历史记录长度，保留最新执行的5条命令"

---

B23 这一项要求把 root 的 shell 历史记录压到只保留最近 5 条。做法就一行配置：改 `/etc/profile` 里的 `HISTSIZE=5`。背后的考虑不是性能，而是敏感信息残留。

### 🔍 风险原理

bash 会把敲过的命令记在内存里，退出时写入历史文件——root 的历史文件是 `/root/.bash_history`，默认可以记上千条（凝思 Linx 6.0 默认 `HISTSIZE=1000`）。

这个文件的风险在于：

1. **口令残留**。管理员在命令行里直接带密码操作的情况很常见：`mysql -uroot -p'123456'`、`smbclient //host/share -Uadmin%pass`、`curl -u user:pass ...`。这些命令原样躺在 `.bash_history` 里，任何拿到 root 权限（哪怕是一次性的）的攻击者，翻一下历史文件就能收集一堆凭据，横向移动的素材就齐了。
2. **运维痕迹泄露**。历史记录会暴露系统的部署结构、内网 IP、习惯用的脚本路径，对攻击者来说是不花钱的侦察报告。
3. **误操作放大**。历史里如果存着几百条旧命令，管理员用 `history` 找旧命令时也更容易敲错带破坏性的那一条。

对调度发令系统这类生产控制大区的主机来说，root 的历史本来就不该长期沉淀，保留 5 条足够应付"刚才那条命令再跑一次"的场景，剩下的全部不留。

### 配置加固方法

按源表的方法，编辑全局 profile：

```bash
vi /etc/profile
```

找到 `HISTSIZE=` 那一行（默认一般是 `HISTSIZE=1000`），改成：

```bash
HISTSIZE=5
```

保存退出后，让配置生效：

```bash
source /etc/profile
```

说明几点：

- 改 `/etc/profile` 是对**所有用户**生效的全局配置。如果只想收紧 root 一个账号，改 `/root/.bashrc` 或 `/root/.bash_profile` 里同名的变量即可，两条路都算满足 B23 的要求。
- `source /etc/profile` 只影响当前这个终端会话。已经开着的其它终端不会自动刷新，新开的终端才会读到新值。最稳妥的做法是改完退出重新登录 root 一次。
- 只改 `HISTSIZE` 影响的是**当前会话内存里**保留的条数。历史文件落盘的大小由 `HISTFILESIZE` 控制，两个变量在多数发行版里是分开的。

### 特殊情况处理

- 如果现场要更彻底——连那 5 条也不想落盘，可以在 root 的 `.bashrc` 里加 `unset HISTFILE`（不写历史文件）或 `HISTCONTROL=ignorespace`（以空格开头的命令不记录）。这些属于加分项，源表只要求 `HISTSIZE=5`，按表做即可。
- 改完之后，`/root/.bash_history` 里**已有的旧记录不会被自动清掉**。需要在本次加固时手动清一次：

```bash
> /root/.bash_history
```

- 用 `set +o history` 可以临时关掉当前会话的历史记录，适合执行完带密码的命令之后现场清理，但这不属于配置项，退会话即失效。

### 📌 加固后的验证

新开一个 root 终端，执行：

```bash
echo $HISTSIZE
```

期望输出 `5`。

再执行：

```bash
history
```

连续敲几条 `echo` 测试命令后再看，列表中最多只保留最近的 5 条。如果 `echo $HISTSIZE` 还是 1000，说明改的不是当前 shell 实际加载的配置文件，回头检查 `/etc/profile`、`/root/.bashrc`、`/root/.bash_profile` 三处的 `HISTSIZE` 取值。
