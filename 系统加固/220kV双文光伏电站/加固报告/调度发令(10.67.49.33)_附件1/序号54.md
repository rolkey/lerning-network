# Firefox 浏览器远程代码执行漏洞

## 问题

- "漏洞名称：Firefox远程代码执行漏洞
  【内容】对使用了Firefox浏览器的服务器采用以下策略：
  1.卸载所有低于Firefox 67.0.3 和Firefox ESR 60.7.1的所有平台的版本，或者升级到最新的67.0.4
  【对象】Firefox浏览器"

---

服务器上装浏览器这件事本身就不该有，但不少运维机器上确实装着 Firefox，用来下载补丁、查资料。这条通报针对的就是它：低版本 Firefox 存在远程代码执行漏洞，而且是当时已经在野外被实际利用的那种。

### 🔍 漏洞原理与风险

**风险原理**：低于 67.0.3（ESR 通道低于 60.7.1）的 Firefox 在处理某些网页内容时存在类型混淆缺陷。攻击者构造一个恶意网页，用户只要打开它，攻击者的代码就能在用户权限下执行。不需要点击"允许"，不需要下载文件，打开页面即中招。

**为什么服务器上的浏览器更危险**：运维人员通常用 root 或高权限账号登录服务器，再用上面的 Firefox 访问互联网。一旦浏览到被挂马的页面，等于把服务器最高权限直接送到攻击者手里。对 AGC/AVC 这类生产系统，浏览器既不是业务组件，也没有任何不可替代性——最干净的整改就是卸载。

### 处置/加固方法

按源数据的策略执行：卸载低于 67.0.3 / ESR 60.7.1 的版本，或者升级到 67.0.4 以上。

```bash
# 1. 查看系统里是否装有 Firefox，以及版本号
rpm -qa | grep -i firefox
firefox --version

# 2a. 推荐做法：直接卸载（服务器没有保留浏览器的理由）
yum -y remove firefox

# 2b. 如果确有保留需要，升级到修复版本
yum -y update firefox
# 升级后确认版本 ≥ 67.0.4（ESR 通道 ≥ 60.7.1）
```

Debian/Ubuntu 系对应操作是 `apt-get remove firefox` 或 `apt-get install --only-upgrade firefox-esr`，思路一样：要么卸载，要么升到修复版本以上。

### 特殊情况处理

- 如果厂家的某些监控页面只能兼容老版 Firefox：把浏览需求挪到独立的维护专用电脑上，服务器上不装。别在服务器里保留旧版浏览器"将就着用"，这正是这条通报要堵的洞。
- 有些国产化系统自带定制版浏览器，包名不一定是 `firefox`，卸载前用 `rpm -qa | grep -i -E 'firefox|browser'` 排查一遍。
- 卸载 Firefox 不影响 AGC/AVC 业务本身，也不影响 `wget`、`curl` 这类命令行下载工具，日常补丁下载照常可用。

### 📌 处置后的验证

```bash
# 卸载方案：应当查不到任何 Firefox 包
rpm -qa | grep -i firefox
# 期望：无输出

which firefox
# 期望：提示命令不存在

# 升级方案：确认版本已过修复线
firefox --version
# 期望：≥ 67.0.4，ESR 通道 ≥ 60.7.1
```
