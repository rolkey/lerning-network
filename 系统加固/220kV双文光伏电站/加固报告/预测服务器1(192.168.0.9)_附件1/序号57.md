# Oracle WebLogic 远程代码执行漏洞（CVE-2020-2798/2801/2828/2867）

## 问题

- "WebLogic是美国Oracle公司出品的一个application server，确切的说是一个基于JAVAEE架构的中间件，WebLogic是用于开发、集成、部署和管理大型分布式Web应用、网络应用和数据库应用的Java应用服务器。将Java的动态功能和Java Enterprise标准的安全性引入大型网络应用的开发、集成、部署和管理之中。
  攻击者可利用漏洞实现远程代码执行。"

---

这批 CVE 是 Oracle 2020 年 4 月关键补丁更新（CPU）集中修复的 WebLogic 远程代码执行漏洞，四个编号合起来覆盖多个组件，其中大部分不需要认证就能利用。电力行业不少信息子站、数据采集系统用的是 WebLogic，一旦被拿下，整台服务器连同上面的数据都保不住。

### 🔍 漏洞原理与风险

**风险原理**：WebLogic 对外暴露的不只是 HTTP（默认 7001 端口），还有 T3、IIOP 等私有协议通道。这些协议为了支持 Java 对象跨 JVM 传输，内置了序列化/反序列化机制。这批漏洞的利用方式，多是向这些通道发送构造好的序列化对象，服务端反序列化时触发恶意代码执行。部分漏洞只需一个特制请求、无需任何凭据，就能以 WebLogic 进程权限（通常就是 root 或管理员）执行任意命令。

**可能后果**：服务器完全沦陷——攻击者可以植入后门、横向探测整个站内网络、窃取生产数据。WebLogic 权限高、位于核心网段，非常适合被当跳板。

### 处置/加固方法

先确认版本，落在影响范围内就打补丁或升级。查看 WebLogic 版本的常用方式：

```bash
# 进入 WebLogic 安装目录（常见如 /u01/app/oracle/middleware、/home/weblogic/Oracle/Middleware）
cd $MW_HOME/wlserver/server/lib
java -cp weblogic.jar weblogic.version
# 输出中可看到 "WebLogic Server ... 12.2.1.4.0" 之类的版本号
```

受影响版本（源数据）：

- Oracle WebLogic Server 10.3.6.0.0
- Oracle WebLogic Server 12.1.3.0.0
- Oracle WebLogic Server 12.2.1.3.0
- Oracle WebLogic Server 12.2.1.4.0
- Oracle WebLogic Server 14.1.1.0.0

如果当前版本在影响范围内，及时进行更新。WebLogic 12.2.1.4 官方下载地址：

`https://www.oracle.com/middleware/technologies/weblogic-server-downloads.html`

从 Oracle 官方获取对应版本的 CPU 补丁（Patch Set Update）并按补丁说明安装；或直接升级到包含修复的版本。打补丁前备份整个 domain 目录（`$MW_HOME/user_projects/domains/`）。

### 特殊情况处理

- 补丁需要停机窗口，业务上先排检修计划。生产系统打补丁前务必先导出备份并在备用环境演练一遍——WebLogic 补丁打坏导致 domain 起不来的事故不少见。
- **临时缓解**：在防火墙/主机层面把 7001 等端口收紧到仅内网维护网段可访问；若业务不依赖 T3/IIOP 协议，在控制台关闭对应协议通道（不同 CVE 的缓解配置略有差异，以 Oracle 官方公告为准）。缓解只能挡一时，最终仍以补丁/升级为准。
- WebLogic 如果是厂家随系统交付的，先和厂家确认补丁版本和兼容性，不要用非官方渠道的补丁包。

### 📌 处置后的验证

```bash
# 1. 版本验证：确认已不在受影响清单内（或已应用 CPU 补丁）
cd $MW_HOME/wlserver/server/lib
java -cp weblogic.jar weblogic.version

# 2. 服务验证：确认端口监听正常
ss -lntp | grep java
# 期望：7001/7002 正常监听

# 3. 功能验证：重启后 console 页面能登录，业务应用正常
```

补丁或升级完成后，让厂家或业务方做一次完整的功能确认；防火墙收紧策略建议保留，遵循最小开放原则。
