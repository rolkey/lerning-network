如果你想直接在交换机的命令行界面（CLI）中逐条输入命令来修改配置，可以在 **系统视图** 下依次执行以下命令：

```text
<SW1> system-view
[SW1] dhcp enable
[SW1] dhcp snooping enable

[SW1] vlan 10
[SW1-vlan10] dhcp snooping enable
[SW1-vlan10] quit

[SW1] vlan 20
[SW1-vlan20] dhcp snooping enable
[SW1-vlan20] quit

[SW1] interface GigabitEthernet 0/0/3
[SW1-GigabitEthernet0/0/3] dhcp snooping trusted
[SW1-GigabitEthernet0/0/3] quit

```

> **提示**：
> 1. 上述命令中，假设连接 DHCP 服务器或上联口的接口是 `GigabitEthernet 0/0/3`。如果你的连线在其他接口（例如 `GigabitEthernet 0/0/24`），请将最后一步的接口编号替换为实际的接口。
> 2. 配置完成后，建议使用 `save` 命令保存当前配置，防止设备重启后配置丢失。
>

在 DHCP Snooping 环境中，`dhcp snooping trusted`（信任端口）的核心作用是**定义合法的 DHCP 报文来源，构建一道安全防线**。

具体来说，它有以下几个关键作用：

1. **放行合法的服务器应答**
交换机默认所有的端口都是“非信任端口（Untrusted）”。当把某个端口配置为 `trusted` 后，就等于告诉交换机：“这个接口连接的是正规的 DHCP 服务器或上层交换机，**允许**从这里发出 `DHCPOFFER`、`DHCPACK` 等服务器响应报文。”
2. **拦截非法的“假网关”或恶意服务器**
如果黑客私自接了一个路由器或在电脑上运行了恶意的 DHCP 服务，试图给局域网内的其他电脑分配错误的 IP 和网关，由于黑客连接的端口是非信任端口（Untrusted），交换机会**直接丢弃**该端口发出的所有 DHCP 应答报文，从而阻止攻击。
3. **辅助生成正确的安全绑定表**
当合法的 `DHCP ACK` 报文从 `trusted` 端口进入交换机时，交换机会顺便“偷看”并记录下客户端的 **IP地址、MAC地址、VLAN 以及对应的交换机端口**。这张绑定表是后续防范 ARP 欺骗（DAI）和 IP 冒用（IPSG）的基础。

简单一句话：**`dhcp snooping trusted` 就是给合法的 DHCP 服务器开绿灯，把非法的 DHCP 服务器挡在门外。**

---

如果没有传统意义上的“上级交换机”或上联口，只要局域网内存在 DHCP 服务器（无论是独立服务器、路由器，还是充当服务器的主机），**连接该 DHCP 服务器所在的物理接口就必须配置为信任端口 (`dhcp snooping trusted`)**。

### 核心原则

DHCP Snooping 不关心端口是不是“上级”，它只识别“哪个接口连接着合法的 DHCP 服务器”。

* **如果不配置信任端口**：交换机会默认所有端口都是非信任端口（Untrusted）。当合法的 DHCP 服务器回应 `DHCPOFFER` 或 `DHCPACK` 时，交换机会把这些合法的回应报文全部丢弃，导致**全网客户端无法获取 IP 地址**。

---

### 配置示例

假设合法的 DHCP 服务器直接插在交换机的 **`GigabitEthernet 0/0/24`** 接口上：

```text
<SW1> system-view
[SW1] interface GigabitEthernet 0/0/24
[SW1-GigabitEthernet0/0/24] dhcp snooping trusted
[SW1-GigabitEthernet0/0/24] quit

```

* **如何验证是否成功**：在系统视图下运行 `display dhcp snooping trusted-interface` 命令，检查返回列表中是否包含了你刚才配置的接口（如 G0/0/24）。

---

- trust可以指向回环端口吗？

**不可以，也不需要。**

关于“回环端口（LoopBack）”和 DHCP Snooping 信任端口的关系，具体原因如下：

### 1. 接口类型不支持

`dhcp snooping trusted` 是一个**二层物理接口**（或二层聚合接口 `Eth-Trunk`）的安全特性。回环接口（LoopBack）是一个纯粹的三层虚拟接口，交换机上无法在该接口下配置 DHCP Snooping 信任状态。

### 2. 本地 DHCP 服务器不需要配置信任端口

结合你前面的配置（在 `Vlanif10` 和 `Vlanif20` 上配置了 `dhcp select interface`），此时**交换机自身正在充当 DHCP 服务器**。

* 当 DHCP 服务器是交换机自己时，它内部生成的 DHCP 响应报文（如 Offer、Ack）是由交换机 CPU 直接发出的，属于合法报文，系统会**自动信任**并放行。
* 因此，**如果 DHCP 服务器是交换机自己，你根本不需要配置任何 `dhcp snooping trusted` 端口**，只需要全局开启并按 VLAN 开启 DHCP Snooping 即可。

### 总结

* **外部独立服务器**：接在哪个物理网口上，就把哪个**物理网口**设为 `trusted`。
* **交换机自身充当服务器**：不需要配置任何 `trusted` 端口。
