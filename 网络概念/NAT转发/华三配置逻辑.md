Ping 通了就好。借着这个实验，我们把 H3C 防火墙里 **`interface`、`nat address-group` 和 `nat policy`** 这三者的关系彻底理清。

你可以把这个过程想象成**“给快递发件”**：`interface` 是发货的邮局，`nat address-group` 是仓库里的“备用寄件人身份证”，而 `nat policy` 则是“什么货、走哪个邮局、用哪张身份证”的调度规则。

### 1. `interface`（发货接口/出接口）
*   **角色**：流量的出口，连接外部网络（Untrust 域）的物理接口（本实验中是 `GigabitEthernet1/0/0`）。
*   **作用**：**决定 NAT 发生在哪里**。防火墙必须在报文离开某个接口时，才知道要对其进行地址转换。如果不在 `nat policy` 里指定 `outbound-interface`，防火墙就不知道从哪个门往外扔包裹时需要换身份证，策略就会显示 `Inactive`（未生效）。

### 2. `nat address-group`（NAT 地址池）
*   **角色**：一个“备用身份证池”，也就是公网 IP 地址的集合（本实验中是 `10.1.23.20` 到 `10.1.23.210`）。
*   **作用**：**决定转换后的源地址是什么**。当内部 PC（比如 `192.168.100.2`）的数据包要出网时，不能带着私网 IP 出去，必须换成这个池子里的某一个公网 IP。如果不配置地址组，可以采用出接口地址（Easy IP）作为转换源，但配置了地址组就是固定从这个池子里挑。

### 3. `nat policy`（NAT 策略）
*   **角色**：**核心调度器（总指挥）**。它负责把前三者串联起来，回答三个问题：“谁要转换？”、“从哪出？”、“转换成什么？”。
*   **作用**：它是一条完整的规则，主要包含三个核心要素：
    1.  **匹配条件**：`source-ip Trust_Net`（谁发出的包需要被转换？即内网 192.168.100.0/24 的流量）。
    2.  **出接口**：`outbound-interface GigabitEthernet1/0/0`（从哪个接口出去？即去往 Untrust 的接口）。
    3.  **转换动作**：`action address-group 1`（转换成什么？即用地址组 1 里的公网 IP 替换源 IP）。

---

### 它们是如何协同工作的？（报文转发全流程）

结合你解决这个问题的经历，当 SW0（`192.168.100.2`）Ping Host_1（`10.1.23.2`）时，防火墙内部的处理逻辑如下：

1.  **路由与策略检查**：报文到达 FW1，先查路由表去往 `10.1.23.2` 从 `GE1/0/0` 出去。然后匹配**安全策略**（`Trust` 到 `Untrust`），放行 ICMP 流量。
2.  **匹配 NAT 策略**：命中 `nat policy` 里的 `rule name snat`。因为源 IP 在 `Trust_Net` 内，且出接口是 `GE1/0/0`，所以需要做源 NAT。
3.  **执行地址转换**：防火墙从 `nat address-group 1` 里取出一个 IP（例如 `10.1.23.20`），将报文的源 IP 从 `192.168.100.2` 替换为 `10.1.23.20`，然后从 `GE1/0/0` 发出去。
4.  **回程转换**：Host_1 收到包后，发现源 IP 是同一网段的 `10.1.23.20`，就直接回复给 FW1。FW1 收到回包，查会话表（Session Table），发现这是刚才 `192.168.100.2` 的会话，于是将目的 IP 还原成 `192.168.100.2`，再转发给 SW0。

### ⚠️ 一个极易踩坑的细节：谁先谁后？

**H3C 防火墙的默认顺序是：先匹配安全策略，后执行 NAT 转换。**

这意味着，安全策略（`security-policy`）里看到的源 IP 永远是**转换前的私网地址**（`192.168.100.2`）。所以你的安全策略 `rule 3` 里只要放通 Trust 到 Untrust 的流量即可，**不要**写成 NAT 转换后的公网地址，否则策略会匹配不上。

### 补充：另一种常见的 NAT 写法（Easy IP）

如果你没有 `10.1.23.20-210` 这样的公网地址池，可以直接借用出接口 `GE1/0/0` 的 IP（`10.1.23.1`）作为转换地址。这种写法不需要 `nat address-group`，直接在 NAT 策略里写 `action easy-ip` 即可，也是家庭宽带和企业边缘最常用的配置。

你现在已经打通了基础链路，后续如果要做端口映射（外网访问内网服务器），用到的是 `nat server`（目的 NAT），逻辑正好反过来，但“出接口”、“地址池”、“策略”这三个元素依然是核心骨架。
