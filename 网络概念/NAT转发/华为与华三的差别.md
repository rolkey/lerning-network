华为和华三在**设计哲学和配置逻辑**上有根本性的不同。你之前在华三上遇到的“策略不生效”问题，在华为的这套配置里，通过不同的机制被规避了。

### 核心差异：NAT 策略的“触发条件”不同

这是两者最本质的区别，也是你之前排错的关键。

*   **华三 (H3C)**：**依赖“出接口”触发**。在华三的 `nat policy` 里，你必须用 `outbound-interface` 命令把 NAT 规则“绑”到一个物理接口上。如果没有绑定，策略状态就是 `Inactive`，完全不工作。它关心的是“报文**从哪个口出去**”。
*   **华为 (Huawei)**：**依赖“安全区域”匹配**。在你提供的华为配置里，`nat-policy` 的规则是用 `source-zone trust` 和 `destination-zone untrust` 来匹配流量的。只要流量被防火墙判定为从 Trust 域去往 Untrust 域，并且路由查到了出接口，这条 NAT 规则就会被触发。它关心的是“报文**属于哪个域间关系**”。

**简单理解**：华三需要你明确告诉它“从 GE1/0/0 出去的流量做 NAT”；华为则只需要你告诉它“从 Trust 去 Untrust 的流量做 NAT”，至于具体从哪个物理口出去，它自己会根据路由表去查。

### 配置逻辑与命令对比

| 对比维度 | 华三 (H3C) 配置逻辑 (你之前的实验) | 华为 (Huawei) 配置逻辑 (你贴出的配置) |
| :--- | :--- | :--- |
| **NAT 策略匹配条件** | 主要靠 `source-ip` (匹配源地址) + `outbound-interface` (匹配出接口) | 主要靠 `source-zone` / `destination-zone` (匹配安全域) + 可选的 `source-address` |
| **地址池配置** | `nat address-group 1` <br> 然后 `address 10.1.23.20 10.1.23.210` | `nat address-group 1 0` <br> `mode pat` <br> `section 0 10.1.23.100 10.1.23.180` |
| **NAT 动作** | `action address-group 1` | `action source-nat address-group 1` |
| **策略生效关键** | 必须在规则里**指定出接口** (`outbound-interface`)，否则 `Inactive` | 无需指定出接口，由**路由表**决定出接口，NAT 策略基于域间匹配自动生效 |

### 为什么华为的配置能“跑通”？

在你的华为 `FW1.cfg` 里，NAT 策略是这样写的：

```
nat-policy
 rule name snat
  source-zone trust
  destination-zone untrust
  action source-nat address-group 1
```

这里**没有任何关于接口的配置**。它的工作流程是：
1.  报文从 `GigabitEthernet1/0/1` (Trust 域) 进入，要去往 `10.1.23.2`。
2.  防火墙查路由表，发现出接口是 `GigabitEthernet1/0/0` (Untrust 域)。
3.  防火墙检查 `nat-policy`，发现报文的源/目的域（Trust -> Untrust）匹配了 `rule name snat`，于是执行源 NAT，从地址组 1 里选一个地址替换源 IP。
4.  转换后的报文从路由查到的出接口发出去。

**整个过程中，NAT 策略的匹配和出接口的选择是解耦的。** 这也解释了为什么你在华三上需要额外绑定接口，而在华为这套配置里完全看不到这一步。

### 补充：关于 Easy IP 的差异

两者都支持 Easy IP（直接使用出接口 IP 做转换），但命令不同：
*   **华为**：`action source-nat easy-ip`
*   **华三**：`action easy-ip`

### 总结

你之前在华三上排查的“NAT 策略 Inactive”问题，根源在于华三的 `nat policy` 设计上必须显式绑定出接口。而华为的 `nat-policy` 通过安全域来匹配流量，出接口由路由决定，因此在配置层面看起来“更简单”，少了一个必须显式绑定的步骤。理解了这一点，以后在这两个品牌的防火墙上做 NAT 排错时，排查方向就会清晰很多。
