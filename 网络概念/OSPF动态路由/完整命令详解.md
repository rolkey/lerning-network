下面把你这份实验里出现的命令，按“配置逻辑”拆开讲清楚。你这份拓扑是典型的：**三台 AR2220 串成一条链，AR1—AR2—AR3，跑 OSPF 单区域 Area 0，用 Loopback0 做 Router ID，同时宣告业务网段和回环网段**。

---

## 一、整体思路先理顺

你的配置其实做了四件事：

1. **改设备名**：`sysname AR1`，方便识别。
2. **配 IP 地址**：物理接口 + Loopback 接口。
3. **启 OSPF 进程**：`ospf 1 router-id x.x.x.x`。
4. **宣告网段**：在 Area 0 里 `network` 宣告直连网段。

OSPF 能通的关键是：
- 接口 IP 要通；
- OSPF 邻居要能建立；
- 宣告的网段要匹配接口所在网段；
- Router ID 要唯一且稳定。

## 二、逐条命令详解

### 1. `system-view`

```text
<Sysname> system-view
```

- `<Sysname>` 是**用户视图**，只能看，不能改配置。
- `system-view` 进入**系统视图**，才能配接口、OSPF、改设备名等。
- 提示符从 `< >` 变成 `[ ]`。

---

### 2. `sysname AR1`

```text
[Sysname] sysname AR1
```

- 修改设备名称。
- 改完后提示符变成 `[AR1]`。
- 实验里三台设备分别叫 AR1、AR2、AR3，方便区分。

---

### 3. `interface LoopBack 0`

```text
[AR1] interface LoopBack 0
[AR1-LoopBack0] ip address 1.1.1.1 255.255.255.255
```

**Loopback 接口是什么？**

- 这是华为/思科设备上的**逻辑接口**，不是物理接口。
- 只要设备开机，它就一直处于 UP 状态，除非你手动删掉。
- 非常稳定，不会因为物理链路抖动而 down。

**为什么用它做 Router ID？**

- OSPF 的 Router ID 是一个 32 位标识，用来唯一标识一台 OSPF 路由器。
- 如果 Router ID 所在的接口 down 了，OSPF 可能会重新选 Router ID，导致邻居关系震荡。
- 所以通常用 Loopback 地址做 Router ID，稳定。
- 这里：
  - AR1：`1.1.1.1/32`
  - AR2：`2.2.2.2/32`
  - AR3：`3.3.3.3/32`

**`255.255.255.255` 是什么？**

- 这是 32 位全 1 掩码，也就是 `/32`。
- 表示这个地址只代表主机本身，不是一个网段。
- Loopback 常用 `/32`。

---

### 4. 物理接口配 IP

```text
[AR1] interface GigabitEthernet 0/0/0
[AR1-GigabitEthernet0/0/0] ip address 192.168.12.1 255.255.255.0
```

- `GigabitEthernet 0/0/0`：千兆以太网接口，槽位 0，子卡 0，端口 0。
- `ip address 192.168.12.1 255.255.255.0`：配 IP 和掩码。
- `255.255.255.0` 就是 `/24`，表示网段 `192.168.12.0/24`。
- AR1 的 GE0/0/0 连 AR2，所以用 `192.168.12.1`。
- AR2 的 GE0/0/0 用 `192.168.12.2`，同一网段。
- AR2 的 GE0/0/1 连 AR3，用 `192.168.23.2`。
- AR3 的 GE0/0/0 用 `192.168.23.3`。

> 注意：接口配完 IP 后，默认是 UP 的（除非 shutdown）。华为路由器物理接口默认不 shutdown。

---

### 5. `ospf 1 router-id 1.1.1.1`

```text
[AR1] ospf 1 router-id 1.1.1.1
```

- `ospf 1`：启动 OSPF 进程，进程号是 1。
  - 进程号只是本地有意义，不同设备可以用不同进程号，不影响邻居建立。
  - 但同一台设备如果要跑多个 OSPF 实例，进程号要不同。
- `router-id 1.1.1.1`：手动指定 Router ID。
  - 如果不指定，OSPF 会自动选：先选 Loopback 中最大的 IP，再选物理接口中最大的 IP。
  - 手动指定更可控。

进入 OSPF 视图后提示符是 `[AR1-ospf-1]`。

---

### 6. `area 0`

```text
[AR1-ospf-1] area 0
```

- OSPF 是分层路由协议，区域号用 32 位表示。
- `area 0` 就是骨干区域，写成 `0.0.0.0` 也一样。
- 所有其他区域必须和 Area 0 相连。
- 你这里三台路由器都在 Area 0，属于单区域 OSPF。

进入区域视图后提示符是 `[AR1-ospf-1-area-0.0.0.0]`。

---

### 7. `network` 命令

```text
[AR1-ospf-1-area-0.0.0.0] network 1.1.1.1 0.0.0.0
[AR1-ospf-1-area-0.0.0.0] network 192.168.12.0 0.0.0.255
```

**`network` 命令的作用：**

- 告诉 OSPF：哪些接口要参与 OSPF。
- 匹配的是**接口 IP 所在的网段**。
- 匹配上的接口会：
  1. 开始发送/接收 OSPF Hello 报文；
  2. 把该接口网段宣告进 OSPF。

**后面的 `0.0.0.0` 和 `0.0.0.255` 是什么？**

- 这是**反掩码**，也叫通配符掩码。
- 反掩码和子网掩码相反：
  - 子网掩码 `255.255.255.0` → 反掩码 `0.0.0.255`
  - 子网掩码 `255.255.255.255` → 反掩码 `0.0.0.0`
- `network 1.1.1.1 0.0.0.0`：精确匹配 `1.1.1.1/32` 这个接口。
- `network 192.168.12.0 0.0.0.255`：匹配 `192.168.12.0/24` 网段。

**为什么 AR1 只宣告两个网段？**

- AR1 只有：
  - Loopback0：`1.1.1.1/32`
  - GE0/0/0：`192.168.12.1/24`
- 所以只宣告这两个。
- AR2 有三个网段：`2.2.2.2/32`、`192.168.12.0/24`、`192.168.23.0/24`。
- AR3 有两个：`3.3.3.3/32`、`192.168.23.0/24`。

---

### 8. `quit`

```text
[AR1-ospf-1-area-0.0.0.0] quit
[AR1-ospf-1] quit
```

- 逐层退出视图。
- 从区域视图退到 OSPF 视图，再退到系统视图。
- 配置已经生效，不需要额外保存命令（但 eNSP 里建议 `save` 保存）。

## 三、OSPF 邻居建立过程（理解这个，就懂为什么能通）

OSPF 邻居建立大致经历：

1. **Down**：刚配好，还没收到 Hello。
2. **Init**：收到对方的 Hello，但对方 Hello 里没有自己的 Router ID。
3. **2-Way**：双方 Hello 里都有对方 Router ID，双向通信正常。
4. **ExStart**：开始选主从，准备交换数据库。
5. **Exchange**：交换 DBD 报文，描述各自 LSDB。
6. **Loading**：请求缺失的 LSA。
7. **Full**：数据库同步完成，邻居关系完全建立。

你执行：

```text
display ospf peer brief
```

看到 `Full`，说明邻居关系正常。

## 四、路由表怎么看

```text
display ip routing-table protocol ospf
```

- 这条命令只看 OSPF 学到的路由。
- AR1 应该能学到：
  - `2.2.2.2/32`（AR2 的 Loopback）
  - `3.3.3.3/32`（AR3 的 Loopback）
  - `192.168.23.0/24`（AR2—AR3 网段）
- 这些路由的下一跳是 `192.168.12.2`（AR2）。
- 因为 AR1 和 AR3 不直连，所以 AR1 去 AR3 的流量要经过 AR2。

---

## 五、`ping -a 1.1.1.1 3.3.3.3` 是什么意思

```text
ping -a 1.1.1.1 3.3.3.3
```

- `-a 1.1.1.1`：指定源地址为 `1.1.1.1`。
- `3.3.3.3`：目的地址是 AR3 的 Loopback。
- 这样测试的是：**从 AR1 的 Loopback 到 AR3 的 Loopback 是否通**。
- 如果通，说明：
  - OSPF 邻居建立成功；
  - 路由学习成功；
  - 全网互通。

如果不指定 `-a`，默认用出接口 IP 做源，可能测的是 `192.168.12.1` 到 `3.3.3.3`。

## 六、你这份配置里几个容易混淆的点

### 1. Router ID 和 Loopback 地址的关系

- Router ID 可以手动指定，也可以自动选。
- 你手动指定了 `router-id 1.1.1.1`，同时 Loopback0 也是 `1.1.1.1`。
- 这是一种常见做法：**让 Router ID 和 Loopback 地址一致**，方便记忆和管理。
- 但 Router ID 不一定要等于 Loopback 地址，只是通常这么配。

### 2. `network` 宣告的是网段，不是接口

- `network 192.168.12.0 0.0.0.255` 匹配的是 `192.168.12.0/24`。
- 只要接口 IP 在这个网段内，该接口就参与 OSPF。
- 如果接口 IP 是 `192.168.12.1`，匹配；如果是 `192.168.13.1`，不匹配。

### 3. 反掩码不要写成子网掩码

- 错误：`network 192.168.12.0 255.255.255.0`
- 正确：`network 192.168.12.0 0.0.0.255`
- 华为 OSPF 用的是反掩码。

### 4. OSPF 进程号本地有效

- AR1 用 `ospf 1`，AR2 用 `ospf 1`，AR3 用 `ospf 1`。
- 其实用 `ospf 100` 也能建立邻居，因为进程号不参与 Hello 报文。
- 但为了统一，实验里都用 1。

### 5. Area 0 是骨干区域

- 所有区域都要和 Area 0 相连。
- 你这里三台都在 Area 0，没有区域间路由，都是区域内路由。

## 七、验证命令补充解释

### `display ospf peer brief`

- 查看 OSPF 邻居简要信息。
- 输出包括：邻居 Router ID、邻居接口地址、状态、接口。
- 状态 `Full` 表示邻居关系完全建立。

### `display ip routing-table protocol ospf`

- 查看 OSPF 路由。
- 输出包括：目的网段、下一跳、出接口、开销、优先级等。
- OSPF 默认优先级是 10（华为设备）。

### `display ospf routing`

- 查看 OSPF 内部路由表。
- 可以看到 OSPF 计算出的路由和开销。

### `display ospf interface`

- 查看哪些接口参与了 OSPF。
- 可以看到接口的 Area、状态、DR/BDR 等。

### 第一层：检查底层链路与接口

*   **命令**：`display interface brief`、`display ip interface brief`
*   **目的**：确认物理接口和协议状态均为 **UP**。如果接口未 UP，OSPF 根本无法在接口上建立邻居。
*   **关键点**：对于连接核心交换机的端口，检查是否被错误地配置为 `shutdown`，或由于生成树（STP）收敛导致长时间处于阻塞状态。


### 第二层：检查 OSPF 邻居关系**

*   **命令**：`display ospf peer brief`（或 `display ospf peer`）
*   **目的**：这是最直接的诊断点。查看邻居状态是否卡在 `Init`、`ExStart` 或 `Exchange`。
*   **关键点**：
    *   如果长时间停留在 `Init`，通常意味着单通（一方能收到 Hello，另一方收不到），需检查链路或 ACL。
    *   如果停留在 `ExStart/Exchange`，通常是 **MTU 不匹配**或 Router ID 冲突导致的。

### 第三层：检查 OSPF 收敛参数与 SPF 计算

*   **命令**：`display ospf brief`、`display ospf interface`
*   **目的**：查看 **Hello 和 Dead 定时器**。华为设备在广播网络（如以太网）上默认 Hello 为 10 秒，Dead 为 40 秒。这意味着拓扑变化后，邻居失效检测最长可能需要 40 秒。
*   **关键点**：医院核心网络通常需要更快的收敛。检查是否配置了 `ospf timer hello 3` 和 `ospf timer dead 10` 等优化参数。同时，`display ospf brief` 中的 SPF 调度延迟也可能成为瓶颈。

### 第四层：检查路由表与协议进程状态**

*   **命令**：`display ospf routing`（查看 OSPF 计算出的路由）、`display ip routing-table protocol ospf`
*   **目的**：如果邻居已 `Full`，但路由表为空，说明 **SPF 计算未触发或失败**。
*   **关键点**：检查是否存在大规模的路由震荡，导致 SPF 频繁计算而“挂起”。可以查看 `display ospf spf-statistics`（如果支持）或设备日志，确认是否有 SPF 计算被延迟的记录。

---

## 八、一句话总结

你这份配置的核心就是：

> **给接口配 IP，用 Loopback 做稳定 Router ID，启动 OSPF 进程，在 Area 0 里用 `network` 反掩码宣告直连网段，让三台路由器互相学习路由，最终实现全网互通。**

如果你后面想加多区域、改开销、做认证、或者加静态路由，都可以在这个基础上扩展。
