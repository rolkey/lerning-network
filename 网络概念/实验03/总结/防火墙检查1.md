# 企业网络防火墙与核心交换机互联排障总结

## 一、实验拓扑与角色说明

### 拓扑结构

```
PC1/PC2/PC3
    │
二层接入交换机
    │
核心三层交换机（LSW1）
    │ 10.1.23.2/30
防火墙 FW1（USG6000V1）
    │ 10.1.23.1/30（内网口 GE1/0/1）
    │ 100.1.1.2/30（外网口 GE1/0/0）
模拟外网路由器 Internet（AR 系列）
    │ 100.1.1.1/30
    │ LoopBack0：200.1.1.1/32
```

### 各设备角色

| 设备 | 角色 | 关键接口/IP |
|------|------|-------------|
| Internet（AR） | 模拟公网 | GE0/0/0：100.1.1.1/30，LoopBack0：200.1.1.1/32 |
| FW1 | 边界防火墙 | GE1/0/0：100.1.1.2/30（untrust），GE1/0/1：10.1.23.1/30（trust） |
| LSW1 | 核心三层交换机 | Vlanif100：10.1.23.2/30，Vlanif10/20/88 业务网关 |
| PC1/PC2/PC3 | 业务终端 | 192.168.10.2 / 20.2 / 88.100 |

### 业务网段规划

| 网段 | 用途 | VLAN |
|------|------|------|
| 192.168.10.0/24 | 业务1 | VLAN 10 |
| 192.168.20.0/24 | 业务2 | VLAN 20 |
| 192.168.88.0/24 | 设备管理 | VLAN 88 |

## 二、初始问题现象

1. **PC1 无法 ping 通防火墙内网口** `10.1.23.1`
2. **PC1 tracert 外网**：第一跳 192.168.10.1 通，后续全部超时
3. **核心交换机 ping 防火墙内网口**：通
4. **核心交换机 ping 外网**：不通
5. **FW1 ping 外网对端** `100.1.1.1`：不通
6. **PC1 ping 模拟公网** `200.1.1.1`：不通

---

## 三、排查过程与关键发现

### 3.1 交换机侧排查

**检查路由表：**

```
[LSW1]display ip routing-table
```

发现：

- ✅ 默认路由 `0.0.0.0/0 → 10.1.23.1` 存在
- ✅ 业务网段直连路由 `192.168.10.0/24`、`192.168.20.0/24` 存在
- ❌ 缺少 `192.168.88.0/24`（Vlanif88 未配）

**结论：** 核心交换机路由基本正确，默认路由指向防火墙，具备转发条件。

### 3.2 防火墙接口排查

**检查接口状态：**

```
[FW1]display ip interface brief
```

发现：

- ✅ `GE1/0/1`：10.1.23.1/30，up/up
- ✅ `GE1/0/0`：100.1.1.2/30，up/up

**结论：** 接口物理层、协议层均正常。

### 3.3 防火墙路由表排查

**第一次检查：**

```
[FW1]display ip routing-table
```

发现只有 127.0.0.0/8，看似没有回程路由。

**进一步检查 default 实例：**

```
[FW1]display ip routing-table vpn-instance default
```

发现：

- ✅ `10.1.23.0/30 Direct`
- ✅ `192.168.10.0/24 Static → 10.1.23.2`
- ✅ `192.168.20.0/24 Static → 10.1.23.2`
- ✅ `192.168.88.0/24 Static → 10.1.23.2`

**结论：** 回程路由其实已经存在，只是接口绑定了 `default` VPN 实例，路由显示在 default 实例中。

### 3.4 防火墙安全策略排查

**检查策略：**

```
[FW1]display security-policy rule all
```

发现：

- `trust_to_local_ping`：trust → local icmp permit ✅
- `trust_to_untrust`：trust → untrust permit ✅
- `local_to_untrust_ping`：local → untrust icmp permit ✅
- `default`：deny，HITS 持续增长 ❌

**关键发现：** PC1 ping 防火墙时，`default` 的 HITS 在涨，说明包到了防火墙但被默认拒绝。

**补充策略：**

```
security-policy
 rule name trust_to_local_ping
  source-zone trust
  destination-zone local
  service icmp
  action permit
```

之后 PC1 能 ping 通防火墙内网口。

### 3.5 防火墙主动 ping 外网排查

**检查策略 HITS：**

```
[FW1]display security-policy rule all
```

ping 前后对比：

- `local_to_untrust_ping` HITS +1 ✅
- `default` HITS 不变

**结论：** FW1 主动 ping 的流量命中了 `local_to_untrust_ping`，策略没问题。

**检查接口计数：**

```
[FW1]display interface GigabitEthernet1/0/0
```

- Output packets 持续增长 → FW1 把包发出去了
- Input packets 不涨 → 对端没回 reply

**检查 ARP：**

```
[FW1]display arp | include 100.1.1
```

- ✅ 学到了 `100.1.1.1` 的 MAC

**根因：** FW1 用 `ping -a 10.1.23.1` 指定源地址，对端收到源地址为 `10.1.23.1` 的包后，**对端没有 `10.1.23.0/30` 的回程路由**，无法回包。

### 3.6 VPN 实例绑定问题

**关键发现：**

```
[FW1]ping -a 10.1.23.1 192.168.10.1
Warning: The specified source address is not a local address
```

**原因：** `GE1/0/1` 绑定了 `ip binding vpn-instance default`，接口 IP `10.1.23.1` 属于 default 实例，不在公网实例，导致：

- FW1 无法用 `10.1.23.1` 作为源地址主动发包
- 核心 ping FW1 内网口时，FW1 收到请求但 Output packets = 0，无法回包

**解决：** 去掉接口的 VPN 实例绑定，统一回到公网实例：

```
interface GigabitEthernet1/0/1
 undo ip binding vpn-instance default
 quit

interface GigabitEthernet0/0/0
 undo ip binding vpn-instance default
 quit
```

### 3.7 核心访问外网排查

**检查 NAT 策略：**

```
[FW1]display nat-policy rule all
```

- `snat_to_internet`：trust → untrust，source-nat easy-ip ✅

**检查会话表：**

```
[FW1]display firewall session table
```

PC1 ping 外网时，会话表有新建会话，源地址被 NAT 转换为 `100.1.1.2`。

**结论：** NAT 生效，PC1 可以访问外网。

### 3.8 最终现象

- PC1 → 100.1.1.1：✅ 通
- PC1 → 200.1.1.1：✅ 通（首次 ping 因 ARP 学习丢包，后续正常）
- 核心 → 外网：✅ 通
- FW1 → 外网：✅ 通

## 四、根因分析汇总

| 问题 | 根因 | 解决方式 |
|------|------|----------|
| PC1 ping 不通防火墙 | 缺 trust → local icmp 策略 | 加 `trust_to_local_ping` |
| 交换机 ping 不通防火墙 | 互联接口未配 IP / 未划 VLAN | 配 Vlanif100 和 GE1/0/1 互联 IP |
| FW1 ping 不通外网 | 源地址用了 10.1.23.1，对端无回程路由 | 改用 `ping -a 100.1.1.2` |
| FW1 收到核心 ping 不回包 | 接口绑定 VPN 实例，源地址不在公网实例 | 去掉 `ip binding vpn-instance default` |
| 核心 ping 不通外网 | NAT 未生效 / 路由未打通 | 确认 NAT HITS 和会话表 |
| PC1 首次 ping 丢包 | ARP 学习需要时间 | 正常现象，后续稳定 |

## 五、最终正确配置

### 5.1 核心交换机（LSW1）

```
vlan batch 10 20 88 100

interface Vlanif10
 ip address 192.168.10.1 255.255.255.0
interface Vlanif20
 ip address 192.168.20.1 255.255.255.0
interface Vlanif88
 ip address 192.168.88.1 255.255.255.0
interface Vlanif100
 ip address 10.1.23.2 255.255.255.252

ip route-static 0.0.0.0 0.0.0.0 10.1.23.1
```

### 5.2 防火墙（FW1）

**接口配置：**

```
interface GigabitEthernet1/0/0
 undo shutdown
 ip address 100.1.1.2 255.255.255.252
 service-manage ping permit
 quit

interface GigabitEthernet1/0/1
 undo shutdown
 ip address 10.1.23.1 255.255.255.252
 service-manage ping permit
 quit
```

**安全区域：**

```
firewall zone trust
 add interface GigabitEthernet1/0/1
 quit

firewall zone untrust
 add interface GigabitEthernet1/0/0
 quit
```

**路由：**

```
ip route-static 0.0.0.0 0.0.0.0 100.1.1.1
ip route-static 192.168.10.0 255.255.255.0 10.1.23.2
ip route-static 192.168.20.0 255.255.255.0 10.1.23.2
ip route-static 192.168.88.0 255.255.255.0 10.1.23.2
```

**安全策略：**

```
security-policy
 rule name trust_to_local_ping
  source-zone trust
  destination-zone local
  service icmp
  action permit

 rule name trust_to_untrust
  source-zone trust
  destination-zone untrust
  action permit

 rule name local_to_untrust_ping
  source-zone local
  destination-zone untrust
  service icmp
  action permit

 rule name untrust_to_local_ping
  source-zone untrust
  destination-zone local
  service icmp
  action permit
```

**NAT：**

```
nat-policy
 rule name snat_to_internet
  source-zone trust
  destination-zone untrust
  action source-nat easy-ip
```

### 5.3 模拟外网（Internet AR）

```
interface GigabitEthernet0/0/0
 ip address 100.1.1.1 255.255.255.252
 quit

interface LoopBack0
 ip address 200.1.1.1 255.255.255.255
 quit
```

## 六、经验总结

### 6.1 三层互联推荐方案

- **防火墙与核心交换机之间用三层互联 IP + 静态路由**，不要在防火墙上开 VLAN 子接口
- 互联 IP 用 `/30` 掩码，节省地址
- 核心默认路由指向防火墙，防火墙回程路由指向核心业务网段

### 6.2 防火墙排障顺序

1. **接口层**：`display ip interface brief`，确认 up/up 和 IP
2. **路由层**：`display ip routing-table`，确认去程和回程路由
3. **策略层**：`display security-policy rule all`，看 HITS 是否命中
4. **NAT 层**：`display nat-policy rule all`，看 HITS 和会话表
5. **会话层**：`display firewall session table`，看会话建立情况
6. **接口计数**：`display interface`，看 Input/Output packets 变化

### 6.3 常见坑点

| 坑点 | 现象 | 解决 |
|------|------|------|
| 接口绑定 VPN 实例 | ping 提示 "not a local address"，回包失败 | 统一接口 VPN 实例，或去掉绑定 |
| 缺 local → trust 策略 | FW1 主动 ping 内网不通 | 加 local → trust icmp permit |
| 缺 untrust → local 策略 | 对端回包被默认 deny | 加 untrust → local icmp permit |
| 源地址选错 | ping 用内网口地址，对端无回程路由 | 用外网口地址作源，或在对端加回程路由 |
| ARP 未学习 | 首次 ping 丢包，后续正常 | 正常现象，等 ARP 完成 |
| Vlanif 掩码显示 /24 | 实际配置 /30，显示按自然掩码 | 不影响转发，忽略 |

### 6.4 验证通断的标准流程

```
1. 本机 ping 网关          → 确认终端到核心
2. 核心 ping 防火墙内网口   → 确认核心到防火墙
3. 防火墙 ping 外网对端     → 确认防火墙到外网
4. 核心 ping 外网对端       → 确认核心经过防火墙到外网
5. 终端 ping 外网对端       → 确认整条链路
6. 终端 ping 模拟公网 IP    → 确认 NAT 生效
```

### 6.5 关键命令速查

| 目的 | 命令 |
|------|------|
| 看接口 IP 和状态 | `display ip interface brief` |
| 看路由表 | `display ip routing-table` |
| 看 VPN 实例路由 | `display ip routing-table vpn-instance default` |
| 看安全策略 | `display security-policy rule all` |
| 看 NAT 策略 | `display nat-policy rule all` |
| 看会话表 | `display firewall session table` |
| 看 ARP | `display arp \| include x.x.x.x` |
| 看接口计数 | `display interface GigabitEthernet1/0/0` |

## 七、结论

本次排障的核心问题有三个：

1. **互联层**：核心交换机与防火墙之间缺少三层互联 IP，导致路由不通
2. **策略层**：防火墙缺少 trust → local、local → trust、untrust → local 的 icmp 放行策略
3. **VPN 实例层**：防火墙接口绑定 `default` VPN 实例，导致源地址识别错误，回包失败

**最终解决思路：**

- 统一接口 VPN 实例，去掉不必要的绑定
- 补齐双向安全策略
- 路由、NAT 按标准企业边界架构配置
- 用逐跳 ping 的方式定位问题所在设备

**整个网络最终实现：PC1/PC2/PC3 → 核心 → 防火墙（NAT）→ 模拟外网，全链路互通。**
