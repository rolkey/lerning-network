# 防火墙侧连接问题排查操作方法详解

## 一、总体排查逻辑

防火墙位于内网和外网之间，所有流量经过它时，要依次经过以下几个环节：

```
接口 → 安全区域 → 路由 → 安全策略 → NAT → 会话表 → 转发
```

任何一个环节出问题，流量都会中断。所以排查时**按这个顺序逐层验证**，每一步都确认“包到没到、有没有被丢弃、有没有被转换”。

---

## 二、第一步：接口层检查

### 2.1 看接口状态和 IP

**命令：**

```
display ip interface brief
```

**判读标准：**

| 字段 | 应满足 |
|------|--------|
| Physical | up |
| Protocol | up |
| IP Address/Mask | 与规划一致 |

**常见问题：**

- 接口 `down` → 对端没开、线没连好、eNSP 没启动
- IP 没配上 → 配了但没生效，或接口被 shutdown
- 掩码不匹配 → 两端掩码不一致，会导致直连不通

### 2.2 看接口详细状态

**命令：**

```
display interface GigabitEthernet1/0/1
```

**重点看：**

- `current state` / `Line protocol` 是否 up
- `Internet Address` 是否正确
- `Input packets` / `Output packets` 是否在涨

**Input/Output 判读：**

| 现象 | 说明 |
|------|------|
| Input 涨，Output 不涨 | 收到包但不回，问题在回包路径 |
| Output 涨，Input 不涨 | 发出去了但对端没回，问题在链路或对端 |
| 两者都不涨 | 包根本没到，问题在链路或对端设备 |

### 2.3 看接口是否绑定 VPN 实例

**命令：**

```
display current-configuration interface GigabitEthernet1/0/1
```

**关键点：**

如果看到：

```
ip binding vpn-instance default
```

说明接口 IP 属于 `default` 实例，不在公网实例里。这会导致：

- `ping -a 接口IP` 提示 "not a local address"
- 核心发来的包，防火墙无法用该 IP 回包（Output packets 不涨）
- 路由表默认显示公网实例，看不到该接口的路由

**解决办法：**

去掉绑定，统一回到公网实例：

```
interface GigabitEthernet1/0/1
 undo ip binding vpn-instance default
 quit
```

## 三、第二步：安全区域检查

### 3.1 查看区域和接口绑定

**命令：**

```
display firewall zone
```

或：

```
display current-configuration | include zone
```

**判读标准：**

- 内网口（如 GE1/0/1）应在 trust 区
- 外网口（如 GE1/0/0）应在 untrust 区
- 管理口（如 GE0/0/0）应在 trust 或独立管理区

**常见问题：**

- 接口没加入任何 zone → 流量无法匹配策略，默认被丢弃
- 接口加入了错误的 zone → 策略匹配错方向

### 3.2 判断一个流量属于哪个 zone 间

防火墙判断流量方向，看的是：

- **源接口** 属于哪个 zone
- **目的接口** 属于哪个 zone

例如 PC1 ping 外网：

- 源接口 GE1/0/1 → trust
- 目的接口 GE1/0/0 → untrust
- 方向：trust → untrust

PC1 ping 防火墙内网口：

- 源接口 GE1/0/1 → trust
- 目的是防火墙自己 → local
- 方向：trust → local

**不同方向需要不同的策略，不能混。**

---

## 四、第三步：路由检查

### 4.1 看公网实例路由表

**命令：**

```
display ip routing-table
```

**应包含：**

- 默认路由 `0.0.0.0/0 → 外网对端`
- 直连路由（各接口网段）
- 回程路由（指向内网业务网段）

### 4.2 看 VPN 实例路由表

**命令：**

```
display ip routing-table vpn-instance default
```

**关键点：**

如果接口绑定了 VPN 实例，路由会出现在这里，而不是公网实例。**这也是为什么有时候 `display ip routing-table` 看不到路由，但 `ip route-static` 又提示 "already exists"**——路由存在，只是在另一个实例里。

### 4.3 验证路由是否可达

**命令：**

```
ping -a <源地址> <目的地址>
```

例如：

```
ping -a 10.1.23.1 192.168.10.1
```

**注意：**

- 如果提示 "not a local address" → 源地址不在当前实例，检查接口 VPN 实例绑定
- 如果 Request timeout → 路由不可达或对端不回

## 五、第四步：安全策略检查

### 5.1 查看所有策略及命中数

**命令：**

```
display security-policy rule all
```

**判读重点：**

| 字段 | 含义 |
|------|------|
| RULE NAME | 规则名 |
| STATE | enable 才生效 |
| ACTION | permit / deny |
| HITS | 命中次数 |

**核心方法：**

- **ping 前记录 HITS**
- **ping 后再看 HITS**
- **HITS 涨了 → 策略命中；没涨 → 策略没匹配上**

### 5.2 常见需要放行的方向

| 方向 | 场景 | 示例策略名 |
|------|------|-----------|
| trust → local | 内网 ping/管理防火墙 | `trust_to_local_ping` |
| local → trust | 防火墙主动 ping 内网 | `local_to_trust_ping` |
| trust → untrust | 内网访问外网 | `trust_to_untrust` |
| untrust → local | 外网 ping 防火墙外网口 | `untrust_to_local_ping` |
| local → untrust | 防火墙主动 ping 外网 | `local_to_untrust_ping` |

### 5.3 策略不命中的排查

**如果 HITS 不涨，可能原因：**

1. **方向不对**：源/目的 zone 写反了
2. **源/目的地址限定太严**：比如写死了 192.168.1.2，实际是 192.168.10.0/24
3. **服务限定太严**：比如只放了 https，实际是 icmp
4. **接口不在 zone 里**：包到了但没匹配到任何 zone
5. **包根本没到防火墙**：需要回到接口层查 Input 计数

### 5.4 临时全放行测试

如果怀疑是策略问题，可以临时加一条全放行规则测试：

```
security-policy
 rule name test_allow
  source-zone any
  destination-zone any
  action permit
 quit
```

**测试通后立刻收紧，不要留在生产环境。**

## 六、第五步：NAT 检查

### 6.1 查看 NAT 策略及命中数

**命令：**

```
display nat-policy rule all
```

**判读：**

- 规则 STATE 是否 enable
- HITS 是否随流量增长

### 6.2 典型 NAT 配置

```
nat-policy
 rule name snat_to_internet
  source-zone trust
  destination-zone untrust
  action source-nat easy-ip
 quit
```

**`easy-ip` 的含义：** 用出接口 IP 做转换。

**注意：**

- NAT 只对**穿越防火墙的流量**生效
- 防火墙自己发起的流量（local → untrust）**不走 NAT**
- 所以 FW1 自己 ping 外网时，源地址是接口地址，不会转换成别的

### 6.3 NAT 不生效的排查

**如果 HITS 不涨：**

1. 源 zone / 目的 zone 写错
2. 流量没命中默认路由，没从外网口出去
3. 出接口不在 untrust 区

---

## 七、第六步：会话表检查

### 7.1 查看会话表

**命令：**

```
display firewall session table
```

**该版本不支持管道过滤**，所以：

- 直接看全部，手动找相关条目
- 或用 `display firewall session table source x.x.x.x`
- 或用 `display firewall session table protocol icmp`

### 7.2 会话表判读

正常会话应包含：

| 字段 | 说明 |
|------|------|
| Source IP | 源地址（NAT 前） |
| Destination IP | 目的地址 |
| Source IP（NAT 后） | 转换后源地址 |
| Protocol | 协议类型 |
| State | normal / 其他 |

**如果 NAT 生效**，会看到源地址被转换成外网口地址。

**如果会话表为空：**

- 包根本没到防火墙
- 或者被策略在更早环节丢弃，没建会话

### 7.3 会话表为空时的排查顺序

1. 核心交换机能不能 ping 通防火墙内网口
2. 防火墙接口 Input packets 是否涨
3. 策略 HITS 是否涨
4. 路由表是否有对应目的网段的路由

---

## 八、第七步：ARP 与二层检查

### 8.1 查看 ARP 表

**命令：**

```
display arp | include 100.1.1
```

**判读：**

- 有表项 → 二层学习正常
- 无表项 → ARP 未学习，可能对端没回 ARP 或链路不通

### 8.2 首次 ping 丢包的原因

- ARP 请求发出后需要等待回应
- eNSP 模拟环境下 ARP 回应延迟较高
- 前几个包会因 ARP 未完成而丢失
- **等 ARP 学完后再 ping 就正常**

**这不是配置问题，是正常现象。**

## 九、防火墙排障完整流程

按顺序执行：

```
1. display ip interface brief              → 确认接口 up、IP 正确
2. display current-configuration interface → 确认是否绑定 VPN 实例
3. display firewall zone                   → 确认接口在正确的 zone
4. display ip routing-table                → 确认去程和回程路由
5. display ip routing-table vpn-instance default → 确认 VPN 实例路由
6. display security-policy rule all        → 确认策略方向、HITS
7. display nat-policy rule all             → 确认 NAT 策略、HITS
8. display firewall session table          → 确认会话建立
9. display arp | include x.x.x.x           → 确认 ARP 学习
10. display interface GigabitEthernet1/0/1 → 确认 Input/Output packets
```

每一步都对应一个环节，哪一步异常就解决哪一步。

## 十、本次排障中防火墙侧的实际操作记录

| 步骤 | 操作 | 发现 | 解决 |
|------|------|------|------|
| 1 | `display ip interface brief` | GE1/0/0、GE1/0/1 均 up | 无需处理 |
| 2 | `display current-configuration interface` | GE1/0/1 绑定 vpn-instance default | 去掉绑定 |
| 3 | `display firewall zone` | GE1/0/1 在 trust，GE1/0/0 在 untrust | 正确 |
| 4 | `display ip routing-table` | 公网实例看不到内网路由 | 查 vpn 实例 |
| 5 | `display ip routing-table vpn-instance default` | 回程路由存在 | 确认路由 |
| 6 | `display security-policy rule all` | 缺 trust→local、local→trust、untrust→local | 补三条策略 |
| 7 | `display nat-policy rule all` | snat_to_internet 存在 | 确认生效 |
| 8 | `display firewall session table` | PC1 ping 外网时有会话 | NAT 生效 |
| 9 | `display arp` | 学到外网对端 MAC | 正常 |
| 10 | `display interface` | Input/Output 正常 | 无需处理 |

## 十一、经验总结

1. **防火墙是分层处理的**：接口 → zone → 路由 → 策略 → NAT → 会话，一层层查，不要跳步
2. **策略看 HITS，是最直接的判断依据**：涨了说明命中，不涨说明没匹配
3. **VPN 实例绑定是隐藏坑**：`display ip routing-table` 看不到路由，不一定是没配，可能在另一个实例
4. **防火墙自己发起的流量不走 NAT**：源地址需要手动指定，且对端要有回程路由
5. **首次 ping 丢包正常**：ARP 学习需要时间，不是配置问题
6. **接口 Input/Output packets 是判断方向的金标准**：涨不涨直接告诉你包走到哪一步
