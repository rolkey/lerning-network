# 防火墙排障：命令 + 反馈 + 讲解

## 一、接口层

### 1.1 查看接口 IP 和状态

**命令：**

```
display ip interface brief
```

**典型反馈：**

```
Interface                         IP Address/Mask      Physical   Protocol  
GigabitEthernet0/0/0              192.168.0.1/24       up         up        
GigabitEthernet1/0/0              unassigned           down       down      
GigabitEthernet1/0/1              10.1.23.1/30         up         up        
GigabitEthernet1/0/2              unassigned           down       down      
```

**讲解：**

- `Physical` 是物理层状态，`Protocol` 是协议层状态。**两个都要 up，接口才能转发流量。**
- `GigabitEthernet1/0/1` 显示 `10.1.23.1/30`，up/up → 内网互联口正常。
- `GigabitEthernet1/0/0` 显示 `unassigned`，down/down → 外网口没配 IP，或者对端没启动。
- **如果某个接口 down，先去查对端设备是否启动、线是否连好，而不是查策略。**

---

### 1.2 查看接口详细状态

**命令：**

```
display interface GigabitEthernet1/0/1
```

**典型反馈：**

```
GigabitEthernet1/0/1 current state : UP 
Line protocol current state : UP
Internet Address is 10.1.23.1/30 
input packets : 20, bytes : 1680, multicasts : 0
output packets : 0, bytes : 0, multicasts : 0
ICMP packet input number: 20
  Echo request: 20
  Echo reply: 0
```

**讲解：**

- `current state : UP` / `Line protocol current state : UP` → 接口正常。
- `Internet Address is 10.1.23.1/30` → IP 正确。
- `input packets : 20` → 收到了 20 个包。
- `output packets : 0` → **一个包都没发出去。**
- `Echo request: 20` → 收到的全是 ping 请求。
- `Echo reply: 0` → **一个应答都没发出去。**

**结论：** 核心发来的 ping 请求，防火墙收到了，但防火墙不回包。

**为什么？** 因为接口绑定了 `ip binding vpn-instance default`，`10.1.23.1` 不在公网实例里，防火墙回包时找不到这个源地址，所以发不出去。

**解决：** 去掉接口的 VPN 实例绑定。

---

### 1.3 查看接口是否绑定 VPN 实例

**命令：**

```
display current-configuration interface GigabitEthernet1/0/1
```

**典型反馈：**

```
#
interface GigabitEthernet1/0/1
 undo shutdown
 ip binding vpn-instance default
 ip address 10.1.23.1 255.255.255.252
 service-manage ping permit
#
```

**讲解：**

- `ip binding vpn-instance default` → **这个接口属于 default VPN 实例，不在公网实例。**
- 这会导致：
  - `ping -a 10.1.23.1` 提示 "not a local address"
  - 路由表 `display ip routing-table` 看不到 `10.1.23.0/30`
  - 核心发来的包，防火墙无法用 `10.1.23.1` 回包
- **解决办法：** `undo ip binding vpn-instance default`

---

## 二、安全区域层

### 2.1 查看区域和接口绑定

**命令：**

```
display zone
```

**典型反馈：**

```
firewall zone trust
 set priority 85
 add interface GigabitEthernet0/0/0
 add interface GigabitEthernet1/0/1

firewall zone untrust
 set priority 5
 add interface GigabitEthernet1/0/0
```

**讲解：**

- `trust` 区包含 `GE1/0/1`（内网口）和 `GE0/0/0`（管理口）。
- `untrust` 区包含 `GE1/0/0`（外网口）。
- **接口必须在正确的 zone 里，流量才能匹配到正确的策略方向。**
- 如果一个接口没加入任何 zone，流量到了防火墙会被直接丢弃。

---

## 三、路由层

### 3.1 查看公网实例路由表

**命令：**

```
display ip routing-table
```

**典型反馈（修复前）：**

```
Routing Tables: Public
         Destinations : 5        Routes : 5        

Destination/Mask    Proto   Pre  Cost      Flags NextHop         Interface

        0.0.0.0/0   Static  60   0          RD   100.1.1.1       GigabitEthernet1/0/0
      100.1.1.0/30  Direct  0    0           D   100.1.1.2       GigabitEthernet1/0/0
      100.1.1.2/32  Direct  0    0           D   127.0.0.1       GigabitEthernet1/0/0
      127.0.0.0/8   Direct  0    0           D   127.0.0.1       InLoopBack0
      127.0.0.1/32  Direct  0    0           D   127.0.0.1       InLoopBack0
```

**讲解：**

- 只有 `100.1.1.0/30` 和默认路由，**看不到 `10.1.23.0/30` 和 `192.168.10.0/24`。**
- 这是因为 `GE1/0/1` 绑定了 `default` VPN 实例，它的路由不在公网实例里。
- **`display ip routing-table` 默认显示的是公网实例，不是所有实例。**

**典型反馈（修复后）：**

```
Routing Tables: Public
         Destinations : 10       Routes : 10       

Destination/Mask    Proto   Pre  Cost      Flags NextHop         Interface

        0.0.0.0/0   Static  60   0          RD   100.1.1.1       GigabitEthernet1/0/0
      10.1.23.0/30  Direct  0    0           D   10.1.23.1       GigabitEthernet1/0/1
      10.1.23.1/32  Direct  0    0           D   127.0.0.1       GigabitEthernet1/0/1
      100.1.1.0/30  Direct  0    0           D   100.1.1.2       GigabitEthernet1/0/0
      100.1.1.2/32  Direct  0    0           D   127.0.0.1       GigabitEthernet1/0/0
   192.168.10.0/24  Static  60   0          RD   10.1.23.2       GigabitEthernet1/0/1
   192.168.20.0/24  Static  60   0          RD   10.1.23.2       GigabitEthernet1/0/1
   192.168.88.0/24  Static  60   0          RD   10.1.23.2       GigabitEthernet1/0/1
```

**讲解：**

- 现在能看到 `10.1.23.0/30 Direct` → 内网互联口直连路由。
- 能看到 `192.168.10.0/24 Static → 10.1.23.2` → 回程路由。
- 能看到 `0.0.0.0/0 Static → 100.1.1.1` → 默认路由。
- **这三类路由齐全，路由层才算正常。**

---

### 3.2 查看 VPN 实例路由表

**命令：**

```
display ip routing-table vpn-instance default
```

**典型反馈：**

```
Routing Tables: default
         Destinations : 7        Routes : 7        

Destination/Mask    Proto   Pre  Cost      Flags NextHop         Interface

      10.1.23.0/30  Direct  0    0           D   10.1.23.1       GigabitEthernet1/0/1
    192.168.0.0/24  Direct  0    0           D   192.168.0.1     GigabitEthernet0/0/0
   192.168.10.0/24  Static  60   0          RD   10.1.23.2       GigabitEthernet1/0/1
   192.168.20.0/24  Static  60   0          RD   10.1.23.2       GigabitEthernet1/0/1
   192.168.88.0/24  Static  60   0          RD   10.1.23.2       GigabitEthernet1/0/1
```

**讲解：**

- 这条命令看的是 `default` 实例的路由。
- 当你执行 `ip route-static 192.168.10.0 255.255.255.0 10.1.23.2` 提示 "already exists" 时，说明路由已经存在，但可能在 default 实例里。
- **用这条命令对比，就能知道路由到底在哪个实例。**

## 四、安全策略层

### 4.1 查看所有策略及命中数

**命令：**

```
display security-policy rule all
```

**典型反馈（修复前）：**

```
Total:2 
RULE ID  RULE NAME                         STATE      ACTION       HITS        
------------------------------------------------------------------------------- 
1        cloud_ping_fw                     enable     permit       0            
0        default                           enable     deny         15            
```

**讲解：**

- 只有一条策略 `cloud_ping_fw`，源 zone 是 untrust，源地址是 192.168.1.2。
- 这条策略**完全不匹配 PC1 的流量**（PC1 是 trust 区，源地址 192.168.10.2）。
- `default` 是默认拒绝策略，HITS = 15 → **PC1 的包被默认拒绝规则丢了 15 次。**
- **这就是 PC1 ping 不通防火墙的直接原因。**

**典型反馈（修复后）：**

```
Total:6 
RULE ID  RULE NAME                         STATE      ACTION       HITS        
------------------------------------------------------------------------------- 
1        cloud_ping_fw                     enable     permit       0            
2        trust_to_local_ping               enable     permit       12            
3        trust_to_untrust                  enable     permit       0            
4        local_to_untrust_ping             enable     permit       39            
5        local_to_trust_ping               enable     permit       12            
0        default                           enable     deny         150           
```

**讲解：**

- `trust_to_local_ping` HITS = 12 → PC1 ping 防火墙的流量命中了这条策略。
- `local_to_untrust_ping` HITS = 39 → FW1 主动 ping 外网的流量命中了这条策略。
- `local_to_trust_ping` HITS = 12 → FW1 主动 ping 核心的流量命中了这条策略。
- `default` HITS = 150 → 还有别的流量被默认拒绝，但不影响当前测试。

**核心方法：**

- **ping 前记录 HITS**
- **ping 后再看 HITS**
- **涨了 → 策略命中；没涨 → 策略没匹配上**

---

### 4.2 策略不命中的排查

**如果 HITS 不涨，可能原因：**

| 原因 | 检查方法 |
|------|----------|
| 方向写反 | 看源 zone 和目的 zone 是否对调 |
| 源地址限定太严 | 比如写死 192.168.1.2，实际是 192.168.10.0/24 |
| 服务限定太严 | 比如只放 https，实际是 icmp |
| 接口不在 zone 里 | `display firewall zone` |
| 包根本没到防火墙 | 看接口 Input packets |

## 五、NAT 层

### 5.1 查看 NAT 策略

**命令：**

```
display nat-policy rule all
```

**典型反馈：**

```
nat-policy
 rule name snat_to_internet
  source-zone trust
  destination-zone untrust
  action source-nat easy-ip
```

**讲解：**

- `source-zone trust` / `destination-zone untrust` → 只对从 trust 到 untrust 的流量做 NAT。
- `source-nat easy-ip` → 用出接口 IP 做转换（即 100.1.1.2）。
- **NAT 只对穿越防火墙的流量生效，防火墙自己发起的流量不走 NAT。**

**验证 NAT 是否生效：**

- 核心 ping 外网时，看 `snat_to_internet` 的 HITS 涨不涨。
- 涨 → NAT 命中，源地址被转换成 100.1.1.2。
- 不涨 → NAT 没命中，检查源/目的 zone 是否正确。

## 六、会话表层

### 6.1 查看会话表

**命令：**

```
display firewall session table
```

**典型反馈（无流量）：**

```
Current Total Sessions : 0
```

**典型反馈（PC1 ping 外网时）：**

```
Current Total Sessions : 1
  ICMP  VPN: default  Status: normal
  Source IP: 192.168.10.2
  Destination IP: 200.1.1.1
  Source IP (NAT): 100.1.1.2
  Destination IP (NAT): 200.1.1.1
```

**讲解：**

- `Status: normal` → 会话正常建立。
- `Source IP: 192.168.10.2` → 原始源地址。
- `Source IP (NAT): 100.1.1.2` → **经过 NAT 转换后的源地址。**
- 有这条会话，说明 NAT 生效，包正常转发。
- **如果会话表为空，说明包根本没到防火墙，或者被更早的环节丢弃。**

**注意：**

该版本不支持 `| include` 管道过滤，可以用：

```
display firewall session table source 192.168.10.2
display firewall session table protocol icmp
```

## 七、ARP 层

### 7.1 查看 ARP 表

**命令：**

```
display arp | include 100.1.1
```

**典型反馈：**

```
IP ADDRESS      MAC ADDRESS     EXPIRE(M) TYPE INTERFACE      VPN-INSTANCE      
100.1.1.2       00e0-fc7c-390f            I -  GE1/0/0
100.1.1.1       00e0-fcfd-333b  10        D-0  GE1/0/0
```

**讲解：**

- `100.1.1.2` 是防火墙自己的接口地址，`I -` 表示 Interface 类型。
- `100.1.1.1` 是对端地址，`D-0` 表示动态学习，EXPIRE(M) = 10 分钟。
- **ARP 表里有对端表项，说明二层学习正常。**
- 如果没有对端表项，说明 ARP 请求没得到回应，链路层可能有问题。

---

## 八、完整排查流程（命令 + 反馈 + 判读）

| 步骤 | 命令 | 反馈重点 | 判读 |
|------|------|----------|------|
| 1 | `display ip interface brief` | Physical/Protocol 是否 up | 接口正常？ |
| 2 | `display current-configuration interface` | 是否绑定 VPN 实例 | 有绑定？去掉 |
| 3 | `display firewall zone` | 接口在哪个 zone | 方向对吗？ |
| 4 | `display ip routing-table` | 去程/回程路由 | 路由齐吗？ |
| 5 | `display ip routing-table vpn-instance default` | VPN 实例路由 | 路由在哪个实例？ |
| 6 | `display security-policy rule all` | HITS 变化 | 策略命中吗？ |
| 7 | `display nat-policy rule all` | HITS 变化 | NAT 命中吗？ |
| 8 | `display firewall session table` | 会话建立 | NAT 生效吗？ |
| 9 | `display arp \| include x.x.x.x` | ARP 表项 | 二层学习了吗？ |
| 10 | `display interface GigabitEthernet1/0/1` | Input/Output packets | 包到哪一步了？ |

---

## 九、关键判读原则

1. **接口 Physical/Protocol 必须双 up**，否则先解决链路问题。
2. **路由表要看对实例**，公网实例和 VPN 实例可能不一样。
3. **策略看 HITS**，涨了才说明命中，不涨就是没匹配上。
4. **NAT 看 HITS 和会话表**，会话表里有 NAT 后地址才说明转换成功。
5. **接口 Input/Output packets 是金标准**：
   - Input 涨、Output 不涨 → 收到包但不回
   - Output 涨、Input 不涨 → 发出去了但对端没回
6. **首次 ping 丢包是正常的**，ARP 学习需要时间。
