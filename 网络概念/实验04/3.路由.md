# 三、路由（静态路由、默认路由）详细讲解

## 1. 背景知识：路由表的三种来源

路由器转发数据包的核心依据是**路由表**。路由表条目按来源可分为三类：

| 类型 | 来源 | 特点 |
|------|------|------|
| **直连路由（Direct）** | 接口配置 IP 并 up 后自动生成 | 无需手动配置，优先级最高（Preference=0） |
| **静态路由（Static）** | 管理员手动配置 `ip route-static` | 精确可控，优先级默认 60 |
| **默认路由（Default）** | 静态路由的特例：`0.0.0.0/0` | 匹配所有目的地址，作为"最后的选择" |

**匹配原则**：最长掩码匹配（Longest Prefix Match）。掩码越长越优先；掩码相同时比较优先级（Preference），优先级小者优先。

## 2. 拓扑结构分析

```
PC1 ---- R1 ---- R2 ---- PC2
     192.168.1.0/24  192.168.2.0/24
         10.0.12.0/24（R1-R2 互联段）
```

**地址规划**：

| 设备 | 接口 | IP 地址 | 说明 |
|------|------|---------|------|
| PC1 | — | 192.168.1.2/24 | 网关 192.168.1.1 |
| R1 | GE0/0/0 | 192.168.1.1/24 | 连接 PC1（直连） |
| R1 | GE0/0/1 | 10.0.12.1/24 | 连接 R2（直连） |
| R2 | GE0/0/0 | 10.0.12.2/24 | 连接 R1（直连） |
| R2 | GE0/0/1 | 192.168.2.1/24 | 连接 PC2（直连） |
| PC2 | — | 192.168.2.2/24 | 网关 192.168.2.1 |

---

## 3. 为什么要用默认路由 + 明细路由的组合？

### 边缘路由器 R1 的视角
- R1 是"边缘设备"，只有两条出路：连 PC1（本地）和连 R2（上行）。
- 除了本地 192.168.1.0/24 和互联段 10.0.12.0/24 是直连外，**其他所有目的地都必须走 R2**。
- 如果为每个远程网段都写一条静态路由，配置量巨大且无法适应网络变化。
- **解决方案**：写一条默认路由 `0.0.0.0/0 → 10.0.12.2`，代表"我不知道去哪儿，全丢给 R2"。

### 核心路由器 R2 的视角
- R2 是"核心/汇聚设备"，下挂多个网段，未来可能连接更多边缘路由器。
- 如果 R2 也配默认路由指向 R1，会造成**路由环路**或错误转发（因为 R2 可能还有别的下行网络）。
- **解决方案**：R2 必须精确知道"PC1 所在的 192.168.1.0/24 要通过 R1 到达"，因此配置**明细静态路由**。

> **口诀**：边缘指默认（"甩锅"给核心），核心指明细（精确回程）。

## 4. 命令语法详解

### 4.1 `ip route-static` 基本语法（华为 VRP）

```
ip route-static <目的网络> <子网掩码> <下一跳IP> [preference <优先级>]
```

| 参数 | 含义 | 示例 |
|------|------|------|
| 目的网络 | 目标网段地址 | `192.168.1.0` |
| 子网掩码 | 可以是点分十进制或掩码长度 | `255.255.255.0` 或 `24` |
| 下一跳 | 下一跳路由器接口 IP | `10.0.12.1` |
| preference | 可选，默认 60 | `preference 100` |

### 4.2 默认路由的写法

```
ip route-static 0.0.0.0 0.0.0.0 10.0.12.2
```

- `0.0.0.0 0.0.0.0` 表示"所有目的地址"，掩码长度 0，是最短匹配。
- 由于最长匹配原则，只有当没有更精确的路由匹配时，才会使用默认路由。

### 4.3 查看路由表

```
display ip routing-table
```

会看到 `Destination/Mask`、`Proto`（Direct/Static）、`Pre`（优先级）、`NextHop`、`Interface` 等列。

## 5. 参考脚本逐行解析

### R1（边缘路由器）

```bash
system-view                       # 进入系统视图
sysname R1                        # 修改设备名
undo info-center enable           # 关闭日志信息干扰（实验环境用）

interface GigabitEthernet0/0/0    # 进入连接 PC1 的接口
 ip address 192.168.1.1 24        # 配置网关地址，自动生成直连路由 192.168.1.0/24
interface GigabitEthernet0/0/1    # 进入连接 R2 的接口
 ip address 10.0.12.1 24          # 自动生成直连路由 10.0.12.0/24

# 默认路由：所有未知流量交给 R2
ip route-static 0.0.0.0 0.0.0.0 10.0.12.2
```

**R1 最终路由表**：
```
Destination/Mask    Proto   Pre  NextHop       Interface
0.0.0.0/0           Static  60   10.0.12.2     GE0/0/1   ← 默认路由
10.0.12.0/24        Direct  0    10.0.12.1     GE0/0/1   ← 直连
192.168.1.0/24      Direct  0    192.168.1.1   GE0/0/0   ← 直连
```

当 PC1 ping 192.168.2.2 时，R1 查表：目的地址 192.168.2.2 不匹配任何直连路由，只匹配 `0.0.0.0/0`，于是转发给 10.0.12.2（R2）。

### R2（核心路由器）

```bash
system-view
sysname R2
undo info-center enable

interface GigabitEthernet0/0/0
 ip address 10.0.12.2 24          # 自动生成直连 10.0.12.0/24
interface GigabitEthernet0/0/1
 ip address 192.168.2.1 24        # 自动生成直连 192.168.2.0/24

# 回程静态路由：告诉 R2，PC1 网段要通过 R1 到达
ip route-static 192.168.1.0 255.255.255.0 10.0.12.1
```

**R2 最终路由表**：
```
Destination/Mask    Proto   Pre  NextHop       Interface
10.0.12.0/24        Direct  0    10.0.12.2     GE0/0/0
192.168.1.0/24      Static  60   10.0.12.1     GE0/0/0   ← 明细静态
192.168.2.0/24      Direct  0    192.168.2.1   GE0/0/1
```

当 R2 收到回包目的地址 192.168.1.2 时，精确匹配 192.168.1.0/24，转发给 10.0.12.1（R1）。

## 6. 数据转发全流程（PC1 ping PC2）

| 步骤 | 设备 | 动作 |
|------|------|------|
| 1 | PC1 | 目的 192.168.2.2 不在本网段 → 交给网关 192.168.1.1 |
| 2 | R1 | 查表，匹配默认路由 `0.0.0.0/0` → 下一跳 10.0.12.2 |
| 3 | R2 | 查表，匹配直连 192.168.2.0/24 → 从 GE0/0/1 发出 |
| 4 | PC2 | 收到 ICMP 请求，构造回包，目的 192.168.1.2 → 交给网关 192.168.2.1 |
| 5 | R2 | 查表，匹配静态 192.168.1.0/24 → 下一跳 10.0.12.1 |
| 6 | R1 | 查表，匹配直连 192.168.1.0/24 → 从 GE0/0/0 发给 PC1 |
| 7 | PC1 | 收到回包，ping 成功 |

**抓包观察点**：
- 在 R1 的 GE0/0/1（或 R2 的 GE0/0/0）抓包，可以看到 ICMP Echo Request 的源 IP 是 192.168.1.2，目的 IP 是 192.168.2.2。
- 在 R1 上 `display ip routing-table 192.168.2.2` 可以看到匹配的是 `0.0.0.0/0`，验证默认路由生效。

## 7. 验证命令汇总

```bash
# 查看完整路由表
display ip routing-table

# 查看某目的地址匹配哪条路由（关键验证命令）
display ip routing-table 192.168.2.2

# 查看静态路由配置
display ip routing-table protocol static

# 测试连通性（在 R1 上）
ping 192.168.2.2

# 追踪路径（在 R1 上）
tracert 192.168.2.2
```

**`display ip routing-table 192.168.2.2` 的典型输出**：
```
Destination/Mask    Proto   Pre  Cost  NextHop       Interface
0.0.0.0/0           Static  60   0     10.0.12.2     GE0/0/1
```
这证明 R1 使用了默认路由来转发目的为 192.168.2.2 的包。

## 8. 常见易错点与排错

| 问题 | 原因 | 解决 |
|------|------|------|
| PC1 能 ping 通 R2 但 ping 不通 PC2 | R2 缺回程路由 | 在 R2 加 `ip route-static 192.168.1.0 24 10.0.12.1` |
| R1 配了默认路由但仍不通 | 下一跳写错 / 接口 down | `display ip interface brief` 检查接口状态 |
| 默认路由被更精确路由覆盖 | 最长匹配原则 | 正常现象，检查是否有冲突的明细路由 |
| PC 网关未配置 | PC 不知道往哪发 | 检查 PC 的 IP/掩码/网关 |
| 单向通（请求通、回包不通） | 只有一边有路由 | 路由必须双向可达 |

## 9. 进阶对比：默认路由 vs 明细路由

| 对比项 | 默认路由 | 明细静态路由 |
|--------|----------|--------------|
| 目的网段 | 0.0.0.0/0 | 具体网段，如 192.168.1.0/24 |
| 匹配优先级 | 最低（掩码最短） | 较高（掩码长） |
| 适用位置 | 边缘/末梢路由器 | 核心/汇聚路由器 |
| 配置量 | 一条搞定 | 每个网段一条 |
| 风险 | 可能造成次优路径或环路 | 精确但维护量大 |
| 典型场景 | 企业出口指向 ISP | 核心指向各分支 |

---

## 10. 总结

1. **直连路由**自动生成，优先级最高，无需配置。
2. **静态路由**手动配置，用于精确控制转发路径。
3. **默认路由**是 `0.0.0.0/0` 的静态路由，作为"兜底"。
4. **边缘路由器配默认路由**（甩锅给核心），**核心路由器配明细路由**（精确回程），这是企业网最经典的配置模式。
5. 转发依据是**最长掩码匹配**，其次是**优先级（Preference）**。
6. 排错三板斧：`display ip routing-table`、`ping`、`tracert`。

---

## 11. 常用查看命令

| 命令 | 作用 |
|---|---|
| `display ip routing-table` | 查看 IPv4 路由表 |
| `display ip routing-table 192.168.2.0` | 查看去往某网段的具体路由 |
| `display ip routing-table protocol static` | 只看静态路由 |
| `display ip routing-table verbose` | 查看详细路由信息（含优先级、Cost等） |
