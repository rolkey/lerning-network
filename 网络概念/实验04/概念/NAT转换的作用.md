# NAT转换的作用

- 配置一个默认路由就可以上网，设置NAT转换有什么作用？

这是一个非常经典且关键的问题。你的观察是对的：**配置默认路由确实是上网的必要条件，但光有默认路由，通常只能让“路由器自己”上网，或者让内网设备在特定条件下上网，却无法让整个内网正常访问互联网。**

NAT 转换的核心作用，是解决**私有 IP 地址无法在公网路由**这个根本矛盾。

我们可以分三步来看清楚：

### 1. 默认路由解决了“往哪走”的问题

默认路由（`0.0.0.0/0`）告诉路由器：**“所有我不认识的目标地址，都从 WAN 口扔给运营商。”**

这解决了**方向**问题。没有它，路由器收到内网发来的包，查路由表发现没有去往 `8.8.8.8` 的路由，就会直接丢弃，根本发不出去。

### 2. 但公网路由器“不认识”你的内网 IP

假设你内网电脑 IP 是 `192.168.1.100`，它想访问 `8.8.8.8`。

- 电脑把包发给路由器，源 IP 是 `192.168.1.100`。
- 路由器有默认路由，把这个包转发给了运营商。
- 运营商的路由器收到包，一看源地址是 `192.168.1.100`——**这是一个私有地址（RFC 1918），互联网上的公网路由器一律不承认、不路由、直接丢弃。**

所以，包虽然发出去了，但**永远收不到回包**。这就是为什么光有默认路由不够。

### 3. NAT 转换解决了“身份”问题

NAT 在路由器转发这个包**之前**，做了一件事：

- 把源 IP `192.168.1.100` **替换成** WAN 口的公网 IP，比如 `203.0.113.5`。
- 同时记录一条映射表：`203.0.113.5:随机端口` ↔ `192.168.1.100:原端口`。

这样，包到了公网，源地址是合法的公网 IP，`8.8.8.8` 的回包就能回到 `203.0.113.5`。路由器再根据映射表，把回包的目标 IP 改回 `192.168.1.100`，最终送到你的电脑。

### 对比总结

| 配置 | 路由器自己能上网吗 | 内网电脑能上网吗 | 原因 |
| :--- | :--- | :--- | :--- |
| 只有默认路由 | ✅ 能 | ❌ 不能 | 内网私有 IP 在公网不可路由，回包丢失 |
| 默认路由 + NAT | ✅ 能 | ✅ 能 | 源 IP 被替换成公网 IP，回包能正确返回 |

### 一个容易混淆的例外

如果运营商直接给你分配了一个**公网 IP 段**，并且在你路由器 WAN 口做了回程路由，那么内网设备用公网 IP 上网时，确实可以不用 NAT。但这在家庭宽带中几乎不存在，企业专线里才可能见到。

所以结论是：**默认路由是“路”，NAT 是“通行证”。** 没有路走不了，没有通行证，路通了也会被公网“遣返”。
