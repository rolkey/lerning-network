要判断设备是否真正用上了 MPLS，不能只看配置，关键要看**LDP 会话是否建立**以及**标签转发路径（LSP）是否生成**。

你可以按以下顺序在 R1 上执行命令来检查：

### 🔍 第一步：检查 LDP 会话状态

首先确认邻居关系是否正常。LDP 会话是交换标签的前提。

```text
<R1> display mpls ldp session
```

**怎么看结果**：看 `Status` 字段。如果显示为 **`Operational`**，说明 R1 与 R2 的 LDP 会话已经成功建立，可以正常交换标签了。如果显示 `Non-existent` 或 `Initialized`，则说明会话还没建立起来。

你也可以用 `display mpls ldp peer` 快速确认发现了哪些 LDP 邻居。

### 🏷️ 第二步：检查 LSP 是否生成（最关键的一步）

这是判断 MPLS 是否“在用”的核心。如果路由表里有去往 `3.3.3.3` 的路由，但没有对应的 LSP，数据包依然走普通的 IP 转发。

```text
<R1> display mpls lsp
```

**怎么看结果**：在输出的 `LDP LSP` 区域中，查找 `FEC` 为 `3.3.3.3/32` 的那一行。

*   如果存在这一行，并且 `In/Out Label` 字段**不是 `NULL/NULL`**，就说明 R1 已经为去往 `3.3.3.3` 的流量生成了 LSP，MPLS 已经在工作了。
*   例如，看到 `3.3.3.3/32    NULL/32829   -/GE0/0/0` 这样的条目，就表示 R1 会把去往 `3.3.3.3` 的包打上标签 `32829`，从 `GE0/0/0` 发出去。

### ⚙️ 第三步：检查接口是否已启用 MPLS

如果前两步不成功，可以回头检查接口配置。

```text
<R1> display mpls interface
```

**怎么看结果**：查看输出列表中是否包含了你的互联接口（如 `GigabitEthernet0/0/0`）。如果接口在列表中，说明该接口的 MPLS 功能已经激活。

### 💡 补充验证：用 MPLS Ping 确认路径连通性

这是最直接的“活体检测”，专门测试 MPLS LSP 的连通性。它和普通 `ping` 不同，普通 `ping` 走的是 IP 路径，而 MPLS Ping 会强制走标签路径。

```text
<R1> ping mpls ipv4 3.3.3.3 32
```

如果能收到回复，就说明整条 MPLS LSP 从 R1 到 R3 完全通畅，MPLS 转发路径已经稳稳地工作了。
