## 一、实验目的

这个实验的目标是：**在 eNSP 上搭建一个三台路由器的 MPLS 基础环境，并验证标签转发路径（LSP）已经建立。**

具体拆解成三个层次：

1. **底层 IP 可达**：三台路由器之间能互相 ping 通对方的 Loopback 地址。
2. **MPLS/LDP 启用**：在互联接口上启用 MPLS 和 LDP，让路由器之间能交换标签。
3. **LSP 建立**：去往远端 Loopback 的标签交换路径已经生成，数据包可以靠标签转发。

你现在完成的是**第 1 层**——底层 IP 可达。这是后面两层的地基。

---

## 二、拓扑结构

```
R1(1.1.1.1) --- 10.0.12.0/24 --- R2(2.2.2.2) --- 10.0.23.0/24 --- R3(3.3.3.3)
```

- R1 和 R3 不直连，中间隔着 R2。
- 每台路由器有一个 Loopback0 接口，作为自己的唯一标识。
- 互联接口用 10.0.x.x 网段。

## 三、每一步的概念讲解

### 第 1 步：配置接口 IP 地址

**操作：**
```text
[R1] interface GigabitEthernet0/0/0
[R1-GigabitEthernet0/0/0] ip address 10.0.12.1 255.255.255.0
```

**概念：**
- 路由器要转发数据包，必须先有接口，接口必须有 IP 地址。
- 直连的两个接口必须在**同一网段**，否则它们无法直接通信。
- 这里的 `10.0.12.0/24` 是 R1 和 R2 之间的"链路网段"，只用于这两台设备之间的通信。

**为什么用 /24 而不是 /30？**
- `/30` 更节省地址（只有 2 个可用地址），是真实网络中的常见做法。
- `/24` 更直观，初学阶段方便记忆。两者在这个实验里效果一样。

---

### 第 2 步：配置 Loopback0 接口

**操作：**
```text
[R1] interface LoopBack0
[R1-LoopBack0] ip address 1.1.1.1 255.255.255.255
```

**概念：**
- Loopback 是**逻辑接口**，不是物理接口。只要路由器开机，它就存在，不会因为线路故障而 down。
- 掩码用 `32`（即 `255.255.255.255`），表示这是一个**主机地址**，不是一个网段。
- 每台路由器的 Loopback0 地址必须**全网唯一**。

**为什么需要 Loopback？**

| 用途 | 说明 |
|---|---|
| 作为 OSPF Router-ID | 唯一标识一台 OSPF 路由器 |
| 作为 MPLS LSR-ID | 唯一标识一台 MPLS 路由器 |
| 作为测试目标 | ping 它等于 ping 这台设备本身，不受物理线路影响 |
| 作为 BGP 邻居地址 | 后续 MPLS VPN 实验中会用到 |

**为什么不用物理接口地址做测试目标？**
- 物理接口如果断了，地址就不可达了。
- Loopback 永远在线，只要路由器有路由能到达它，它就可达。

---

### 第 3 步：配置 OSPF

**操作：**
```text
[R1] ospf 1 router-id 1.1.1.1
[R1-ospf-1] area 0
[R1-ospf-1-area-0.0.0.0] network 1.1.1.1 0.0.0.0
[R1-ospf-1-area-0.0.0.0] network 10.0.12.0 0.0.0.255
```

**概念：**
- OSPF 是**动态路由协议**，作用是让路由器互相学习路由，自动构建路由表。
- `network` 命令的作用是：**把匹配这个网段的接口，加入到 OSPF 进程中**。
- `network 1.1.1.1 0.0.0.0` 中的 `0.0.0.0` 是**反掩码**，表示精确匹配 `1.1.1.1` 这一个地址。
- `network 10.0.12.0 0.0.0.255` 表示匹配 `10.0.12.0/24` 这个网段。

**反掩码是什么？**
- 反掩码 = `255.255.255.255` 减去 正常掩码。
- `/24` 的正常掩码是 `255.255.255.0`，反掩码就是 `0.0.0.255`。
- `/32` 的正常掩码是 `255.255.255.255`，反掩码就是 `0.0.0.0`。

**为什么每台路由器只宣告自己直连的网段？**

| 设备 | 应宣告 | 原因 |
|---|---|---|
| R1 | 1.1.1.1/32、10.0.12.0/24 | 这两个是 R1 直连的 |
| R2 | 2.2.2.2/32、10.0.12.0/24、10.0.23.0/24 | 这三个是 R2 直连的 |
| R3 | 3.3.3.3/32、10.0.23.0/24 | 这两个是 R3 直连的 |

如果 R1 宣告了 `10.0.23.0/24`，但 R1 根本没有这个网段的接口，OSPF 会忽略这条宣告，不会报错，但配置没有意义，反而让配置变得混乱。

**OSPF 邻居关系：**
- R1 和 R2 通过 `10.0.12.0/24` 网段建立邻居。
- R2 和 R3 通过 `10.0.23.0/24` 网段建立邻居。
- R1 和 R3 不直连，所以它们不是邻居，但可以通过 R2 学习到对方的路由。

---

### 第 4 步：验证底层 IP 可达

**操作：**
```text
<R1> ping 3.3.3.3
```

**概念：**
- 这个 ping 的**源地址**是 R1 的某个接口地址（通常是出接口地址或 Loopback0）。
- **目的地址**是 R3 的 Loopback0（3.3.3.3）。
- 数据包的路径是：R1 → R2 → R3。
- R1 查路由表，发现去往 `3.3.3.3/32` 的路由下一跳是 `10.0.12.2`（R2）。
- R2 查路由表，发现去往 `3.3.3.3/32` 的路由下一跳是 `10.0.23.3`（R3）。
- R3 收到包，发现目的地址是自己的 Loopback0，回复 ICMP Echo Reply。
- 回复包沿原路返回 R1。

**ping 通说明：**
1. R1 有去往 3.3.3.3 的路由。
2. R2 有去往 3.3.3.3 的路由。
3. R3 有去往 R1 源地址的路由（否则回复包回不来）。
4. 整条路径的接口都是 up 的。

**如果 ping 不通，排查顺序：**
1. `display ip interface brief` — 接口是否 up，IP 是否配对。
2. `display ospf peer brief` — OSPF 邻居是否 FULL。
3. `display ip routing-table 3.3.3.3` — 路由表里有没有这条路由。
4. `display current-configuration` — 配置有没有漏。

## 四、这个实验在 MPLS 学习中的位置

你现在完成的是 MPLS 实验的**第一阶段**。完整的 MPLS 实验分三个阶段：

| 阶段 | 目标 | 状态 |
|---|---|---|
| 第一阶段 | 底层 IP 可达（OSPF 通） | ✅ 已完成 |
| 第二阶段 | 启用 MPLS 和 LDP，建立 LDP 邻居 | 下一步 |
| 第三阶段 | 验证 LSP 生成，抓包看标签转发 | 最终目标 |

**为什么必须先做第一阶段？**
- MPLS 的标签分发依赖 IP 路由。LDP 需要知道对方的 LSR-ID（Loopback 地址）怎么走。
- 如果 OSPF 没通，LDP 邻居就建不起来，标签也分不下去。
- 所以 OSPF 是 MPLS 的"地基"，地基不稳，后面全塌。
