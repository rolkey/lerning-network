# 📑 跨平台（eNSP + HCL）A/B 平面实验排错总结

## 一、 核心架构与原理
*   **设计目标**：使用华为（A面）和华三（B面）设备，通过 VRRP 实现网关冗余，通过浮动静态路由实现出口链路冗余。
*   **技术难点**：跨厂商、跨模拟器（eNSP 和 HCL 底层不互通，必须依靠宿主机虚拟网卡进行 L2 桥接）。

---

## 二、 遇到的核心“坑”与解决方法

### 💣 坑 1：底层桥接不通，数据包石沉大海
*   **现象**：配置全对，但跨平台设备互 Ping 不通。抓包能看到 ARP 请求，但没有回应。
*   **原因**：
    1.  **网卡未“激活”**：宿主机虚拟网卡（VirtualBox Host-Only）未配置 IP。Windows 认为其未激活，底层抓包驱动（WinPcap/Npcap）无法将其作为透明通道收发数据帧。
    2.  **端口映射缺失**：eNSP 的 Cloud 配置了 UDP 绑定，但漏了“端口映射（双向通道）”。
    3.  **HCL Host 假死**：HCL 的 Host 设备底层驱动未刷新。
*   **解决办法**：给宿主机所有用于桥接的虚拟网卡配置一个**与模拟器业务无关的“废 IP”**（如 192.168.25x.1）；确保 Cloud 映射双向；重启 HCL 设备。

### 💣 坑 2：“幽灵 IP”导致全网瘫痪
*   **现象**：没开 eNSP，但在宿主机上能 ping 通模拟器网段的 IP（如 172.16.0.1），导致模拟器内部频繁丢包。
*   **原因**：宿主机连了真实的 Wi-Fi，而真实物理网络中恰好存在同网段设备；或者宿主机虚拟网卡残留了模拟器网段的静态 IP，导致 Windows 路由表抢答，拦截了模拟器的数据包。
*   **解决办法**：
    1.  做实验时**关闭 Wi-Fi**。
    2.  **清理宿主机网络**：网卡 IP 设为自动获取，执行 `arp -d *` 清空缓存。

### 💣 坑 3：VLAN 成员缺失导致三层接口 DOWN
*   **现象**：`Vlanif 100` 怎么都起不来，VRRP 卡在 `Initialize` 状态。
*   **原因**：物理端口虽然 `UP`，但并没有被真正划分到该 VLAN 的成员列表（`Untagged ports`）中。没有物理端口支撑，VLAN 接口就是死的。
*   **解决办法**：进入物理端口，强刷 `port access vlan xxx`。用 `display vlan xxx` 确认端口在成员列表中。

### 💣 坑 4：单台设备双网卡同网段冲突
*   **现象**：模拟双网卡 PC（路由器）时，配置第二个接口报错 `Error: The specified address conflicts...`。
*   **原因**：华为 VRP 系统底层防环机制，禁止同一台设备（即使是路由器模拟的PC）的两个物理接口配置在同网段（即使掩码改为 /25 或 /30 拆分也不行）。
*   **解决办法**：换用**两台独立的设备**分别连接 A/B 面，或者用核心路由器作为源进行测试。

### 💣 坑 5：主备路由“假死”不切换
*   **现象**：断开 A 面接口，核心路由器依然把包发给 A 面，导致全 Timeout。
*   **原因**：
    1.  只 `shutdown` 了三层 `Vlanif` 接口，物理口依然是 UP 的，eNSP 路由进程认为主路还能走，没有触发备用路由。
    2.  备用路由（`preference 70`）根本没配成功。
*   **解决办法**：**关闭物理接口**（`shutdown` GE 口）模拟断线；用 `display current-configuration | include ip route-static` 检查备用路由是否存在。

## 三、 网络排错的“黄金三板斧”

将来再遇到网络不通，不要瞎猜，按这个顺序查，99% 的问题都能现形：

### 🪓 第一斧：看接口与链路状态
*   检查物理层：`display interface GigabitEthernet 0/0/x` （物理和协议双 UP 吗？）
*   检查二层：`display vlan xxx` （端口在不在里面？）
*   检查三层：`display interface Vlanif xxx` （状态是不是 UP？IP 对不对？）

### 🪓 第二斧：看路由与 ARP 缓存
*   查路由表：`display ip routing-table x.x.x.x` （下一跳是谁？走的哪个接口？）
*   查 ARP 表：`display arp | include x.x.x.x` （有没有学到对端的 MAC？MAC 对不对？）
*   *排查大法*：直接去对端设备 ping 源端，**双向互测**，看是单向不通还是双向不通。

### 🪓 第三斧：抓包看底层（终极法医）
*   **eNSP 内部**：用内置抓包工具，看接口有没有收发包。
*   **跨平台链路**：在宿主机打开 **Wireshark**，抓取桥接的虚拟网卡，看数据包是死在宿主机层面，还是进了 HCL 层面。

## 四、 实验建议与好习惯

1.  **先规划，后配置**：做复杂实验前，用 Excel 或画图软件写清楚 IP 规划表（A面、B面、心跳、业务），**千万不要随手乱配 IP**，今天你在 PC1 上配成 `192.168.10.3` 就是一个典型教训。
2.  **分层测试**：不要配完所有设备再测，一定要“配一段测一段”。先直连 Ping 通，再配路由，最后配 VRRP。
3.  **善用 Clean 机制**：跨平台实验很脏，如果拓扑彻底乱了，不要死磕，直接关掉模拟器，清空 Windows 缓存，重新连线，往往比排错快得多。
