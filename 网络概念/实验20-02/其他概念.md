# 概念

## 概念讲解

- 核心交换机：核心交换机是网络中的关键设备，它连接着网络中的各个部分，如接入交换机、汇聚交换机等。核心交换机通常具有高带宽、高可靠性、高性能等特点，可以处理大量的数据流量，保证网络的稳定性和可靠性。
- POE：接入交换机
- PBR：
- NQA：
- IP-Link联动：IP-Link联动是华为交换机的一种特性，当交换机检测到某个端口上的链路出现故障时，会自动将该端口上的所有VLAN的流量切换到其他端口上，从而保证网络的稳定性和可靠性。IP-Link联动可以应用于各种网络环境，包括数据中心、园区网、城域网等。

# 策略路由（PBR）讲解

## 一句话本质

普通路由是**「只看收件地址」**的快递分拣：查路由表，按目的 IP 找下一跳。
策略路由（Policy-Based Routing, PBR）是**「先看包裹标签」**：源地址是谁、什么业务、从哪个口进来的、要不要走专线——按管理员写好的策略强行指定路径，**优先级高于路由表**。

> 只要报文命中策略，路由表就被"绕过"；没命中，才老老实实回去查路由表。

---

## 一、和普通路由的区别

| 维度 | 普通路由（Destination-based） | 策略路由 PBR |
|---|---|---|
| 决策依据 | **目的 IP** | 源 IP、目的 IP、协议、端口、DSCP/TOS、入接口、报文长度、应用等 |
| 决策位置 | 全局路由表（RIB/FIB），所有报文一视同仁 | 接口/全局上挂的策略，按需匹配 |
| 优先级 | 兜底 | **先于路由表**执行，命中即改道 |
| 谁来定 | 动态路由协议 / 静态路由自动生成 | 管理员手工定义"哪类流量走哪条路" |
| 典型诉求 | 全网可达 | 分流、引流、差异化服务 |

一个直观例子：公司有电信和联通两条出口，路由表默认只指向电信。想让**财务网段走联通专线、其他人都走电信**——路由表做不到（两条默认路由等价就变负载均衡了），PBR 一行策略就搞定。

---

## 二、报文是怎么被"改道"的

```
报文进入接口
   ↓
① 匹配（match）：ACL / 流分类，判断"是不是这类流量"
   ↓ 命中
② 动作（set / apply）：指定下一跳、出接口、优先级标记……
   ↓
③ 转发：按策略指定的路径走（不再按目的地址查表）
   ↓ 未命中
④ 回退：正常查路由表转发
```

**能匹配什么**
- 源/目的 IP、网段（最常用）
- 协议类型、TCP/UDP 端口号（如 HTTP、视频流）
- DSCP / IP Precedence / TOS
- 入接口、报文长度、时间段（部分厂商支持）

**能做什么动作**
- `set ip next-hop` → 指定下一跳 IP
- `set interface` → 指定出接口（多用于点对点链路）
- `set ip default next-hop` → **先查路由表，没明细路由才用策略**（和普通 PBR 顺序相反，容易混）
- `set ip precedence / dscp` → 顺手打 QoS 标记
- 多下一跳 + Track/NQA → 主备切换，避免黑洞

## 三、配置骨架（Cisco 风格）

```cisco
! 1. 定义"谁"要被管
access-list 10 permit 192.168.10.0 0.0.0.255     ! 财务网段

! 2. 定义"怎么走"
route-map PBR-FINANCE permit 10
 match ip address 10
 set ip next-hop 10.1.2.254                       ! 走联通专线
!
route-map PBR-FINANCE permit 20                   ! 其余流量不设动作 = 查路由表

! 3. 挂到流量**进入**的那个接口（关键：是入方向）
interface GigabitEthernet0/0
 ip policy route-map PBR-FINANCE
```

排查三板斧：`show route-map`、`show ip policy`、`debug ip policy`（生产环境慎用），再加 `traceroute` 带源地址验证。

**华为系**思路相同、语法不同：用 `traffic classifier` + `traffic behavior`（`redirect ip-nexthop`）+ `traffic policy` 挂在入方向；或用 `policy-based-route` 的 `if-match` / `apply ip-address next-hop`。另外华为/华三的**本地 PBR** 和**接口 PBR** 也分开，前者管设备自己发出的报文。

---

## 四、典型使用场景

1. **多出口分流**：办公网走廉价宽带，服务器/财务/视频会议走高质量专线。
2. **服务链引流（Service Chaining）**：把流量先拐去防火墙、IPS、WAF、审计设备，洗完再回网络——旁挂部署不用改物理拓扑，全靠 PBR 拽过去。
3. **VPN / 隧道选路**：指定某业务进 IPsec / GRE 隧道，其余走公网。
4. **灰度与测试**：把某个测试终端的流量引到新链路或新版本网关，不影响其他人。
5. **QoS 前置标记**：在入口按业务打 DSCP，后面设备按标记做队列调度。
6. **成本/合规**：特定地区、特定合作方的流量必须走指定运营商或境内链路。

---

## 五、容易踩的坑

- **挂错方向**：PBR 作用在**入接口**（流量进设备的那一侧），挂到出接口不生效，这是新手第一大坑。
- **设备自己发的流量不生效**：接口 PBR 只管"过路"报文；路由器自身产生的（如本机 ping、SNMP、BGP）默认不命中，需要 `ip local policy route-map` 之类的本地策略。
- **下一跳挂了就黑洞**：策略指定的下一跳不可达时，报文不会自动回退到路由表（各平台行为有差异）。生产上一定配 `set ip next-hop verify-availability` + Track/NQA/联动，或用 `default next-hop`。
- **把路由表"架空"**：策略优先级太高，一旦写宽了（比如 ACL 写成 `permit ip any any`），所有流量都被拽走，路由协议算出来的最优路径全白算。排障时先怀疑 PBR。
- **和 NAT / VRF / ECMP 的顺序**：引流后地址转换、VRF 归属、回程路由都要对齐，尤其**回程流量不走同一条路**会造成不对称路径，被状态防火墙丢包。
- **硬件资源**：复杂匹配要占 ACL/TCAM 表项，老设备或低端盒子上大量 PBR 可能退化为 CPU 转发，吞吐掉一截。
- **IPv6 是另一套**：`ipv6 policy route-map`，别混用。

---

## 小结

PBR 的价值就一句：**让"谁走哪条路"由业务说了算，而不是由目的地址说了算**。它是分流、引流、服务链这类需求的标配工具，但也是一把双刃剑——策略越靠前、越隐蔽，排障时越容易被忽略。用它的三条纪律：挂入接口、给下一跳做可用性检测、写清"未命中就回退路由表"。
