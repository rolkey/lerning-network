在华为设备（交换机或防火墙）上实现策略路由，核心逻辑是“**定义匹配条件 + 指定转发动作 + 在接口入方向调用**”。结合你之前规划的双出口网络，最常用的方式是**通过流策略（MQC）将特定源网段的流量重定向到指定下一跳**，从而实现有线办公走固定专线、无线访客走拨号宽带的分流目标。

下面分别给出在**交换机**和**防火墙**上的实现方法，你可以根据策略部署的位置选择。

### 🛠️ 方式一：在交换机上配置（基于流策略的重定向）

这是最通用的方式。华为S系列交换机通过“流分类（匹配ACL）→ 流行为（重定向下一跳）→ 流策略（绑定两者）→ 接口入方向应用”的流程来实现策略路由。

**配置逻辑与关键命令：**
1.  **定义流分类**：用ACL匹配需要分流的内网源网段（例如有线办公网 `192.168.10.0/24`）。
2.  **定义流行为**：将匹配到的流量重定向到指定下一跳（即固定专线的网关）。可以配置多个下一跳实现主备，先配置的优先。
3.  **定义流策略**：将上述流分类和流行为绑定。
4.  **应用流策略**：在连接内网（Trust区域侧）的接口**入方向**调用该策略。

```bash
# 1. 匹配有线办公网段
acl 3000
 rule 5 permit ip source 192.168.10.0 0.0.0.255

# 2. 定义流分类，关联ACL
traffic classifier office_isp1 operator or
 if-match acl 3000

# 3. 定义流行为，重定向到固定专线下一跳
traffic behavior to_isp1
 redirect ip-nexthop 10.0.0.1   # 假设固定专线网关为10.0.0.1

# 4. 定义流策略，绑定分类与行为
traffic policy pbr_policy
 classifier office_isp1 behavior to_isp1

# 5. 在核心交换机连接防火墙的接口入方向应用
interface GigabitEthernet0/0/1
 traffic-policy pbr_policy inbound
```

**关键注意点**：策略路由要生效，交换机必须能学习到下一跳IP的ARP表项。如果ARP学习失败，报文会回退到原始路由表转发，重定向不生效。

### 🛡️ 方式二：在防火墙（USG6000V）上配置

如果你的核心交换机做二层透传，策略路由部署在防火墙上，配置方式略有不同。防火墙通常有专门的策略路由视图，或支持更智能的ISP选路。

**方式 A：命令行策略路由视图**
在系统视图下进入 `policy-based-route`，定义规则。匹配条件可以基于源安全区域、源IP等，动作是重定向到下一跳或出接口。
```bash
policy-based-route
 rule name office_to_isp1
  source-zone trust
  source-address 192.168.10.0 mask 255.255.255.0
  action redirect ip-nexthop 10.0.0.1
```

**方式 B：Web界面智能选路（更直观）**
对于双ISP出口，防火墙Web界面支持“智能选路”功能。你可以创建策略路由，匹配内网源地址，并将出接口指向固定专线。这种方式的好处是可以关联**健康检查（Health Check）**，当固定专线故障时，策略路由自动失效，流量回落到路由表走拨号备用链路，正好对应你需求5中的故障切换要求。

### 💡 针对你网络规划的两个实操要点

1.  **策略路由与NAT的配合**：策略路由只管“从哪个口出去”，NAT管“出去后源IP变成什么”。在你的出口防火墙上，需要确保**固定专线接口的NAT策略匹配的是有线办公网段**，这样策略路由将包引到该接口后，NAT才能正确转换。两条WAN口务必分别配置独立的NAT策略，避免回程流量混乱。
2.  **验证与排错**：配置完成后，在交换机或防火墙上使用 `display traffic policy statistics interface xxx inbound` 查看策略命中计数。如果计数不增长，优先检查：ACL是否匹配了正确网段、下一跳是否可达（ARP是否学到）、策略是否应用在了正确的接口和方向（**必须是入方向**）。
