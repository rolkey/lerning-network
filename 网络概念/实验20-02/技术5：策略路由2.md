在 USG6000V1（V500R005C10SPC300）上实现策略路由，核心是通过**策略路由规则（PBR Rule）** 匹配特定流量，并为其指定**出接口或下一跳**，同时结合 **IP-Link** 实现链路故障时的自动切换。

你的场景（有线办公/服务器走固定IP，访客走拨号）非常适合基于**源IP地址**进行匹配。以下是在该特定版本上的两种配置方式。

### 方式一：命令行（CLI）配置（推荐，更精准）

该版本的命令行策略路由配置逻辑清晰：定义规则 → 匹配源地址 → 执行动作（指定下一跳或出接口）。

**1. 基础准备：配置 IP-Link 健康探测**
为了让策略路由在固定IP断线时自动失效（流量回落到拨号链路），建议先配置 IP-Link 探测固定IP专线的网关。这是后续策略路由联动的关键。
```bash
system-view
ip-link check enable
ip-link name to_ISP1_Fixed
 destination <固定IP网关地址> interface GigabitEthernet1/0/1 mode icmp next-hop <固定IP网关地址>
```
*注：`GigabitEthernet1/0/1` 是假设的固定专线出接口，请根据实际拓扑替换。*

**2. 配置策略路由规则**
进入策略路由视图，创建规则，匹配有线办公网段，并重定向到固定专线网关。如果配置了 IP-Link，可以关联探测结果。
```bash
policy-based-route
 rule name Office_to_Fixed
  source-zone trust                    # 匹配来自内网信任区域的流量
  source-address 192.168.10.0 24       # 匹配有线办公网段（按你的规划修改）
  action redirect ip-nexthop <固定IP网关地址> ip-link to_ISP1_Fixed
```
*说明：`action redirect ip-nexthop` 用于指定下一跳。如果你希望直接指定出接口（例如拨号口是 Dialer 接口），也可以使用 `action redirect interface <接口名>`，但指定下一跳通常更灵活。*

**3. 验证与保存**
配置完成后，可以使用 `display policy-based-route rule name Office_to_Fixed` 查看规则状态，并通过 `display firewall session table` 观察流量是否按预期走向了固定专线。

### 方式二：Web 界面配置（直观，适合快速调整）

USG6000V 的 Web 界面（`https://<管理IP>:8443`）同样支持策略路由，且选项更直观。

1.  **登录 Web**：使用 admin 账号登录（首次登录需修改密码）。
2.  **进入配置页**：导航至 **“策略” > “策略路由”**，点击“新建”。
3.  **配置匹配条件**：
    *   **名称**：`Office_to_Fixed`
    *   **源安全区域**：选择 `trust`（内网）。
    *   **源地址**：选择或新建包含 `192.168.10.0/24` 的地址对象。
4.  **配置动作**：
    *   **动作**：选择“重定向”。
    *   **出接口/下一跳**：选择固定专线的出接口（如 `GE1/0/1`）或填入其下一跳 IP。
    *   **IP-Link 关联**：如果之前配了 IP-Link，这里可以下拉选择 `to_ISP1_Fixed`，实现联动。
5.  **应用**：点击确定保存。规则默认启用，按顺序匹配。

### 关键注意事项

*   **安全策略放行**：策略路由只负责“把包从哪个口送出去”。包被引到固定专线接口后，必须确保有一条**安全策略**允许 `trust` 到 `untrust`（或对应安全区域）的流量通过，否则会被防火墙默认拒绝。
*   **NAT 配合**：别忘了在固定专线的出接口上配置 **源 NAT（源地址转换）**，将 `192.168.10.0/24` 转换为该接口的公网 IP 或地址池，否则回包无法正确返回。
*   **版本差异**：你提到的 `V500R005C10SPC300` 是较早期的版本，Web 界面或部分命令细节可能与最新文档略有出入。如果命令行提示命令不存在，优先检查是否在正确的视图（`policy-based-route` 视图）下操作。
