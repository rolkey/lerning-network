“收敛”是网络工程里一个非常核心的概念，简单说就是：

**网络在发生拓扑变化后，所有设备重新达成一致、恢复无环路转发状态的过程。**

### 打个比方

想象一个会议室里几十个人在传话。平时大家都知道“找A要走左边，找B要走右边”。突然有人喊了一句“左边路断了！”

- 有人立刻改口：“那找A改走右边。”
- 有人还没听到，仍然说“找A走左边”。
- 这段时间里，信息是混乱的，有人会把消息传错方向，甚至传回原点形成环路。

直到**所有人都更新了自己的认知，并且对外说法一致**，会议室才恢复秩序。这个“从混乱到一致”的过程，就是收敛。

### 在网络里具体指什么

以 OSPF 为例：

1. **稳定状态**：所有路由器都有一致的链路状态数据库（LSDB），路由表里都有到达各个网段的正确路由。
2. **拓扑变化**：某条链路断了，或者新接入了一台设备。
3. **泛洪与计算**：检测到变化的路由器发出 LSA，其他路由器收到后更新 LSDB，各自重新跑 SPF 算法算路。
4. **收敛完成**：所有路由器的路由表都更新到新的一致状态，不再有错误路由或环路。

**收敛时间**就是从“变化发生”到“所有设备重新一致”所花的时间。

### 为什么你之前遇到的“路由表为空”和收敛有关

`display ip routing-table protocol ospf` 显示为空，通常就是：

- OSPF 邻居还没建立（还没开始交换信息）
- 或者邻居刚建立，SPF 还没算完
- 或者网络正在震荡，反复计算

也就是说，**网络还没收敛到稳定状态**，所以 OSPF 路由还没被装进路由表。

### 收敛快慢受什么影响

| 因素 | 影响 |
|---|---|
| Hello/Dead 定时器 | 默认 Hello 10s、Dead 40s，邻居失效检测慢，收敛就慢 |
| SPF 计算延迟 | 设备 CPU 忙时，SPF 会被推迟 |
| 网络规模 | 几千台设备，LSA 泛洪和 SPF 计算量巨大 |
| 路由震荡 | 反复变化会让 SPF 反复触发，甚至被抑制 |
| 协议选择 | OSPF 通常秒级到十几秒，BGP 可能几十秒到几分钟 |

### 医院网络为什么特别在意收敛

医院里有很多实时业务：HIS 系统、PACS 影像、监护仪数据、移动护理终端。这些业务对中断非常敏感。

- 如果收敛慢，手术中的影像可能传不过去
- 监护数据可能断连
- 移动查房车可能掉线

所以医院核心网络通常会做**快速收敛优化**：调小 Hello/Dead 定时器、启用 BFD（双向转发检测，毫秒级故障感知）、配置 FRR（快速重路由）等，把收敛时间从几十秒压到毫秒级。

### 一句话总结

**收敛 = 网络从“出事了”到“大家重新商量好、恢复稳定转发”的全过程。** 你看到的“命令延迟生效、路由表为空”，本质就是网络还在收敛中。
