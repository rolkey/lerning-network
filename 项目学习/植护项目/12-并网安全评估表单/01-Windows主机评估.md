> 对应原表 sheet：`二、安全评估(windows-X.X.X.X)`（105 行 × 13 列）

## 三、逐项操作方法（A1–A28）

> 完整现场实施步骤见 [OMS主机 A1–A27 参考文档](<../../../系统加固/220kV双文光伏电站/加固报告/OMS主机(10.172.242.203)__附件1/README.md>)；本节给出要点与验证方式。

### A1 病毒查杀与日志导出

**问题**：使用主机杀毒或杀毒 U 盘软件完成病毒查杀与日志导出。

#### 🔍 风险原理

病毒查杀不只是"扫一遍"。**超过六个月未扫描**意味着新出现的病毒可能长期驻留；U 盘介质管控未开启则病毒可通过移动介质横向扩散；日志未导出则无法证明查杀过程，事后无法追溯。

#### 配置/加固方法

1. 确认已安装杀毒软件（本项目为**安天防病毒软件**），并开启软件自带的 **U 盘介质管控**功能；
2. 执行全盘扫描，记录**发现病毒数量**与**清除病毒数量**；
3. **导出扫描日志**；
4. 记录病毒库更新时间，确认**不超过六个月**；
5. 记录最近一次扫描时间，确认**不超过六个月**。

#### 特殊情况处理

- **扫描会占用 I/O 与 CPU**，生产主机应在业务低峰期执行，避免影响业务；
- 若杀毒软件与业务中间件存在兼容性冲突（如误杀 Java 进程），**先加白名单再扫描**，不得直接关闭防护；
- 杀毒软件需保持病毒库自动更新，离线主机应定期手动更新。

#### 📌 加固后的验证

```powershell
# 确认病毒库与扫描记录的时间戳
# 安天客户端路径随安装版本不同，以实际安装路径为准
```

期望结果：病毒库更新时间 ≤ 6 个月，最近扫描时间 ≤ 6 个月，日志已导出，发现/清除病毒数量已记录。

### A2 空口令用户排查

**问题**：逐个尝试登录系统账号，判断是否存在空口令用户。

#### 🔍 风险原理

空口令账号意味着任何人坐在物理机前或拿到远程会话即可登录系统，无需任何凭据。内置账号（如 `Guest`、`ASPN`、`IUSR`、各类应用池账号）是空口令高发区。

#### 配置/加固方法

```
控制面板 → 管理工具 → 计算机管理 → 系统工具 → 本地用户和组 → 用户
```

逐个选择账号 → 右键 → **设置密码**，为空口令的立即设置。

或用命令行快速筛查（需管理员权限）：

```powershell
# 列出当前本地用户
net user

# 逐个测试空口令登录（返回"命令成功完成"即为可空口令登录）
net user <用户名> <空密码>
```

#### 特殊情况处理

- **内置服务账号不要删**（如 `IUSR`、`ASPN`、`SQLService` 等），改为设置强口令或**勾选"用户下次登录时不需要输入密码"并禁用交互式登录**；
- 锁定状态的账号可用 `net user <用户名> /active:no` 禁用而非删除；
- 删除前须确认该账号无业务依赖，参照 A7 流程。

#### 📌 加固后的验证

```powershell
net user
```

期望结果：所有可交互登录的账号均无空口令，内置服务账号已禁用或锁定。

### A3 密码复杂度策略

**问题**：密码策略设置符合复杂度要求。

#### 🔍 风险原理

策略强度决定了**所有用户**密码的底线。若"密码必须符合复杂性要求"未启用，弱口令（如 `123456`、用户名拼音）可直接通过，导致撞库/爆破成功。

#### 配置/加固方法

```
gpedit.msc → 计算机配置 → Windows 设置 → 安全设置 → 账户策略 → 密码策略
```

| 策略 | 值 |
| --- | --- |
| 密码必须符合复杂性要求 | **启用** |
| 密码长度最小值 | **8** |
| 密码最长使用期限 | **180 天** |
| 密码最短使用期限 | **1 天** |
| 强制密码历史 | **3 次** |

也可以用命令批量设置与审计：

```powershell
# 查看当前策略
net accounts

# 设置最小长度
net accounts /minpwlen:8
net accounts /maxpwage:180
net accounts /minpwage:1
net accounts /passwordhistory:3
```

> 注：`net accounts` **不能**设置"复杂性要求"开关，该项只能用 `gpedit.msc` 或域策略。

#### 特殊情况处理

- **设置"密码最短使用期限 1 天"前须确认**：若系统中存在自动化脚本使用固定账号且不会改密，缩短更换周期会导致脚本中断；
- 域环境下**本地策略不生效**，须在域控的 `Default Domain Policy` 中配置，否则重启后被策略刷新覆盖；
- 8 位最小长度与 A8 要求的"含大小写字母、数字、特殊字符中的两种"配合使用，**A8 更高，以 A8 为准**。

#### 📌 加固后的验证

```powershell
net accounts
```

期望结果：账户策略显示最小长度 8、最长 180 天、最短 1 天、历史 3 次，复杂性要求已启用。

### A4 账户锁定策略

**问题**：启用账户锁定策略。

#### 🔍 风险原理

无账户锁定时，攻击者可对 admin 账号无限次尝试口令。**锁定阈值与锁定时间的组合**决定暴力破解的可行性：5 次即锁、锁 30 分钟，是常见的抗暴破参数。

#### 配置/加固方法

```
secpol.msc（或 gpedit.msc → 计算机配置 → Windows 设置 → 安全设置 → 账户策略 → 账户锁定策略）
```

| 策略 | 值 |
| --- | --- |
| 复位账户锁定计数器 | **3 分钟** |
| 账户锁定时间 | **5 分钟** |
| 账户锁定阈值 | **5 次无效登录** |

> 注意：A4 要求**锁定 5 分钟**；Linux 主机 B7 要求**锁定 30 分钟**（`unlock_time=1800`）。两者不一致，**按各自 sheet 执行，不要互相套用**。

#### 特殊情况处理

- **锁定策略同时作用于服务账号**：若某服务账号口令固定且被反复错误认证（如配置错误的计划任务），会连带锁死服务，需先修正调用方；
- 锁定时间过短会削弱抗暴破效果，过长则运维被锁在外无法处置；变更前与运维确认。

#### 📌 加固后的验证

```powershell
net accounts
```

期望结果：显示"锁定阈值为 5 次"、"锁定时间为 5 分钟"、"复位计数器为 3 分钟"。

### A5 用户权限指派

**问题**：本地策略 → 用户权限指派，收紧敏感权限并配置拒绝本地登录。

#### 🔍 风险原理

默认配置下，部分高危权限授予了 `Users`、`Everyone` 等宽泛主体：

- **从远程系统强制关机**、**关闭系统**——任意本地用户可关机/重启，导致业务中断与日志未落盘；
- **取得文件或其他对象的所有权**——任意用户可夺取文件所有权，绕过 ACL 读取敏感文件；
- **拒绝本地登录**——未配置时 `Guest`、`IUSR`、`IWAN` 等服务账号可交互登录。

#### 配置/加固方法

```
secpol.msc → 本地策略 → 用户权限指派
```

| 权限 | 授予 |
| --- | --- |
| 从远程系统强制关机 | `administrators` |
| 关闭系统 | `administrators` |
| 取得文件或其他对象的所有权 | `Administrators` |
| 拒绝本地登录 | 增加 `IUSR_<主机名>`、`IWAN_<主机名>` 等不需要的账户 |
| 从网络访问此计算机 | 保持 `Administrators`、`Users`（本表建议检查） |

设置后刷新策略：

```powershell
secedit /refreshpolicy machine_policy
```

### A6 默认账户权限控制

**问题**：已禁用 Guest 账户；已重命名 Administrator 管理员账号。

#### 🔍 风险原理

`Administrator` 是 Windows 的默认超级用户，全系统预置、权限最高。攻击者只需猜中这一账号的口令即取得完全控制；而 `Guest` 若启用则提供无需凭据的匿名入口。

#### 配置/加固方法

1. **禁用 Guest**：
   ```
   控制面板 → 管理工具 → 计算机管理 → 系统工具 → 本地用户和组 → 用户 → Guest → 右键 → 禁用
   ```
2. **重命名 Administrator**：
   ```
   同上，右键 Administrator → 重命名 → 输入新名称
   ```
   或用命令：
   ```powershell
   Rename-LocalUser -Name "Administrator" -NewName "<新名称>"
   ```

> 重命名后，所有脚本、服务、计划任务中引用 `Administrator` 或 `.\Administrator` 的地方都会失效，必须同步排查。

#### 特殊情况处理

- **原表明确"若影响业务不做此步，填异常情况"**——本条允许带缺陷交付，但须在"异常情况记录"栏写明未重命名原因；
- 域控（DC）上的 `Administrator` **禁止禁用**，由 `krbtgt` 与目录服务依赖，域控上此条按域安全基线执行；
- **使用内置 `Administrator` 而非新建管理员账号是反模式**：新账号可加入 Administrators 组且更易审计归属；
- 重命名前应确认无脚本/备份任务依赖原名。

#### 📌 加固后的验证

```powershell
net user Administrator   # 应提示"用户不存在"
net user Guest           # 应显示"是/否"状态为 停用
```

期望结果：`Administrator` 已不存在，`Guest` 已停用；或已在异常情况记录中说明未重命名原因。

### A8 应用软件账户权限设置

**问题**：禁用或删除无用、过期用户；用户设置最小化权限；密码复杂度最少 8 位，含大小写字母、数字、特殊字符中的两种；不存在空口令或弱密码。

#### 🔍 风险原理

应用账号是攻击首选目标：中间件/数据库账号通常权限大，且口令常写入配置文件后长期不变。A8 是本表**密码复杂度要求最高**的一条（比 A3 的 8 位更严），针对的正是这类账号。

#### 配置/加固方法

对每个应用账号（数据库账号、中间件运行账号、备份账号、服务账号）：

| 检查项 | 要求 |
| --- | --- |
| 用途 | 专用，不复用、不共享 |
| 权限 | 最小化——按"运行/只读/读写"精确授予，不给 DBA/系统管理员 |
| 口令长度 | ≥ 8 位 |
| 口令字符 | **大小写字母、数字、特殊字符中至少两种** |
| 口令存放 | **不写入明文配置文件**，用受控凭据存储 |
| 默认/弱口令 | 一律修改 |

```powershell
net user <应用账号>                       # 查看账号状态
net user <应用账号> <符合复杂度的新口令>  # 修改口令
```

> **本条要求严于 A3**：A3 只要求启用"复杂性要求"开关（8 位 + 满足复杂性），A8 明确要求**含两类字符**。填表时按 A8 执行。

#### 特殊情况处理

- **中间件配置文件中存在明文口令是常见遗留**（如 Tomcat `context.xml`、WebLogic `boot.properties`），须改为加密存储或引用凭据；
- 应用账号密码轮换会中断连接，须与业务方确认窗口；
- 数据库账号建议单独授权并**禁止交互式登录**（策略拒绝本地登录，参见 A5）。

#### 📌 加固后的验证

```powershell
net user <应用账号>
```

期望结果：账号口令满足 8 位 + 两类字符，非默认口令，权限最小化。

### A9 审核策略

**问题**：配置 9 项审核策略。

> ⚠️ **原表两列自相矛盾**：完成情况列写"目录服务访问=失败、特权使用=失败、过程追踪=无审核"，加固方法列要求三项均设为成功和失败都审核。**以"加固方法"列为准**（引用标准 1），见第七节。

#### 🔍 风险原理

审核策略是**事后溯源的唯一依据**。未审核的对象访问、特权操作、进程创建不会被记录，事件发生时无法回答"谁在何时做了什么"。

#### 配置/加固方法

```
gpedit.msc → 计算机配置 → Windows 设置 → 安全设置 → 本地策略 → 审核策略
```

| 审核策略 | 要求 |
| --- | --- |
| 审核账户登录事件 | 成功、失败 |
| 审核账户管理 | 成功、失败 |
| 审核目录服务访问 | 成功、失败 |
| 审核登录事件 | 成功、失败 |
| 审核对象访问 | 成功、失败 |
| 审核策略更改 | 成功、失败 |
| 审核特权使用 | 成功、失败 |
| 审核进程跟踪 | 成功、失败 |
| 审核系统事件 | 成功、失败 |

命令审计与导出：

```powershell
auditpol /get /category:"详细跟踪"
auditpol /set /category:"详细跟踪" /success:enable /failure:enable
auditpol /backup /file:C:\audit.cfg
```

#### 特殊情况处理

- **"审核对象访问"生成的事件量极大**，在高 IO 主机上可能撑爆 102400 KB 日志上限并频繁改写，导致真正关键的老日志被覆盖。**建议：对象访问只审计敏感目录/文件**，其余按需关闭；
- **"审核目录服务访问"在非域控主机上无对象可审**，设为全成功会产出空事件；
- 审核策略产生的事件量须与 A10 的日志大小、改写周期配套核算（事件量 × 覆盖天数 ≰ 日志容量）。

#### 📌 加固后的验证

```powershell
auditpol /get /category:"详细跟踪"
auditpol /get /category:"系统"
```

期望结果：9 项策略均按要求设置成功/失败审计。

### A10 系统日志

**问题**：日志大小不小于 102400 KB，达到最大尺寸时"按需要改写事件"，改写久于 90 天的事件，日志保存 6 个月以上。

#### 🔍 风险原理

日志有两个硬约束：**容量**与**留存期**。默认 Windows 日志上限往往偏小且选择"按需要覆盖旧事件"，事件量大时关键的老日志在几天内被冲掉，直接破坏 A9 建立的审计价值。

#### 配置/加固方法

```
事件查看器 → 应用程序 / 系统 / 安全 → 右键 → 属性 → 日志
```

| 配置项 | 值 |
| --- | --- |
| 日志大小 | **≥ 102400 KB**（即 100 MB） |
| 达到最大尺寸时 | **按需要改写事件** |
| 事件日志保留时间 | **90 天** |

> **注意**：将"保留时间"设为 90 天**不能**保证 6 个月留存——A10 两处要求本身不一致（90 天改写 vs 6 个月保存）。见第七节。

#### 特殊情况处理

- **安全日志需要显式开启"审核成功"才能记录成功事件**（对应 A9），否则日志里只有失败记录；
- 若须真正满足 6 个月留存，应把日志大小按事件量放大（可用 `wevtutil` 或日志收集工具评估），并配合 A26 将日志实时外送到态势感知/日志服务器做集中留存——**本机日志留存期再长也不抗硬盘损坏与篡改**；
- 事件查看器"安全"日志需管理员权限查看。

#### 📌 加固后的验证

```powershell
wevtutil gli Security      # 查看 Security 日志配置（含最大大小与保留模式）
```

期望结果：三个日志的大小、覆盖策略、保留期均符合要求。

每个监听服务都是一个潜在入口。邮件、Telnet、FTP 均为明文协议且常带已知漏洞；NetBIOS/SMB 是横向移动的主要通道；UPnP 可被用于内网端口映射与设备劫持。

| Automatic Updates（可选） | Terminal Service（可选） | UPnP Device Host |


- 生产主机变更须在窗口期执行，参见 A11 类变更的通用要求。

#### 📌 加固后的验证

```powershell

# 确认监听端口无残留

```

期望结果：清单内非业务必需服务均已停止且启动类型为 Disabled，无 Telnet(23)/SMTP(25)/FTP(21) 监听。

### A13 文件共享管控

**问题**：原则上禁止配置文件共享；必须配置共享时须设置账户与口令，只将权限授权于指定账户。

#### 🔍 风险原理

共享目录是数据泄露主通道。共享一旦设匿名访问或 `Everyone` 完全控制，等于把目录公开；配置文件共享更危险，其中常含数据库连接串与账号口令。

#### 配置/加固方法

```powershell
# 查看现有共享
net share

# 查看共享权限与 NTFS 权限
net share <共享名>
icacls <路径>
```

如确需共享：

1. 设置**共享级权限**（只授予指定账户，不加 `Everyone`）；
2. 同时收紧**NTFS 权限**（两层都收才有效，NTFS 优先）；
3. 需要写权限的用"更改"，只读的用"读取"。

```powershell
net share <共享名>=<路径> /grant:<账户>,read
icacls <路径> /grant <账户>:(R)
```

#### 特殊情况处理

- **共享权限与 NTFS 权限取交集**，常见误配是共享给 `Everyone` 但 NTFS 收紧——此时有效权限仍受 NTFS 限制，但两处都应按规范配置；
- 配置文件目录**原则上不共享**；确需运维读取的，走堡垒机账号授权（A26 限制来源 IP）而非共享；
- 使用 `\\IP\C$` 访问的是管理共享，需靠 A14 关闭。

#### 📌 加固后的验证

```powershell
net share
```

期望结果：无匿名/Everyone 共享；必要共享均指定账户并设口令。

### A14 关闭 Windows 默认共享

**问题**：删除 IPC$、ADMIN$、C$、D$ 等。

#### 🔍 风险原理

默认共享（管理共享）在服务启动时自动创建，即使从未显式配置。其中 `ADMIN$`/`C$` 提供**完整文件系统访问**，`IPC$` 是命名管道共享，是空连接利用（如 net use /user:""）的目标。

#### 配置/加固方法

```powershell
# 查看
net share

# 逐个删除
net share IPC$ /delete
net share ADMIN$ /delete
net share C$ /delete
net share D$ /delete
```

**注册表固化（防重建）**：

`HKEY_LOCAL_MACHINE\System\CurrentControlSet\Services\LanmanServer\Parameters`

| 名称 | 类型 | 值 |
| --- | --- | --- |
| `AutoShareServer` | REG_DWORD | `0` |
| `AutoShareWKS` | REG_DWORD | `0` |

```powershell
# 设置
New-ItemProperty -Path "HKLM:\SYSTEM\CurrentControlSet\Services\LanmanServer\Parameters" -Name AutoShareServer -Value 0 -PropertyType DWord -Force
New-ItemProperty -Path "HKLM:\SYSTEM\CurrentControlSet\Services\LanmanServer\Parameters" -Name AutoShareWKS -Value 0 -PropertyType DWord -Force
```

> `AutoShareServer` 对应本机作为服务端（即 `C$`/`ADMIN$`）；`AutoShareWKS` 对应作为工作站（`ADMIN$` 出站）。

#### 特殊情况处理

- **删除后 `LanmanServer` 服务重启或系统重启会重建**，必须配合注册表项才持久；
- 关闭管理共享后，`\\IP\C$` 方式的远程管理与部分备份工具会失效，须先确认无依赖；
- 与 A15/A25 一并生效效果最好：默认共享 + 匿名访问 + 远程注册表三条都堵住。

#### 📌 加固后的验证

```powershell
net share
# 重启后再次执行，确认未重建
```

期望结果：列表中无 IPC$、ADMIN$、C$、D$ 等默认共享，重启后仍然不存在。

### A15 禁用匿名远程连接

**问题**："网络访问: 可匿名访问的共享""可匿名访问的命名管道"设为空；不允许枚举 SAM 账号和共享。

### A19 禁止开机自动登录

**问题**：注册表 `Winlogon` 下 `AutoAdminLogon` = 0。

#### 🔍 风险原理

自动登录意味着**任何人接触这台机器的物理键盘即可进入系统**，无口令、无审计归属。虽有安全风险较低的场景（如无人值守终端），但变电站/调度主机原则上不允许。

#### 配置/加固方法

`HKEY_LOCAL_MACHINE\Software\Microsoft\WindowsNT\CurrentVersion\Winlogon`

| 名称 | 类型 | 值 |
| --- | --- | --- |
| `AutoAdminLogon` | REG_DWORD | `0` |
| `DefaultPassword`（若存在） | REG_SZ | **删除** |
| `DefaultUserName`（若存在） | REG_SZ | 可保留，但与 `AutoAdminLogon=1` 同在才生效 |

```powershell
Set-ItemProperty -Path "HKLM:\Software\Microsoft\WindowsNT\CurrentVersion\Winlogon" -Name AutoAdminLogon -Value 0
Remove-ItemProperty -Path "HKLM:\Software\Microsoft\WindowsNT\CurrentVersion\Winlogon" -Name DefaultPassword -ErrorAction SilentlyContinue
```

#### 特殊情况处理

- **修改自动登录后开机可能无人能登录**：若机器失去远程可达且无人知晓本地口令会彻底锁死，改前须确认恢复途径；
- 开启远程桌面（RDP）不影响本项，RDP 是另一种登录方式；
- `DefaultPassword` 以明文存于注册表，必须清除。

#### 📌 加固后的验证

重启后停留在登录界面，不自动进入桌面。

期望结果：登录界面无自动填充的用户名与密码。

### A20 DDoS/SYN Flood 攻击保护参数

**问题**：注册表 `Tcpip\Parameters` 下添加 SYN 攻击防护参数。

#### 🔍 风险原理

SYN Flood 靠半连接耗尽协议栈资源。Windows 默认的 SYN 重传上限较高，攻击流量下连接队列被占满，正常业务连接被丢弃。收紧这些参数可让主机在攻击下更快丢弃半连接、保留资源。

#### 配置/加固方法

`HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Services\Tcpip\Parameters`

| 名称 | 类型 | 值 | 含义 |
| --- | --- | --- | --- |
| `SynAttackProtect` | REG_DWORD | `2` | 启用 SYN 攻击防护 |
| `TcpMaxHalfOpen` | REG_DWORD | `500` | 半连接队列上限 |
| `TcpMaxHalfOpenRetried` | REG_DWORD | `400` | 处于 SYN_RECV 状态的连接重试上限 |
| `TcpMaxPortsExhausted` | REG_DWORD | `5` | 连接端口耗尽时是否启用防护 |
| `EnableICMPRedirect` | REG_DWORD | `0` | 禁用 ICMP 重定向 |

```powershell
$p = "HKLM:\SYSTEM\CurrentControlSet\Services\Tcpip\Parameters"
New-ItemProperty -Path $p -Name SynAttackProtect -Value 2 -PropertyType DWord -Force
New-ItemProperty -Path $p -Name TcpMaxHalfOpen -Value 500 -PropertyType DWord -Force
New-ItemProperty -Path $p -Name TcpMaxHalfOpenRetried -Value 400 -PropertyType DWord -Force
New-ItemProperty -Path $p -Name TcpMaxPortsExhausted -Value 5 -PropertyType DWord -Force
New-ItemProperty -Path $p -Name EnableICMPRedirect -Value 0 -PropertyType DWord -Force
```

#### 特殊情况处理

- **`TcpMaxHalfOpen` 过低会在高并发/高延迟链路上误杀正常连接**，Linux B18 同类项按 ≥16 位/≥24 位取更严值，本项调整后须压测或观察业务；
- `EnableICMPRedirect=0` 对应 Linux B18 的 `accept_redirects=0`，两端一致；
- 修改后**需重启**生效。

#### 📌 加固后的验证

```powershell
Get-ItemProperty "HKLM:\SYSTEM\CurrentControlSet\Services\Tcpip\Parameters" | Select-Object SynAttackProtect, TcpMaxHalfOpen, EnableICMPRedirect
```

期望结果：五项参数均已写入，重启后生效。

### A26 关闭高危端口、限制远程管理 IP

**问题**：开启 IPSEC 服务或启用本地防火墙；限制远程管理 IP，**仅允许堡垒机访问 23333 远程端口**；添加组策略和防火墙出入站策略禁用高危端口。

#### 🔍 风险原理

开放的高危端口是外部突破后的第一落点。远程桌面（3389）、SMB（445）、NetBIOS（135–139）历史上是 Windows 被利用最多的入口。同时**管理端口必须限定来源 IP**，否则限制端口本身没有意义。

#### 配置/加固方法

**1. 启用本地防火墙**

```
控制面板 → Windows Defender 防火墙 → 启用；入站规则默认阻止
```

或"启用 IPSEC 服务"（原表给出的备选）。

**2. 端口清单**

| 类别 | 端口 | 说明 |
| --- | --- | --- |
| 必须禁用 | 135、137、138、139、445、3389、53、23333 | 防跳板攻击 |
| 原则上禁用 | 23（telnet）、25（SMTP）、20、21（ftp）、513（login）、110（e-mail）、1900（UPnP） | 按业务实际判断 |

> `23333` 为本项目约定的远程管理端口。**注意 Linux B24 原表将其误写为 `5323333`**，正确值为 `23333`，见第七节。

**3. 入站规则（限制管理端口来源）**

```powershell
# 允许管理端口仅来自堡垒机
New-NetFirewallRule -DisplayName "23333-Only-Bastion" -Direction Inbound -Protocol TCP -LocalPort 23333 `
  -RemoteAddress <堡垒机IP> -Action Allow -Profile Any

# 明确阻断其余来源
New-NetFirewallRule -DisplayName "23333-Deny-Other" -Direction Inbound -Protocol TCP -LocalPort 23333 `
  -RemoteAddress Any -Action Block -Profile Any
```

**必须禁用端口（示例规则集）**：

```powershell
$block = 135,137,138,139,445,3389,53,23333
foreach ($p in $block) {
  New-NetFirewallRule -DisplayName "Block-TCP-$p" -Direction Inbound -Protocol TCP -LocalPort $p -Action Block
  New-NetFirewallRule -DisplayName "Block-UDP-$p" -Direction Inbound -Protocol UDP -LocalPort $p -Action Block
}
```

**4. IP 安全策略（原表备选路径）**

`gpedit.msc` → 计算机配置 → Windows 设置 → 安全设置 → IP 安全策略 → 右键 → 创建 IP 安全策略 → 命名 → 不勾选下一步 → 编辑属性 → 规则 → 添加 → IP 筛选器列表 → 添加 → 填写名称 → 下一步 → 下一步 → **指定源目的地址** → **协议选 TCP** → 设置 IP 协议端口为"从任意端口到此端口 445" → 下一步完成 → 筛选器操作 → 添加 → 填写名称 → 选"**阻止**" → 应用。

#### 特殊情况处理

- **"仅允许堡垒机访问"与"禁用该端口"存在冲突**：原表同时要求"仅允许堡垒机访问 23333"和"禁用 23333"。**实践取法：禁用端口的入站访问，仅保留来自堡垒机 IP 的例外**（见上方两条规则），二者不冲突；
- 禁用 53（DNS）会破坏主机名解析，**除非该主机确实无需 DNS**（纯静态 IP 且不使用域名），否则不可禁；
- 禁用 3389 会切断远程桌面，须确认无 RDP 运维依赖——**本项目远程管理约定走 23333 + 堡垒机**；
- **防火墙规则顺序**：Block 规则需在 Allow 规则**之前**生效，或用更精确的 `RemoteAddress` 限定 Allow；
- 禁用规则须在变更窗口执行，并保留回滚方式（组策略"另存为"策略备份）。

#### 📌 加固后的验证

```powershell
# 确认规则已建立
Get-NetFirewallRule -DisplayName "23333-*" | Select-Object DisplayName, Action, Enabled

# 从非授权主机测试（应不通）
Test-NetConnection -ComputerName <目标IP> -Port 23333
# 从堡垒机测试（应通）
```

期望结果：必需禁用端口入站被阻断；23333 仅堡垒机可达，其他来源不通。

### A27 卸载非法软件

**问题**：卸载盗版软件、无用多余软件；卸载高风险远程运维软件。

#### 🔍 风险原理

盗版/破解软件常捆绑后门与挖矿程序；高风险远程运维软件（TeamView、向日葵等）是典型的**绕过堡垒机的旁路通道**——攻击者用它们建立不受监管的远程会话，既能进入系统又无审计记录。

#### 配置/加固方法

```
控制面板 → 程序 → 程序和功能
```

| 类别 | 示例 | 处置 |
| --- | --- | --- |
| 盗版软件 | 破解版 WinRAR、Acrobat、Microsoft Office | **卸载** |
| 无用软件 | 冗余工具、试用版残留 | **卸载** |
| **高风险远程运维** | TeamView、向日葵、QQ、百度浏览器、360 极速浏览器、搜狗输入法、金山输入法 | **卸载** |
| 多余浏览器 | Chrome、Firefox、Edge（除业务必需） | **卸载** |

命令行卸载：

```powershell
# 已安装程序列表
Get-ItemProperty HKLM:\Software\Microsoft\Windows\CurrentVersion\Uninstall\*
Get-ItemProperty HKLM:\Software\Wow6432Node\Microsoft\Windows\CurrentVersion\Uninstall\*

# 卸载（需产品代码）
msiexec /x {产品代码} /quiet
```

#### 特殊情况处理

- **卸载前确认业务依赖**：输入法可能影响业务系统录入；浏览器可能用于某专用页面访问；
- 远程运维工具与 A26 端口管控、A23 USB 封堵是同一治理思路——**杜绝旁路通道**；
- 若确需远程运维能力，应统一走**堡垒机**（见 A26 与第五节"是否接入堡垒机"），而非安装第三方远控；
- 卸载后清理残留目录与启动项（任务管理器 → 启动）。

#### 📌 加固后的验证

```powershell
Get-Service | Where-Object { $_.DisplayName -match "TeamViewer|Sunlogin|向日葵" }
```

期望结果：目标软件均已卸载，无残留服务与自启动项。

### A28 清理默认路由

**问题**：禁止存在默认路由，必须全为明细路由，路由掩码应 **≥16 位**（即 255.255.0.0）。

> ⚠️ **OMS 参考目录未覆盖 A28**，本节依据原表要求给出通用方法，Windows 具体操作请以现场为准并在异常情况记录中说明。

#### 🔍 风险原理

默认路由（0.0.0.0/0）意味着**任何未被明确路由的目的地址都会被转发**。安全域之间靠"明细路由"精确控制可达范围：没有默认路由，跨安全区的访问必须逐条配置，不存在"漏一条就全通"的可能。

#### 配置/加固方法

```powershell
# 查看路由表，确认默认路由
route print -4
```

删除默认路由（0.0.0.0 网关上标 `*` 的那条）：

```powershell
# 假设默认路由的接口索引为 12（以 route print 结果为准）
route delete 0.0.0.0 mask 0.0.0.0 12
```

**必须持久化**，否则重启后默认路由会回来：

- 图形界面：`ncpa.cpl` → 右键网卡 → 属性 → IPv4 → 高级 → **不要勾选"自动跃点"，取消默认网关的自动获取**
- 或确保各连接均未配置网关；若网关由 DHCP 下发，改为**静态配置、网关留空**。

同时检查并补充所需明细路由（掩码 ≥16 位，即 255.255.0.0）：

```powershell
route print -4 | Select-String "^\s+\d+\.\d+\.\d+\.\d+\s+255\.255\.\d+\.\d+"
```

#### 特殊情况处理

- **删除默认路由会中断本机对外（含 DNS、NTP、补丁源、态势感知上报）的访问**，须先确认所需明细路由齐备再删，删后立即验证；
- 逐条配置明细路由前，先从交换机/路由器侧确认实际需要可达的目标网段与下一跳；
- **路由必须保存到配置文件**，否则重启丢失（与 Linux B26 的同一注意点）；
- 与 Linux B26 的差异：Linux 要求掩码 **≥24 位**并显式配置 `10.67.x.0` 明细路由，Windows 为 **≥16 位**，填表时不要互相套用。

#### 📌 加固后的验证

```powershell
route print -4
```

期望结果：无 0.0.0.0/0 默认路由（或按审批保留并有例外说明），所有明细路由掩码为 255.255.0.0 及以上。
