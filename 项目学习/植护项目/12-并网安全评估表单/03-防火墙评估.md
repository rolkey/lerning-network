## 三、逐项操作方法（C1–C19）

### C1 策略备份

**问题**

> 评估表原文：对防火墙进行策略备份，可以直接导出备份文件或 Excel 表格记录备份。本项目设备到货后应先做一次基线备份

---

#### 🔍 风险原理

策略是防火墙全部安全逻辑的载体。一次误改或一次策略同步覆盖就可能让整台设备的防护失效，且往往无法回溯。设备到货时未留基线，日后无法证明初始配置状态，也无法区分"原始设计"与"运维期间被改动"。

#### 配置/加固方法

**1. 导出当前配置（留存到货基线）**

```text
display current-configuration | no-more
```

将输出保存为文本文件，文件名包含设备型号与管理 IP，标注"到货基线"。

Web 路径：**系统 → 配置文件管理 → 当前配置 → 导出**。

**2. 保存设备配置文件**

```text
save backup_configuration.zip
```

**3. 备份到运维 PC（推荐 SFTP，加密传输）**

```text
ftp <PC_IP>
# 登录运维 PC 上的 FTP/SFTP 服务端
[ftp] put config.cfg
```

**4. 同步做 Excel 台账**

C1 要求"可以直接导出备份文件**或** Excel 表格记录备份"，但两者一起做更稳妥：导出文本用于精确还原，Excel 台账用于记录策略条数、修改人、修改时间、审批单号。

**5. 记录配置文件位置**

设备当前配置文件位于 `hda1:/vrpcfg.zip`。**更换设备或格式化 CF 卡前必须先备份此文件**，否则配置无法迁移。

#### 特殊情况处理

- 基线备份必须在**设备上架、接入网络之前**完成；已接入网络的设备先备份再改任何配置。
- 每次策略变更后重复导出，文件名带日期与工单号，形成时间序列，便于回溯。

#### 📌 加固后的验证

```text
save
# 期望：出现配置保存成功的提示，无报错
```

比对 PC 上 `config.cfg` 与设备侧文件大小一致，并确认 PC 上文件可正常打开。

依据：华为官方配置文件备份说明 <https://support.huawei.com/enterprise/zh/doc/DOC1000160160/3dfeaf3f>

### C2 对防火墙的管理地址做源地址限制

**问题**

> 评估表原文：使用防火墙自身的限定功能，或在防火墙管理口的接入设备上设置 ACL，仅允许堡垒机、态势感知等访问 SSH 和 HTTPS（webui）

---

#### 🔍 风险原理

设备管理面是最高价值的攻击目标。一旦管理口可被调度数据网内任意主机访问，攻击者即可修改安全策略、关闭日志、甚至重置设备，等于绕过全部边界防护。

#### 配置/加固方法

**1. 检查管理服务与来源现状**

```text
display current-configuration | include service-manage
display current-configuration configuration user-interface
# 期望：能看到已开启的管理服务清单及其允许的来源
```

若 SSH 尚未开启，可参照 [实验04/2.防火墙允许连接.md](../../../网络概念/实验04/2.防火墙允许连接.md)（USG SSH/AAA/VTY 配置步骤）。

**2. 通过安全策略限制管理面来源**

建立两条策略，仅允许堡垒机与态势感知访问管理口，其余源地址一律拒绝：

```text
security-policy
  rule name mgmt_only_bastion
   source-zone <管理区>
   destination-zone <local>
   source-address <堡垒机IP>
   source-address <态势感知IP>
   destination-port ssh
   action permit
   quit
  rule name mgmt_deny_all
   source-zone any
   destination-zone <local>
   action deny
   quit
  rule move mgmt_deny_all bottom
```

**3. Web 路径**

**策略 → 安全策略 → 新建规则**，源区域选管理区，源地址填堡垒机与态势感知地址，目的端口 SSH（22）与 HTTPS（443）。

> ⚠️ 区域名称（`zone`）写法随本机安全区域划分而定，执行前用 `source-zone ?` 回显确认；策略命令在 V600R007C20 前后存在差异，若本机无 `rule move`，改用 Web 界面的"移动"菜单。

#### 特殊情况处理

- **本项目绑定**：仅允许堡垒机（清单序号 8，LOSA-BU-A00，名称待确认）与态势感知（清单序号 6，HR CRPM-3000，2 台）访问 SSH 与 HTTPS。这两台设备 IP 必须先确认再写入策略。
- 应急排障需要临时放开时，只能在维护窗口内从堡垒机单点临时开启，并在工单中记录开启与关闭时间。
- 管理口若直接从调度数据网可访问，**C2 即为不合格**。

#### 📌 加固后的验证

```text
display security-policy rule all
# 期望：管理面 permit 规则仅两条源地址，兜底 deny 规则在列表最末
```

从非堡垒机/态势感知的主机尝试访问管理口，应被拒绝；SSH 重新登录观察，**不得提示输入用户名即失败**。

### C3 用户帐号权限分配

**问题**

> 评估表原文：按照用户分配帐号，无不同用户间共享帐号

---

#### 🔍 风险原理

共享账号使操作无法追溯到自然人，日志里只会出现同一个名字。事后追责、审计取证、权限回收全部失效，等于放弃了审计能力。

#### 配置/加固方法

**1. 导出当前账号清单**

```text
display current-configuration configuration aaa
display aaa configuration
# 期望：列出所有 local-user 及其 service-type / privilege
```

**2. 按人建账号、回收共享账号**

```text
system-view
 aaa
  local-user <姓名拼音> password irreversible-cipher <口令>
  local-user <姓名拼音> service-type ssh
  local-user <姓名拼音> privilege level 15
  quit
```

`privilege level` 按岗位分配：日常运维 3 级、审计 2 级、专职管理员 15 级。

**3. 删除共享账号与多余账号**

```text
aaa
 undo local-user <共享账号名>
```

#### 特殊情况处理

- 厂商默认维护账号（如 `admin`）在 C6 处理：若因厂商保修要求必须保留，须记录在台账并纳入审计范围。
- 人员调岗离场当日回收账号，回收记录进台账。

#### 📌 加固后的验证

```text
display aaa configuration
# 期望：每个账号对应一个自然人，无 shared / generic / test 类账号
```

用两个不同账号分别登录，确认日志中记录的是各自的账号名。

依据：华为 USG AAA 配置与 `display aaa configuration` 命令核实

### C4 静态口令安全

**问题**

> 评估表原文：若可使用 SSH 登录管理，查看配置文件，静态口令以密文形式存放

---

#### 🔍 风险原理

配置文件中若出现明文口令，任何一次配置文件泄露（备份文件外发、FTP 传输、工程文档截图）都直接等于管理账号失守。明文口令是配置文件泄露中最常被低估的风险。

#### 配置/加固方法

**1. 核查配置文件中是否存在明文口令**

```text
display current-configuration | include password
# 期望：口令字段为密文（irreversible-cipher / cipher），不含明文字符
```

**2. 设置口令时强制使用密文存储**

```text
system-view
 aaa
  local-user <姓名拼音> password irreversible-cipher <口令>
```

`irreversible-cipher` 为不可逆加密存储；SSH/协议类密钥用 `cipher`。

**3. 检查配置文件传输通道**

C1 的备份走 SFTP；如需 FTP，必须限制在管理网段内，且用完即停。

#### 特殊情况处理

- 原表另注（A12/B19/D15）：全网 SNMP 团体名统一为 `GXhmrjsw-q3`。**该值以 `cipher` 密文写入配置**，不得明文下发工单。
- SSH 本身已不使用口令传输，但本项要求的是**配置文件落盘形态**，两者都要满足。

#### 📌 加固后的验证

```text
display current-configuration | include password
# 期望：所有口令行均带 cipher 关键字，无明文
```

将导出配置文件交给现场人员人工复核，确认无法直接读出任何口令。

### C5 帐户口令长度及复杂度

**问题**

> 评估表原文：密码长度最小值为 8 位，复杂度要求数字、字母大小写、特殊符号

---

#### 🔍 风险原理

弱口令是边界设备被攻破的首要原因。设备管理面通常不对公网开放，攻击面小但价值高，因此口令复杂度要求必须严格执行，不能因"设备在内网"而放松。

#### 配置/加固方法

**1. 检查当前口令策略**

进入 Web：**系统 → 用户管理 → 用户管理 / AAA**，查看口令策略页面当前设置。

**2. 设置口令复杂度**

同页面设置：最小长度 8 位，要求包含数字、大写字母、小写字母、特殊符号中的至少三类，口令有效期与重复杂度按规范配置。

**3. CLI 侧逐个账号设置符合策略的口令**

```text
system-view
 aaa
  local-user <姓名拼音> password irreversible-cipher <口令>
```

> ⚠️ 需现场确认：USG6000E V600R007C20 的口令复杂度全局强制命令，官方文档中未检索到该版本的可发布 CLI 页（仅在更新的 V600R025 平台上验证过 `password-policy` 类命令）。请在 Web 口令策略页设置，或在 CLI 下执行 `password-policy ?` 确认本机可用命令后再配置，不要照抄其他产品线命令。

#### 特殊情况处理

- 密码复杂度策略应作用于**所有** local-user，包括厂商默认账号。
- 口令由系统管理员按工单派发并强制首次登录修改，不通过聊天工具传送。

#### 📌 加固后的验证

用不符合策略的口令尝试创建/修改账号，应被拒绝；Web 口令策略页截图留档。

### C6 默认账户密码修改

**问题**

> 评估表原文：修改默认管理账号（支持的情况下）、修改默认登录密码

---

#### 🔍 风险原理

默认口令是公开信息，任何一次设备泄露或扫描都能立刻拿到管理权限。设备到货未改默认口令，等同于未设防。

#### 配置/加固方法

**1. 列出全部账号，识别默认账号**

```text
display aaa configuration
# 重点关注 admin、default、test、debug、guest 等厂商预设账号
```

**2. 修改默认账号口令**

```text
system-view
 aaa
  local-user admin password irreversible-cipher <新口令>
```

**3. 建立专用管理员账号**

按 C3 建立个人账号并赋 15 级权限，日常运维不使用默认账号登录。

#### 特殊情况处理

- 若设备因厂商保修条款要求保留默认账号，须：① 重置为强口令；② 在台账登记该账号用途与责任人；③ 纳入日志审计重点关注。
- 默认账号名如支持修改，改名后同步更新台账与运维手册。

#### 📌 加固后的验证

用旧默认口令登录应失败；用新口令登录成功。用 `display aaa configuration` 复核配置中无默认口令残留。

### C7 帐户登录超时

**问题**

> 评估表原文：配置定时帐户自动登出，空闲 5 分钟自动登出

---

#### 🔍 风险原理

空闲会话长期不关闭，等于把已认证的管理会话留在设备上无人看管。离开工位未锁屏的场景下，任何人可直接继续操作配置。

#### 配置/加固方法

**1. 检查当前空闲超时**

```text
display current-configuration configuration user-interface
# 期望：user-interface vty 视图下已配置 idle-timeout
```

**2. 配置 5 分钟空闲自动退出**

```text
system-view
 user-interface vty 0 4
  idle-timeout 5 0
  quit
 user-interface console 0
  idle-timeout 5 0
  quit
```

参数含义：第一个 `5` 为 5 分钟，第二个 `0` 为 0 秒（立即断开）。

**3. Web 路径**

**系统 → 用户管理 → 会话管理 / 远程登录**，将空闲超时设为 5 分钟。

#### 特殊情况处理

- Console 口同样需要设置，避免物理接入绕过。
- 变更策略、批量导入等长耗时操作，可临时放宽至 30 分钟，操作结束立即恢复为 5 分钟。

#### 📌 加固后的验证

```text
display current-configuration configuration user-interface
# 期望：vty 与 console 均为 idle-timeout 5 0
```

登录后静置 5 分钟，确认会话被自动断开。

依据：华为 `idle-timeout` 命令核实（USG V600 命令基线）

### C8 记录用户对设备的操作

**问题**

> 评估表原文：已配置记录防火墙管理员操作日志

---

#### 🔍 风险原理

设备自身日志是安全事件的**第一现场**。策略被改动、日志被关闭、口令被重置，都只有设备日志能证明。没有操作日志，事后追查无从下手。

#### 配置/加固方法

**1. 确认日志功能已开启**

```text
display current-configuration | include info-center
# 期望：存在 info-center enable（缺省即开启），确认未被关闭
```

### C12 使用 SNMP V3 管理、配置 SNMP TRAP

**问题**

> 评估表原文：使用 SNMP V3 以上版本对防火墙做远程管理，更改 SNMP 主机 IP；删除默认的 public、private 团体名

---

#### 🔍 风险原理

SNMP v1/v2c 团体名等价于明文口令，抓包即可获得设备完整管理权限。v3 才有认证与加密。此外，攻击者常保留默认团体名用于发现设备。

#### 配置/加固方法

**1. 检查现有 SNMP 配置与团体名**

```text
display snmp-agent sys-info version
display current-configuration | include snmp-agent
# 期望：确认当前启用的版本，以及存在哪些团体名
```

**2. 配置 SNMP v3 用户（认证 + 加密）**

```text
system-view
 snmp-agent
  version v3
  usm-user <用户名> authentication-mode sha cipher <认证口令>
  usm-user <用户名> privacy-mode aes128 cipher <加密口令>
```

v3 需区分两级认证：认证协议（SHA/SM3）与加密协议（AES128/SM4）。

**3. 配置 SNMP TRAP 上送**

```text
system-view
 snmp-agent
  host <态势感知采集口IP> version 3 priv <用户名>
```

**4. 核查并删除遗留团体名**

```text
display snmp-agent community
```

> **重要事实**：华为设备**缺省不存在** public / private 团体名（官方原文："缺省情况下，系统中没有配置团体名"）。因此 C12 的"删除默认 public、private"在华为设备上应落实为：**核查配置中是否存在遗留或未使用的团体名，逐一删除**。

#### 特殊情况处理

- **本项目绑定**：团体名/认证信息全网统一为 `GXhmrjsw-q3` 对应的凭据信息，以 `cipher` 密文写入配置，不在工单中明文传递。
- 本表 C12 与 D15（交换机）表述存在矛盾——D15 要求"删除默认团体名"，C12 要求使用指定团体名。华为设备无默认团体名，两者并不冲突，均可通过"删除遗留未用团体名 + 保留 v3 专用凭据"满足。
- SNMP 采集口应限制源地址，只允许态势感知访问。

> ⚠️ 需现场确认：SNMP 命令族在 VRP V600 上已验证，但 USG6000E 本机 `snmp-agent ?` 的可用子命令请执行后确认；若本机不支持 v3 加密套件，须按实际可用算法调整并在台账说明。

#### 📌 加固后的验证

```text
display snmp-agent usm-user
display snmp-agent community
# 期望：v3 用户存在且启用了认证与加密；community 列表为空
```

在态势感知侧确认能正常收到该防火墙的 TRAP，且 v1/v2c 采集已不可用。

### C15 拒绝常见漏洞所对应端口或者服务的访问

**问题**

> 评估表原文：以置顶黑名单对 135、137、138、139、445、3389 等高危端口进行双向策略封堵，并开启策略日志记录功能；在网络边界屏蔽 TCP 23、4444、593、5000、5554、6667、9996，udp 1434，tftp UDP 69，并开启策略日志记录功能

---

#### 🔍 风险原理

这些端口对应着已知高危漏洞与典型攻击工具：135/137/138/139 是 Windows 横向移动通道，445 是勒索软件主通道，3389 是 RDP 远程执行，23/telnet、1434/msblast、5554 是蠕虫传播端口，593、5000、4444、6667、9996 是常见后门与远控端口。边界上把它们挡住，可在攻击进入的第一时间切断大量攻击链。

#### 配置/加固方法

**1. 定义自定义服务对象**

```text
system-view
 ip service-set BLOCK_HIGH type object
  service protocol tcp source-port 0 to 65535 destination-port 135
  service protocol tcp source-port 0 to 65535 destination-port 137
  service protocol tcp source-port 0 to 65535 destination-port 138
  service protocol tcp source-port 0 to 65535 destination-port 139
  service protocol tcp source-port 0 to 65535 destination-port 445
  service protocol tcp source-port 0 to 65535 destination-port 3389
  quit
 ip service-set BLOCK_BOUNDARY type object
  service protocol tcp source-port 0 to 65535 destination-port 23
  service protocol tcp source-port 0 to 65535 destination-port 4444
  service protocol tcp source-port 0 to 65535 destination-port 593
  service protocol tcp source-port 0 to 65535 destination-port 5000
  service protocol tcp source-port 0 to 65535 destination-port 5554
  service protocol tcp source-port 0 to 65535 destination-port 6667
  service protocol tcp source-port 0 to 65535 destination-port 9996
  service protocol udp source-port 0 to 65535 destination-port 1434
  service protocol udp source-port 0 to 65535 destination-port 69
  quit
```

> **关键点**：匹配的是 **destination-port（目的端口）**。源端口无意义——攻击者可以指定任意源端口，源端口也可伪造，只有目的端口对应被攻击的服务。

**2. 建立双向拒绝策略并置顶**

```text
security-policy
 rule name blacklist_high_risk_to_untrust
  source-zone <trust>
  destination-zone <untrust>
  service BLOCK_HIGH
  action deny
  quit
 rule name blacklist_high_risk_to_trust
  source-zone <untrust>
  destination-zone <trust>
  service BLOCK_HIGH
  action deny
  quit
 rule move blacklist_high_risk_to_untrust top
 rule move blacklist_high_risk_to_trust top
```

`BLOCK_BOUNDARY` 按同样方式建双向规则。

**3. 置顶的必要性**

华为官方明确说明："虽然防火墙会默认阻断所有未明确允许的报文，但是，让流量被默认策略阻断是非常不明智的……请务必为已知的、需要被阻断的流量设置明确的禁止策略"。

黑名单**必须**放在策略列表最前面。若黑名单排在某条 allow 规则之后，流量会先命中 allow 而被放行，黑名单形同虚设。

**4. 开启策略日志**

Web：**策略 → 安全策略 → 日志**，勾选"记录会话日志 / 策略命中日志"。

> ⚠️ 需现场确认：本项的"策略日志记录"开关未检索到 V600R007C20 的官方 CLI 页面。请先在 Web"策略 → 安全策略 → 日志"确认，或在 CLI 下执行 `logging ?`、`session ?` 查看本机可用命令后再配置。

#### 特殊情况处理

- **每次修改策略后必须重新确认置顶状态**：`rule move ... top` 的位置可能因后续新增策略而改变顺序，这是本项最常见的失效方式。
- 确认业务是否确实需要用到上述任一端口；若确需（如某业务占用 5000），须走例外审批并在工单中记录，不得直接放开。
- 交换机的同类封堵见 D20，注意**交换机侧 ACL 末尾不要加兜底拒绝**（原因见 `04-交换机路由器评估.md`）。

#### 📌 加固后的验证

```text
display security-policy rule all
# 期望：两条 blacklist 规则位于列表最前，命中数随扫描流量递增
```

从边界内外两侧分别尝试访问 445、3389，均应被拒绝且日志有记录。

依据：`ip service-set ... type object` 与 `service protocol` 语法见华为官方 USG6000F/12000 V600 案例集 <https://support.huawei.com/enterprise/zh/doc/EDOC1100387633/6a67c8f1>；策略顺序与 `rule move` 见 <https://support.huawei.com/enterprise/zh/doc/EDOC1100172314/77c9e91b>

> ⚠️ 上述对象/策略语法在同代 SecOS 官方案例中已验证，USG6000E V600R007C20 执行前请用 `ip service-set ?` 复核。

### C16 开启防源地址欺骗功能

**问题**

> 评估表原文：防火墙各逻辑接口均配置开启防源地址欺骗功能

---

#### 🔍 风险原理

源地址欺骗是内网攻击的常用手法：攻击者把源地址伪造成网关或服务器地址，企图骗过基于源地址的访问控制与审计。若边界不做防欺骗，内网的 ACL、日志、溯源全部失效。

#### 配置/加固方法

**1. 枚举逻辑接口**

```text
display ip interface brief
# 期望：列出所有逻辑接口，逐个确认是否均需开启防欺骗
```

**2. 开启防源地址欺骗**

Web：**网络 → 接口 → 接口列表 → 编辑 → 高级**，勾选"源地址欺骗检查 / IP Source Guard"。

> ⚠️ 需现场确认：本项在 USG6000E 官方文档中**未检索到对应 CLI 命令**（URPF 仅见于华为路由器文档，非 USG 防火墙）。请在 Web 接口高级设置中确认是否有该选项；若无，须按本机实际能力记录，不照抄其他产品线命令。

**3. 接口级配置策略**

对每个**外部**逻辑接口确认：只接受源地址属于该接口所属网段的流量，丢弃源地址为其他网段（含内网地址）的包——这是防源地址欺骗的基本语义。

#### 特殊情况处理

- 内部互联接口（如连接态势感知的接口）通常不需要开启，需按接口用途逐个判断，不是一律开启。
- 若设备无该功能，记为"本机型号不支持，按接口网段反查规则实现等效防护"，并说明实现方式。

#### 📌 加固后的验证

从外部向内发送一个源地址伪造成内网网段的报文，确认被丢弃；Web 接口配置页截图留档。

### C17 最后一条显式拒绝策略

**问题**

> 评估表原文：访问规则列表最后一条必须是显式拒绝一切流量（双向）

---

#### 🔍 风险原理

防火墙虽然缺省会阻断未明确允许的报文，但把安全寄托在"缺省行为"上是脆弱的：一次策略导入、一次版本升级或一次误操作都可能改变缺省行为。显式兜底拒绝是把安全意图写进配置，而不是依赖设备默认值。

#### 配置/加固方法

**1. 检查缺省动作**

```text
security-policy
 default action deny
```

**2. 建立显式兜底拒绝规则**

```text
security-policy
 rule name deny_all
  source-zone any
  destination-zone any
  action deny
  quit
 rule move deny_all bottom
```

`rule move deny_all bottom` 把兜底规则移到列表**最末**，位于所有 allow 规则之后、缺省动作之前。

**3. 验证策略列表完整性**

```text
display security-policy rule all
# 期望：兜底 deny_all 在列表最后一条
```

#### 特殊情况处理

- **本项最容易在策略调整时被破坏**。每次新增或修改策略都必须确认 `deny_all` 仍在原位，这是日常巡检的固定检查项。
- "双向"指两个方向域都要覆盖，配置时用 `source-zone any` / `destination-zone any` 一次覆盖双向。
- **不要把这一条搬到交换机上**：交换机 `traffic-filter` 对未匹配报文是放行，末尾加兜底拒绝会直接断掉所有未列流量。见 `04-交换机路由器评估.md` D20。

#### 📌 加固后的验证

```text
display security-policy rule all
# 期望：最后一条为 deny_all，source-zone any / destination-zone any / action deny
```

用一条不在任何 allow 规则中的流量测试，确认被明确拒绝且策略命中数递增。

依据：华为安全策略顺序与 `rule move` 官方说明 <https://support.huawei.com/enterprise/zh/doc/EDOC1100172314/77c9e91b>

### C18 配置 DOS 和 DDOS 攻击告警

**问题**

> 评估表原文：限制网络最大流量数及网络连接数，能抵御异常攻击

---

#### 🔍 风险原理

SYN Flood 等攻击用少量攻击流量耗尽设备或主机的连接资源，正常业务因此不可用。攻击特征不明显，靠人工发现来不及，必须有设备侧告警与连接数限制。

#### 配置/加固方法

**1. 确认本机攻击防范能力**

官方 FAQ 证实 USG6000E 设备确有 SYN-Flood 攻击防范能力（排查端口扫描误报时可关闭 SYN-Flood 检测）。

Web：**系统 → 攻击防范 → SYN Flood 防护**，按需配置。

> ⚠️ 需现场确认：本项命令在 USG6000E V600R007C20 上**未检索到官方 CLI 页面**。请执行 `firewall defend ?`、`anti-ddos ?` 确认本机可用命令集后再配置，不要照抄其他产品线命令。

**2. 可参考的同类命令（AR6710 路由器侧已验证）**

若本机防火墙确无对应命令，可参考 AR 侧同类能力理解配置意图，或在网络侧由 AR 承担攻击防范：

```text
system-view
 firewall defend all enable
 firewall defend syn-flood enable
 firewall defend syn-flood zone <区域> max-rate <pps>
 firewall defend udp-flood enable
 firewall defend icmp-flood enable
```

验证：`display firewall defend flag`

AR6700 V600R023 另有 CPU 防护族：`anti-attack tcp-syn enable`、`anti-attack tcp-syn car cir 15000`，验证 `display anti-attack statistics`。

**3. 连接数限制**

> ⚠️ 需现场确认：USG6000E 未找到公开的连接数限制语法。可参考的同类官方能力为 AR 侧区域连接数限制：`statistics connect-number ip range ... tcp high 200 low 100`。

#### 特殊情况处理

- 开启 SYN 防护后可能出现端口扫描误报告警，需与监控人员约定告警阈值，避免告警风暴导致真实攻击被淹没。
- 连接数阈值须按业务基线设定，设定过低会误伤正常并发。

#### 📌 加固后的验证

Web 攻击防范页截图留档；若本机无对应功能，记为"本机型号/版本不支持该功能，已在 AR 侧或其他设备配置等效防护"，并注明实施位置。

### C19 最小权限原则

**问题**

> 评估表原文：已配置双向策略，业务以最小权限开放 IP 地址及端口

---

#### 🔍 风险原理

"默认允许、逐条加例外"会让策略列表膨胀到无法审计，最终变成一条宽泛的 any-any 放行兜底。最小权限要求每一笔放行都有明确的源、目的、端口依据，攻击面才能真正收敛。

#### 配置/加固方法

**1. 导出当前策略清单并统计**

```text
display security-policy rule all
```

导出为 Excel 台账（呼应 C1），逐条记录：规则名、源区域/地址、目的区域/地址、服务、动作、对应业务、审批单号。

**2. 逐条清理**

| 检查点 | 处理 |
| --- | --- |
| any / any 的 allow 规则 | 全删；有业务需要的改为具体源+目的+端口 |
| 与业务清单无关的规则 | 删除 |
| 已下线业务遗留规则 | 删除 |
| 临时调试规则 | 到期删除，并在台账标注清理日期 |
| 单向规则 | 补齐反向的显式拒绝（配合 C17 兜底） |

**3. 业务白名单化**

每条 allow 规则必须能回答："这是哪个业务、源是谁、目的是谁、为什么需要这个端口、谁批的"。答不上来的规则应删除。

#### 特殊情况处理

- **C19 与 C17 是一对**：C19 是白名单思路（业务最小权限开放），C17 是兜底黑名单思路（其余全拒），两者同时成立才构成完整边界。
- 清理策略前先做 C1 备份，避免误删无法回退。
- 策略清理后须做业务连通性回归，确认无业务中断。

#### 📌 加固后的验证

```text
display security-policy rule all
# 期望：无 any-any 的 permit 规则；allow 规则总数与业务清单条数可对应
```

Excel 台账条数与设备实际策略条数一致，逐条可追溯到业务与审批单。

## 四、关键配置说明

### C15 端口封堵

两处封堵要求，方向不同：

| 位置 | 端口 | 方向 | 要求 |
| --- | --- | --- | --- |
| 置顶黑名单 | 135、137、138、139、445、3389 等高危端口 | **双向策略封堵** | 开启策略日志记录 |
| 网络边界 | TCP 23、4444、593、5000、5554、6667、9996；udp 1434；tftp UDP 69 | 网络边界屏蔽 | 开启策略日志记录 |

"置顶"的要求意味着黑名单规则要放在策略列表最前面，避免被前面的允许规则绕过。

**封堵必须匹配目的端口**。华为高级 ACL 同时提供 `source-port` 与 `destination-port`，但"只堵源端口是没有用的"——攻击者可用任意源端口，源端口亦可伪造，只有目的端口对应被攻击服务。

### C17 显式拒绝

访问规则列表最后一条必须是显式拒绝一切流量（双向）。这条最容易在策略调整时被破坏——每次新增或修改策略都要确认最后一条拒绝规则仍在原位。

C19 与 C17 是一对：C19 要求业务以最小权限开放（白名单思路），C17 要求兜底全拒（黑名单思路），两者同时存在才构成完整边界。

### C2 与本项目的绑定

仅允许堡垒机、态势感知访问管理口 SSH 与 HTTPS。这两台设备对应清单序号 8（运维堡垒机，LOSA-BU-A00，名称待确认）与序号 6（态势感知，HR CRPM-3000，2 台）。

防火墙管理口如果直接从调度数据网可访问，C2 即为不合格。华为 USG6000E-S12-AC 提供管理口专用配置。

### 与交换机侧的差异

C15 与 D20 都是"封堵高危端口"，但**实现机制与收尾规则不同**：

| 项 | 防火墙 C15/C17 | 交换机 D20 |
| --- | --- | --- |
| 应用对象 | 安全策略（security-policy） | 接口 ACL（`traffic-filter`） |
| 兜底拒绝 | **需要**（C17 要求显式拒绝一切） | **禁止**，末尾加 `rule deny ip` 会断网 |
| 置顶要求 | 需要（`rule move ... top`） | 不适用 |
