# 交换机与路由器安全评估

> 对应原表 sheet：`二、安全评估（交换机、路由器X.X.X.X）`（42 行 × 9 列）
> 作业项 D1–D21，共 21 项；填表数量 = 8 台交换机（清单序号 1、2、3）+ 调度数据网路由器（AR6710、MSR3620-X1）

交换机与路由器执行安全加固。本表分 5 组：设备管理、用户账号与口令安全、日志与审计、服务优化、安全防护。

本文分两部分：**第二节**保留原表作业项总览，**第三节**逐项给出可执行的加固方法与验证命令。

> ## ⚠️ 平台差异警告（执行前必读）
>
> 本项目设备分属**三套互不兼容的操作系统**，命令语法**不可混用**：
>
> | 设备 | 操作系统 | 命令体系 | 关键差异 |
> | --- | --- | --- | --- |
> | 华为 S5735S-S24T4S-XA | VRP **V200** | 华为 V200 语法 | NTP 用 `ntp-service`；VTY 无 `shutdown` |
> | 华为 AR6710 | VRP **V600** | 华为 V600 语法 | NTP 用 `ntp`；VTY 有 `shutdown` |
> | **MSR3620-X1** | **H3C Comware V7** | **H3C 语法** | **不是华为设备**；ACL 用 `packet-filter`；RBAC `user-role` |
>
> **把华为命令用在 MSR3620-X1 上，或把 H3C 命令用在华为设备上，都会失败。**
> 下文每一项均按平台分块标注。凡官方未发布对应 CLI 的，一律标注 `⚠️ 需现场确认` 并给出确认方法，**不要照抄其他型号命令**。

### D1 端口与实际应用相符

**问题**

> 评估表原文：已将使用的端口、VLAN 添加符合实际应用的描述

---

#### 🔍 风险原理

端口描述是运维排查时唯一可靠的现场线索。没有描述时，工程师只能靠拔插线缆和逐口测试判断用途，既慢又容易误插。描述错误或缺失还会让后续的端口安全绑定、ACL 策略配错位置。

#### 配置/加固方法

**1. 导出当前端口描述**

```text
display interface description
```

或直接看接口配置：

```text
display current-configuration interface GigabitEthernet0/0/1
```

**2. 逐口配置描述**

**【S5735S】【AR6710】**

```text
system-view
 interface GigabitEthernet0/0/1
  description <对接设备名>-<对端口用途，如：调度数据网核心交换机Gi1/0/24>
  quit
```

**【MSR3620】**（H3C）

```text
system-view
 interface GigabitEthernet0/0/1
  description <对接设备名>-<用途>
  quit
```

`description` 在两套体系下命令同名、位置相同，此处是少数通用命令之一。

**3. VLAN 接口同样需要描述**

```text
interface Vlanif10
 description <用途，如：交换机管理网>
```

#### 特殊情况处理

- D1 要求"使用的端口、VLAN"都要有描述。**空余端口**也要写明"空闲"，否则下次有人接线时无从判断这是备用口还是已用口（已用口被误当备用，备用口被误接入业务）。
- 描述文本要与施工图、端口分配表一致；本项目端口分配参考 [Hybrid与Trunk概念.md](../../../网络概念/Hybrid与Trunk概念.md) 与 [nterface Vlanif 10说明.md](../../../网络概念/nterface%20Vlanif%2010说明.md)。
- 远动专线交换机（D 系列）的端口用途与调度数据网平面内设备不同，**不能套用同一套描述模板**。

#### 📌 加固后的验证

```text
display interface description
# 期望：在用端口、空余端口、VLAN 接口均有描述，无空白项
```

逐条与端口分配表核对，描述与实际用途一致。

依据：华为 VRP 接口管理命令 <https://support.huawei.com/enterprise/zh/doc/EDOC1100459421>

### D2 远程 SSH 管理设备

**问题**

> 评估表原文：已启用 SSH 协议，远程维护的设备使用 SSH 加密协议

---

#### 🔍 风险原理

Telnet、HTTP、SNMP v1/v2c 都以明文传输凭据或管理信息。在调度数据网内，任意一台主机被攻破后即可直接抓取设备管理流量，横向获取其他设备凭据。SSH 是管理面的唯一可接受协议。

#### 配置/加固方法

**1. 检查 SSH 服务状态**

**【S5735S】【AR6710】**

```text
display ssh server status
# 期望：SSH server is enabled
```

**2. 检查是否有明文管理协议仍开启**

```text
display current-configuration | include telnet|http|server-manage
```

**3. 启用 SSH（若未启用）**

**【S5735S】【AR6710】**

```text
system-view
 ssh server enable
 rsa local-key-pair create
# 期望：提示创建公钥成功
 ssh server authentication-type password
```

**【MSR3620】**（H3C，Telnet 关闭方式已官方验证）

```text
system-view
 undo telnet server enable
```

**4. 生成认证密钥（RSA）**

**【S5735S】【AR6710】**

```text
system-view
 rsa local-key-pair create
# 期望：提示 The key file is named HUAWEI_SSH_HOST.key
```

**5. 配置 SSH 管理来源限制**

配合 D4 的 ACL 使用，见下一项。

#### 特殊情况处理

- V200 与 V600 的 SSH 支持参数存在差异，**SSH 版本、认证方式的可选值须用 `ssh server ?` 确认本机支持集**。
- MSR3620 未验证 SSH 配置命令，按 D13 同批在 Web/CLI 确认本机可用命令。

#### 📌 加固后的验证

```text
display ssh server status
display ssh user-information
# 期望：SSH 处于 enabled，Telnet 处于 disabled
```

用 SSH 登录成功；用 Telnet 登录应失败。

### D3 启用 AAA 本地认证

**问题**

> 评估表原文：VTY 启用设备 AAA 本地认证方式

---

#### 🔍 风险原理

VTY 若使用 `authentication-mode password` 甚至 `none`，则登录凭据与用户身份分离，无法追溯到自然人，且可能被暴力破解。使用 AAA 本地认证后，账号、权限、审计三者绑定。

#### 配置/加固方法

**1. 创建本地账号并赋权**

**【S5735S】【AR6710】**

```text
system-view
 aaa
  local-user <姓名拼音> password irreversible-cipher <口令>
  local-user <姓名拼音> service-type ssh
  local-user <姓名拼音> privilege level 15
  quit
```

**2. 配置 VTY 使用 AAA**

```text
system-view
 user-interface vty 0 4
  authentication-mode aaa
  quit
```

**3. 确认 AAA 视图配置**

```text
display current-configuration configuration aaa
display aaa configuration
```

**【MSR3620】**（H3C 已官方验证）

```text
system-view
 local-user <姓名拼音> class manage
  authorization-attribute user-role network-admin
  service-type ssh
  password cipher <口令>
  quit
 line vty 0 63
  authentication-mode scheme
  quit
```

> **Comware 与 VRP 差异**：H3C 用户角色是 RBAC（`user-role network-admin`），**没有 `privilege level 0-15` 体系**。切勿混用。

#### 特殊情况处理

- `irreversible-cipher` 不可逆加密；如需定期更换口令且设备支持，可考虑 `cipher`。
- 每个自然人一个账号，禁止 `shared`/`admin` 多人共用（呼应 D6）。
- 远程专线交换机是否与平面内交换机共用 AAA 策略，须按现场规划确认。

#### 📌 加固后的验证

```text
display user-interface vty 0
# 期望：VTY 的 authentication-mode 为 aaa
display current-configuration configuration aaa
# 期望：账号清单与人员名单一致
```

用两个不同账号分别登录，确认日志记录各自账号名。

### D4 远程服务只允许特定地址访问

**问题**

> 评估表原文：配置访问控制列表，只允许堡垒机、态势感知等访问网络设备 SSH 管理服务

---

#### 🔍 风险原理

设备管理面一旦被区域内任意主机可达，攻击者即可获取全网设备配置（含路由、ACL、加密策略），为横向渗透提供完整地图。限制管理来源到堡垒机与态势感知，是把管理流量收敛到可审计的通道上。

#### 配置/加固方法

**1. 创建管理访问 ACL**

**【S5735S】【AR6710】**（华为 VRP）

```text
system-view
 acl number 3001
  rule 5 permit tcp source-port eq 0 to 65535 destination-port eq 22 source <堡垒机IP> 0.0.0.0
  rule 6 permit tcp source-port eq 0 to 65535 destination-port eq 22 source <态势感知IP> 0.0.0.0
  rule 7 deny tcp destination-port eq 22
  quit
```

**2. 应用到 VTY**

**【S5735S】**（VRP V200）

```text
user-interface vty 0 4
 acl 3001 inbound
 quit
```

**【AR6710】**（VRP V600）

```text
user-interface vty 0 4
 acl 3001 inbound
 quit
```

**【MSR3620】**（H3C）

```text
system-view
 line vty 0 63
  acl 3001 inbound
  quit
```

**3. 验证**

```text
display acl 3001
display current-configuration | include acl
```

#### 特殊情况处理

- **本项目绑定**：仅允许堡垒机（清单序号 8，LOSA-BU-A00，名称待确认）与态势感知（清单序号 6，HR CRPM-3000，2 台）访问 SSH。两个 IP 必须在实施前确认。
- **必须有兜底 deny**：ACL 末尾缺 `rule 7 deny`，则未匹配流量按 ACL 缺省行为处理；华为 ACL 中未匹配报文**默认放行**，所以这一条不能省。
- 现场应急时如需临时放开其他地址，须经审批并在工单中记录开启与恢复时间。
- 建议同时在交换机侧上行口再做一层源限制（双保险），参考 [vlan间安全策略.md](../../../网络概念/vlan间安全策略.md)。

#### 📌 加固后的验证

```text
display acl 3001
# 期望：命中计数显示堡垒机与态势感知有流量，其他源为 0
```

从堡垒机 SSH 登录成功；从其他主机尝试 SSH 应被拒绝。

### D5 配置 consol 口密码保护功能

**问题**

> 评估表原文：配置 consol 口密码保护功能，防止无认证直连设备

---

#### 🔍 风险原理

Console 口是物理直连通道，绕过网络层的所有访问控制。任何能到机房机柜的人都能直接连接设备。配置认证与空闲超时，可防止无认证直连与"插着不管"两种风险。

#### 配置/加固方法

**1. 配置 Console 口认证与超时**

**【S5735S】【AR6710】**（华为 VRP）

```text
system-view
 user-interface console 0
  authentication-mode aaa
  idle-timeout 5 0
  quit
```

> **重要事实**：**Console 口没有 `shutdown` 语义**（Console 是物理接口，无法关闭）。加固方式是**认证 + 超时**，不要试图 shutdown。

**2. 若设备存在 AUX 口**

**【AR6710】**

```text
user-interface aux 0
 authentication-mode aaa
 idle-timeout 5 0
 quit
```

**3. 确认设备是否真有 AUX 口**

```text
display current-configuration | include user-interface
```

执行 `user-interface ?` 查看本机支持哪些线路类型。

> **需现场确认**：AR6710 / S5735S 面板是否实际带 AUX 口**须按实物确认**。若设备无 AUX 口，本项记"设备无 AUX 口，不适用"，不要凭空写出 AUX 配置。

#### 特殊情况处理

- 机房物理准入控制（门禁、登记、监控）与本项配合使用——Console 口绕过网络 ACL，物理安全是唯一补充。
- 现场调试期间可临时把 Console 认证改为 `password` 便于快速登录，但**必须记录并在调试结束后恢复为 aaa**。

#### 📌 加固后的验证

```text
display current-configuration | include user-interface
# 期望：console 0 下存在 authentication-mode aaa 与 idle-timeout 5 0
```

拔线重插 Console，按提示需输入凭据方可登录。

依据：华为 Console 用户界面认证与超时命令核实 <https://support.huawei.com/enterprise/zh/doc/DOC1000057409>

### D6 用户帐号权限分配

**问题**

> 评估表原文：按照用户分配帐号，无不同用户间共享帐号

---

#### 🔍 风险原理

共享账号使操作无法追溯到自然人，日志中只会出现同一个名字，审计与追责同时失效。账号一旦泄露也无法精准回收。

#### 配置/加固方法

**1. 导出账号清单**

**问题**

#### 🔍 风险原理

**1. 设置符合策略的口令**

```text

  local-user <姓名拼音> password irreversible-cipher <长度≥8 含大小写数字符号的口令>

```

**【AR6710】**（华为 VRP V600）


**【MSR3620-X1】**（H3C Comware V7 —— **无 `irreversible-cipher`**）


> ⚠️ **Comware 与 VRP 的关键差异**：`irreversible-cipher` 是**华为 VRP 专有**参数，H3C Comware 用 `password cipher`；且 Comware **无 `privilege level 0-15` 体系**，改用 `class manage`（等价于 VRP 的 level 15）。在 MSR3620 上照抄 `irreversible-cipher` 会直接报错。

>
> **【MSR3620】** Comware 侧须用 `password-policy complexity ?` 现场确认，**不存在** `user-password complexity-check`。

- 口令复杂度策略应作用于所有 local-user，包括厂商默认账号。

- **`simple` vs `cipher`**：Comware 若用 `password simple` 则配置文件明文可读，**不符合本项要求**；必须用 `password cipher`。设置后用 `display current-configuration | include local-user` 复核显示为密文。

#### 📌 加固后的验证

用弱口令尝试设置，应被拒绝或产生告警；`display current-configuration configuration aaa` 复核已设口令长度与复杂度达标。


### D9 限制管理员权限登录

**问题**

> 评估表原文：配置特权模式口令，口令加密存储，并满足口令复杂度要求（密码不小于 8 位）；配置登录默认级别，登录默认级别配置为访问级（level 0）

---

#### 🔍 风险原理

若 SSH 登录后直接进入特权模式，攻击者一旦拿到登录凭据即拥有完全控制。把默认级别降为 level 0，增加了一道"提权需再验证"的环节。

#### 配置/加固方法

**1. 配置特权模式口令并设为 level 0**

**【S5735S】【AR6710】**

```text

 quit
user-interface vty 0 4
 user privilege level 0
 quit
```

进入 user-view 后须输入 `enable` 并提供 `super password` 才能提权。

**2. 确认配置**

```text
display current-configuration | include super|privilege
display user-interface vty 0
# 期望：VTY 的 user privilege level 为 0
```

**【MSR3620】**（H3C 无 `privilege level` 体系）

```text
system-view

# 或通过 RBAC 角色控制
 local-user <姓名拼音> class manage
  authorization-attribute user-role network-admin
  quit
```

> **Comware 与 VRP 差异**：H3C 用 `user-role` RBAC，命令为 `super password level 3 simple` 或角色授权，**不是** `privilege level 0-15`。

#### 特殊情况处理

- level 0 设计使粘贴命令与自动化脚本受限（脚本需先 `enable`）。这是标准的**有意设计**，不是缺陷，不得为图方便改回 level 3 或 15。
- ⚠️ 需现场确认：`super` 提权命令在 AR6710 已验证，**S5735S 交换机侧请用 `super ?` 确认本机支持集**。

#### 📌 加固后的验证

```text

# 期望：user privilege level 为 0
```

SSH 登录后确认直接进入 `<设备名>`（user-view，尖括号），输入 `enable` 后才变为 `[设备名]`。

依据：华为 SSH/AAA/VTY `user privilege level` 语法核实；H3C `super password` 待按本机版本确认

### D15 配置 SNMP V2 或以上版本、配置 SNMP TRAP

**问题**

> 评估表原文：SNMP Community 口令强度长度至少 8 位，并包括数字、小写字母、大写字母和特殊符号 4 类中至少 2 类；使能 snmpv2c、v3 版本；只与特定主机进行 SNMP 协议交互，设置 ACL 进行限制；关闭未使用的 SNMP 协议，禁用 SNMP 的 WRITE 功能

---

#### 🔍 风险原理

SNMP v1/v2c 团体名等价于明文口令，抓包即可获得设备完整管理权限；WRITE 功能更可修改设备配置，是间接接管设备的路径。攻击者常保留默认团体名用于扫描发现设备。

#### 配置/加固方法

**1. 检查当前 SNMP 配置**

**【S5735S】【AR6710】**

```text
display current-configuration | include snmp
display snmp-agent community
# 期望：确认启用的版本、团体名清单
```

**2. 配置 v3（推荐：认证 + 加密）**

**【S5735S】【AR6710】**

```text
system-view
 snmp-agent
  version v3
  usm-user <用户名> authentication-mode sha cipher <口令>
  usm-user <用户名> privacy-mode aes128 cipher <口令>
  quit
```

v3 需区分两级：认证协议（SHA/SM3）与加密协议（AES128/SM4）。

**3. 配置 v2c 只读团体（无 write 即禁用写）**

```text
snmp-agent community read cipher <团体名> acl <ACL编号>
```

**不配置 `write` 关键字，即为只读**——这正是 D15"禁用 SNMP 的 WRITE 功能"的落地方式。

**4. 删除已存在的 write 团体**

```text
snmp-agent community write cipher <团体名>
# 删除时：
undo snmp-agent community write cipher <团体名>
```

**5. 设置 ACL 限制来源**

```text
system-view
 snmp-agent
  acl 3002
  quit
```

ACL 3002 中只放行态势感知地址。

**6. 配置 TRAP 上送**

```text
snmp-agent
 host <态势感知采集口IP> version 3 priv <用户名>
 quit
```

**【MSR3620】**（H3C 已官方验证）

```text
system-view
 snmp-agent sys-info version v3
 snmp-agent community read cipher <团体名> acl <ACL编号>
 snmp-agent acl <ACL编号>
 quit
```

验证：`display snmp-agent community`、`display snmp-agent sys-info`

#### 特殊情况处理

- **重要事实**：华为设备**缺省没有** public / private 团体名（官方原文："缺省情况下，系统中没有配置团体名"）。因此 D15 的"禁用默认团体名"在华为设备上应落实为：**核查配置中是否存在遗留或未使用的团体名，逐一删除**。
- **本项目绑定**：团体名统一为 `GXhmrjsw-q3`。核对其复杂度：长度 11 位（≥8），含大写（G、X）、小写（h、m、r、j、s、w、q）、数字（3）、特殊符号（-），满足 D15"4 类中至少 2 类"的要求。
- 本表 C12（防火墙）与 D15 表述矛盾，但华为设备无默认团体名，两者并不冲突：删除遗留未用团体名 + 保留 v3 专用凭据，可同时满足。
- SNMP 来源应由 ACL 限制为态势感知，**不要 any-any**。

#### 📌 加固后的验证

```text
display snmp-agent community
display snmp-agent usm-user
# 期望：v3 用户存在且启用认证+加密；无 write 团体；团体名仅受 ACL 限制
```

在态势感知侧确认能收到该设备 TRAP，且 v1/v2c 采集已不可用。

依据：华为 SNMP v3 命令族核实；H3C `snmp-agent community` / `snmp-agent acl` 见 <https://www.h3c.com/en/d_202411/2299316_294551_0.htm>

### D18 启用路由协议认证功能

**问题**

> 评估表原文：启用动态 IGP（RIPv2、OSPF、ISIS 等）或 EGP（BGP）协议时，启用动态路由协议认证功能，如 MD5 加密

---

#### 🔍 风险原理

动态路由协议报文默认不认证。攻击者若能在网络中伪造路由通告（哪怕只有一次），即可把流量导向自己，实施中间人攻击；或注入大量路由把设备 CPU 占满导致路由协议震荡。

#### 配置/加固方法

**1. OSPF —— 区域级（区域 0 内所有接口生效）**

**【S5735S】【AR6710】**

```text
system-view
 ospf 1
  area 0
   authentication-mode md5 1 cipher <密码>
   quit
  quit
```

**2. OSPF —— 接口级（优先级高于区域级）**

```text
system-view
 interface Vlanif10
  ospf authentication-mode md5 1 cipher <密码>
  quit
```

**3. BGP —— TCP MD5**

```text
system-view
 bgp 100
  peer <对端IP> as-number 200
  peer <对端IP> password cipher <密码>
  quit
```

**4. 验证**

```text
display ospf peer
display bgp peer verbose
# 期望：邻居状态 Full/Established，且认证已协商
```

#### 特殊情况处理

- ⚠️ **重要提醒**（华为官方原文）：**MD5 已被华为列为弱算法，"推荐使用 HMAC-SHA256 加密算法"**。新版本使用 MD5 可能需先安装 WEAKEA 弱协议插件。
- 原表写"如 MD5 加密"，建议实施时**优先使用 `hmac-sha256`**，并在工单中注明"如标准强制 MD5，需确认本机是否支持/是否需插件"：
  ```text
  ospf authentication-mode hmac-sha256 1 cipher <密码>
  ```
- **两端设备必须配置相同认证方式与密钥**，否则邻居无法建立。本项目调度数据网为双平面设计（见 [../04-调度数据网设备.md](../04-调度数据网设备.md)），**对端设备型号可能不同（华为 vs MSR3620-X1），认证算法须两端一致**。
- 若本项目实际未启用动态路由协议，本项记"本设备未启用动态路由协议，不适用"，但需说明确认依据。

#### 📌 加固后的验证

```text
display ospf peer
# 期望：邻居状态为 Full，认证协商成功
```

抓包确认 OSPF 报文中携带认证字段。

依据：接口级 `ospf authentication-mode` 语法 <https://support.huawei.com/enterprise/zh/doc/EDOC1100333406/21008723>；区域级 <https://support.huawei.com/enterprise/zh/doc/EDOC1100333406/ecbefd39>；BGP MD5 <https://support.huawei.com/enterprise/zh/doc/DOC1000089018/dbb7c28d>

### D20 过滤已知攻击

**问题**

> 评估表原文：在交换机上设置 ACL 安全访问控制，通过 ACL 过滤掉已知安全攻击数据包。屏蔽端口清单：TCP/UDP 135、137、138、139、445、3389；TCP 593、5000、4444、5554、6667、9996；UDP 1434；TFTP UDP 69

---

#### 🔍 风险原理

这些端口对应已知高危漏洞与典型攻击工具：135/137/138/139 是 Windows 横向移动通道，445 是勒索软件主通道，3389 是 RDP 远程执行，23/telnet 与 1434/msblast 是蠕虫传播端口，5000/5554/6667/9996 是常见后门与远控端口。

#### 配置/加固方法

**1. 创建 ACL —— 按目的端口封堵**

**【S5735S】【AR6710】**（华为 VRP）

```text
system-view
 acl number 3000
  rule 5  deny tcp destination-port eq 135
  rule 6  deny tcp destination-port eq 137
  rule 7  deny tcp destination-port eq 138
  rule 8  deny tcp destination-port eq 139
  rule 9  deny tcp destination-port eq 445
  rule 10 deny tcp destination-port eq 3389
  rule 11 deny tcp destination-port eq 593
  rule 12 deny tcp destination-port eq 5000
  rule 13 deny tcp destination-port eq 4444
  rule 14 deny tcp destination-port eq 5554
  rule 15 deny tcp destination-port eq 6667
  rule 16 deny tcp destination-port eq 9996
  rule 17 deny tcp destination-port eq telnet
  rule 18 deny udp destination-port eq 1434
  rule 19 deny udp destination-port eq tftp
  quit
```

> **关键点（回应原表附注）**：华为高级 ACL 同时提供 `source-port` 与 `destination-port`，但"只堵源端口是没有用的"——攻击者可用任意源端口，源端口亦可伪造，只有**目的端口**对应被攻击服务。上例按 `destination-port` 封堵即为正确做法。

**【MSR3620】**（H3C Comware V7）

```text
system-view
 acl number 3000
  rule 0 deny tcp destination-port eq 135
  rule 1 deny tcp destination-port eq 445
  ...
  quit
```

> **Comware 与 VRP 差异**：H3C 高级 ACL 命令为 `acl advanced 3000` 或 `acl number 3000`，规则语法基本一致，但**接口下应用命令完全不同**（见下）。

**2. 应用到接口 —— 三平台命令不同**

**【S5735S】【AR6710】**

```text
system-view
 interface GigabitEthernet0/0/1
  traffic-filter inbound acl 3000
  quit
```

**【MSR3620】**（H3C）

```text
system-view
 interface GigabitEthernet0/0/1
  packet-filter 3000 inbound
  quit
```

> ⚠️ **华为用 `traffic-filter`，H3C 用 `packet-filter`，不可互换。**

**3. 两条重要行为语义（务必写入实施记录）**

> **① 交换机 ACL 末尾不要加兜底拒绝。**
> `traffic-filter` 只对**命中 deny 规则**的报文丢包，官方原文："若报文没有匹配任何一条规则，则允许该报文通过"。
> 因此**末尾加 `rule deny ip` 会直接断掉所有未列流量**。
> "最后一条显式拒绝一切"是**防火墙安全策略 C17** 的要求，**不要套用到交换机**。

> **② S5735 必须入方向过滤。**
> 华为官方文档明确：对 S5735-S / S5735S-S 等型号，**若 ACL 的 deny 规则用 `traffic-filter` 应用在出方向，会把 CPU 发出的 ICMP/OSPF/BGP/RIP/SNMP/Telnet 等协议控制报文一并丢掉，影响协议运行**。
> **因此优先入方向过滤，避免在出方向挂 deny ACL。**

#### 特殊情况处理

- 确认业务是否确实需要上述任一端口；确需（如某业务占用 5000）须走例外审批并在工单记录，**不得直接放开**。
- ACL 应应用在**靠近不可信侧**的接口入方向。
- 跨平面/跨区域的访问控制思路另见 [vlan间安全策略.md](../../../网络概念/vlan间安全策略.md) 与 [实验02/README.md](../../../网络概念/实验02/README.md)。
- 防火墙侧的同类封堵见 C15，**但收尾规则与交换机相反**（防火墙需兜底拒绝），对比见 [03-防火墙评估.md](03-防火墙评估.md)。

#### 📌 加固后的验证

**【S5735S】【AR6710】**

```text
display acl 3000
display traffic-filter applied-record
display traffic-filter statistics interface GigabitEthernet0/0/1 inbound
# 期望：deny 规则命中计数随扫描流量递增
```

**【MSR3620】**

```text
display acl 3000
display packet-filter statistics interface GigabitEthernet0/0/1 inbound
```

从边界内外两侧分别尝试访问 445、3389，均应被拒绝且计数递增。

依据：华为高级 ACL `destination-port` 规则 <https://support.huawei.com/enterprise/zh/doc/DOC1000178157/b1e74756>；`traffic-filter` 未匹配放行语义 <https://support.huawei.com/enterprise/zh/doc/EDOC1100333808/94692823/traffic-filter-inbound-tunnel-interface-view>；S5735 出方向风险 <https://support.huawei.com/enterprise/zh/doc/EDOC1100410520/e9b94643>；H3C `packet-filter` <https://www.h3c.com/en/d_202409/2267460_294551_0.htm>

### D21 交换机端口安全

**问题**

> 评估表原文：重要服务器采用 IP+MAC+端口绑定

---

#### 🔍 风险原理

交换机默认转发数据帧，不校验 MAC 与 IP 来源。攻击者接入空闲端口后可伪造服务器 MAC 与 IP 冒充该服务器，接收本应发给它的流量，甚至在实施 D20 封堵后另寻路径。IP+MAC+端口三元绑定把"哪台服务器只能用哪个口、并且只能以自己的身份出现"固定下来。

#### 配置/加固方法

**方案 1（推荐，最贴近"IP+MAC+端口绑定"）：静态绑定表 + IPSG**

**【S5735S】【AR6710】**

```text
system-view
 interface GigabitEthernet0/0/2
  ip source check user-bind interface GigabitEthernet0/0/2
  ip source check user-bind ip-address <服务器IP> mac-address <服务器MAC>
  quit
```

验证：

```text
display ip source check user-bind interface GigabitEthernet0/0/2
# 期望：列出绑定的 IP、MAC、接口三元组
```

**方案 2：端口安全（限制 MAC 数量、Sticky MAC）**

```text
system-view
 interface GigabitEthernet0/0/2
  port-security enable
  port-security mac-address max 2
  port-security mac-address sticky
  port-security protect-action restrict
  quit
```

验证：`display port-security`

> **重要提醒**：`port-security protect-action shutdown` 会导致业务口 **err-down**（华为官方知识库有误触发致断网案例）。生产环境建议用 **`restrict`** + 告警，**不要用 shutdown**。

**【MSR3620】**（H3C）

⚠️ **需现场确认**：H3C Comware 的端口安全 / IP-MAC 绑定命令与华为差异较大，请按本机版本与 H3C 命令参考确认，不要照抄华为 `port-security` 语法。

#### 特殊情况处理

- 绑定项须**逐台服务器**登记（IP、MAC、端口三者缺一不可），登记前用 `display mac-address` 核对实际 MAC，防止填错导致服务器网络不通。
- 服务器更换网卡、重装系统后 MAC 变化，**必须同步更新绑定**，否则服务器无法通信。建议绑定台账与资产台账联动。
- 虚拟机/云主机 MAC 会变化，应使用静态绑定并由资产系统保证一致性。
- 本项是网络侧绑定，与主机侧 A23/B25 的 USB 封条共同构成管控闭环，见 [03-防火墙评估.md](03-防火墙评估.md) C16。

#### 📌 加固后的验证

```text
display ip source check user-bind interface GigabitEthernet0/0/2
display port-security
display mac-address interface GigabitEthernet0/0/2
# 期望：绑定三元组与实际服务器一致
```

将服务器网线换到未绑定的端口，确认网络不通；伪造 MAC 接入，确认被丢弃。

依据：华为静态绑定与 IPSG、端口安全命令核实；`port-security protect-action shutdown` 风险依据华为官方知识库

## 四、交换机与防火墙的差异对照（实施时最易混淆处）

| 项 | 防火墙 C15 / C17 | 交换机 D20 |
| --- | --- | --- |
| 应用对象 | 安全策略 `security-policy` | 接口 ACL `traffic-filter`（华为）/ `packet-filter`（H3C） |
| 未匹配报文 | 缺省拒绝 | **放行** |
| 末尾兜底拒绝 | **需要**（C17 显式拒绝一切） | **禁止**，加 `rule deny ip` 会断网 |
| 规则置顶 | 需要（`rule move ... top`） | 不适用 |
| 应用方向 | 双向策略 | **S5735 必须入方向**（出方向会丢 CPU 控制报文） |
