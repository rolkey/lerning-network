# 加密装置安全评估

> 对应原表 sheet：`加密装置`（6 行 × 7 列）
> 作业项 E1–E4，共 4 项；填表数量 = 6 台（清单序号 5 纵向加密认证装置，到货 6 台，Sheet1 另写 7 套）

纵向加密认证装置执行安全加固。本 sheet 只有 4 个作业项，是 5 个 sheet 中最简的一张，**缺"基本信息""异常情况记录""作业终结"三章，也没有作业项分组**，「依据」列全空。

本文分两部分：**第一节**保留原表作业项，**第二节**逐项给出可执行的加固方法与验证步骤。

## 二、逐项操作方法（E1–E4）

### E1 策略最小化、策略备份

**问题**

> 评估表原文：已配置双向策略，业务以最小权限开放 IP 地址及端口。登录设备检查策略、并做好备份
> 作业项分组：策略检查

---

#### 🔍 风险原理

加密装置部署在厂站与调度数据网（地调/中调）之间的**纵向边界**上，靠加密策略/隧道决定哪些业务数据加密传输、哪些明文放行。策略是这台设备的核心配置：

- **策略过宽等于开洞。** 源/目的 IP 与端口全放开，或存在不必要的"明文通"通道，等于在纵向边界留了一个不加保护的口子，攻击者横向摸进来即可绕过加密直接访问业务系统。
- **策略不对称会造成业务中断或明文泄露。** 纵向加密靠两端协商隧道，本端与对端（主站/对侧厂站）策略不匹配或算法不一致会导致隧道协商失败，远动、AGC/AVC、保信等业务中断；误配成单向或明文则敏感调度数据在链路上裸奔。
- **没有备份，出问题只能"干瞪眼"。** 整机故障或配置被误清空后，重新配置需人工逐条核对，耗时且易错，也无法证明配置"原本是什么样"。

#### 配置/加固方法

**1. 登录设备**

通过本地串口（Console）或专用网口，用厂商配套的配置管理软件 / Web 管理界面登录。

> ⚠️ 菜单名称以本机 Web 界面为准，需现场确认。

**2. 核查加密策略清单**

进入策略/隧道配置界面，逐条核对：

| 策略编号/名称 | 对端装置 | 本地 IP:端口 | 对端 IP:端口 | 模式 | 算法 |
| --- | --- | --- | --- | --- | --- |
| 001 主站-远动 | 地调加密装置 | `<本地IP>`:`<端口>` | `<对端IP>`:`<端口>` | 双向加密 | SM4/SM2 |
| 002 … | … | … | … | … | … |

重点检查三点：

- **双向策略是否建立**——每条业务通道都应是双向加密隧道，且本端与对端参数匹配；
- **IP、端口是否最小化**——只保留业务实际需要的源/目的 IP 和端口，测试遗留、长期不用的策略标记待清理；
- **算法是否合规**——确认为国密算法（SM2/SM3/SM4），非明文方式。

**3. 最小权限收口**

关闭多余端口、删除无用策略、停用非必要的"明文通"通道。涉及改动的提前报备并避开业务高峰，改动前后截图留档。

**4. 备份配置**

在管理软件中"导出/备份配置"，导出为本地文件，按"设备名 + 日期 + 版本"命名归档：

```bash
# 归档示例（运维 PC 上的文件操作，非设备命令）
mkdir -p 加密装置配置备份/2026-10-01
cp 加密机导出配置.cfg 加密装置配置备份/2026-10-01/加密机_20261001.cfg
```

备份文件存于受控目录并登记台账，明确备份人与时间。

> **注意**：备份文件通常与设备型号、软件版本强绑定，**跨版本导入可能失败**，备份时记下型号与版本号。

#### 特殊情况处理

- **本项目绑定**：本设备为卫士通 SJJ1632-B，为**纵向加密认证装置**，按清单要求"国产设备、使用国密算法、具备公安部销售许可证"。国密合规证据（设备型号核准证书）属**文档交付物**，不是 CLI 操作项，须单独收集归档。
- 明文通通道只保留确需的（如个别远动、保信业务），关闭前务必确认该业务真的不需要明文。
- **修改策略属于影响业务的变更**，须安排在检修窗口并提前与主站/调度沟通。
- 站内再改本地策略前**必须先与主站沟通**，否则可能被主站统一下发的策略覆盖（与 E4 相关）。

#### 📌 加固后的验证

```bash
# 1. 策略清单与业务台账一致，无多余 IP / 端口
# 2. 各双向隧道协商正常，无"协商失败/告警"
# 3. 配置文件已导出并归档
ls -l 加密装置配置备份/2026-10-01/
```

期望结果：策略清单与业务台账一一对应，业务以最小权限开放 IP 和端口，无多余策略与明文通通道；双向加密隧道状态正常；当前配置已完整备份并归档、可随时用于恢复。

### E2 日志服务器配置

**问题**

> 评估表原文：配置加密装置日志服务器 IP 为态势感知采集口 IP
> 作业项分组：日志服务器

---

#### 🔍 风险原理

- **日志不上送，等于"盲人摸象"。** 加密装置是纵向边界的第一道闸门，隧道异常、非法接入、认证失败等关键安全事件都在此发生。不配置日志服务器就只能登录设备本地翻看，值班与安防平台无法实时感知。
- **缺乏审计证据，事后无法溯源。** 无集中留存日志就无法还原"谁在何时做了什么操作""哪条隧道何时异常"，难以定责，也不满足电力监控系统对日志集中审计的合规要求。
- **日志时间戳不准会毁掉溯源。** 各设备时间不同步时，平台上事件顺序错乱，关联分析无法进行。

#### 配置/加固方法

**1. 确认态势感知采集口 IP（前置条件）**

先向安防平台运维或项目负责人确认态势感知的**日志采集口 IP 与接收端口**（常见 syslog 为 UDP 514，**具体以平台要求为准**），确认加密装置与该采集口网络可达。

> ⚠️ **本项目数据缺口**：资料中态势感知装置只写了"10M/100M/1000M 自适应以太网电口 ≥16 个，光口 ≥8 个"，**没有 IP 规划**，见 [../07-二次安防系统.md](../07-二次安防系统.md) 资料缺口一节。**E2 必须在该 IP 确定后才能实施。**

**2. 登录设备并进入日志配置**

通过本地串口/专用网口登录管理界面，进入"系统配置 / 日志配置 / Syslog 服务器"类菜单。

> ⚠️ 菜单名称以本机 Web 界面为准，需现场确认。

**3. 配置日志服务器**

| 配置项 | 值 |
| --- | --- |
| 日志服务器地址 | **态势感知采集口 IP**（本项目硬绑定） |
| 端口 | 按平台要求（常见 UDP 514） |
| 协议 | 按平台要求（UDP 或 TCP，勿默认） |
| 日志级别 | 至少含**安全事件**与**系统告警** |

一般至少上送安全事件和系统告警；运行信息按平台容量酌情勾选，避免无关信息淹没关键告警。

**4. 保存并下发**

保存配置并下发到装置，确认链路可达。若加密装置与态势感知采集口不在同一网段或跨安全分区，需同步放通相应的网络策略/路由。

**5. 确认时间同步**

**先对时再验证日志**。核对装置时间，必要时配置 NTP，否则平台侧看到的日志时间会偏差。

#### 特殊情况处理

- **本项目硬绑定**：加密装置日志服务器 IP 必须为**态势感知采集口 IP**。对应清单序号 6 态势感知装置 2 台，到货型号 HR CRPM-3000（数量存在 1 台与 2 台两种说法）。**该绑定项无替代方案。**
- 采集口 IP 与加密装置可能不在同一网段，须先做连通性测试再确认，不要先改配置后测连通。
- 加密装置与防火墙 C9、交换机 D11 应指向**同一套日志平台**，构成统一的日志汇集。

#### 📌 加固后的验证

```bash
# 1. 本地连通性测试（在可达网段的运维机上执行）
ping <态势感知采集口IP>
telnet <态势感知采集口IP> <端口>
# 期望：可达

# 2. 触发一次测试事件（在装置上登录一次），到态势感知平台查看是否收到
```

期望结果：态势感知平台上能看到该加密装置的日志上送；触发登录/操作后平台实时收到对应日志；日志时间戳与现场时间一致，无时间偏差。

### E3 登录口令强度、保存问题

**问题**

> 评估表原文：加密装置登录口令是否登记保存，并检查加密装置口令是否满足 8 位（字母+数字）。做好加密装置登录口令登记保存。若忘记加密装置密码，则联系对应厂家重置密码（不是重置加密装置）
> 作业项分组：口令问题

---

#### 🔍 风险原理

- **弱口令/默认口令极易被攻破。** 装置出厂带默认账号口令，若上线后未修改或改成"12345678"这类弱口令，攻击者猜测或暴力破解即可登录，进而篡改加密策略、放行明文通道，纵向边界失守。
- **口令无人登记，关键时刻进不去。** 口令只记在某人脑子里，人员变动或遗忘后设备"无人能进"，业务故障应急时连设备都登录不了，只能干等厂家。
- **口令管理混乱导致泄露。** 多台装置共用同一口令、口令写在设备标签或纸条上、放在无权限控制的共享目录，都会显著增加泄露风险，一旦泄露影响面覆盖多台设备。

#### 配置/加固方法

**1. 检查当前口令强度**

登录设备，进入"用户/口令管理"界面核对：

| 检查项 | 要求 |
| --- | --- |
| 口令长度 | ≥ 8 位 |
| 字符构成 | 字母 + 数字（建议再叠加大小写与特殊符号） |
| 是否默认 | **非厂商出厂默认口令** |

不满足的立即修改。设置新口令时避免使用设备名、厂商名、工号、连续数字等易猜测内容。

> **注意**：本表要求为"8 位（字母+数字）"，比其他 sheet 的"8 位含数字、大小写字母、特殊符号"略低——加密装置固件支持的字符集通常受限，**以本表要求为准**，但有余量时建议按更高标准设置。

**2. 修改/清除默认账号口令**

将厂方出厂默认管理账号口令改掉；存在多余账号（如调试临时账号）的一并清理或禁用，只保留必要的管理账号。

**3. 口令登记保存**

把各台加密装置口令正式登记进口令台账，明确保管人与保管方式：

- 纸质台账密封保存，或使用加密电子文档；
- 逐台记录：设备名称/型号、管理 IP、账号、口令（或口令密级保管位置）、保管人、更新时间；
- 口令变更后同步更新台账，**交接时当面核对**。

**4. 明确"忘密码"的处置流程**

确认现场人员都清楚：**忘记密码时联系对应厂家重置密码，而不是复位/重置整台加密装置。**

> 整台装置复位会清空全部加密策略和隧道配置，导致业务大面积中断，代价远高于重置口令。厂家为**卫士通**。

#### 特殊情况处理

- 修改口令前先确认当前口令可正常登录，避免改完自己进不去；建议保留一个备用管理账号或临时会话再操作。
- **6 台装置避免使用完全相同的口令**，至少区分主站侧与站内各台，缩小单一口令泄露的影响面。
- 口令台账属敏感资料，须落实权限控制与更新机制，不得放在共享目录。
- 厂家重置密码通常需现场或远程配合，可能涉及停机窗口，**重置前先备份配置（见 E1）**。

#### 📌 加固后的验证

```bash
# 1. 用新口令登录设备，确认可正常登录
# 2. 核对口令长度 ≥ 8 位、含字母 + 数字
# 3. 确认口令已登记进台账，保管人明确
```

期望结果：使用新口令可正常登录；口令满足 8 位（字母+数字）强度要求且非默认口令；口令已登记保存、保管人明确；现场人员能正确说出"忘密码 → 联系厂家重置密码，而非重置整台加密装置"的处置流程。

### E4 加密装置远程管理

**问题**

> 评估表原文：加密装置是否与主站加密管理装置建立远程管理。与加密装置主站（地调或中调）联系，与主站加密管理装置建立连接
> 作业项分组：远程管理

---

#### 🔍 风险原理

- **装置"离线"，主站看不见。** 未建立远程管理时本站装置在主站侧是"失联"状态，主站无法远程监控运行状态、隧道健康度与告警，异常只能靠站内人员现场发现，响应慢、盲区大。
- **策略/证书无法统一下发。** 加密装置需主站定期下发策略更新与证书，**证书到期不换会导致隧道中断**。没有远程管理通道只能现场手工同步，易出现本站与主站策略不一致、证书过期未换而业务中断。
- **故障处置依赖现场，效率低。** 建立远程管理后主站可远程读取状态、协助排查、远程下发配置，否则只能等人员到场。

#### 配置/加固方法

**1. 与主站（地调或中调）联系**

先与主站加密管理值班联系，确认本站装置的登记信息：装置名称、设备 ID、证书、管理 IP、归属关系，并约好联调时间窗口。

**2. 配置远程管理通道**

在加密装置上配置指向主站加密管理装置的管理通道：

| 配置项 | 值 |
| --- | --- |
| 管理通道方式 | 专用管理网口 或 调度数据网管理 VLAN |
| 主站管理装置 IP | 由主站提供 |
| 本端管理 IP | 按主站分配 |

确保该管理通道与主站加密管理装置网络可达，且不与业务加密隧道冲突。

**3. 完成注册与证书对接**

配合主站把本站装置注册进主站加密管理装置，完成证书对接，使主站侧能看到本站装置并显示"在线/正常"状态。

**4. 与主站核对状态**

与主站值班共同核对装置状态、策略版本、证书有效期是否一致，确认远程管理建立成功并留档。

#### 特殊情况处理

- **本项目绑定**：本项目对接的是**地调或中调**主站。资料中**没有**主站加密管理装置的 IP、隧道参数、认证方式等信息，因此**无法判断 6 台装置是否够用，也无法开通**——须先向主站索取。
- 远程管理建立涉及主站、厂站双方配合，需提前约好时间窗口；涉及策略/证书下发时须避开业务高峰并报备。
- 管理通道与业务通道可能共用调度数据网，注意区分管理 VLAN/管理口，避免与业务隧道互相影响。
- **证书校验对时间敏感**，先确认装置时间与主站时钟同步，避免时间偏差导致校验失败。
- 建立主站集中管理后，站内改本地策略前须先与主站沟通，否则可能被统一下发的策略覆盖。
- 不同厂家的管理通道配置界面差异较大，联调时按主站下发的联调指导书操作，不要自行摸索。

#### 📌 加固后的验证

```bash
# 1. 在主站加密管理装置上确认本站装置状态为"在线/正常"
# 2. 主站可远程读取本站装置状态、策略版本
# 3. 与主站核对后，双方对装置状态、策略版本记录一致
```

期望结果：主站（地调或中调）加密管理装置上能看到本站加密装置且状态为"在线/正常"；主站可远程读取装置状态与策略版本；双方记录一致，远程管理通道建立成功。

## 三、关键说明

### E2 日志服务器指向态势感知

这是本表唯一的硬绑定项：加密装置的日志服务器 IP 必须配成态势感知的采集口 IP。

对应本项目：清单序号 6 态势感知装置 2 台，到货型号 HR CRPM-3000（数量存在 1 台与 2 台两种说法）。

配置前必须先确定态势感知采集口的实际 IP。资料中态势感知装置只写了"10M/100M/1000M 自适应以太网电口 ≥16 个，光口 ≥8 个"，没有 IP 规划，见 [../07-二次安防系统.md](../07-二次安防系统.md) 资料缺口一节。

### E3 口令无法本地找回

原文明确："若忘记加密装置密码，则联系对应厂家重置密码（不是重置加密装置）"。

含义是加密装置没有本地密码找回机制，忘记只能找厂家。6 台装置的密码必须登记造册并交由运维保管。联系厂家为卫士通 SJJ1632-B 的纵向加密认证装置。

口令复杂度要求 8 位字母+数字，比其他 sheet 的"8 位含数字、大小写字母、特殊符号"要求略低——加密装置固件支持的字符集通常受限，以本表要求为准。

### E4 与主站加密管理装置建立连接

纵向加密不是点对点独立运行，需要与上级主站的加密管理装置建立管理通道。本项目对接的是**地调或中调**。

资料中没有主站加密管理装置的 IP、隧道参数、认证方式等信息，无法判断 6 台装置是否够用，也无法开通。

纵向加密装置数量在资料中存在 6 台与 7 套两种说法，见 [../09-文件间参数差异对照.md](../09-文件间参数差异对照.md)。

### E1 策略备份

与防火墙 C1 同属"策略备份"要求。加密装置的 IPsec 隧道配置、加密算法、认证方式属于敏感配置，备份后随设备台账一并存档。

## 六、原表问题

| 位置 | 问题 |
| --- | --- |
| sheet 结构 | 只有作业项表格，缺"一、基本信息"（无 IP、无设备名称、无品牌固件版本栏）、缺"三、异常情况记录"、缺"四、作业终结"（无评估结论与签字栏） |
| 作业项分组 | 其他 sheet 有"设备管理""用户账号与口令安全"等分组，本表无分组，4 项平铺 |
| 「依据」列 | 全空，未标注引用标准。其他 sheet 每项均引用标准 1～6 之一 |
| sheet 命名 | 表名仅为"加密装置"，未含 X.X.X.X 占位符，与其他 4 个 sheet 的命名格式不一致，无法按名称区分不同设备 |
| E3 | "若忘记加密装置密码，则联系对应厂家重置密码（不是重置加密装置）"这句是提醒性说明而非标准要求，与同列其他内容体例不同 |
