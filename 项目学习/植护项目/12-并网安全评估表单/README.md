# 并网安全评估表单

本目录是广西电网/南方电网统一的**并网网络安全管控（安全评估）表单 V3 空白模板**，按原表的 5 个标签页拆分为 5 个文件。

原表：`项目资料/植护项目/并网网络安全管控表单V3.xlsx`（31.4 MB，含内嵌截图；5 个 sheet）

## 三个必须先说清楚的事实

**1. 表单是空白的，没有为本项目填写。** 所有 IP、主机名、设备名、品牌、固件版本、作业时间、负责人、完成情况（打√）栏位全部为空。文件名中的 "V3" 是模板版本号，不是项目代号。

**2. 这不是本项目自编的表格。** 引用依据全部指向电网企业标准（见第三节），说明它来自广西电网或南方电网的安全评估体系，本项目作为并网工程需按此表单向电网公司报备。

**3. 它的价值是"验收基准"，不是"已完成记录"。** 表单里写死了大量具体参数值（口令长度、日志大小、禁用端口、SNMP 团体名、时区、锁定阈值等），这些是本项目二次安防设备与主机加固的**考核红线**。设备到货后配置与主机加固施工，都应对照本表单逐项自查。

## 二、每篇文档的结构与写法

5 篇文档统一采用**五段式**结构，与 [AGCAVC1 附件1](<../../../系统加固/220kV双文光伏电站/加固报告/AGCAVC1(198.120.0.206)_附件1/README.md>) 的现场写法一致：

| 章节 | 内容 |
| --- | --- |
| 标题 + 引用块 | 对应 sheet 名、行列数、作业项编号范围、填表数量 |
| 平台说明块 | 厂商/型号/固件版本、操作依据来源（⚠️ 标注推断或未核实处） |
| 第一节 | 基本信息（待填）或作业项原表内容 |
| 第二节 | **逐项操作方法**：`## 问题` → `### 🔍 风险原理` → `### 配置/加固方法` → `### 特殊情况处理` → `### 📌 加固后的验证` |
| 后续章节 | 必装补丁、漏洞清单、必装软件、本项目相关、原表不一致处、逐项参考文档索引、相关文档 |

每项的"配置/加固方法"含**可执行命令或 GUI 路径**、"特殊情况处理"覆盖例外与业务冲突、"加固后的验证"含验证命令与期望结果。

**平台差异是本轮整理中最易出错的地方**：

- **MSR3620-X1 是 H3C 设备（Comware V7），不是华为设备**——其 ACL、SNMP、SSH 命令语法与华为 VRP 完全不同，04 文档已按平台分块给出；
- **防火墙 V600R007C20/SecOS 与交换机 VRP V200 的命令不同**（如防火墙用 `firewall session-table`、`web-cli`，交换机用 `acl`、`snmp-agent`）；
- **加密装置无公开 CLI**，不得照搬其他厂家（南瑞、科东、东土）命令。

防病毒系统"每套配备 10 个 windows 服务器防护授权、10 个 linux 服务器防护授权"这个配置，直接解释了表单为什么分 Windows 和 Linux 两个独立 sheet——两种操作系统要分别出表单、分别打钩。

光传输设备（华为 E6616）不在本表单覆盖范围内，需另找对应作业表。

### 表单与设备的硬绑定关系

表单不只是检查设备本身，还规定了设备之间必须怎么连：

| 表单项 | 规定内容 | 绑定的设备 |
| --- | --- | --- |
| E2 | 加密装置日志服务器 IP = **态势感知采集口 IP** | 纵向加密 ↔ 态势感知 |
| B13 | syslog 转发至 `loghost`（态势感知） | Linux 主机 ↔ 态势感知 |
| A12 / B19 | SNMP 团体名 **`GXhmrjsw-q3`**，且限定合法来源主机 IP | 主机 ↔ 态势感知/堡垒机 |
| C2 | 管理口仅允许**堡垒机、态势感知**访问 SSH 与 HTTPS | 防火墙 ↔ 堡垒机/态势感知 |
| D4 | ACL 仅允许**堡垒机、态势感知**访问网络设备 SSH 管理服务 | 交换机/路由器 ↔ 堡垒机/态势感知 |
| A26 / B3 | 远程管理端口 **23333**（Linux SSH 改 **22222**），仅堡垒机可达 | 主机 ↔ 堡垒机 |
| A23 / B25 | USB 口封死，**原则上保留一个数据拷贝接口** | 清单序号 13 杀毒 U 盘、序号 14 安全 U 盘 |
| A27 | 卸载 TeamView、向日葵等远程运维软件 | 与堡垒机强制收口一致 |
| D21 | 重要服务器采用 IP+MAC+端口绑定 | 交换机 ↔ 主机 |

结论：堡垒机、态势感知、安全审计三台设备是整个体系的汇聚点，表单里所有"仅允许堡垒机、态势感知访问"的条款都指向它们。这三台设备不到位，主机加固和设备加固就形成不了闭环。

## 五、表单结构与填写规则

四个 sheet（Windows、Linux、防火墙、交换机路由器）结构一致：

| 章节 | 内容 |
| --- | --- |
| 一、基本信息 | 作业时间、作业任务、作业负责人、作业人员、主机名/设备名、IP 地址、Windows/Linux 版本、数据库版本、中间件版本、设备品牌与固件版本 |

| 四、作业终结 | 总体评估结论【合格、不合格】+ 评估作业人员签字 + 日期 |

**结论规则：各项合格总体才合格。** 任一作业项不合格，整台设备/主机判定为不合格。

`加密装置` sheet 是简化版，只有作业项表格（E1–E4），缺"基本信息""异常情况记录""作业终结"三章，也没有作业项分组。

### Windows 与 Linux 的差异（易填错）

| 项 | Windows | Linux |
| --- | --- | --- |
| 默认路由掩码要求 | ≥16 位（255.255.0.0） | **≥24 位** |
| 明细路由 | 禁止默认路由 | 禁止默认路由，并须显式配置 `10.67.x.0` 网段路由 |
| 远程管理协议 | SSH、HTTPS | SSH（端口 22 改 **22222**） |
| root / Administrator | 重命名 Administrator，禁用 Guest | `PermitRootLogin no` 或 `/etc/securetty` |
| 必装防病毒 | 安天 | 安天 |
| 日志转发 | SNMP 接入态势感知 | SNMP + **SYSLOG** 接入安管平台 |
| USB | 封条封死 | 封条封死（可加 `blacklist usb_storage`） |
| 病毒查杀路径 | 控制面板 / 服务 | `/opt/LinuxKPC/ini/` |
| 日志配置文件 | 事件查看器 | `/etc/syslog.conf`（RHEL 6 系）/ `/etc/rsyslog.conf`（CentOS 7 系） |
| 服务管理 | `services.msc` | `systemctl`（CentOS 7）/ `chkconfig`、`startsrc`（RHEL 6 系） |
| umask | 不适用 | `umask 022` |
| UID 0 检查 | 不适用 | `awk -F: '($3==0){print $1}' /etc/passwd` |

### ⚠️ Linux 发行版差异（本表最大落地风险）

原表命令**混用了 CentOS 7 系与凝思 Linx（RHEL 6 系）两套体系**，直接照抄会失败。**填表前必须 `cat /etc/redhat-release` 确认实际发行版**：

| 项目 | CentOS 7 系 | 凝思 Linx / RHEL 6 系 |
| --- | --- | --- |
| 服务管理 | `systemctl` | `chkconfig --list`、`service`、`startsrc`/`stopsrc` |
| 日志 | rsyslog（`/etc/rsyslog.conf`） | syslog（`/etc/syslog.conf`） |
| 日志文件 | `/var/log/messages` | `/var/adm/messages` |
| 时间同步 | `chronyd`/`chronyc` | `ntpd`/`ntpdate` |
| 防火墙 | firewalld（iptables 底层） | iptables |
| 路由持久化 | `nmcli` 或 `network-scripts/` | `network-scripts/` |

**不要在同一台主机上混用两套命令。** 02 文档每项均标注了两套分支。

## 七、表单自身的问题

模板本身存在若干错误，使用时需注意，不要照抄错值。

| 位置 | 问题 | 修正 |
| --- | --- | --- |
| Windows 作业项编号 | 顺序为 1、2、3、4、**6**、7、8、**8**、9——缺"5"，且"8"重复（"默认路由"与"漏洞名称"同编号） | 按编号对应内容填即可 |

| Windows A24 | 注册表键名写成 `npserver` | 正确键名为 **`NtpServer`**（`HKLM\SYSTEM\CurrentControlSet\Services\W32Time\Parameters`） |
| Windows A26 | 同时要求"仅堡垒机访问 23333"与"禁用 23333" | 不矛盾：禁用非堡垒机来源，保留堡垒机例外 |
| Windows A26 | 要求禁用 53（DNS） | 会破坏解析。除非纯静态 IP 且不用域名，否则不可禁 |
| Linux B24 | 端口列表写成 `5323333` | 应为 **`23333`**，与 A26 一致 |
| Linux B12 / B15 | 只给 `/etc/syslog.conf`、`/var/adm/messages`、`startsrc` | 均为 RHEL 6 系路径/命令，**CentOS 7 系须替换** |
| Linux B2 | 含 `Protocol`、`RhostsAuthentication`、`RhostsRSAAuthentication` | **OpenSSH 7.x 起已废弃**，新版主机可忽略 |
| Linux B6 | PAM 栈含 `nullok` | `nullok` 允许空口令通过 PAM，须配合空口令检查清零 |
| Linux B16 | 只有"日志记录满足 6 个月"一句，**无任何配置** | 须自行制定 logrotate `rotate` 周数 + 集中留存，并向电网公司确认 |
| Linux B26 | `GATEWAY=` 只能一条且等于默认网关，与"禁止默认路由"冲突 | 要精确控制须用 `static-routes` 或 nmcli routes |
| Linux B26 参考文档 | AGCAVC1 序号42 的 B26 是"调度发令主机特有加固" | **与本表 B26 不是同一项，不可直接套用** |
| 防火墙 sheet | 存在两个"6"（"6 关闭不必要的网络服务"与"6 安全防护"） | 按分组标题区分 |
| 交换机 D20 附注 | "只是赌了源端口"应为"堵" | 错别字 |
| 加密装置 sheet | 缺"基本信息""异常情况记录""作业终结"三章，无作业项分组，「依据」列全空 | 见 05 文档第六节 |
| 标准口径 | 南网标准（依据 3）与广西电网标准（依据 4、6）并存，未说明以哪个为准 | 向电网公司确认 |
| 时效性 | 漏洞清单止于 2020 年 20-10 期 | 须补充此后通报，并确认补丁仍适用 |

## 八、主机台账缺口

二次安防设备清单的序号存在缺项：**序号 1–11 之后直接跳到 13，16 之后跳到 18，序号 12 与序号 17 在原表中不存在对应行。**

序号 12 位于"防病毒系统"（11）与"杀毒 U 盘"（13）之间，序号 17 位于"专用调试电脑"（16）与"等级保防测评"（18）之间。这两个位置的合理候选（结合表单体系）可能是序号 12 为某类 U 盘或专用终端、序号 17 为测评或服务类项，但原表无任何线索，不做推测。

影响：Windows/Linux 主机的数量与类型无法从清单完整确定，而表单要求**每台主机单独出一份 sheet**。序号 12/17 澄清之前，无法确定需要填报多少份 Windows 表单和多少份 Linux 表单。

## 十、与等级保测评的区别

清单序号 18「等级保防测评及安全评估服务」与本表单是**不同体系**：

| 项 | 本表单 | 等级保测评 |
| --- | --- | --- |
| 性质 | 电网并网管控作业表 | 第三方等级保护测评 |
| 标准 | 电力监控系统网络安全合规基线技术规范 | 等级保护 2.0 |
| 执行方 | 现场运维/实施人员 | 具备资质的测评机构 |
| 目的 | 向电网公司报备并网安全状况 | 出具等级测评报告 |
